# Design — T-004: Vehicle-data adapter — NHTSA vPIC + Recall API (`packages/adapters/nhtsa`)

- **Task:** `tasks/T-004-nhtsa-vpic-recall-adapter.md`
- **Spec basis:** `specs/00-shared-core-architecture.md` — "Vehicle data" (VIN decode + recalls → NHTSA vPIC + Recall API. Free, authoritative.), "Integrations — anti-corruption / adapter layer (shared)" (Core services never see a provider's shape.), "Core domain model" (`ValuationSnapshot · VehicleData (cached, timestamped)`); `specs/01` A1 scanner card and `specs/02` "Vehicle data / VIN" are downstream consumers only — they impose no additional shape here.
- **ADRs honored:** ADR-001 (Node/TS, vitest, one toolchain), ADR-003 (npm workspaces), ADR-004 (`@deal-copilot/*` npm names, bare import aliases)
- **Spine reference:** `docs/design/T-001.md` §2–§3 and the built `packages/core/src/{domain,adapters}.ts`. This design **references** the spine; it redefines nothing.
- **Stage:** design → build
- **Scope:** one adapter package implementing `VehicleDataAdapter` from `@core` against the real NHTSA public endpoints (live-approved, no credentials), with hermetic fixture tests. VIN decode + recalls **only** — reliability indices, repair ledger, depreciation/TCO (other rows of specs/00 "Vehicle data") are out of Epic 1 scope.

## 0. Interpretive calls made by this design (drift trip-wire log)

| # | Call | Basis |
|---|------|-------|

## 1. Package layout (all inside `packages/adapters/nhtsa/**` ownership)

```
packages/adapters/nhtsa/
├── package.json            ({ "name": "@deal-copilot/adapters-nhtsa", "private": true } — marker only, NO deps)
├── tsconfig.json           (extends ../../../tsconfig.base.json; include: ["src", "test"])
├── src/
│   ├── index.ts            (public API — the only import surface, per T-001 D3 bare-alias rule)
│   ├── adapter.ts          (VehicleDataAdapter implementation; owns error mapping)
│   ├── vin.ts              (local VIN normalization/validation, D3 — pure)
│   ├── vpic.ts             (vPIC raw-shape types + narrowing → VinDecode; INTERNAL, not exported)
│   └── recalls.ts          (Recall API raw-shape types + narrowing → RecallRecord[]; INTERNAL, not exported)
└── test/
    ├── fixtures/           (checked-in recorded payload shapes, §5)
    │   ├── vpic-decode-success.json
    │   ├── vpic-decode-undecodable.json
    │   ├── vpic-malformed.json
    │   ├── recalls-success.json
    │   └── recalls-empty.json
    ├── decode.test.ts
    ├── recalls.test.ts
    ├── vehicle-data.test.ts   (toVehicleData assembly)
    └── live-smoke.test.ts     (opt-in, D7)
```

Rules encoded:

- **Zero dependencies.** `package.json` has no `dependencies`/`devDependencies` keys at all (root owns `typescript` + `vitest`; HTTP is built-in `fetch`, D1). Any dep appearing here is a review finding (CLAUDE.md invariant 2).
- **Raw NHTSA shapes never escape.** The types describing vPIC/Recall JSON live in `vpic.ts`/`recalls.ts` and are **not** re-exported from `index.ts`. Since `@adapters/nhtsa` resolves only to `src/index.ts` (T-001 D3, bare aliases), a caller cannot import a provider shape even deliberately — the anti-corruption boundary is structural.
- **No `npm install`, no root edits.** The alias `@adapters/nhtsa` and the vitest include-glob are already predeclared by T-001. Typecheck: `npx tsc -p packages/adapters/nhtsa --noEmit`. Tests: `npx vitest run packages/adapters/nhtsa` from root.

## 2. Exact interface signatures (public API of `src/index.ts`)

The adapter contract itself is **`VehicleDataAdapter` from `@core`** — restated here for reference only, never redefined (single source of truth: `packages/core/src/adapters.ts`):

```ts
// @core (frozen spine — shown for reference, NOT part of this package)
export interface VehicleDataAdapter {
  readonly source: string;
  decodeVin(vin: Vin): Promise<AdapterResult<VinDecode>>;
  getRecalls(vin: Vin): Promise<AdapterResult<RecallRecord[]>>;
}
```

This package exposes exactly three things:

```ts
// packages/adapters/nhtsa/src/index.ts — public API (signatures only; no bodies in this doc)
import type {
  AdapterResult, IsoTimestamp, RecallRecord, VehicleData,
  VehicleDataAdapter, Vin, VinDecode,
} from '@core';

/** Adapter id used in `source` fields and error provenance (D4). */
export const NHTSA_SOURCE: 'nhtsa-vpic';

/** All optional; defaults target the real public endpoints (live-approved, credential-free). */
export interface NhtsaAdapterOptions {
  /** HTTP client injection point — tests pass a fixture-backed stub (D1). Default: globalThis.fetch. */
  fetchFn?: typeof fetch;
  /** Default: 'https://vpic.nhtsa.dot.gov/api' */
  vpicBaseUrl?: string;
  /** Default: 'https://api.nhtsa.gov' */
  recallsBaseUrl?: string;
  /** Per-request timeout, ms. Default 10_000 (D8). */
  timeoutMs?: number;
}

/** Factory — returns a stateless implementation of the @core contract. */
export function createNhtsaVehicleDataAdapter(options?: NhtsaAdapterOptions): VehicleDataAdapter;

/**
 * Pure assembly of the cached, timestamped aggregate (specs/00 core model; AC-3, D5).
 * Caching/persistence of the result is the caller's job — the adapter holds no state.
 * `history` is deliberately absent: Carfax/AutoCheck is T-005's mock-only territory.
 */
export function toVehicleData(
  decode: VinDecode,
  recalls: RecallRecord[],
  fetched_at: IsoTimestamp,
): VehicleData;
```

Nothing else is exported. No class is required by the contract; the factory closes over options and returns an object satisfying the interface.

### Endpoints targeted (live-approved, no credentials — CLAUDE.md "Build and wire now" list)

| Operation | Endpoint | Notes |
|---|---|---|
| `decodeVin` | `GET {vpicBaseUrl}/vehicles/DecodeVinValues/{vin}?format=json` | Flat-format vPIC decode; single response object in `Results[0]`. |
| `getRecalls` (step 1) | same vPIC decode (D2) | Obtains make / model / modelYear. |
| `getRecalls` (step 2) | `GET {recallsBaseUrl}/recalls/recallsByVehicle?make={make}&model={model}&modelYear={year}` | Free Recall API; keyed by vehicle, not VIN (D2). |

Any paid or credentialed NHTSA-adjacent variant is out of scope; introducing one = escalate (task note).

## 3. Data shapes (canonical, all from `@core`)

No new domain types. Mapping targets, by name, from `packages/core/src/domain.ts`:

- **`VinDecode`** `{ vin, make, model, year, trim?, body_class?, engine? }` — target of `decodeVin`. vPIC's ~140 flat fields are narrowed to exactly these; everything else is dropped at the boundary (anti-corruption).
- **`RecallRecord`** `{ campaign_id, component, summary, issued_at }` — element type of `getRecalls`. Maps from Recall API `NHTSACampaignNumber` → `campaign_id`, `Component` → `component`, `Summary` → `summary`, `ReportReceivedDate` → `issued_at` (normalized to `IsoTimestamp`).
- **`VehicleData`** `{ vin, decode, recalls, history?, fetched_at }` — the cached, timestamped aggregate (specs/00 core model), assembled by `toVehicleData` (D5). `history` stays absent here (T-005's contract fills it).
- **`AdapterResult<T>` / `AdapterError`** — the uniform result shape; adapter never throws across the boundary.

Relation to the aggregate root (reference only — owned by core, untouched here): `Deal.resolved_vehicle` is a `Vin`; once a deal resolves a VIN, core services call this adapter and persist the resulting `VehicleData` keyed by that VIN (Postgres, specs/00 "Store"). `DealerThread` / `Message` / `Offer` are not read or written by this package — it has no comms surface at all.

## 4. Error paths per operation

Binding baseline: T-001 §5.1 (outbound-feed adapter table). This section instantiates it for NHTSA. `AdapterError.source` is always `'nhtsa-vpic'`; `retryable` is always stated explicitly and derived from `code`.

### 4.1 `decodeVin(vin)`

| # | Failure mode | Detection | Result (`code`, `retryable`) | Logged (structured) | Surfaces to caller as |
|---|---|---|---|---|---|
| 1 | Mangled VIN (length ≠ 17, illegal chars) | Local pre-validation, **before any HTTP** (D3) | `invalid_input`, `false` | op, source, code — **no VIN in message** | Validation error; fix upstream |
| 2 | Network failure / timeout / abort | `fetchFn` rejects or `AbortSignal.timeout` fires (D8) | `provider_unavailable`, `true` | op, source, code, duration | Caller retries with backoff, or serves stale cached `VehicleData` (it is timestamped for exactly this) |
| 3 | HTTP 5xx | status ≥ 500 | `provider_unavailable`, `true` | op, source, code, status | Same as #2 |
| 4 | HTTP 429 (throttle) | status = 429 | `rate_limited`, `true` | op, source, code | Caller backoff + jitter |
| 5 | Other 4xx (endpoint moved, contract broke) | status 400–499 ≠ 429 | `malformed_response`, `false` | op, source, code, status — **operator alert** | Degraded-feature state ("vehicle data unavailable") |
| 6 | 200 but body is not the expected vPIC shape (JSON parse failure, `Results` missing/empty) | narrowing in `vpic.ts` fails | `malformed_response`, `false` | op, source, code — **operator alert**; **never the raw body** | Degraded-feature state |
| 7 | 200, shape fine, but vPIC could not decode (no usable make/model/year; vPIC in-band error text for undecodable VIN) | field-level check on `Results[0]` | `not_found`, `false` | op, source, code — VIN-less message | "No vehicle data for this VIN" — terminal |
| 8 | 200, vPIC in-band error indicating structurally invalid VIN that passed the local check | vPIC `ErrorCode` field | `invalid_input`, `false` | op, source, code | Validation error |

`auth` is unreachable by construction: the endpoints are credential-free, and no credential exists in this repo to misconfigure (CLAUDE.md structural enforcement).

### 4.2 `getRecalls(vin)`

Two-step (D2); each step maps independently.

| # | Failure mode | Result | Notes |
|---|---|---|---|
| 1 | Step-1 decode fails (any row of §4.1) | The **same** `AdapterError` propagates unchanged | Source stays `nhtsa-vpic`; caller sees one coherent failure, never the internal composition |
| 2 | Step-2 network / 5xx / timeout | `provider_unavailable`, `true` | As §4.1 #2–3 |
| 3 | Step-2 HTTP 429 | `rate_limited`, `true` | As §4.1 #4 |
| 4 | Step-2 other 4xx | `malformed_response`, `false`, operator alert | As §4.1 #5 |
| 5 | Step-2 200 but unexpected shape | `malformed_response`, `false`, operator alert | Narrowing in `recalls.ts` fails; raw body never logged |
| 6 | Step-2 200, valid shape, zero campaigns (`Count: 0`) | **`{ ok: true, value: [] }`** | Empty recalls is a **successful** answer, not `not_found` — a clean vehicle must not look like an error |

### 4.3 Retry / idempotency (both operations)

- Both operations are **pure reads** — naturally idempotent; a retry can never double-write anything. No idempotency key is needed (contrast with outbound comms `client_ref`; nothing of that kind applies here).
- The adapter performs **zero internal retries** (D6). It reports `retryable` truthfully; backoff/jitter policy belongs to the caller per T-001 §5.1. If invoked from an event consumer (e.g. a future vehicle-data refresh flow), the bus's bounded-redelivery discipline (T-001 §5.3) is the retry mechanism — `retryable:false` results must dead-letter/alert, not spin.
- Freshness/staleness policy lives with the caller: `VehicleData.fetched_at` exists precisely so callers can decide serve-stale vs. refetch. The adapter is stateless and does no caching (D5).

### 4.4 Logging discipline

- Logged per call: operation name, `source`, outcome (`ok`/`code`), HTTP status where applicable, duration, attempt context supplied by the caller.
- **Never logged:** raw NHTSA payloads (even though NHTSA data is public, the rule is uniform — provider payloads never enter logs, T-001 §5.1), and no VIN inside `AdapterError.message` (messages are defined log-safe and VIN-less).
- `malformed_response` and unexpected-4xx paths carry an operator-alert obligation: they mean the recorded contract drifted and fixtures must be re-recorded.

### 4.5 Webhooks — none (ack-then-queue rule untouched)

This package registers **no HTTP handler and no webhook surface**; NHTSA is pull-only. The binding specs/00 rule — "webhooks ack immediately, all heavy work runs on the event bus" — is therefore not implemented here, and this design must not weaken it from the consuming side either: because `decodeVin`/`getRecalls` do network I/O, **they must never be called inside a comms webhook handler before the ack** (T-009's handler sequence permits only the synchronous, pure `parseInboundWebhook` pre-ack). Any vehicle-data work triggered by an inbound message belongs in an event consumer after `comms.inbound.received.v1` is durably enqueued and acked. This adapter is only ever a downstream callee of consumers or request-path services with their own timeout budget.

## 5. Test design (hermetic; fixtures only)

- **Fixtures are recorded real shapes**, checked in under `test/fixtures/` (§1 list): a successful flat-format vPIC decode, an undecodable-VIN vPIC response, a malformed body, a recalls response with campaigns, and a recalls response with `Count: 0`. They capture the real contract so `malformed_response` detection is tested against truth, not invention.
- **Every test injects `fetchFn`** (D1): a stub that serves fixtures keyed by URL, records the request (asserting endpoint/query construction, e.g. the D2 two-step for `getRecalls`), or rejects/returns synthetic statuses to drive every row of §4.1–§4.2. **No test touches the network; no test relies on `globalThis.fetch`.**
- Coverage obligations: every error row above; VIN pre-validation short-circuits with zero `fetchFn` invocations; empty recalls ⇒ `ok: []`; decode-failure propagation through `getRecalls`; `toVehicleData` assembles `VehicleData` with the caller-supplied `fetched_at` and no `history`; exported surface is exactly `{ NHTSA_SOURCE, NhtsaAdapterOptions, createNhtsaVehicleDataAdapter, toVehicleData }` (type-level check that no raw provider shape is importable via `@adapters/nhtsa`).
- **Live smoke** (`live-smoke.test.ts`): opt-in via `NHTSA_LIVE=1`, skipped by default (D7) — CI never depends on the network (AC-4).
- Run from root: `npx vitest run packages/adapters/nhtsa`.

## 6. Invariant touchpoints

| Invariant (source) | How this task could break it | How the design protects it |
|---|---|---|
| No unapproved integration or spend (CLAUDE.md #2) | Adding an HTTP lib; targeting a paid/credentialed vehicle-data variant | Zero deps — built-in `fetch` only (D1); endpoints are exactly the free public NHTSA vPIC + Recall API on the "build and wire now" list; `auth` path unreachable because no credential exists (§4.1); anything paid = escalate (§2 note) |
| Core never sees a provider's shape (specs/00 adapter layer) | Exporting vPIC/Recall response types; leaking raw fields through results | Raw shapes are internal modules never re-exported (§1); bare-alias resolution makes deep import impossible (T-001 D3); results are spine types only (§3); tests assert the export surface (§5) |
| Spine defined once (ADR-001) / no parallel types | Re-declaring `VinDecode`/`RecallRecord`/`VehicleData` or widening `VehicleDataAdapter` | Everything imported from `@core`; AC-3 met by a pure helper (D5) instead of a contract change; validator grep for spine `interface` declarations outside core stays clean |
| `VehicleData` cached + timestamped (specs/00 core model) | Adapter caching internally or omitting timestamps | Adapter stateless; `toVehicleData` requires `fetched_at`; staleness policy explicitly caller-side (§4.3) |

None — no frozen-spine change and no unapproved integration is required. Deviations resolved in-design and logged (not blocking):

1. **Recall API is not VIN-keyed** — resolved as the two-step decode → `recallsByVehicle` composition behind the unchanged spine signature (D2).
