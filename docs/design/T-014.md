# Design — T-014: Comms service v0.5 — notes-first capture, call metadata only, transcription stage removed (`services/comms`)

- **Task:** `tasks/T-014-comms-service-v05-migration.md`
- **Spec basis (authoritative, v0.5):** `specs/00-shared-core-architecture.md` — "Comms aggregation layer (provider-agnostic — shared)", "Core domain model", "Cardinality invariants (structurally enforced)", "Budget ceiling vs. fair price — two different questions", "Dealership data tenancy", "Async backbone (shared)", "Receipt layer (trust engine)"; `specs/01-consumer-product-spec.md` — "Consent & recording posture *(resolved 2026-08-07)*", "Web surface — war room first"
- **Decisions honored:** `decisions/OPEN-QUESTIONS.md` Q12 (AMENDED — dealership tenancy), Q14 (transcription dropped from scope), Q16 (VIN user-entered), Q17 (concierge comparative not forensic), Q22 (`Message` RATIFIED); ADR-001 (Node/TS; spine defined once, no parallel type definitions), ADR-005 (`sale_price` optional; a missing required input is **UNEVALUABLE**, never zero), ADR-006 (`current_offer` = per-field newest-message-wins), ADR-008 (Epic-2 library set; API defaults to in-memory), ADR-009 (dependency edits are T-015-only; `typecheck` scripts are T-016…T-019-only)
- **Predecessor design:** `docs/design/T-009.md` is the behavioral baseline for this service. **This document supersedes it where they differ**, and only inside `services/comms/**`. `docs/design/T-010.md` (spine) and `docs/design/T-012.md` (`extractOffer`, receipt contract) are upstream and binding — this design consumes them and never restates them.
- **Stage:** design → build
- **Scope:** one service. No HTTP surface (T-019), no Postgres/S3 implementation (T-017/T-018), no origination, no new dependency, no `package.json` edit, no root-config edit.

**Ownership boundary.** Writes are confined to `services/comms/**`, plus `tasks/T-014-*.md` and this file. `packages/core` is frozen and imported. `packages/flag-engine`, `packages/adapters/*` are red against the v0.5 spine by design — T-011/T-013 repair them. **A builder on this task must not touch them and must not report their breakage as a finding.** `services/comms/package.json` is NOT edited: ADR-009 confines dependency edits to T-015 and per-package `typecheck` scripts to T-016…T-019, and T-014 is in neither set.

**Starting state (measured, not assumed — 2026-08-07).** `npx tsc -p services/comms --noEmit` reports **52 errors** across `src/**` and `test/**`. They fall into exactly five families, and every one of them is a v0.5 spine change this task exists to absorb:

| Family | Representative error | Why |
|---|---|---|
| Transcription contracts gone from `@core` | `Module '"@core"' has no exported member 'TranscriptionRequestedV1'`; `Type '"comms.transcription.requested.v1"' does not satisfy the constraint 'SpineEventType'` | Q14 removed the stage from the bus entirely |
| `Message.author` now required | `Property 'author' is missing … but required in type 'Message'` | Q22 ratified `author`; it is never inferred |
| `Message.transcript` gone | `Property 'transcript' does not exist on type 'Message'` | specs/01 consent posture — the field was removed, not nulled |
| `DealerThread` reshaped | `Property 'dealer_id' \| 'dealer_name' \| 'contact' does not exist on type 'DealerThread'`; `'"@core"' has no exported member named 'DealerContact'` | Q12 AMENDED — `dealership_id` + `working_with` + `process_step` + `vehicle_instance` |

## 0. Interpretive calls made by this design (drift trip-wire log)

Every call below sits inside spec ambiguity or is a mechanical consequence of a v0.5 spec line. None touches a protected path, none adds an integration, none amends the frozen spine. **A builder who finds any insufficient must stop and escalate — do not improvise an alternative.**

| # | Call | Basis |
|---|------|-------|
| **D1** | The `TranscriptStub` port, both transcription consumers (`transcription-stub-worker.ts`, `transcription-apply.ts`), `CommsStore.setTranscript`, `CommsServiceDeps.transcribe`, and the two queue subscriptions are **deleted** — not stubbed, not feature-flagged, not left as a no-op. | AC-1; specs/01 "Consent & recording posture": "No ASR/transcription provider is required, so none is approved or wired"; Q14. `@core` already deleted the event contracts, so a retained port would be a seam to a stage that cannot be published to. A dormant port is also an unapproved-integration invitation (CLAUDE.md invariant 2) — the absence *is* the enforcement. |
| **D2** | `ConsentHook` **survives with its name and its single method**, but the method returns `void` instead of `{ transcribe: boolean }`. It is an inbound-call **observation** seam for per-product behavior, and it can no longer authorise anything because it has no return channel to authorise with. | AC-4: "The consent hook no longer gates a transcription decision; whatever per-product seam remains does not exist to authorise recording or transcription". specs/00's call flow still says "(consent handling per product)" for products that owe a *disclosure*, and the task objective keeps `ConsentHook` in the port list as a swap seam. `{ transcribe: boolean }` is literally a transcription authorisation, so the return type had to go; the seam itself did not. Reversal cost if the chief prefers outright deletion: delete one interface, one const, one dep field, one call site. |
| **D3** | The hook is invoked **after** the call `Message` is appended and cannot suppress the append, the alert, or anything else. A hook that throws yields `retry` (bounded → dead-letter, envelope intact), never a silent swallow and never a dropped message. | specs/00: "Provider timeouts must never drop a dealer message." A per-product hook that runs before the durable write could delete a dealer contact record by throwing — the exact failure the no-drop rule forbids. Ordering makes suppression unrepresentable rather than merely discouraged. |
| **D4** | A note is **not** modelled as an `InboundComms` and never rides `comms.inbound.received.v1`. It enters through its own service surface (`NoteIntake.submitNote`) and its heavy work is enqueued as `offer.extraction.requested.v1` with `channel: 'note'`. | `@core` `InboundChannel = Exclude<MessageChannel, 'note'>` with the stated reason "A note is authored in-app and can never arrive from a provider webhook". `SpineEventType` is a closed union in the frozen spine and `offer.extraction.requested.v1` already documents `message_ref` as "caller-generated ref for a note" — the spine anticipated this path exactly. No new event type is invented (that would require editing frozen `packages/core`). |
| **D5** | Note submission **appends synchronously, then enqueues extraction** — it is not ack-then-queue. The provider path is unchanged (parse → enqueue → ack, no store I/O before the ack). | specs/00's ack-then-queue rule is scoped to *webhooks* ("webhooks ack immediately … Provider timeouts must never drop a dealer message"): its purpose is that a provider's timeout cannot lose a message we have not yet stored. A note has no provider and no retrying counterparty — the buyer is the durability mechanism, and returning "saved" for something not yet stored is the failure mode here. The *heavy* work (extraction) still runs on the bus, which is the half of the rule that is universal (AC-11). |
| **D6** | `Message.author` for provider-originated inbound (`sms`, `email`, **and `call`**) is the constant `'dealer'`. It is read off the fact that the message arrived inbound through the deal's identity, never off body content, never off a provider field. | specs/00 `Message`: author is "who produced this text — never inferred". For an inbound provider message the counterparty is *known from the transport*, not inferred. For a bare call record there is no text at all, so the honesty risk the field guards (self-authored text wearing a dealer label) is structurally absent — and `'dealer'` states the true fact "the dealership called". Reversal cost: one constant in `buildMessage`. **Note the deliberate difference from `docs/design/T-012.md` D7**, where a *receipt* `call_meta` entry's author means "who logged the call on the account side"; that is a different question asked by a different type, and neither answer may be copied onto the other. |
| **D7** | `Message.author` for a note is **caller-supplied and required**, typed `Exclude<MessageAuthor, 'dealer'>`; `direction` is not caller-supplied at all — the service fixes it to `'internal'`. A missing or unknown author rejects the submission with nothing written. | AC-7; Q22; specs/00 `Message` ("`internal` = the buyer's/operator's own record"; core `domain.ts`: "`note` = text the buyer/operator authored"). A dealer-authored note and a non-internal note are contradictions of the spec's own gloss, so they are unrepresentable rather than merely rejected — the same enforcement shape T-012 D6 fixed for receipt entries. Accepting `direction` from the caller would add a way to spell a contradiction for no gain. |
| **D8** | `StoredMessage.provider_message_ref` becomes `message_ref`, and `source: string` becomes a discriminated `origin: { kind: 'provider'; source } \| { kind: 'in_app' }`. In-app refs are namespaced `note:<client_note_ref>` at the intake boundary. | The correlation column now carries two kinds of ref (provider id, caller-generated note ref) and `source` meant "adapter id that parsed it", which no note has. `origin` makes a fabricated adapter id on an in-app message **unrepresentable** — the same rule T-012 D9 applied to `provider_message_ref` on receipt notes. Namespacing removes any chance a client-chosen note ref collides with a provider id in the per-deal ref index (a collision would silently swallow one of the two messages as a "duplicate"). |
| **D9** | Thread resolution is **two steps**: (a) account-private contact → `dealership_id` (per-deal index, may miss), then (b) `dealership_id` → thread row, **created if absent** with `process_step: 'information_gather'`. The service **never mints a `Dealership`**. | specs/00 "Dealership data tenancy": `Dealership` is "one shared row per real dealership", global and batch-loadable. Minting `dealership:+15550200001` from an unrecognised phone number would inject account-guessed junk into a globally shared namespace, which is precisely what the tenancy split exists to prevent. AC-8 says thread resolution "produces/updates" a thread — step (b) is that production; step (a) is a lookup, never a creation. `information_gather` is Q12's first process step and the only one true of a relationship whose first message just arrived. |
| **D10** | Inbound from a **known deal identity** but an **unknown dealership contact** is recorded in the existing unrouted holding area with a second reason, `'no_thread_match'`, carrying `deal_id`. It is not dropped, not guessed onto a thread, and not turned into a new `Dealership`. | Composition of the no-drop rule (specs/00) with D9. This is a **behavior change from T-009**, where an unknown sender auto-created a thread keyed by its own contact point — that key no longer exists on `DealerThread`. The record is held whole and replayable, so once the buyer names the dealership the message lands in the right thread; nothing is lost and nothing is fabricated. |
| **D11** | The call path publishes `alert.dispatch.requested.v1` with `kind: 'call_logged'` and **publishes no extraction request** (there is no text to extract). SMS/email publish `kind: 'message_received'` plus an extraction request, unchanged. The note path publishes an extraction request and **no** `message_received` alert. | specs/00 v0.5 call flow: "log call metadata … → notify owner → owner writes a note → run offer-extraction on the note"; `@core` documents `call_logged` as exactly "the 'you had a call — write your note' prompt". Suppressing `message_received` on notes is not a spec line but its inverse is absurd — notifying the buyer that the buyer wrote something. `offer_received` still fires from `extraction-apply` when the note yields terms, so the useful signal survives. |
| **D12** | When `InboundComms.call_meta` is present it is copied **verbatim**; when absent, the service synthesizes `{ started_at: received_at, party?: from.phone ?? from.email }` and **never** a `duration_seconds`. | specs/00: "log call metadata (time, direction, party) on DealerThread". Under v0.5 a `Message` carries no `from`/`to`, so an absent `call_meta` would lose the party the spec names. `received_at` and `from` are provider-supplied facts already inside the envelope — copying them is not inference. A duration is *not* derivable from anything present, and ADR-005's rule is that a missing input stays missing rather than becoming zero. Half-merging a present-but-incomplete `call_meta` is deliberately not done: the adapter is the authority on its own record. |
| **D13** | Note text has a bounded maximum (`max_note_chars`, injectable, default **20 000**). **Provider-inbound text is never capped, never truncated, and never rejected for size.** | `docs/design/T-012.md` §4.1 assigned "bounding message size" to this boundary and forbade the extractor from truncating (a false `found: false` on a long email is the one failure the product cannot afford). The asymmetry is the point: a note is in-app authored input on a write path with no retrying counterparty, so an unbounded string there is a resource-exhaustion vector; a dealer message is evidence, and no-drop outranks tidiness. The number has no spec line — it is a designer call, injectable, and the reversal is one default. |
| **D14** | The comms service does **not** write to `@receipt` in this task. | Task ACs do not mention the receipt layer; wiring it would require a `services/comms/package.json` dependency edit, which ADR-009 confines to T-015. `docs/design/T-012.md` §4.6 already fixes the rules the eventual writer inherits (append after the ack, `dedupe_key` from `idempotency_key`, author from the authenticated session). Recorded here as a forward note (§7.5), not built. |

#### Store port — seam: Postgres relational core (T-017)

```ts
/**
 * Where a stored message came from. A note is authored in-app and has no
 * adapter and no provider id, so a fabricated one is unrepresentable (D8).
 */
export type MessageOrigin =
  | { kind: 'provider'; source: string }  // adapter id that parsed it
  | { kind: 'in_app' };                   // authored in the product

/**
 * Spine Message + correlation columns. Postgres seam: the messages table,
 * where these are ordinary columns. `message_ref` is persistence metadata, NOT
 * a spine field — no field is added to any spine type (ADR-001).
 */
export interface StoredMessage {
  message: Message;      // the ONLY message shape stored — @core, verbatim
  message_ref: string;   // provider id, or `note:<client_note_ref>` (D8)
  origin: MessageOrigin;
}

/** Seam: quarantine table. No-drop holding area for unparseable payloads. */
export interface QuarantinedRecord {
  source: string;
  parse_error: AdapterError;   // @core shape, from CommsInboundQuarantinedV1
  raw_payload_ref: string;     // → RawPayloadStore
  recorded_at: IsoTimestamp;
}

/** Why an inbound item could not be placed. Both are HELD, never dropped, never guessed. */
export type UnroutedReason =
  | 'no_identity_match'  // no deal owns the identity that was contacted
  | 'no_thread_match';   // deal found, but the sender maps to no known Dealership (D9, D10)

/** Seam: unrouted-inbound table. Held whole, replayable. */
export interface UnroutedRecord {
  source: string;
  inbound: InboundComms;   // @core shape — held whole
  reason: UnroutedReason;
  /** Present only for 'no_thread_match' — the deal is known, the dealership is not. */
  deal_id?: string;
  recorded_at: IsoTimestamp;
}

/** Read side. Returns are store-internal references; the read model deep-clones. */
export interface CommsStoreReader {
  /** Assembled @core aggregate: deal + dealer_threads[] + messages[] + current_offer. */
  getDeal(deal_id: string): Deal | undefined;
  getThread(deal_id: string, dealership_id: string): DealerThread | undefined;
  /** Correlation-index lookup — the rollup reads the contributing Message.timestamp here. */
  getMessageByRef(deal_id: string, message_ref: string): StoredMessage | undefined;
  listQuarantined(): readonly QuarantinedRecord[];
  listUnrouted(): readonly UnroutedRecord[];
}

export interface CommsStore extends CommsStoreReader {
  // -- seeding + identity routing (the AUTHORITATIVE mapping) --------------
  putDeal(deal: Deal): void;
  /**
   * Seed/replace a thread row for a KNOWN dealership. Also binds
   * `working_with`'s phone/email into the account-private contact index.
   */
  putThread(deal_id: string, thread: DealerThread): void;
  /** Normalization at bind and at resolve is identical (E.164-shaped phones, lowercased aliases). */
  bindIdentity(deal_id: string, identity: IdentityRef): void;
  /** EXACT match only over normalized values — never fuzzy. */
  resolveDealByIdentity(to: { phone_number?: string; email_alias?: string }): string | undefined;

  // -- account-private dealership contact routing (Q12 AMENDED, D9) --------
  /**
   * Binds a dealership contact point → dealership_id WITHIN ONE DEAL. The
   * deal_id parameter is first and mandatory: a contact lookup that is not
   * scoped to one account-owned deal is inexpressible on this port (AC-9).
   */
  bindThreadContact(
    deal_id: string,
    dealership_id: string,
    contact: { phone?: string; email?: string },
  ): void;
  /** EXACT match only, within this deal. undefined ⇒ unrouted (D10) — never a guess, never a new Dealership. */
  resolveDealershipByContact(
    deal_id: string,
    from: { phone?: string; email?: string },
  ): string | undefined;

  // -- threading (append-only; idempotent by construction) -----------------
  /**
   * Returns the thread for a KNOWN dealership_id, creating the row on first
   * contact with `process_step: 'information_gather'` and no vehicle_instance
   * and no working_with (D9). Deterministic key ⇒ idempotent under redelivery.
   */
  resolveOrCreateThread(deal_id: string, dealership_id: string): { dealership_id: string };
  /** No-op when (deal_id, message_ref) already appended — the keyed write that makes redelivery safe. */
  appendMessage(deal_id: string, dealership_id: string, row: StoredMessage): 'appended' | 'duplicate';

  // -- fill-once enrichment (never overwrites, never deletes) --------------
  attachExtractedOffer(deal_id: string, message_ref: string, offer: Offer): 'set' | 'already_set' | 'not_found';
  /** Applies §3 mergeCurrentOffer to the thread; stores offer + RollupState (ADR-006). */
  rollupCurrentOffer(deal_id: string, dealership_id: string, contribution: RollupContribution): void;

  // -- no-drop holding areas (operator surfaces via read model) ------------
  recordQuarantined(rec: QuarantinedRecord): void;
  recordUnrouted(rec: UnroutedRecord): void;

  // -- consumer idempotency ledger (belt; the keyed writes above are braces)
  hasProcessed(consumer: string, idempotency_key: string): boolean;
  /** Called only AFTER a handler's writes and publishes succeed. */
  markProcessed(consumer: string, idempotency_key: string): 'first' | 'duplicate';
}
```

**Deleted from this port (D1):** `setTranscript`. There is no fill-once transcript enrichment because there is no transcript.

**Never on this port, by construction:** any method that mutates `process_step`, `working_with`, `vehicle_instance`, `target_vehicle`, `walk_away_number`, or a `Dealership` record. The comms service threads messages and rolls up offers; negotiation state and vehicle identity belong to the buyer through the API (T-019/T-020). A message arriving cannot advance a negotiation step, and nothing here can infer one.

### 1.3 Note intake — `src/notes.ts` (new)

```ts
import type { IsoTimestamp, MessageAuthor } from '@core';

/**
 * The buyer's or operator's own written record. `direction` is NOT accepted
 * from the caller — the service fixes it to 'internal'; `author` is required
 * and cannot be 'dealer' (D7; AC-7; specs/00 Message: "never inferred").
 */
export interface NoteSubmission {
  deal_id: string;
  /** Which dealership relationship this note is about. The thread must already exist. */
  dealership_id: string;
  /** Caller-generated idempotency anchor. Required — it is what makes a retry safe. */
  client_note_ref: string;
  /** Who typed it. From the authenticated session on the write path, NEVER from a request body. */
  author: Exclude<MessageAuthor, 'dealer'>;
  body: string;
  /** When the buyer/operator wrote it. Defaults to the injected clock when absent. */
  occurred_at?: IsoTimestamp;
}

export type NoteRejectionReason =
  | 'blank_deal_id'
  | 'blank_dealership_id'
  | 'blank_client_note_ref'
  | 'blank_body'
  | 'body_too_long'
  | 'invalid_author'
  | 'invalid_occurred_at';

/**
 * Transport-neutral outcome that ENCODES the HTTP status, exactly as
 * WebhookIngestOutcome does — the T-019 shell maps it 1:1 and decides nothing.
 */
export type NoteSubmitOutcome =
  | {
      kind: 'recorded';
      http_status: 201;
      message_ref: string;
      disposition: 'appended' | 'duplicate';
    }
  | {
      /** Note IS durably stored; only the extraction enqueue failed. Caller retries the SAME client_note_ref. */
      kind: 'recorded_extraction_deferred';
      http_status: 503;
      message_ref: string;
      disposition: 'appended' | 'duplicate';
    }
  | { kind: 'rejected'; http_status: 400; reason: NoteRejectionReason }
  | { kind: 'unknown_deal'; http_status: 404 }
  | { kind: 'unknown_thread'; http_status: 404 };

export interface NoteIntake {
  submitNote(input: NoteSubmission): Promise<NoteSubmitOutcome>;
}

export interface NoteIntakeDeps extends EventSeams {
  store: CommsStore;
  queue: EventQueue;
  /** D13 — in-app input bound. Default 20_000. Provider-inbound text is never capped. */
  max_note_chars?: number;
}

export function createNoteIntake(deps: NoteIntakeDeps): NoteIntake;
```

**Sequence (binding):** validate (pure, no I/O) → resolve deal + thread (both must exist; nothing is created here) → `appendMessage` with `message_ref = 'note:' + client_note_ref` and `origin: { kind: 'in_app' }` → publish `offer.extraction.requested.v1` with `channel: 'note'` → outcome. Append happens before the publish so an extraction request never names a row that will never exist (D5); the publish is re-attempted, not the append, because `appendMessage` is keyed and a repeat is a no-op.

export interface CommsReadModel {
  /** Assembled @core aggregate, deep snapshot (structuredClone) — append-only posture. */

## 2. Data shapes — how the pieces sit together

### 2.1 The three v0.5 flows

```
INBOUND SMS / EMAIL          (specs/00: "webhook → thread onto DealerThread → extract offer")
provider webhook
  └▶ intake.ingest ── parse (sync, pure) ──▶ queue.publish(comms.inbound.received.v1) ──▶ 200 ack
                                                     │
        ┌────────────────────────────────────────────┘
        ▼ inbound-router
        ├─ resolveDealByIdentity(to_identity)            exact match, else → unrouted{no_identity_match}
        ├─ resolveDealershipByContact(deal_id, from)     exact match, else → unrouted{no_thread_match}   (D10)
        ├─ resolveOrCreateThread(deal_id, dealership_id) creates row @ process_step information_gather   (D9)
        ├─ appendMessage  Message{channel, direction:'in', author:'dealer', body, timestamp}             (D6)
        ├─ publish offer.extraction.requested.v1 {channel, text: body}
        └─ publish alert.dispatch.requested.v1  {kind:'message_received'}

INBOUND CALL                 (specs/00: "log call metadata → notify owner → owner writes a note → extract on the note")
provider webhook
  └▶ intake.ingest ──▶ comms.inbound.received.v1 ──▶ 200 ack
        ▼ inbound-router
        ├─ (identity + dealership resolution — identical to above)
        ├─ appendMessage  Message{channel:'call', direction:'in', author:'dealer', call_meta, NO body}   (D12)
        ├─ publish alert.dispatch.requested.v1 {kind:'call_logged'}   ← "notify owner"                   (D11)
        ├─ consent.onInboundCall(deal_id, inbound)  — observation only, after the write, cannot suppress (D2, D3)
        └─ NO extraction request: there is no text.  NO audio. NO ASR. NO transcript. Nothing to consent to.

NOTE (the owner's answer to that prompt — and the primary v0.5 extraction input)
in-app write
  └▶ notes.submitNote ── validate ──▶ appendMessage  Message{channel:'note', direction:'internal',
        │                                                     author:'buyer'|'concierge', body, timestamp}
        │                              message_ref = 'note:<client_note_ref>', origin { kind:'in_app' }  (D7, D8)
        └─▶ publish offer.extraction.requested.v1 {channel:'note', text: body} ──▶ 201

SHARED TAIL — one extractor for all three text sources (specs/00: "The extractor is channel-agnostic")
  extraction-worker : extractOffer({ channel, text })  →  offer.extraction.completed.v1 (offer absent = valid)
  extraction-apply  : attachExtractedOffer (fill-once) → rollupCurrentOffer (ADR-006) → alert{offer_received}
```

The note path and the SMS/email path converge on the **same event type, the same consumer, the same `extractOffer` call, and the same rollup**. There is no note-specific extraction branch anywhere in this service (AC-6).

### 2.2 What a `DealerThread` carries after this task (AC-8)

| Field | Source | Written by this service? |
|---|---|---|
| `dealership_id` | the account-private contact index, bound by the API when the buyer names the dealership | Only as a thread-row key on first contact (D9) — the `Dealership` record itself is **never** created or edited here |
| `vehicle_instance?` | the buyer, through the API | **No.** Absent during `information_gather` and the comms service never fills it |
| `working_with?` | the buyer, through the API (account-private `DealershipContact`) | **No** — read for routing only, and only within its own deal |
| `process_step` | the buyer/operator, through the API | Set **once**, to `information_gather`, at thread-row creation. Never advanced by a message arriving |
| `messages[]` | this service | **Yes** — append-only |
| `current_offer?` | this service | **Yes** — per-field newest-wins rollup (ADR-006) |

### 2.3 Where each `Message` field comes from

| Field | inbound sms/email | inbound call | note |
|---|---|---|---|
| `channel` | `inbound.channel` | `'call'` | `'note'` (fixed) |
| `direction` | `'in'` | `'in'` | `'internal'` (fixed by the service, not caller-supplied — D7) |
| `author` | `'dealer'` (D6) | `'dealer'` (D6) | caller-supplied, `buyer \| concierge`, **required** (D7) |
| `body` | `inbound.body` verbatim | **absent, always** | caller-supplied, non-blank |
| `call_meta` | absent | verbatim, else derived from `received_at`/`from` (D12) | absent |
| `timestamp` | `inbound.received_at` | `inbound.received_at` | `occurred_at ?? now()` |

No field is ever inferred from body content. No field named `recording_url`, `transcript`, `audio_ref`, or `call_ref` exists anywhere on this path — they do not exist on the spine (AC-3).

## 3. Error paths per operation

**Logging.** This service still has **no logger seam** (T-009 §4.1, retained) — nothing here writes a log line, and the rule is recorded so the T-019 HTTP shell inherits it rather than re-deciding it:

> A comms log line MAY carry: `source`, `channel`, `message_ref` or `raw_payload_ref`, `deal_id`, `dealership_id`, consumer name, idempotency key, outcome kind, attempt count, and error codes. It MUST NOT carry: message bodies, note text, email subjects, phone numbers, email addresses, `call_meta.party`, identity aliases, or raw provider payloads.

Note `call_meta.party` is on the forbidden list: it is a phone number or a person's name, and it is the one PII-shaped field the v0.5 call record legitimately stores.

### 3.1 `intake.ingest(channel, raw_payload)` — never throws

| Failure mode | Result | Retry / idempotency | Logged | Surfaces to caller |
|---|---|---|---|---|
| Parse fails (`AdapterResult.ok === false`) | Raw payload stashed → quarantine variant enqueued → **200 `quarantined`** | Deterministic quarantine key: redelivered garbage records once | source, error code, `raw_payload_ref` | 200 — a 5xx would make the provider retry unparseable bytes forever and eventually drop a dealer message |
| Adapter **throws** despite the sync-pure contract | Caught, treated as parse failure → same quarantine path → **200** | same | source, "parse threw" marker | 200. The no-drop rule outranks blame; the payload is preserved either way |
| `queue.publish` fails | **503 `enqueue_failed`**, nothing stored | The provider's own retry is the durability mechanism; the redelivered payload dedupes downstream | source, channel, outcome | 503 — the **only** deliberate non-ack in the service |
| Everything succeeds | 200 `parsed` | Key `<source>:<provider_message_ref>` | source, channel, ref | 200 |

Store reads/writes, routing, and extraction are **structurally absent** from this function; a 200 means exactly "durably enqueued", never "processed".

### 3.2 `inbound-router` (consumes `comms.inbound.received.v1`)

| Failure mode | Verdict | Retry / idempotency | Logged | Effect |
|---|---|---|---|---|
| Wrong event type delivered | `poison` | Immediate DLQ, envelope intact | consumer, type | Wiring bug, loudly visible — never silently ignored |
| Ledger already marked | `done` | The belt half of belt-and-braces | consumer, key | Exactly-once effect under at-least-once delivery |
| Quarantined payload variant | `recordQuarantined` → `done` | Keyed no-op on `(source, raw_payload_ref)` | source, ref | Operator queue |
| No deal owns the identity | `recordUnrouted{no_identity_match}` → `done` | Keyed no-op on `(source, provider_message_ref)` | source, ref, reason | Held whole, replayable. **Never** a guessed deal (AC-13) |
| Deal found, sender maps to no dealership (D10) | `recordUnrouted{no_thread_match, deal_id}` → `done` | same | deal_id, source, ref, reason | Held whole, replayable. **Never** a minted `Dealership` (AC-9) |
| `appendMessage` returns `duplicate` | Continue to fan-out, then `done` | The braces half — redelivery cannot double-append | deal_id, ref | Exactly one message row |
| A follow-up `queue.publish` fails | `retry` **without marking** | Redelivery re-runs the handler; keyed writes no-op; only the publish is re-attempted | reason, attempt | No double-append, no lost fan-out |
| `consent.onInboundCall` throws (D3) | `retry` | Bounded attempts → DLQ, envelope intact. The call message is **already appended** | consumer, reason | A defective per-product hook is visible in the DLQ and costs no dealer record |
| Store throws (unknown deal, unavailable backend) | `retry` | Bounded → DLQ | consumer, reason | Transient class; operator alert on exhaustion |
| Attempts exhausted | Dead-letter, **envelope intact** | Replayable by an operator | consumer, attempts, last reason | Never a silent drop |

### 3.3 `notes.submitNote(input)` — never throws

| Failure mode | Result | Retry / idempotency | Logged | Surfaces to caller |
|---|---|---|---|---|
| Blank `deal_id` / `dealership_id` / `client_note_ref` / `body` | `rejected` 400 with the reason code | None — caller bug. **Nothing written** | reason code only | Programming-error state |
| `body` longer than `max_note_chars` (D13) | `rejected` 400 `body_too_long` | None. Nothing written | reason code, length | The buyer is asked to shorten. **Never truncated** — a truncated note is silently altered evidence |
| `author` missing / not `buyer\|concierge` (AC-7) | `rejected` 400 `invalid_author`, **nothing written** | None | reason code, author label (an enum — log-safe) | Unreachable from TypeScript callers (`Exclude<…>`); the check exists for the JSON boundary an HTTP shell creates |
| Malformed `occurred_at` | `rejected` 400 `invalid_occurred_at` | None | reason code | Programming-error state |
| Unknown deal | `unknown_deal` 404, nothing written | None | deal_id | The note is not silently parked on a deal that does not exist |
| Known deal, no such thread | `unknown_thread` 404, nothing written | None | deal_id, dealership_id | The caller must name the dealership first; this service never creates one (D9) |
| Append succeeds, `queue.publish` fails | **`recorded_extraction_deferred` 503** — note IS stored | Caller retries the **same `client_note_ref`**: append returns `duplicate`, the publish is re-attempted under the same idempotency key | deal_id, message_ref, outcome | "Saved, terms not parsed yet" — never "failed", because it did not fail |
| Same `client_note_ref` submitted twice | `recorded` 201, `disposition: 'duplicate'`, one row | The keyed write is the mechanism | deal_id, message_ref, disposition | Idempotent by construction |
| Store throws | Propagated as a rejected/retryable outcome by the T-019 shell; the service does not swallow it | — | code | Never a partially written note |

A note is **never** enqueued before it is stored (D5): the buyer's own record must be durable at the moment the UI says it is.

### 3.4 `extraction-worker` (consumes `offer.extraction.requested.v1`)

| Failure mode | Verdict | Retry / idempotency | Logged | Effect |
|---|---|---|---|---|
| Wrong event type | `poison` | Immediate DLQ | consumer, type | Wiring bug |
| Ledger already marked | `done` | Belt | consumer, key | — |
| `extractOffer` returns `{ found: false }` | **Not an error.** Completed event published with `offer` absent | Pure ⇒ re-extraction is byte-identical | deal_id, ref, found=false | Valid terminal outcome — "no offer in this message" |
| `extractOffer` **throws** (T-012 contract violation) | `poison` | Immediate DLQ, envelope intact — never silent | consumer, reason | A contract breach in a pure function is a defect, not a transient |
| `queue.publish` fails | `retry` without marking | Redelivery re-extracts deterministically | reason | Idempotent |

This is the **only** module in the service that imports `@offer-extraction` — a verifier grep for that alias outside this file is a finding. Extraction never runs inline in the webhook path or inline in note submission, even though it is cheap (AC-11).

### 3.5 `extraction-apply` (consumes `offer.extraction.completed.v1`)

| Failure mode | Verdict | Retry / idempotency | Logged | Effect |
|---|---|---|---|---|
| Wrong event type | `poison` | Immediate DLQ | consumer, type | Wiring bug |
| `offer` absent on the payload | `done`, thread unchanged | — | deal_id, ref | The valid "no offer here" terminal state |
| `attachExtractedOffer` → `not_found` | `retry` | The append is upstream in the causal chain; an out-of-order artifact resolves on redelivery. Exhaustion → DLQ | reason | Never fabricates a row |
| `attachExtractedOffer` → `already_set` | `done` | Fill-once: the run that set it owned the follow-up | deal_id, ref | Idempotent duplicate |
| `getMessageByRef` → `undefined` after a successful attach | `retry` | Same class | reason | The rollup orders by `Message.timestamp`, never by processing order |
| `queue.publish` (offer_received alert) fails | `retry` without marking | Re-run: `attachExtractedOffer` no-ops as `already_set`… | reason | …see the note below |
| Store throws | `retry` → bounded → DLQ | — | reason | Transient class |

**One ordering subtlety a builder must preserve.** On a re-run after a failed alert publish, `attachExtractedOffer` returns `already_set` and the handler returns `done` **before** re-publishing the alert. That is correct and deliberate: the alert is an at-least-once notification with a stable idempotency key, and re-driving the rollup on every redelivery is a no-op anyway (the merge is idempotent on `(at, ref)` — §1.6). The design does **not** add a second ledger to make the alert exactly-once; the key does that job downstream.

### 3.6 ADR-005 posture across every path

An absent field is absent. `extractOffer` may return an `Offer` with no `sale_price` — that means *the dealer stated no price*, a first-class common state. Nothing in this service zero-fills, defaults, or drops such an offer, and `flags` is always `[]` here because this service never evaluates a flag: flag evaluation (and the unevaluable distinction) belongs to `packages/flag-engine` (T-011). A builder must not add flag logic here to "help".

## 4. Invariant touchpoints — what could break, and what stops it

| Invariant (source) | How this task could break it | How this design protects it |
|---|---|---|
| **No audio, no transcription, nothing to consent to** (specs/01 "Consent & recording posture"; Q14; AC-1, AC-3, AC-4) | A `TranscriptStub` kept "for later"; a transcript field smuggled onto `StoredMessage`; a consent hook that still returns `{ transcribe }`; an ASR SDK added to make the stub real | Port, both consumers, `setTranscript`, the dep, and the subscriptions are **deleted** (D1). `@core` has no transcription event type, so publishing one is a **compile error**. `Message` has no `recording_url`/`transcript`, so writing one is a compile error. `InboundComms` has no audio handle. `ConsentHook` returns `void` — it has no channel through which to authorise capture (D2). Standing gate: `grep -rin "transcript\|recording\|asr\|call_ref" services/comms` returns **zero** hits including comments, fixtures, and test names |
| **Quarantined raw payloads are not a back door to audio** (AC-3) | A telephony provider's raw JSON containing a `RecordingUrl` is stashed by the quarantine path and then read back into a message | The stash is a byte-preserving hold of an **unparseable** payload for operator replay; the only reader is `RawPayloadStore.get`, and replay re-enters through `parseInboundWebhook`, whose output type (`InboundComms`) has **no field** an audio reference could land in. Nothing in this service parses, indexes, or fetches a URL out of a stashed payload, and there is no HTTP client in the service at all |
| **Webhooks ack immediately; a provider timeout never drops a dealer message** (specs/00; AC-11) | Threading, extraction, or a store read creeping into `intake.ingest` "because it's cheap"; a 5xx on unparseable input | `intake.ts` is **not touched by this task** (§1.2). Its dependency list contains no `CommsStore`, so a store call there does not compile. Parse failure is not representable as a non-200; 503 occurs on exactly one condition (enqueue failed). Every heavy step is a bus consumer |
| **Exactly-once effect under at-least-once, unordered delivery** (T-001 §5.3; AC-11) | Marking the ledger before publishes succeed; adding an unkeyed write; making the rollup order-dependent | Belt: `hasProcessed` peek first. Braces: every write is keyed (`appendMessage` on `message_ref`, fill-once enrichment, dedupe on the holding areas). `markProcessed` runs **only** after all writes and publishes succeed — a retry never marks. The rollup orders by `Message.timestamp` with a `ref` tie-break, so any interleaving yields the same `current_offer` |
| **`author` is never inferred** (specs/00 "Core domain model"; Q22; AC-7) | Defaulting a note's author; deriving author from `direction` or `channel`; an optional `author?` | Required on the spine type, so an authorless `Message` does not compile. Provider-inbound author is the constant `'dealer'`, read off the transport, never off content (D6). Note author is caller-supplied, typed `Exclude<MessageAuthor,'dealer'>`, runtime-rejected when missing or unknown with **nothing written** (D7, §3.3), and taken from the authenticated session — never from a request body |
| **A note is first-class and runs the same extractor** (specs/00 "Comms aggregation layer"; AC-6) | A note-specific extraction path; a note that skips the rollup; extraction inlined into note submission | One event type, one consumer, one `extractOffer({channel,text})` call, one fill-once attach, one rollup for all three sources (§2.1). The only note-specific code is validation and the `note:` ref prefix, both above the bus |
| **`current_offer` = per-field newest-message-wins** (ADR-006; AC-10) | "Simplifying" the merge to last-write-wins; ordering by processing order | `mergeCurrentOffer` is unchanged apart from a field rename (§1.6); ADR-006 ratifies it and superseding it requires an ADR. Order-independence is a standing test |
| **Threads carry `dealership_id`, `vehicle_instance`, `working_with`, `process_step`** (specs/00; Q12 AMENDED; AC-8) | Re-adding `dealer_id`/`dealer_name`/`contact` to the store's thread record; the router advancing `process_step` because a message arrived | The store assembles `DealerThread` from `@core` verbatim, so a stray field does not compile. Thread creation sets `process_step: 'information_gather'` once and no port method can change it thereafter (§1.1, §2.2) |
| **Dealership tenancy: names global, people private** (specs/00 "Dealership data tenancy"; Q12 AMENDED; AC-9) | Minting a `Dealership` from an unrecognised phone number; a global contact index; a cross-deal contact lookup | The service has **no** method that creates or edits a `Dealership` (D9). The contact index is keyed `(deal_id, contact)` — `bindThreadContact`/`resolveDealershipByContact` both take `deal_id` first, so an unscoped contact lookup is inexpressible. `DealershipContact` exists only embedded in an account-owned `DealerThread`; there is no free-standing contact record to leak. Unmatched senders go to the unrouted area rather than into the global namespace (D10) |
| **`identity_ref` routing is provider-agnostic and exact-match** (specs/00; AC-13) | Fuzzy matching a near-miss number; a provider name entering the routing key; learning who provisioned an identity | Normalization is identical at bind and at resolve and only strips formatting — it never guesses a country code or an alias variant. A near-miss is a **non-match** (standing test). No provider name appears in the store module; `IdentityRef` carries no provisioner field |
| **Ports are swap seams; no signature encodes an in-memory assumption** (specs/00 "Store", "Async backbone"; AC-12) | A synchronous store method that only a Map can satisfy; leaking `Map`/`Set` types across a port; a queue method with in-process semantics | Every port speaks `@core` types plus plain records; the store's synchronous shape mirrors row operations a Postgres implementation performs (`SELECT`/`INSERT`/unique-index conflict) and T-017 substitutes behind it. `EventQueue.publish` returns a **value**, never throws, so a network queue fits without redesign. `hasProcessed`/`markProcessed` map to a `processed_events` table with a unique `(consumer, key)` index; `appendMessage`'s keyed no-op maps to `ON CONFLICT DO NOTHING`; `RawPayloadStore.stash` returns a content-addressed ref that is an S3 key |
| **Spine defined once, no parallel types** (ADR-001; AC-14) | Re-declaring `Message`, `DealerThread`, or a channel literal union locally; a hand-written channel `Set` in a fixture | Every domain name is an `@core` import (§1.1). Local types are orchestration only (`StoredMessage`, `MessageOrigin`, `RollupState`, the outcome unions). Narrowings use `Exclude<…>` over spine types rather than new literal unions. Standing gate: no `interface (Deal\|DealerThread\|Message\|Offer\|Dealership\|DealershipContact)\b` outside `packages/core` |
| **ADR-005: absence is never zero, never "not triggered"** | Zero-filling a partial offer; dropping an offer with no `sale_price`; populating `flags` here | Partial offers attach and roll up verbatim; conditional spreads keep absent fields absent; `flags` is always `[]` because this service never evaluates a flag (§3.6) |
| **One deal, one make/model; budget ceiling ≠ fair price** (specs/00 "Cardinality invariants", "Budget ceiling vs. fair price") | The router inferring a vehicle, valuation, or walk-away comparison from message text | This service writes `messages[]` and `current_offer` and nothing else on the aggregate (§2.2). It has no valuation input and no vehicle write path, so neither comparison is expressible here; both live in the flag engine against the instance's own snapshot (ADR-007) |
| **No unapproved integration or spend** (CLAUDE.md invariant 2) | An ASR/transcription SDK arriving to make the stub real; an HTTP client; a queue SDK | Zero dependencies added; `services/comms/package.json` is not edited at all (ADR-009). No ASR provider is approved (Q14), and deleting the port removes the socket one would plug into. Outbound stays type-only |
| **No silent interpretive drift** (CLAUDE.md invariant 3) | Behavior changes smuggled in as a migration | §0 logs D1–D14 with spec/ADR basis; the two a reviewer is most likely to challenge (D6 `author:'dealer'` on a call record, D10 unrouted-instead-of-auto-thread) are named with their exact reversal cost |
| **Fleet cannot mutate its constitution** (CLAUDE.md invariant 1) | Touching protected paths or another task's files | Write set is exactly `services/comms/**`, `tasks/T-014-*.md`, `docs/design/T-014.md`. The `@comms` alias and the vitest alias already exist (T-015), so no root edit is needed |

New suites this task owes:

6. **Call flow (AC-2, AC-3, D11, D12):** an inbound call threads a `Message{channel:'call', direction:'in', author:'dealer', call_meta, body absent}`; **exactly one** `call_logged` alert is enqueued; **no** `offer.extraction.requested.v1` is published; a call with adapter-supplied `call_meta` round-trips it verbatim; a call without one gets `started_at = received_at` and `party` from `from.phone`, and **no** `duration_seconds`; after a full drain the thread has no `current_offer`.
7. **Call → note → extraction, the whole v0.5 loop (AC-2, AC-6):** call logged → owner submits a note whose text states terms → after drain the note `Message` carries `extracted_offer` and the thread's `current_offer` reflects it, on the **same thread** the call landed on.
8. **Note is a first-class message (AC-6, AC-7, D7):** a note stores `channel:'note'`, `direction:'internal'`, the caller's `author`, body verbatim; a note and an SMS with **identical text** produce the identical `extracted_offer` (one extractor, no note-specific path); a note with `author` missing/`'dealer'`/`'operator'` is rejected and `read` confirms **nothing** was written; `expectTypeOf` asserts `author:'dealer'` and any caller-supplied `direction` are compile errors.
9. **Note idempotency + deferred extraction (D5, §3.3):** the same `client_note_ref` twice → one message row, `disposition:'duplicate'`, one extracted offer, one rollup; with the queue induced to fail, `submitNote` returns `recorded_extraction_deferred` **and the note is readable**; re-submitting the same ref then completes extraction with no second row.
10. **Note validation (D13):** blank ids/body, over-long body, malformed `occurred_at` → `rejected` with the right reason code and nothing written; unknown deal → 404; known deal + unknown dealership → 404; **provider-inbound text of the same length is accepted and stored untruncated** (the asymmetry is the assertion).
11. **Thread resolution + tenancy (AC-8, AC-9, D9, D10):** a bound contact routes to its `dealership_id` and creates the thread row at `process_step:'information_gather'` with no `vehicle_instance` and no `working_with`; a thread seeded with `working_with.phone` routes by that contact; a **second** message never re-creates the row and never resets `process_step`; an unknown sender on a known deal lands in `listUnrouted()` with `reason:'no_thread_match'` and `deal_id` set, **and no new thread and no new dealership id appears anywhere in the read model**; a contact bound in deal A never resolves inside deal B (account-private index).
12. **Consent hook (AC-4, D2, D3):** the hook is invoked once per inbound call with `(deal_id, inbound)`; it is **not** invoked for sms/email/note; the call message is already appended when it runs; a throwing hook yields bounded retries → DLQ with the envelope intact **and the call message still threaded and still exactly one row**; `expectTypeOf` asserts `onInboundCall` returns `void` (a `{ transcribe: … }` return does not typecheck).
13. **Transcription-free surface (AC-1, AC-3):** a source-and-test text scan asserts zero occurrences of `transcript`, `recording`, `asr`, and `call_ref` under `services/comms/**`; a type-level assertion that `@comms` exports no `TranscriptStub` and `CommsStore` has no `setTranscript`; an assertion that `SpineEventType` contains no `transcription` member (the upstream guarantee this service now depends on).
14. **Port swap-seam shape (AC-12):** a type-level check that no exported port signature mentions `Map`, `Set`, or `Promise`-free I/O assumptions where a durable implementation needs one; a second `CommsStore` implementation stub (a thin recording double) is accepted by `createCommsService` without a cast — the mechanical proof that the seam is a seam.

## 7. Deviations and blockers

**Blocked: no.** This design needs no change to the frozen spine (every shared type is imported or narrowed by reference), no unapproved integration (no ASR — none is approved; no HTTP client; no queue or storage SDK), no dependency change (ADR-009 keeps those in T-015), and no edit outside the task's ownership globs.

Deviations resolved by the designer and logged rather than escalated:

1. **D2 — `ConsentHook` kept with a `void` return.** AC-4 permits removing the seam outright ("whatever per-product seam remains"), while the task objective lists `ConsentHook` among the ports that keep their swap-seam shape. Keeping the seam and deleting its decision satisfies both and is the smaller diff. If the chief prefers outright deletion, the reversal is one interface, one const, one dep field, one call site — and no AC changes.
2. **D6 — `author: 'dealer'` on an inbound call record.** A bare call record has no text, so "who produced this text" is degenerate; `'dealer'` states the true fact that the dealership called, and the honesty risk the field exists for (self-authored text wearing a dealer label) is structurally absent where there is no text. Deliberately **different** from `docs/design/T-012.md` D7, where a receipt `call_meta` entry's author answers "who logged this on the account side". Reversal is one constant.
3. **D10 — unmatched dealership contact goes to the unrouted holding area instead of auto-creating a thread.** This is a behavior change from T-009, forced by v0.5: a thread now needs a `dealership_id` into a **globally shared** `Dealership` table, and minting one from a phone number would put account-guessed rows into the shared namespace the tenancy split exists to protect. Nothing is dropped — the item is held whole, operator-visible, and replayable once the buyer names the dealership.
4. **D13 — note length bound (default 20 000 chars), provider text uncapped.** T-012 §4.1 assigned message-size bounding to this boundary; the number itself has no spec line, so it is injectable and the default is a one-line reversal. The asymmetry is deliberate and is asserted as a test (test 10).
5. **Forward notes (not this task's files).**
   - **T-017 (`@store-pg`)** inherits the whole `CommsStore` contract: `appendMessage` = `INSERT … ON CONFLICT (deal_id, message_ref) DO NOTHING`; `markProcessed` = insert against a unique `(consumer, idempotency_key)` index; fill-once enrichment = a conditional `UPDATE … WHERE extracted_offer IS NULL`; **no** `UPDATE`/`DELETE` of message content anywhere. There must be **no** `transcript` or `recording_url` column, and the dealership-contact index must be keyed by `(deal_id, contact)` so a cross-account lookup is not expressible in SQL either.
   - **T-018 (`@object-store`)** inherits `RawPayloadStore` unchanged: content-addressed keys, and the only reader is operator replay.
   - **T-019 (HTTP)** maps `WebhookIngestOutcome` and `NoteSubmitOutcome` 1:1 onto responses and decides nothing itself; it owns the logger and inherits the never-logged list in §3 verbatim; it must take a note's `author` from the authenticated session and **never** from the request body.
   - **Receipt wiring (D14)** is not built here. Whoever wires it inherits `docs/design/T-012.md` §4.6 unchanged: append after the ack, inside a consumer, with `dedupe_key` taken from the event envelope's `idempotency_key`.
