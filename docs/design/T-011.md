# Design — T-011: Flag engine v0.5 — per-instance market value and `above_market`

- **Task:** `tasks/T-011-flag-engine-above-market.md`
- **Spec basis:** `specs/00-shared-core-architecture.md` — "Flag engine (shared)", "Budget ceiling vs. fair price — two different questions *(resolved 2026-08-07)*", "Core domain model" (`Offer.flags[]`, `ValuationSnapshot`), "Cardinality invariants"; `decisions/OPEN-QUESTIONS.md` Q20 (ANSWER: adopt the split)
- **ADRs honored:** ADR-001 (Node/TS, spine defined once, no parallel types), ADR-002 (`payment_packing` canonical), ADR-005 (missing input ⇒ **unevaluable**, never zero, never "not triggered"), **ADR-007 (`above_market` measures against `ValuationSnapshot.retail` for THAT `VehicleInstance`, tolerance is config not a constant)**, ADR-009 (this package is not on the typecheck-script list — its `package.json` is untouched)
- **Supersedes nothing.** This is a **strictly additive** amendment to `docs/design/T-002.md`. T-002 §0 calls **D1–D7 remain in force verbatim**; nothing in T-002 is re-decided here. New calls are numbered **D8–D14** so code comments can cite them unambiguously.
- **Spine reference:** the as-built `packages/core` after T-010 (`OfferFlag` already carries `above_market`; `OFFER_FLAGS` already has 5 entries; `ValuationSnapshot` is already `vehicle_instance_id`-bound with a flat `retail?` band). - **Stage:** design → build
- **Scope:** `packages/flag-engine/**` only. One new flag rule, one new context field pair, one new config knob, and the test migration off the four-flag vocabulary. No I/O, no async, no new dependency, no core edit.

## 0. Interpretive calls made by this design (drift trip-wire log)

Every call below is a mapping inside ambiguity the task file explicitly delegates to the designer ("thresholds stay injectable"; "the designer must select" the band — already resolved upstream by **ADR-007**). None requires changing a frozen file. None is blocking.

| # | Call | Basis |
|---|------|-------|
| **D8** | **The market-value input is the whole `ValuationSnapshot` (imported from `@core`), not a pre-extracted number.** `FlagContext.valuation?: ValuationSnapshot`. The engine — not each caller — performs ADR-007's band selection. | ADR-007 ("`FlagContext` gains the instance's retail value"), read together with ADR-001 no-parallel-types. Passing a bare `retail_value?: MoneyCents` would move the ADR-007 band decision *out* of the engine and into every call site, where it is unreviewable, untested, and silently overridable. Carrying the spine type keeps the decision in one cited place and preserves the "snapshot exists but has no retail band" state (D11), which a flat scalar erases. |
| **D9** | **`above_market` compares `offer.sale_price` alone — fees excluded.** This is deliberately *not* the out-the-door total that `over_walkaway` uses (T-002 D2). | specs/00 "the offer is **priced** above this specific car's own valuation" and ADR-007 "the offer's **price** exceeds it". `ValuationSnapshot.retail` is a *vehicle* price, not a transaction total: it contains no doc fee, tax, or registration. Comparing a fee-inclusive total against a fee-exclusive book value would (a) double-count fees that `junk_fee` already judges, and (b) fire on nearly every legitimate deal — the exact "cry wolf" failure ADR-007 rejected the wholesale band for. |
| **D10** | **Tolerance is an integer basis-points-of-retail knob**, `above_market_tolerance_bps`, evaluated with integer arithmetic: `threshold = retail + Math.trunc(retail * bps / 10_000)`; fires on strict `>`. `0` = any excess over retail flags. No default ships. | ADR-007 ("tolerance is a config threshold … not hard-coded") + T-002 D1 (no baked-in business constants) + T-002 D4 (spec words "above" / "crosses" are strict). **Basis points rather than a float fraction** because the spine's money rule is "integer USD cents — no floats" (`@core` `MoneyCents`): `retail * bps` is exact for every realistic price (a $1M car at 10 000 bps is ~1e12, far inside `Number.MAX_SAFE_INTEGER`), so the boundary is exactly reproducible in fixtures. **Percentage rather than absolute cents** because fair-price deviation is proportional — $500 over on a $12k car and on an $80k car are not the same finding. `Math.trunc` because fractional cents do not exist in the spine; the resulting allowance differs from the ideal by at most one cent, and the boundary is documented strict. |
| **D11** | **No band fallback, and the band is not configurable.** A `ValuationSnapshot` that is present but has no `retail` (e.g. a wholesale-only snapshot) makes `above_market` **unevaluable** — the engine never substitutes `private_party`, `trade_in`, or `wholesale`. `FlagEngineConfig` exposes a tolerance knob and **no band selector**. | ADR-007 "Revisiting the band requires a superseding ADR." A runtime fallback or a config selector would let an operator (or a partially-populated adapter response) silently overturn an ADR at runtime — CLAUDE.md invariant 3, "no silent interpretive drift". Unevaluable is the honest report; ADR-005 §2 is the mechanism. |
| **D12** | **Instance-binding guard.** `FlagContext` also carries the optional `vehicle_instance_id` the offer belongs to. If it and `valuation.vehicle_instance_id` are both present and **differ**, `above_market` is **unevaluable** — never a verdict. Absent id ⇒ no check possible, binding taken on the caller's word. | ADR-007 binds the comparison to **THAT** `VehicleInstance`; specs/00 "Cardinality invariants" states the load-bearing reason — "one vehicle per deal is the only way to honestly tell a customer whether they are getting a good deal … let a deal span two different vehicles and there is no longer anything to compare against". Pricing one dealership's 40k-mile car against another's 90k-mile snapshot reproduces that failure one level down, and it is the single most dangerous *silent* wrong answer this task can produce: authoritative-looking, plausible, and undetectable downstream. One optional field plus one string comparison converts it into a reported non-answer. Purity is preserved: the mismatch does **not** throw. |
| **D13** | **Snapshot staleness is not the engine's concern.** `ValuationSnapshot.captured_at` is never read — the engine has no clock (T-002 §2 purity contract). A caller that judges a snapshot too old withholds it, and `above_market` becomes unevaluable by the ordinary D11/AC-5 path. | specs/00 "Provider-agnostic, **pure** function"; T-002 D3/§4.1 (no clock, no I/O). A freshness policy is caller/product configuration, and reading a clock inside the engine would break determinism and every fixture. |
| **D14** | **`FlagEvaluation`'s shape is unchanged** — still `{ flags, unevaluable }`, both `OfferFlag[]` in `OFFER_FLAGS` order. No reason codes, no per-flag detail object. | T-002 D7 + ADR-005 §4 ("Events … carry the (possibly partial) `Offer` unchanged — T-009 needs no special seam"). The change is purely a fifth member of an existing vocabulary landing in existing arrays, so T-012 / T-014 / T-020 need no migration seam. Distinguishing *why* something is unevaluable is a UI concern the caller can derive from the same inputs it passed in. |

## 2. Public interface — exact signatures

All spine vocabulary comes from `@core`. This package defines **only** its own input/result types; it declares no `Offer`, no `ValuationSnapshot`, and no flag union (ADR-001, ADR-002). **Bold** marks what T-011 adds; everything else is T-002 as-built, reproduced so the file reads as one contract.

```ts
import { OFFER_FLAGS } from '@core';
import type { MoneyCents, Offer, OfferFlag, ValuationSnapshot } from '@core';

/**
 * The evaluation's non-Offer inputs: the buyer's qualified rate, the deal's
 * budget ceiling, and — v0.5 — THIS VehicleInstance's own market value
 * (specs/00 "Budget ceiling vs. fair price"; Q20). Field names mirror the spine
 * sources they are read from; this type is a projection, not a parallel model.
 */
export interface FlagContext {
  /**
   * Buyer's qualified APR, same units as Offer.apr (e.g. 6.9).
   * Sourced from PrequalResult.qualified_apr (@core; specs/01 credit residency:
   * derived number only — no credit payload can pass through this field).
   * Absent → rate_markup is unevaluable (ADR-005).
   */
  qualified_apr?: number;

  /**
   * Deal.walk_away_number (@core), integer USD cents — the deal-level BUDGET
   * CEILING and nothing else. Q20/ADR-007: it is NOT a fair-price judgement and
   * is NOT re-pointed at valuation. `over_walkaway` semantics are unchanged.
   */
  walk_away_number: MoneyCents;

  /**
   * ★ T-011 — the market-value input, carried PER VehicleInstance: the
   * ValuationSnapshot of the car THIS offer is for, read from
   * DealerThread.vehicle_instance (specs/00 "Budget ceiling vs. fair price":
   * "The flag engine gains a market-value input per instance"; Q20).
   *
   * The whole snapshot travels, not a pre-picked number (D8) — ADR-007's band
   * selection happens inside this engine, once, where it is tested and citable.
   * Absent (no valuation yet for this instance) → above_market is UNEVALUABLE,
   * never "fine" (ADR-005; specs/00 "never as 'fine'").
   */
  valuation?: ValuationSnapshot;

  /**
   * ★ T-011 — VehicleInstance.id (@core) of the car this offer came from, i.e.
   * DealerThread.vehicle_instance.id. Supplied so the engine can verify that
   * `valuation` really is THIS car's snapshot (ADR-007: "for THAT
   * VehicleInstance"). Mismatch → above_market is unevaluable, never a verdict
   * computed against another dealership's car (D12). Absent → no check is
   * possible and the binding is taken on the caller's word.
   */
  vehicle_instance_id?: string;
}

/**
 * Injectable thresholds (T-002 D1 — required, no defaults; business constants
 * are the caller's to cite, not this engine's to invent).
 */
export interface FlagEngineConfig {
  /** Term at/above which the term counts as stretched (>=, T-002 D4). Spec example: 72. */
  stretched_term_min_months: number;
  /** APR points of excess over qualified_apr tolerated before rate_markup fires (strict >). 0 = any excess flags. */
  rate_markup_tolerance_points: number;
  /** Fair-value caps per fee (T-002 D6). A fee strictly above its cap is junk. */
  fee_fair_caps: readonly FeeFairCap[];
  /** Cap for fees matching no fee_fair_caps entry. Omitted = unmatched fees never flag. */
  unmatched_fee_cap?: MoneyCents;

  /**
   * ★ T-011 — basis points of ValuationSnapshot.retail tolerated before
   * above_market fires (ADR-007: "tolerance is a config threshold … not
   * hard-coded"; D10). Integer bps of the retail band, so the knob is
   * scale-invariant and the arithmetic stays integer-exact:
   *
   *     threshold = retail + Math.trunc(retail * above_market_tolerance_bps / 10_000)
   *     fires when offer.sale_price > threshold        (strict — T-002 D4)
   *
   * 0 = any price above retail flags. 300 = 3% over retail tolerated.
   * There is deliberately NO band selector here: ADR-007 fixes the band to
   * `retail`, and overturning it requires a superseding ADR, not a config value (D11).
   */
  above_market_tolerance_bps: number;
}

export interface FeeFairCap {
  /** Matched against OfferFee.name after normalization: trim + lowercase, exact match. */
  name: string;
  max_amount: MoneyCents;
}

/**
 * Evaluation result (ADR-005) — SHAPE UNCHANGED by T-011 (D14). A flag whose
 * required inputs are absent is NOT emitted and is surfaced in `unevaluable`,
 * distinguishable from "evaluated, not triggered" (present in neither array).
 * Missing inputs are never defaulted to zero.
 *
 * Required inputs per flag (★ = new):
 *  - payment_packing: term_months                      (evaluable from term alone — ADR-005 §2)
 *  - rate_markup:     apr AND context.qualified_apr
 *  - junk_fee:        none beyond fees[] — always evaluable
 *  - over_walkaway:   sale_price
 *  - above_market ★:  sale_price AND context.valuation AND valuation.retail,
 *                     and no instance-id mismatch (D11, D12)
 *
 * Both arrays are duplicate-free, disjoint, and in OFFER_FLAGS order (T-002 D7),
 * so `above_market` always sorts last.
 */
export interface FlagEvaluation {
  flags: OfferFlag[];
  unevaluable: OfferFlag[];
}

/**
 * THE flag engine (specs/00 "Flag engine (shared)"): pure, provider-agnostic,
 * synchronous, total. No I/O, no clock, no randomness, no mutation of any
 * argument, no exceptions on well-typed input. Ignores offer.flags (T-002 D5).
 *
 * Rules:
 *  - payment_packing: term_months >= config.stretched_term_min_months
 *  - rate_markup:     apr > qualified_apr + rate_markup_tolerance_points
 *  - junk_fee:        any fee.amount > its matched cap
 *  - over_walkaway:   sale_price + Σ fees[].amount > walk_away_number   (T-002 D2 — UNCHANGED)
 *  - above_market ★:  sale_price > retail + trunc(retail * bps / 10_000) (ADR-007, D9, D10)
 *
 * over_walkaway and above_market read DIFFERENT numerators (out-the-door total
 * vs. bare sale price) against DIFFERENT denominators (deal budget ceiling vs.
 * this instance's retail band) and neither gates the other — so all four
 * budget × market combinations are emittable (specs/00: "A cheap car can be a
 * bad deal and an expensive one a fair deal — both must be sayable").
 */
export declare function evaluateOffer(
  offer: Offer,
  context: FlagContext,
  config: FlagEngineConfig,
): FlagEvaluation;
```

**Public surface is unchanged in shape:** `src/index.ts` still exports exactly `evaluateOffer` plus the types `FlagContext`, `FlagEngineConfig`, `FeeFairCap`, `FlagEvaluation`. Still deliberately **not** exported: per-flag predicates, any "attach flags to offer" helper (callers spread `{ ...offer, flags: evaluateOffer(...).flags }` so replace-not-merge stays visible — T-002 D5), any re-export of `@core` types, and — new — any band-selection or threshold-defaulting helper (a default would be an uncited business constant, T-002 D1).

### 2.1 Reference rule (build target, not a second definition)

```ts
// inside evaluateOffer, after the over_walkaway block
// above_market — priced above THIS car's own valuation (ADR-007; AC-2).
// Requires a stated price AND this instance's retail band. Never falls back to
// another band (D11); never evaluated against another car's snapshot (D12).
const valuation = context.valuation;
const retail = valuation?.retail;
const instanceMismatch =
  valuation !== undefined &&
  context.vehicle_instance_id !== undefined &&
  valuation.vehicle_instance_id !== context.vehicle_instance_id;

if (offer.sale_price === undefined || retail === undefined || instanceMismatch) {
  unevaluable.add('above_market');
} else {
  const allowance = Math.trunc((retail * config.above_market_tolerance_bps) / 10_000);
  if (offer.sale_price > retail + allowance) {
    fired.add('above_market');
  }
}
```

Nothing else in `engine.ts` changes: `over_walkaway`'s block is byte-for-byte untouched (AC-3), and the final `OFFER_FLAGS.filter(...)` return already orders and de-duplicates the fifth member for free.

| `Offer.fees[]` | Feeds `junk_fee` and the `over_walkaway` total **only**. Deliberately not part of the `above_market` comparison (D9) | `@core` domain |

| `Deal.walk_away_number` | Budget ceiling for `over_walkaway`, unchanged (Q20, AC-3) | `@core` domain |
| `OfferFlag` / `OFFER_FLAGS` (5 entries incl. `above_market`) | The **only** flag vocabulary; T-010 already added the member, so this package cannot name a flag `@core` does not define | `@core` — ADR-002, ADR-007 |
| `ValuationAdapter.getValuation(req): Promise<AdapterResult<ValuationSnapshot>>` | Where callers obtain the snapshot — **outside** this package. The engine never calls it | `@core` adapters (T-003/T-013) |

The engine still takes no `Deal`, no `DealerThread`, no `Message`, no `VehicleInstance`, no adapter, and no event envelope — only the three-argument projection. That narrowness is what keeps it shared verbatim across consumer and B2B: there is no product/tenant parameter in the signature and there must never be one.

**Caller assembly (normative for T-014/T-020, illustrative here):**

```ts
const thread = deal.dealer_threads[i];
const instance = thread.vehicle_instance;                       // may be undefined
const context: FlagContext = {
  qualified_apr: prequal?.qualified_apr,
  walk_away_number: deal.walk_away_number,
  valuation: instance ? valuationCache.get(instance.id) : undefined,

```

Both new fields are read from the **same** `instance` binding in the same expression, which is the ergonomic half of D12's protection; the id comparison is the enforcing half.

## 4. Error paths per operation

There is exactly one operation and it is pure, so most failure machinery is *provably absent* rather than handled — that absence is the design. Rows marked ★ are new in T-011; the rest restate T-002 §4.1 unchanged.

### 4.1 `evaluateOffer` (the only operation)

**Idempotency.** Unchanged and reinforced: referential transparency *is* the idempotency story. Same `(offer, context, config)` → identical `FlagEvaluation`, always. `above_market` adds no state, no memo, no cache. Under the bus's at-least-once, unordered delivery, a consumer re-running evaluation on a redelivered event produces the same result, and per T-002 D5 replace-not-merge the re-write is a no-op. One genuinely new wrinkle worth stating: **a later valuation refresh legitimately changes the answer** for the same offer — that is not non-determinism, it is a different `context`. Callers must therefore re-evaluate (and replace `current_offer.flags`) when a `ValuationSnapshot` lands for an instance, not only when a new message arrives; the flag set is a function of current inputs, never an append-only annotation. No idempotency key is needed *inside* the engine; the enclosing event's key covers the write.

**Logging.** The engine logs nothing — purity means no logger dependency, and there is nowhere for data to leak from a function that cannot perform output. Observability belongs to callers, which log `deal_id`, `kind: 'flag_raised'`, and the `flags[]` / `unevaluable[]` arrays (flag names are PII-free enum literals), never offer bodies and never valuation payloads. **New guidance for the unevaluable set:** callers should log `unevaluable` alongside `flags`, because "we could not price this car" is operationally actionable (it means a valuation is missing for an instance that has offers) in a way that "no flags fired" is not — and ADR-005's whole point is that the two must not look alike.

### 4.2 Webhook / async posture (binding on callers)

Unchanged from T-002 §4.2 and restated because the new input touches it. This package exposes no webhook, HTTP, or queue surface — nothing to ack. The engine is never called inside a webhook's pre-ack window; its callers are event consumers. The new input does **not** introduce a fetch: `FlagContext.valuation` is read from the already-cached snapshot the valuation adapter produced on its own event-bus path (specs/00: "webhooks ack immediately, all heavy work … runs on the event bus"). A caller must **never** make evaluation block on a live valuation call — if the snapshot is not already there, the correct behavior is to evaluate now and report `above_market` unevaluable (row 1), then re-evaluate when the snapshot lands. The engine remains structurally incapable of violating the ack rule: synchronous, allocation-cheap, I/O-free.

### 4.3 What surfaces where (end-to-end)

`flags[]` → written into `Offer.flags` by the caller → visible on `DealerThread.current_offer` → consumer UI foregrounds them; B2B renders them advisory. `unevaluable[]` travels beside it (ADR-005 consequences: "the unevaluable set travels with flag results") and is what lets the war room's **value-adjusted cross-dealership ranking** (specs/00 "Cross-dealership comparison is value-adjusted, not raw-price") honestly mark a thread as *not yet rankable* rather than sorting it as if it were fairly priced. Nothing in this package knows or encodes the consumer/B2B difference.

### 5.1 Fixture changes (`test/fixtures.ts`)

```ts

above_market_tolerance_bps: 0,   // any price above retail flags — the clearest boundary (D10)

// New helper — a snapshot bound to the fixture instance:
export const FIXTURE_INSTANCE_ID = 'vi-fixture-1';
export function makeValuation(overrides: Partial<ValuationSnapshot> = {}): ValuationSnapshot {
  return {
    vehicle_instance_id: FIXTURE_INSTANCE_ID,
    retail: 2_500_000,             // $25,000 — equals the benign offer's sale_price,
    source: 'mock-kbb',            // so equal-to does NOT fire (strict >, T-002 D4)

}

// BENIGN_CONTEXT gains:
valuation: makeValuation(),
```

### 5.3 New `above_market` suite

| Case | Assertion |
|---|---|
| Fires (AC-2) | `sale_price` above retail + allowance → `flags` contains `above_market` |

| **Independence — all four combinations (AC-4)** | See §5.4 — the load-bearing table |
| `over_walkaway` unchanged (AC-3) | Existing `over_walkaway` suite (lines 237–292) passes **untouched** except where the price input is shared; the total is still `sale_price + Σ fees`, still compared to `walk_away_number`, never to retail |

### 5.4 The four budget × market combinations (AC-4 — every one a fixture)

Fees `[{ name: 'doc fee', amount: 40_000 }]` throughout (under the 50 000 cap, so `junk_fee` never confounds); `above_market_tolerance_bps: 0`. Out-the-door total = `sale_price + 40_000`.

| # | Narrative (specs/00) | `sale_price` | `retail` | `walk_away_number` | total vs. ceiling | price vs. retail | Emitted |

| 1 | cheap car, fair price | 2 400 000 | 2 500 000 | 2 600 000 | 2 440 000 ≤ 2 600 000 | 2 400 000 ≤ 2 500 000 | — (neither) |

## 8. Blockers

**None.** `blocked = false`.

Resolved-in-design notes, recorded for the chief:

1. **The band question the task file raised is already closed.** The task note says the designer must select the comparison band and "the chief must log the selection as an ADR before build proceeds". That happened ahead of this design: **ADR-007** (accepted, 2026-08-07) fixes `retail`, on Corban's explicit instruction. This design implements ADR-007 rather than re-deciding it, and D11 makes the choice non-overridable at runtime so the ADR stays the only place it can change.
2. **The tolerance *unit* was left open and is decided here (D10):** integer basis points of retail, chosen over a float fraction to protect the spine's integer-cents rule and over absolute cents because fair-price deviation is proportional. Logged, non-blocking, and reversible by changing one config field's type.
3. **The instance-binding guard (D12) is a small addition beyond the literal AC list.** It is included because ADR-007 binds the comparison to *that* instance and specs/00's cardinality rationale makes a cross-car comparison the exact failure the one-vehicle rule exists to prevent. It is optional (absent id = no check), never throws, and can be dropped without touching any other rule if the chief prefers a narrower surface.
4. **No frozen-spine change, no new integration, no dependency.** `packages/core` needs nothing: T-010 already landed `above_market`, the 5-entry `OFFER_FLAGS`, and the instance-bound `ValuationSnapshot` with an optional flat `retail` band.
5. **Mid-migration scope discipline.** `packages/adapters/*` and `services/comms` are red against the v0.5 spine and belong to T-013/T-014. Verification for this task is package-scoped (`npx vitest run packages/flag-engine`, `npx tsc -p packages/flag-engine --noEmit`); a repo-wide run is expected red and is not this task's signal.
