# Design — T-009: Comms aggregation service — in-memory (`services/comms`)

- **Task:** `tasks/T-009-comms-aggregation-service.md`
- **Spec basis:** `specs/00-shared-core-architecture.md` — "Comms aggregation layer (provider-agnostic — shared)" (inbound flows, ack-immediately rule, offer-extraction rollup), "Core domain model" (`Deal`/`DealerThread`/`Message`/`Offer`, provider-agnostic `identity_ref`, Store), "Async backbone (shared)"; `specs/01` (transcribe-only posture — shape constraint only, hook point here); `specs/02` (B2B relay rules NOT implemented here — per task note)
- **ADRs honored:** ADR-001 (Node/TS, spine defined once, no parallel types), ADR-002 (`payment_packing` vocabulary never touched here), ADR-003 (npm workspaces), ADR-004 (`@deal-copilot/*` marker names, bare import aliases), ADR-005 (`Offer.sale_price` optional; partial `Offer`s flow through `Message.extracted_offer` / events / `current_offer` unchanged; missing values never default to zero)
- **Upstream designs honored (binding):** `docs/design/T-001.md` — §2 spine types, §3.3 comms adapter contracts (`parseInboundWebhook` sync + pure), §4 event contracts, **§5.2 ack-then-queue decision table**, §5.3 consumer idempotency + key derivations, D2 (no synthetic fields on spine types), D3 (bare aliases, `src/index.ts` is the only import surface); `docs/design/T-007.md` — §2 `extractOffer` API, §5.2 seam rules (extraction runs ONLY as a bus consumer; T-009 owns the rollup policy)
- **Core as built (referenced, never redefined):** `packages/core/src/events.ts` — `CommsInboundReceivedV1`, `CommsInboundQuarantinedV1`, `CommsInboundPayloadV1`, `isQuarantinedInbound`, `EventEnvelope.idempotency_key`; `packages/core/src/adapters.ts` — `InboundComms`, `TelephonyAdapter`, `EmailAdapter`, `AdapterResult`
- **Stage:** design → build
- **Scope:** one service, `services/comms/**`, in-memory infrastructure only. No HTTP framework, no provider payload translation (fixture payloads in the normalized shape), no outbound origination, no consent policy, no receipt-layer writes (`packages/receipt/**` untouched), no new dependencies.

## 0. Interpretive calls made by this design (drift trip-wire log)

| # | Call | Basis |
|---|------|-------|
| D1 | **Webhook intake is transport-neutral: a plain async function returning a typed outcome that *encodes* the HTTP status** (`http_status: 200 \| 503`), not an HTTP server. Only `typescript` + `vitest` exist in the repo (CLAUDE.md invariant 2; root devDeps frozen by T-001), so express/fastify are unavailable by constitution. The eventual HTTP shell (later epic) maps `WebhookIngestOutcome` 1:1 onto a response; the T-001 §5.2 decision table is thereby fully expressed and testable now. | CLAUDE.md invariant 2; T-001 §1.2 (root devDeps only); T-001 §5.2 (the table is about ack semantics, not transport). |
| D2 | **Quarantine idempotency key = `source + ':quarantine:' + raw_payload_ref`**, where `raw_payload_ref` is the sha-256 hex of the canonical JSON serialization of the raw payload (`node:crypto`, a Node builtin — not a dependency). T-001 §5.3 fixes the parsed-inbound key as `source:provider_message_ref`, but a failed parse has no `provider_message_ref`; the deterministic hash makes provider redelivery of the same unparseable payload dedupe exactly like a parsed redelivery, and doubles as the `CommsInboundQuarantinedV1.raw_payload_ref` (core doc: "reference to where the raw provider payload was stashed"). | T-001 §5.2 row 1 + §5.3 (producers own key derivation); core `CommsInboundQuarantinedV1.raw_payload_ref` contract. |
| D3 | **`provider_message_ref` is persisted as a store-internal correlation column, not a spine field.** The store row is `StoredMessage { message: Message; provider_message_ref; source }` — the `@core` `Message` is stored verbatim and the correlation ref sits *beside* it, exactly as a Postgres `messages` table would carry it as a column. No field is added to any spine type (T-001 D2 letter preserved: correlation identifiers live in the envelope, and this column is envelope-derived persistence metadata, not domain model). Consumers correlate `Transcription*/OfferExtraction*` events to messages via this index (`deal_id` + `provider_message_ref`). | T-001 D2 (no quiet spine field additions — none made); T-001 §5.3 (events carry `provider_message_ref` for exactly this correlation); specs/00 "Store" (the eventual relational core needs the column regardless). |
| D4 | **`current_offer` rollup = per-field newest-message-wins merge with provenance** (§6): each of `sale_price`/`apr`/`term_months`/`monthly` is the most recently *stated* value across the thread's extracted offers; `fees[]` contends as a whole (latest non-empty wins; `[]` never erases known fees); `flags` stays `[]` (flag engine is T-002, downstream). "Newest" is the contributing **`Message.timestamp`** (tie-break: `provider_message_ref` lexicographic), NOT processing order — making the merge commutative/idempotent under at-least-once unordered delivery. Absent fields stay absent (ADR-005: never zero). **This reads spec text "rolled into the thread's `current_offer`" as accumulate-not-replace — an interpretive call beyond the literal text; per the task note it requires a lead resolve-and-log ADR before T-009's build merges.** Documented fallback if the lead rules otherwise: wholesale replacement by newest `(timestamp, ref)` — isolated to `rollup.ts` (§6), no other section changes. | Task note ("`current_offer` rollup policy … is designed here; log an ADR via the lead if the merge rule requires an interpretive call beyond the spec text"); T-007 D5 ("a gap, which the thread rollup (T-009) can fill from a later message" — anticipates accumulation); ADR-005 §1 (absence is a first-class state). |
| D5 | **Unroutable parsed inbound (no identity match) goes to an `unrouted` holding area — never guessed onto a deal, never dropped.** Exact-match-only resolution over the authoritative identity table; a near-miss identity is a non-match. The record is operator-visible via the read model and replayable once an identity is registered (replay wiring is a later epic; the holding area is the no-drop guarantee now). | specs/00 "Provider timeouts must never drop a dealer message" (extended: mis-threading to the *wrong* deal is worse than holding); specs/00 `identity_ref` authority; task AC-3. |
| D6 | **`dealer_id` is derived deterministically from the normalized sender contact** (`'dealer:sms:' + E.164` / `'dealer:email:' + lowercased address`); an inbound `from` matching an existing thread's contact threads onto it, otherwise a new `DealerThread` is created with `dealer_name` defaulted to the normalized contact string (enrichment later). Determinism makes thread creation idempotent under redelivery without extra bookkeeping. | specs/00 `DealerThread` ("dealer_id / name, contact info" — spec is silent on provenance); T-001 §5.3 (consumers must be idempotent). |
| D7 | **Call messages are appended at routing time (transcript absent); `transcript` and `extracted_offer` are fill-once enrichments** via the D3 correlation index (`setTranscript`/`attachExtractedOffer` return `'already_set'` rather than overwrite). Appending only after transcription would mean a failed/DLQ'd transcription silently keeps a dealer call out of the thread — a dropped message. Fill-once (never overwrite non-empty, never delete) is how this service reads the receipt layer's append-only posture; spec flow order "record/transcribe → store" is honored in *content* (the transcript lands on the stored message) without violating no-drop. | specs/00 no-drop rule; specs/00 "Receipt layer" (append-only); specs/00 inbound-call flow. |
| D8 | **Consent handling is an injected `ConsentHook` interface with a pass-through default** — called by the inbound router for calls, before `comms.transcription.requested.v1` is published. `{ transcribe: false }` skips transcription (the call message still threads). No consumer/B2B consent *policy* is implemented here. | specs/00 inbound-call flow "(consent handling per product)"; task note ("expose a hook point only"). |
| D9 | **Transcription is a stubbed event stage:** a worker consumes `comms.transcription.requested.v1`, resolves the transcript via an injected `TranscriptStub` (fixture-backed in tests), and publishes `comms.transcription.completed.v1`. `undefined` from the stub ⇒ `retry` (bounded → DLQ), exercising the poison path. The real transcription integration is a later epic behind this same seam; **audio is never fetched, stored, or referenced beyond the opaque `call_ref` inside events** (never on a stored `Message`). | Task AC-2 ("transcription as a stubbed event stage"); specs/01 transcribe-only posture; T-001 §7 (transcription events carry `call_ref` + `transcript`, never audio bytes). |
| D10 | **Outbound is a type-level seam only:** an `OutboundPort` interface typed against `@core` `TelephonyAdapter`/`EmailAdapter` shapes exists in `ports.ts`; nothing implements or calls it in Epic 1. | Task note ("outbound port … implements no origination"). |
| D11 | **The in-memory queue is a faithful at-least-once simulator, not a toy:** per-consumer delivery attempts, bounded redelivery (`maxAttempts`, default 3), an inspectable dead-letter list with envelopes intact, and a test hook to fail the next N publishes (the only way to exercise the §5.2 enqueue-failure 5xx row deterministically). `drain()` delivers until quiescent, including events published by handlers mid-drain. | T-001 §5.3 (at-least-once, unordered, DLQ with envelope intact — the behavior downstream code must be designed against *now* so the SQS swap is wiring, not redesign); task note ("Design the queue and store behind interfaces"). |

## 2. Exposed interfaces (exact TS — `src/index.ts` surface)

Every domain/event/adapter shape below is an **import from `@core`** — referenced, never redefined. The service adds only orchestration and infrastructure types.

### 2.1 Webhook intake

```ts
import type { TelephonyAdapter, EmailAdapter } from '@core';

/** Which adapter parses the payload. Fixture adapters in Epic 1 (task note);
 *  real Twilio/SES translation is a later-epic adapter behind the SAME
 *  @core contracts — this type never grows provider names. */
export type WebhookChannelKind = 'telephony' | 'email';

/**
 * The T-001 §5.2 decision table as a type. `http_status` is what the eventual
 * HTTP shell returns verbatim (D1):
 *   - 200 ⇔ the comms.inbound.received.v1 envelope (parsed OR quarantined
 *     payload) is durably enqueued — 2xx means exactly that, nothing more.
 *   - 503 ⇔ enqueue failed — the ONE deliberate non-ack; the provider's
 *     retry is then the durability mechanism.
 * Parse failure is NOT representable as a non-200 — by construction.
 */
export type WebhookIngestOutcome =
  | { kind: 'enqueued'; http_status: 200; disposition: 'parsed' | 'quarantined' }
  | { kind: 'enqueue_failed'; http_status: 503 };

export interface WebhookIntake {
  /** Sync-pure parse (adapter contract) → durable enqueue → outcome.
   *  Performs NO store reads/writes, NO routing, NO extraction, NO transcription. */
  ingest(channel: WebhookChannelKind, raw_payload: unknown): Promise<WebhookIngestOutcome>;
}
```

## 3. Ports and in-memory data shapes (swap seams named)

Each port is the seam the task demands: swapping the implementation is wiring, not redesign. **Seam map:** `EventQueue` → SQS/SNS or equivalent (specs/00 "Async backbone"); `CommsStore` → Postgres relational core (specs/00 "Store"); `RawPayloadStore` → S3-compatible object store. All three targets are on the CLAUDE.md approved build-and-wire list; none is wired in Epic 1.

### 3.1 Queue port (`EventQueue`) — seam: managed queue (SQS/SNS or equivalent)

```ts
import type { SpineEvent, SpineEventType } from '@core';

export type EnqueueResult = { ok: true } | { ok: false; reason: string };

/** Consumer verdicts — T-001 §5.3 made operational. */
export type ConsumeResult =
  | { status: 'done' }                      // success OR idempotent duplicate — never redeliver
  | { status: 'retry'; reason: string }     // transient — redeliver, bounded attempts
  | { status: 'poison'; reason: string };   // non-retryable — dead-letter immediately, envelope intact

export type EventHandler = (event: SpineEvent) => Promise<ConsumeResult>;

export interface EventQueue {
  /** Durable enqueue. Resolving { ok: true } IS the webhook 2xx precondition.
   *  Never throws — failure is a value (house style, @core AdapterResult). */
  publish(event: SpineEvent): Promise<EnqueueResult>;
  /** At-least-once, UNORDERED delivery to each (consumer, type) subscription. */
  subscribe(consumer_name: string, type: SpineEventType, handler: EventHandler): void;
}

// -- in-memory implementation extras (D11) --------------------------------
export interface DeadLetter {
  event: SpineEvent;          // envelope intact (T-001 §5.3)
  consumer: string;
  attempts: number;
  last_reason: string;
}

export interface InMemoryQueue extends EventQueue {
  /** Deliver until quiescent — including events published by handlers mid-drain. */
  drain(): Promise<void>;
  readonly deadLetters: readonly DeadLetter[];
  /** Test hook: make the next n publish() calls return { ok: false } (§5.2 row 3). */
  failNextPublishes(n: number): void;
}
// construction: new InMemoryQueue({ maxAttempts?: number })  — default 3
```

Payloads on the wire are exactly `@core` `SpineEvent` envelopes — JSON-serializable by the T-001 smoke contract, so the SQS swap serializes without adaptation (AC-5).

### 3.2 Store port (`CommsStore`) — seam: Postgres relational core

In-memory rows mirror the eventual tables; the `@core` `Message` is stored **verbatim** inside its row (AC-6 — no parallel message shape).

```ts
import type { Deal, DealerContact, DealerThread, IdentityRef, Message, Offer } from '@core';
import type { AdapterError, InboundComms, IsoTimestamp } from '@core';

/** D3: spine Message + correlation columns. Postgres seam: the messages table,
 *  where these are ordinary columns and message fields are the row. */
export interface StoredMessage {
  message: Message;               // the ONLY message shape stored — @core, verbatim
  provider_message_ref: string;   // envelope-derived correlation column (NOT a spine field)
  source: string;                 // adapter id that parsed it
}

export interface QuarantinedRecord {                   // seam: quarantine table
  source: string;
  parse_error: AdapterError;      // @core shape, from CommsInboundQuarantinedV1
  raw_payload_ref: string;        // → RawPayloadStore (§3.3)
  recorded_at: IsoTimestamp;
}

export interface UnroutedRecord {                      // seam: unrouted-inbound table (D5)
  source: string;
  inbound: InboundComms;          // @core shape — held whole, replayable
  reason: 'no_identity_match';
  recorded_at: IsoTimestamp;
}

export interface CommsStore {
  // -- seeding + identity routing (the AUTHORITATIVE mapping — §8 invariant 1)
  putDeal(deal: Deal): void;
  /** Binds identity → deal in the routing table. Normalization at bind and at
   *  resolve is identical (E.164 for phones, lowercased for email aliases). */
  bindIdentity(deal_id: string, identity: IdentityRef): void;
  /** EXACT match only over normalized values — never fuzzy (D5). */
  resolveDealByIdentity(to: { phone_number?: string; email_alias?: string }): string | undefined;

  // -- threading (append-only; idempotent by construction)
  /** Match `from` against existing thread contacts, else create (D6). */
  resolveOrCreateThread(deal_id: string, from: { phone?: string; email?: string }): { dealer_id: string };
  /** No-op when (deal_id, provider_message_ref) already appended — the keyed
   *  write that makes redelivery safe even without the processed-ledger. */
  appendMessage(deal_id: string, dealer_id: string, row: StoredMessage): 'appended' | 'duplicate';

  // -- fill-once enrichment via the D3 correlation index (D7: never overwrites, never deletes)
  setTranscript(deal_id: string, provider_message_ref: string, transcript: string): 'set' | 'already_set' | 'not_found';
  attachExtractedOffer(deal_id: string, provider_message_ref: string, offer: Offer): 'set' | 'already_set' | 'not_found';
  /** Applies §6 mergeCurrentOffer to the thread; stores offer + RollupState. */
  rollupCurrentOffer(deal_id: string, dealer_id: string, contribution: RollupContribution): void;

  // -- no-drop holding areas (operator surfaces via read model)
  recordQuarantined(rec: QuarantinedRecord): void;
  recordUnrouted(rec: UnroutedRecord): void;

  // -- consumer idempotency ledger (belt; the keyed writes above are braces)
  /** Seam: Postgres processed_events table w/ unique (consumer, key) index. */
  markProcessed(consumer: string, idempotency_key: string): 'first' | 'duplicate';
}
```

In-memory internals (implementation guidance, not contract): `Map<deal_id, DealRecord>` where `DealRecord = { deal: Deal; threads: Map<dealer_id, ThreadRecord>; refIndex: Map<provider_message_ref, {dealer_id, row_index}> }` and `ThreadRecord = { dealer_id; dealer_name; contact: DealerContact; rows: StoredMessage[]; current_offer?: Offer; rollup: RollupState }`. The read model assembles `DealerThread`s (`messages: rows.map(r => r.message)`) and deep-clones. `refIndex` is per-deal; `provider_message_ref` is treated as opaque-unique within a deal (provider refs are provider-unique; a cross-source collision within one deal is accepted as out of scope and noted for the Postgres seam, where the unique index is `(deal_id, source, provider_message_ref)`).

## 4. Pipeline design

### 4.1 Webhook intake (`intake.ts`) — the §5.2 sequence, verbatim

For `ingest(channel, raw_payload)` with `adapter = channel === 'telephony' ? deps.telephony : deps.email`:

1. `adapter.parseInboundWebhook(raw_payload)` — **synchronous, pure, no I/O** (contractually, `@core` §3.3). Nothing else runs before the ack decision: no store access, no routing, no extraction, no transcription (T-007 §5.2 seam rule — even though `extractOffer` is cheap, it does not run here).
2. Build the single `comms.inbound.received.v1` envelope:
   - parse **ok** → payload `CommsInboundReceivedV1 { source, inbound }`, `idempotency_key = source + ':' + inbound.provider_message_ref` (T-001 §5.3 fixed derivation);
   - parse **failed** → `ref = raw_payloads.stash(raw_payload)`, payload `CommsInboundQuarantinedV1 { source, parse_error, raw_payload_ref: ref }`, `idempotency_key = source + ':quarantine:' + ref` (D2). Both payload variants ride the same event type per core `CommsInboundPayloadV1`.
   - Envelope: `event_id = new_event_id()`, `occurred_at = now()`, `deal_id` **absent** (not yet attributable).
3. `queue.publish(envelope)` — `{ ok: true }` → return `{ kind: 'enqueued', http_status: 200, disposition }`; `{ ok: false }` → return `{ kind: 'enqueue_failed', http_status: 503 }`.

Logged at ingest (T-001 §5.2): source, channel, `provider_message_ref` (or `raw_payload_ref`), outcome. Never: bodies, phone numbers, email addresses, raw payloads.

### 4.2 Consumers (all registered by `createCommsService`; all idempotent per §5.4)

| # | Consumer | Subscribes to | Work | Publishes (producer-derived keys, T-001 §5.3) |
|---|----------|---------------|------|-----------------------------------------------|
| C1 | `inbound-router` | `comms.inbound.received.v1` | `isQuarantinedInbound(payload)` (core guard) → `recordQuarantined`, done. Else: normalize `inbound.to_identity`, `resolveDealByIdentity` → no match → `recordUnrouted`, done (D5). Match → `resolveOrCreateThread(deal_id, inbound.from)` (D6) → `appendMessage` with `Message` built as §4.3 → for **sms/email**: publish extraction-requested; for **call**: `consent.onInboundCall` (D8) → if `transcribe`, publish transcription-requested. Always: publish alert (`message_received`). | `offer.extraction.requested.v1` — key `deal_id:ref:extraction-request`; `comms.transcription.requested.v1` — key `deal_id:ref:transcription-request`; `alert.dispatch.requested.v1` — key `deal_id:message_received:ref` (no consumer in this service — dispatch is a later epic) |
| C2 | `transcription-stub-worker` | `comms.transcription.requested.v1` | `transcribe.transcriptFor(call_ref)` (D9); `undefined` → `retry` | `comms.transcription.completed.v1` — key `deal_id:ref:transcription-complete` |
| C3 | `transcription-apply` | `comms.transcription.completed.v1` | `setTranscript(deal_id, ref, transcript)` (`not_found` → `retry`; `already_set` → done) | `offer.extraction.requested.v1` with `text = transcript` — key `deal_id:ref:extraction-request` |
| C4 | `extraction-worker` | `offer.extraction.requested.v1` | `extractOffer({ channel, text })` (`@offer-extraction` — **the only module importing it**; pure, total, deterministic per T-007) | `offer.extraction.completed.v1` (`offer` present iff `found`) — key `deal_id:ref:extraction-complete` |
| C5 | `extraction-apply` | `offer.extraction.completed.v1` | if `offer` present: `attachExtractedOffer` (verbatim extractor output — possibly partial per ADR-005) then `rollupCurrentOffer` (§6); if absent: done (thread unchanged, T-007 §5.2) | `alert.dispatch.requested.v1` (`offer_received`) when offer present — key `deal_id:offer_received:ref` |

Envelope fields on all published events: fresh `event_id`, `occurred_at = now()`, `deal_id` set (attributable from C1 onward).

### 4.3 Message construction (AC-6 — spine shape, verbatim)

| Channel | `Message` built by C1 | Enriched later by |
|---|---|---|
| sms / email | `{ channel, direction: 'in', body: inbound.body, timestamp: inbound.received_at }` | C5: `extracted_offer` |
| call | `{ channel: 'call', direction: 'in', timestamp: inbound.received_at }` — **no `body`, no `recording_url` (never set by this service — §8), no `transcript` yet** (D7) | C3: `transcript`; C5: `extracted_offer` |

`inbound.call_ref` travels only inside `TranscriptionRequestedV1` — it is never stored on a `Message` (no such spine field exists; none is added).

## 5. Error paths per operation

### 5.1 Webhook ingest — **ack-then-queue, BINDING** (T-001 §5.2 decision table, restated as implemented here)

specs/00 rule: "webhooks ack immediately, all heavy work (transcription, extraction) runs on the event bus. Provider timeouts must never drop a dealer message."

| Failure | Behavior | Why / mechanics |
|---|---|---|
| Parse fails (`malformed_response` or any parse error) | **Still ack 200.** Stash raw payload (§3.3), enqueue `comms.inbound.received.v1` with `CommsInboundQuarantinedV1` (core contract) | A 5xx makes the provider retry the same unparseable payload forever; giving up drops a dealer message — both violate the no-drop rule. Quarantine keeps it, operator-visible + replayable |
| Enqueue fails (queue down) | **503 — the ONE deliberate non-ack** (`enqueue_failed` outcome) | Provider-side retry becomes the durability mechanism; the redelivery dedupes downstream (below) |
| Provider redelivers (slow ack / their retry / our 503) | 200 again; duplicate envelope enqueued; C1 dedupes on `source:provider_message_ref` (quarantined: `source:quarantine:sha256(raw)`, D2 — same raw bytes ⇒ same key) | At-least-once end to end; no double thread entry |
| Adapter *throws* despite the sync-pure contract | Defect, not a path: intake catches, treats as parse failure → quarantine + 200 | The no-drop rule outranks blame — the payload is preserved either way |

Logged/never-logged per §4.1.

### 5.2 Enqueue / publish from consumers

`publish` returning `{ ok: false }` inside a consumer → the consumer returns `retry` (transient infrastructure failure) **without** marking processed; redelivery re-runs the handler. All store writes are keyed no-ops on re-run (§5.4), so the retry only re-attempts the failed publish. Attempts exhausted → DLQ with envelope intact → operator alert surface (T-001 §5.3: never silently dropped; for comms events this is the receipt trail's feedstock).

### 5.3 Consumer failure classification (per consumer)

| Consumer | Condition | Verdict | Surfaces as |
|---|---|---|---|
| C1 | quarantined payload | `done` (after `recordQuarantined`) | `listQuarantined()` operator queue |
| C1 | no identity match | `done` (after `recordUnrouted`, D5) | `listUnrouted()` operator queue; **never a guessed deal, never a drop** |
| C1 | store unavailable / write failed (in-memory: shouldn't happen; the verdict class exists for the Postgres seam) | `retry` | bounded redelivery → DLQ |
| C2 | transcript unavailable (`undefined`) | `retry` → DLQ after `maxAttempts` | call `Message` is ALREADY threaded (D7) — the dealer contact is never lost; missing transcript is operator-visible via DLQ |
| C3 / C5 | correlation `not_found` (completed event arrived but row missing) | `retry` (out-of-order/redelivery artifact; the append is upstream in the causal chain) | bounded → DLQ |
| C3 / C5 | `already_set` (redelivered enrichment) | `done` | idempotent duplicate |
| C4 | `extractOffer` returns `{ found: false }` | `done` — publish completed **without** `offer` (valid terminal outcome, core contract) | thread unchanged; message still captured |
| C4 | `extractOffer` throws (T-007 D4 contract violation) | `poison` — immediate DLQ, envelope intact | operator alert; never silent |
| any | duplicate `idempotency_key` (§5.4) | `done` | no state change |

Consumer logging (T-001 §5.3): `event_id`, `type`, `deal_id`, attempt count, outcome (booleans/enums). Never message bodies, transcripts, extracted amounts alongside identifying refs, phone numbers, or email addresses.

### 5.4 Idempotency (two layers, both designed in)

1. **Ledger (belt):** each consumer first calls `markProcessed(consumer_name, envelope.idempotency_key)`; `'duplicate'` → `done` immediately. Marked only **after** the handler's writes and publishes succeed (so a `retry` never marks).
2. **Keyed writes (braces):** every state change is independently idempotent — `appendMessage` no-ops on a seen `(deal_id, provider_message_ref)`; `setTranscript`/`attachExtractedOffer` are fill-once; `mergeCurrentOffer` is commutative + idempotent (§6); deterministic `dealer_id` (D6) makes thread creation re-runnable. A crash between write and ledger-mark therefore cannot double-apply — the T-001 §5.3 "idempotent on `idempotency_key`" obligation holds even under partial failure.

Key derivations used (all fixed by T-001 §5.3; quarantine extension per D2): inbound `source:provider_message_ref` / `source:quarantine:<sha256>`; transcription request/complete and extraction request/complete `deal_id:provider_message_ref:<stage>`; alert `deal_id:kind:provider_message_ref`.

## 6. `current_offer` rollup policy (`rollup.ts` — D4; lead ADR required before build merges)

```ts
import type { IsoTimestamp, Offer } from '@core';

export interface RollupProvenance { at: IsoTimestamp; ref: string }   // contributing Message.timestamp + provider_message_ref

/** Store-internal (NOT a spine type): which contribution last set each field. */
export interface RollupState {
  sale_price?: RollupProvenance;
  apr?: RollupProvenance;
  term_months?: RollupProvenance;
  monthly?: RollupProvenance;
  fees?: RollupProvenance;
}

export interface RollupContribution { offer: Offer; at: IsoTimestamp; ref: string }

/** Pure, deterministic, commutative, idempotent. */
export function mergeCurrentOffer(
  prev: { offer?: Offer; state: RollupState },
  next: RollupContribution,
): { offer: Offer; state: RollupState };
```

Rules (primary policy):

1. **Per-field newest-wins:** for each of `sale_price`, `apr`, `term_months`, `monthly` — a field *present* on `next.offer` replaces the current value iff `(next.at, next.ref) > (state[field].at, state[field].ref)` (timestamp order, tie-broken by `ref` lexicographic). Fields absent on `next.offer` are **not** touched (the dealer didn't state them — ADR-005: absence is a state, never zero).
2. **`fees[]` contends as a unit:** a non-empty `fees` replaces wholesale under the same ordering; an empty `fees: []` never erases known fees (extractor emits `[]` for "no fee lines found", not "fees are zero" — T-007 §4.2).
3. **`flags` is always `[]`** in this service: the extractor emits `[]` (T-007 D3) and flag evaluation is T-002's, run downstream of the spine — this service never populates or interprets flag vocabulary (ADR-002 untouched).
4. **Ordering source is the contributing `Message.timestamp`** (= `InboundComms.received_at`), not processing order — under at-least-once *unordered* delivery, any interleaving of the same contribution set yields the same `current_offer` (per-field max over a set is commutative/associative/idempotent). Redelivered contributions are exact no-ops.
5. `Message.extracted_offer` is never derived from the rollup — it stays the extractor's verbatim per-message output; only `current_offer` is composite.

**ADR gate (per task note):** reading "rolled into" as accumulate-not-replace is an interpretive call beyond the spec text — the lead must resolve-and-log an ADR ratifying this merge rule (or the documented fallback: wholesale newest-offer-wins by the same `(at, ref)` ordering) **before T-009's build merges**. Either resolution is contained in `rollup.ts` + its tests; no other section of this design changes. (Precedent for accumulation: T-007 D5 — "a gap, which the thread rollup (T-009) can fill from a later message".)

## 10. Blockers / deviations

**No design blockers** — no frozen-spine (`specs/**`) change and no unapproved integration is required. The event contract this service needs (`CommsInboundQuarantinedV1` et al.) already exists in `packages/core` as built; ADR-005 already makes partial offers flow without any special seam.

**One open-for-the-lead deviation (D4, §0/§6), per the task's own instruction:** the `current_offer` merge rule (per-field newest-wins accumulation vs. wholesale replacement) is an interpretive call beyond the spec text "rolled into the thread's `current_offer`". This design specifies the primary policy (accumulation, §6) and a contained fallback; the lead must resolve-and-log an ADR **before T-009's build merges** (same escalation pattern as T-007 D1 → ADR-005). The design is complete under either resolution; the blast radius is `rollup.ts` and its tests.
