## 2. Exact interface signatures (public API of `@adapters/vehicle-history`)

The behavioral contract this package implements is **`VehicleHistoryAdapter` from `@core`** (T-001 §3.2, `packages/core/src/adapters.ts`):

```ts
// FROM @core — implemented, NOT redefined here:
// export interface VehicleHistoryAdapter {
//   readonly source: string;
//   getHistory(vin: Vin): Promise<AdapterResult<VehicleHistorySummary>>;
// }
```

What this package exports (`src/index.ts`, complete surface):

```ts
import type { VehicleHistoryAdapter, IsoTimestamp } from '@core';

/** Options shared by both mock factories. */
export interface MockHistoryOptions {
  /** Injectable clock for deterministic `fetched_at` in tests (D3). Defaults to system time. */
  now?: () => IsoTimestamp;
}

/** Carfax mock — source id "mock-carfax". */
export function createCarfaxMock(options?: MockHistoryOptions): VehicleHistoryAdapter;

/** AutoCheck mock — source id "mock-autocheck". */
export function createAutoCheckMock(options?: MockHistoryOptions): VehicleHistoryAdapter;

/** Adapter ids — the `source` provenance strings (match `VehicleHistorySummary.source`). */
export const CARFAX_MOCK_SOURCE: 'mock-carfax';
export const AUTOCHECK_MOCK_SOURCE: 'mock-autocheck';

/**
 * Well-known fixture VINs, exported so downstream packages/tests can exercise
 * every path offline without knowing fixture internals (D2). All syntactically
 * valid 17-char VINs; recognized by BOTH mocks.
 */
export const FIXTURE_VINS: {
  /** Clean history: 0 accidents, no title brands (task note: clean path). */
  readonly clean: string;
  /** Accident history, clean title. */
  readonly accident: string;
  /** Branded title (e.g. salvage + flood) with accident(s) (task note: branded path). */
  readonly branded_title: string;
  /** Triggers { code: 'rate_limited', retryable: true }. */
  readonly trigger_rate_limited: string;
  /** Triggers { code: 'provider_unavailable', retryable: true }. */
  readonly trigger_provider_unavailable: string;
  /** Triggers { code: 'malformed_response', retryable: false } (shape-drift drill). */
  readonly trigger_malformed_response: string;
};
```

Nothing else is exported. In particular: **no fixture-table export** (fixtures are reachable only through `getHistory`, so no caller can grow a dependency on a raw table shape that bypasses the adapter boundary), no Carfax/AutoCheck-specific result types, no configuration for URLs/keys — such options are inexpressible in this API by design.

Internal (not exported): `mock-history-adapter.ts` holds one `createMockHistoryAdapter(source, fixtureTable, options)` used by both provider modules; `fixtures.ts` holds two `ReadonlyMap<Vin, HistoryFixture>` tables where `HistoryFixture = { accident_count: number; title_brands: string[]; owner_count?: number }` — exactly the `VehicleHistorySummary` payload minus `vin`/`source`/`fetched_at`, which the factory stamps per call.

## 3. Data shapes (canonical spine types only)

- **Output:** `VehicleHistorySummary` from `@core` (`vin`, `accident_count`, `title_brands[]` — empty array = clean, `owner_count?`, `source`, `fetched_at`). Adapter output maps into the cached, timestamped `VehicleData` spine type: callers place the summary at `VehicleData.history` (specs/00 "Core domain model", `VehicleData (cached, timestamped)`). **This package does not construct or cache `VehicleData`** — assembly/caching is the caller's job (T-001 §5.1: snapshots are timestamped precisely so stale cache is a legal fallback); the adapter stamps `fetched_at` so every summary is cacheable.
- **Input:** `Vin` from `@core` (17-char uppercased VIN scalar).
- **Relation to `Deal`/`DealerThread`/`Message`/`Offer`:** this adapter never touches them. Its position in the object graph is `Deal.resolved_vehicle: Vin → getHistory(vin) → VehicleData.history` on the deal's vehicle-data view. No Carfax/AutoCheck shape can reach `Deal` because none exists in any exported type — the anti-corruption boundary holds by construction.
- **Fixtures** (per task note, both providers): at least `clean` (0 accidents, `title_brands: []`) and `branded_title` (≥1 accident, e.g. `["salvage", "flood"]`), plus `accident` (accidents, clean title) so consumers can distinguish "accident" from "brand". Per D4, the two providers return divergent details (e.g. differing `owner_count`) for the same VIN.

## 4. Error paths per operation

One operation exists: `getHistory(vin)`. It **never throws across the boundary** — every outcome is an `AdapterResult<VehicleHistorySummary>` (T-001 §3.1). The behavioral contract is T-001 §5.1 (outbound-feed table), applied as follows; the mocks make every row exercisable offline:

| Failure mode | Mock trigger | Result | Retry / idempotency | Logged (by caller) | Surfaces as |
|---|---|---|---|---|---|
| Bad input (non-17-char / illegal chars / empty) | Any malformed VIN string | `{ ok:false, code:'invalid_input', retryable:false }` | None — caller bug, fix upstream | code, source, message (message never echoes the raw input) | Validation error to caller |
| No data for VIN | Any well-formed VIN not in the fixture table (D1) | `{ ok:false, code:'not_found', retryable:false }` | None — terminal, valid outcome | code, source, VIN-less message | "No history available" |
| Rate limit | `FIXTURE_VINS.trigger_rate_limited` | `{ ok:false, code:'rate_limited', retryable:true }` | Caller backoff + jitter; the read is naturally idempotent — same VIN, same answer, always | code, source | Stale cached `VehicleData.history` (timestamped for exactly this) or "data unavailable" |
| Provider timeout / 5xx | `FIXTURE_VINS.trigger_provider_unavailable` | `{ ok:false, code:'provider_unavailable', retryable:true }` | Same as above | code, source | Same as above |
| Provider shape drift | `FIXTURE_VINS.trigger_malformed_response` | `{ ok:false, code:'malformed_response', retryable:false }` | None; operator alert (in mock-land: fixture or contract broke) | code, source | Degraded-feature state |
| Credential failure | **Not simulatable** (D2) | — | The `auth` code stays reachable in the type but no mock path emits it; there are no credentials to fail, and that absence is the enforcement | — | — |

Cross-cutting rules (binding on the builder):

- **Determinism / idempotency:** `getHistory` is a pure lookup + clock stamp. Same VIN in, same fixture out, every time, unbounded call count, no state, no ordering sensitivity. Retries are trivially safe.
- **Never in any result or error `message`:** provider payload facsimiles, credentials, URLs, PII. `AdapterError.message` is log-safe by contract (T-001 §5.1); there is no field where anything else fits.
- **The mocks perform no I/O whatsoever** — no HTTP, no fs, no env reads. `getHistory` resolves in-memory (async only to honor the interface's `Promise` shape). This is what "tests run fully offline" (task objective) means structurally, not just in CI configuration.
- **Logging:** the package itself logs nothing (it is a pure library); the table's "Logged" column states what *callers* log per T-001 §5.1, so this adapter must give them the code/source/message to do it — and nothing more.

### Webhooks — none (ack-then-queue N/A, stated for the record)

This package exposes **no webhook handler, no inbound surface, no event producer/consumer**. Real Carfax/AutoCheck integrations are request/response feeds, and these are their mocks. The spec's binding webhook rule — "webhooks ack immediately, all heavy work runs on the event bus" (specs/00 "Comms aggregation layer"; T-001 §5.2 ack-then-queue) — applies to comms ingest (T-009), not here. The builder must not add any HTTP server, route, or bus wiring to this package; if a future live-provider callback ever seems needed, that is a new-integration escalation to Corban, not a T-005 extension.

## 6. Test design (co-located, vitest, offline — task AC-4)

1. **Contract conformance (both mocks):** factory return satisfies `VehicleHistoryAdapter`; `source` equals the exported constant; results for fixture VINs are valid `VehicleHistorySummary` values (typechecked via `satisfies`, runtime-asserted for field presence).
2. **Fixture paths:** `clean` → `accident_count: 0`, `title_brands: []`; `accident` → count ≥ 1, empty brands; `branded_title` → non-empty brands (task note's two required paths plus the distinguishing third).
3. **Error paths:** malformed VIN → `invalid_input`; unknown VIN → `not_found`; each trigger VIN → its code with the contract's `retryable` value (T-001 §5.1 table row by row).
4. **Determinism:** repeated calls with a fixed injected clock return deeply-equal results; JSON round-trip unchanged (cache-serializable).
5. **Provider-agnosticism:** same VIN across both mocks yields the same *shape* but divergent details (D4); a test asserts no exported symbol references a provider-specific type.
6. **Never-throws:** `getHistory` resolves (never rejects) for adversarial inputs (empty string, lowercase VIN, 16/18 chars, unicode).
