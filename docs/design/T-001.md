# Design — T-001: Monorepo scaffold + core spine contracts (`packages/core`)

- **Task:** `tasks/T-001-monorepo-scaffold-core-spine.md`
- **Spec basis:** `specs/00-shared-core-architecture.md` — "Core domain model", "Comms aggregation layer", "Integrations — anti-corruption / adapter layer (shared)", "Async backbone (shared)"; `specs/01` (consent posture, credit residency — shape constraints only); `specs/02` (sender-of-record invariant — shape constraints only)
- **ADRs honored:** ADR-001 (Node/TS, spine defined once), ADR-002 (`payment_packing` canonical)
- **Stage:** design → build
- **Scope:** contracts + types + workspace tooling only. No provider logic, no I/O, no DB wiring, no adapter implementations.

## 1. Monorepo layout & tooling (the T-001 EXTRA, binding)

### 1.1 Files this task creates

```
package.json            (root — ONLY place with dependencies)
tsconfig.base.json      (root — all nine aliases predeclared)
vitest.workspace.ts     (root — same aliases, resolved for vitest)
packages/core/
├── package.json        ({ "name": "@core", "private": true } — marker only, no deps)
├── tsconfig.json       (extends ../../tsconfig.base.json; include: ["src", "test"])
├── src/
│   ├── index.ts        (public API — the only import surface)
│   ├── domain.ts       (spine types, §2)
│   ├── adapters.ts     (adapter contracts, §3)
│   └── events.ts       (event contracts, §4)
└── test/
    └── smoke.test.ts   (type-level + runtime smoke, §6)
```

Reserved (documented, **not created** here): `packages/flag-engine`, `packages/adapters/{valuation,nhtsa,vehicle-history,credit-prequal}`, `packages/offer-extraction`, `packages/receipt`, `services/comms` — per ADR-001 layout and tasks T-002…T-009 ownership globs.

### 1.2 Root `package.json` (design)

```jsonc
{
  "name": "deal-copilot-kit",
  "private": true,
  "type": "module",
  "workspaces": ["packages/*", "packages/adapters/*", "services/*"],
  "scripts": {
    "test": "vitest run",
    "typecheck": "tsc -p packages/core --noEmit"
  },
  "devDependencies": {
    "typescript": "^5.5",
    "vitest": "^3"
  }
}
```

Rules this encodes:

- **Root devDeps only** — `typescript` + `vitest`, nothing else, nowhere else. Any other `dependencies`/`devDependencies` key appearing anywhere in the repo is a review finding (CLAUDE.md invariant 2).
- **One install, ever.** The T-001 builder runs `npm install` at root once. Later packages need **no** `npm install`: cross-package imports never touch `node_modules` — they resolve via tsconfig paths (typecheck) and the vitest alias map (tests). A later package is just a directory with `src/`, `test/`, and a `tsconfig.json` extending the base; a `package.json` marker is optional (npm workspace globs simply ignore directories without one).
- **No root-file edits by later tasks.** The three root files are frozen after T-001 publishes (they are T-001 ownership; every other task's globs exclude them). The alias maps below predeclare every downstream package so no later task ever needs a root edit. Per-package typecheck is `npx tsc -p packages/<name> --noEmit` — no root script change required.

### 1.4 `vitest.workspace.ts` (design)

Task ownership grants exactly this filename, so the root vitest config lives here (vitest ≥3 still honors workspace files). One inline project carries the alias map — the **same eight entries** as `tsconfig.base.json`, resolved to absolute paths:

```ts
import { defineWorkspace } from 'vitest/config';

const r = (p: string) => fileURLToPath(new URL(p, import.meta.url));

  '@flag-engine':              r('packages/flag-engine/src/index.ts'),
  '@adapters/valuation':       r('packages/adapters/valuation/src/index.ts'),
  '@adapters/nhtsa':           r('packages/adapters/nhtsa/src/index.ts'),
  '@adapters/vehicle-history': r('packages/adapters/vehicle-history/src/index.ts'),
  '@adapters/credit-prequal':  r('packages/adapters/credit-prequal/src/index.ts'),
  '@offer-extraction':         r('packages/offer-extraction/src/index.ts'),
  '@receipt':                  r('packages/receipt/src/index.ts'),
};

export default defineWorkspace([
  {
    test: {
      name: 'workspace',
      include: [
        'packages/**/src/**/*.test.ts',
        'packages/**/test/**/*.test.ts',
        'services/**/src/**/*.test.ts',
        'services/**/test/**/*.test.ts',

```

Consequences: `npx vitest run packages/core` (or any later package path) works from root for **every** package with zero per-package config, zero per-package installs, zero root edits. **Sync rule (binding on any future root change):** the alias map here and `paths` in `tsconfig.base.json` must stay entry-for-entry identical; both files are T-001-owned and frozen, so drift requires a deliberate, reviewed change to both.

## 2. Spine domain types (`packages/core/src/domain.ts`)

These are the **single definition** of the spine (ADR-001: "defined once … no parallel type definitions"). The authoritative field list is specs/00 "Core domain model"; the TypeScript below is that model transcribed, not a second model. Downstream packages import these via `@core` and never re-declare them.

```ts
// ---- scalars ----------------------------------------------------------
/** ISO-8601 UTC timestamp string. */
export type IsoTimestamp = string;
/** Integer USD cents. All money in the spine is integer cents — no floats. */
export type MoneyCents = number;
/** 17-char VIN, uppercased. Validation is downstream's job; the type is nominal-ish documentation. */
export type Vin = string;

// ---- enums (spec-fixed) ----------------------------------------------
export type DealPath = 'online' | 'hybrid' | 'in_person';
export type DealStatus = 'draft' | 'active' | 'negotiating' | 'closed' | 'burned';
export type MessageChannel = 'call' | 'sms' | 'email';
export type MessageDirection = 'in' | 'out';

/** ADR-002: canonical name is `payment_packing`; specs/00's `packing` is shorthand for it. */
export type OfferFlag = 'payment_packing' | 'rate_markup' | 'junk_fee' | 'over_walkaway';
export const OFFER_FLAGS: readonly OfferFlag[] = ['payment_packing', 'rate_markup', 'junk_fee', 'over_walkaway'];

// ---- identity (provider-agnostic by construction) --------------------
/**
 * Points at *an* identity — a number + inbox — without encoding who
 * provisioned it (specs/00: "`identity_ref` is deliberately provider-agnostic").
 * There is intentionally NO provider/provisioner/vendor field on this type.
 */
export interface IdentityRef {
  /** Opaque handle into whichever identity store the product wired up. */
  identity_id: string;
  /** E.164 phone number, when the identity has one. */
  phone_number?: string;
  /** Email alias/inbox address, when the identity has one. */
  email_alias?: string;
}

// ---- vehicle ----------------------------------------------------------
/** Buyer's target spec, pre-VIN. */
export interface VehicleSpec {
  make: string;
  model: string;
  year?: number;
  trim?: string;
}

// ---- aggregate root ---------------------------------------------------
export interface Deal {
  id: string;
  /** User in consumer, Org/Seat in B2B — core does not distinguish. */
  owner_id: string;
  path: DealPath;
  status: DealStatus;
  target_vehicle: VehicleSpec;
  /** VIN, once identified. */
  resolved_vehicle?: Vin;
  budget: MoneyCents;
  walk_away_number: MoneyCents;
  /** Absent until first dealer contact (lazy provisioning, specs/01). */
  identity_ref?: IdentityRef;
  dealer_threads: DealerThread[];
  offers: Offer[];
  receipt_bundle_id?: string;
  created_at: IsoTimestamp;
  burned_at?: IsoTimestamp;
}

export interface DealerThread {
  dealer_id: string;
  dealer_name: string;
  contact: DealerContact;
  messages: Message[];
  current_offer?: Offer;
}

export interface DealerContact {
  phone?: string;
  email?: string;
  address?: string;
}

export interface Message {
  channel: MessageChannel;
  direction: MessageDirection;
  /** SMS/email body. */
  body?: string;
  /**
   * Call recording pointer. Consumer policy (specs/01 consent posture) keeps
   * this null forever — the field exists because the spine is shared, the
   * policy lives in the product, not the type.
   */
  recording_url?: string | null;
  /** Call transcript (transcribe-only posture on consumer). */
  transcript?: string;
  timestamp: IsoTimestamp;
  extracted_offer?: Offer;
}

export interface OfferFee {
  name: string;
  amount: MoneyCents;
}

export interface Offer {
  sale_price: MoneyCents;
  fees: OfferFee[];
  /** Annual percentage rate, e.g. 6.9 — absent on cash deals. */
  apr?: number;
  term_months?: number;
  monthly?: MoneyCents;
  flags: OfferFlag[];
}

// ---- cached, timestamped (specs/00: "ValuationSnapshot · VehicleData") ----
export interface ValuationSnapshot {
  vehicle: VehicleSpec | { vin: Vin };
  mileage?: number;
  /** Blend per specs/00 Valuation: wholesale vs trade-in vs retail (+ private-party). */
  values: {
    wholesale?: MoneyCents;
    trade_in?: MoneyCents;
    retail?: MoneyCents;
    private_party?: MoneyCents;
  };
  /** Adapter id (e.g. "mock-kbb") — provenance, never a provider payload. */
  source: string;
  fetched_at: IsoTimestamp;
}

export interface VinDecode {
  vin: Vin;
  make: string;
  model: string;
  year: number;
  trim?: string;
  body_class?: string;
  engine?: string;
}

export interface RecallRecord {
  campaign_id: string;
  component: string;
  summary: string;
  issued_at: IsoTimestamp;
}

export interface VehicleHistorySummary {
  vin: Vin;
  accident_count: number;
  title_brands: string[];   // e.g. ["salvage", "flood"] — empty = clean
  owner_count?: number;
  source: string;           // adapter id
  fetched_at: IsoTimestamp;
}

export interface VehicleData {
  vin: Vin;
  decode: VinDecode;
  recalls: RecallRecord[];
  history?: VehicleHistorySummary;
  fetched_at: IsoTimestamp;
}
```

Notes:

- `Deal`, `DealerThread`, `Message`, `Offer` carry exactly the spec's fields (AC-1); support types (`DealerContact`, `OfferFee`, `VehicleSpec`) name the spec's inline composites ("contact info", "fees[]", "target_vehicle (spec)") without adding data.
- `MoneyCents` everywhere kills float-money bugs before the flag engine (T-002) does arithmetic on `sale_price`/`monthly`/`walk_away_number`.
- Postgres/S3 is the eventual store (specs/00 "Store") — **no** persistence annotations, ORMs, or ids beyond the spec's appear here (D2).

## 3. Adapter contracts (`packages/core/src/adapters.ts`)

specs/00: "Every external feed sits behind one internal interface. Core services never see a provider's shape." Every contract therefore speaks **only** in §2 types plus the neutral request/receipt types below. No provider SDK type, header, URL, or credential appears anywhere in core.

### 3.1 Uniform result & error shape

Adapters **never throw across the boundary**; every operation returns `AdapterResult`.

```ts
export type AdapterErrorCode =
  | 'invalid_input'         // caller bug — not retryable
  | 'not_found'             // provider has no data — not retryable
  | 'auth'                  // credential problem — not retryable, alert operator
  | 'rate_limited'          // retryable with backoff
  | 'provider_unavailable'  // timeout / 5xx — retryable with backoff
  | 'malformed_response';   // provider shape drifted — not retryable, alert operator

export interface AdapterError {
  code: AdapterErrorCode;
  /** Whether the SAME call may succeed on retry. Derived from code; stated explicitly so callers never guess. */
  retryable: boolean;
  /** Adapter id, e.g. "mock-manheim", "nhtsa-vpic". */
  source: string;
  /** Log-safe, PII-free, provider-payload-free description. */
  message: string;
}

export type AdapterResult<T> =
  | { ok: true; value: T }
  | { ok: false; error: AdapterError };
```

### 3.2 Outbound-feed adapters (T-003…T-006 implement these)

```ts
export interface ValuationRequest {
  vehicle: VehicleSpec | { vin: Vin };
  mileage?: number;
}

/** specs/00 "Valuation" — retail/trade-in/wholesale/private-party feeds. */
export interface ValuationAdapter {

/** specs/00 "Vehicle data" — VIN decode + recalls (NHTSA vPIC + Recall API, T-004). */
export interface VehicleDataAdapter {
  readonly source: string;
  decodeVin(vin: Vin): Promise<AdapterResult<VinDecode>>;
  getRecalls(vin: Vin): Promise<AdapterResult<RecallRecord[]>>;

/** specs/00 "Vehicle data" — accident/title (Carfax/AutoCheck, mock-only, T-005). */
export interface VehicleHistoryAdapter {
  readonly source: string;
  getHistory(vin: Vin): Promise<AdapterResult<VehicleHistorySummary>>;
}

/**
 * specs/01 "Credit data residency" — pass-through only. The contract makes the
 * forbidden thing inexpressible: there is no method returning raw credit data,
 * and PrequalResult holds a provider token + derived results ONLY.
 */
export interface PrequalResult {
  provider_token: string;     // opaque reference into the provider's hosted flow
  qualified_apr: number;
  approved_amount_max: MoneyCents;

  readonly source: string;
  getPrequal(provider_token: string): Promise<AdapterResult<PrequalResult>>;

```

### 3.3 Comms adapters (telephony, email — T-009 consumes)

Two directions, one rule: **inbound parsing is synchronous and cheap** (it runs inside a webhook handler that must ack immediately, §5.2); everything slow is an event consumer's job.

```ts
export interface OutboundSms {
  /** Sends FROM this identity — dealer never sees a real personal line (specs/00 "Outbound"). */
  from: IdentityRef;
  to_phone: string;
  body: string;
  /** Caller-supplied idempotency key; adapters must dedupe on it. */
  client_ref: string;
}

export interface OutboundEmail {
  from: IdentityRef;
  to_email: string;
  subject: string;
  body: string;
  client_ref: string;
}

export interface ProviderSendReceipt {
  /** Provider's opaque message id — provenance only, never interpreted by core. */
  provider_message_ref: string;
  accepted_at: IsoTimestamp;
}

/**
 * Normalized inbound item — the ONLY shape a webhook payload may become.
 * This is what gets wrapped into a `comms.inbound.received` event (§4).
 */
export interface InboundComms {
  channel: MessageChannel;
  /** Which of OUR identities the dealer contacted — routes to the Deal. */
  to_identity: { phone_number?: string; email_alias?: string };
  from: { phone?: string; email?: string };
  /** SMS/email body; absent for calls. */
  body?: string;
  /** For calls: provider's opaque handle to audio/stream — consumed by transcription, per product policy. */
  call_ref?: string;
  /** Provider's message id — idempotency anchor (§5.3). */
  provider_message_ref: string;
  received_at: IsoTimestamp;
}

export interface TelephonyAdapter {
  readonly source: string;
  sendSms(msg: OutboundSms): Promise<AdapterResult<ProviderSendReceipt>>;
  /**
   * SYNCHRONOUS, pure, no I/O: verify + normalize a raw webhook payload.
   * Must be safe to call before the handler acks.
   */
  parseInboundWebhook(payload: unknown): AdapterResult<InboundComms>;
}

export interface EmailAdapter {
  readonly source: string;
  sendEmail(msg: OutboundEmail): Promise<AdapterResult<ProviderSendReceipt>>;
  parseInboundWebhook(payload: unknown): AdapterResult<InboundComms>;
}
```

The same four comms methods serve both products: consumer wires our-provisioned identities, B2B wires connected ones (specs/02 connector layer points these adapters inbound). The contract cannot tell the difference — that is the point.

## 4. Event contracts (`packages/core/src/events.ts`)

specs/00 "Async backbone": the bus drives inbound-comms processing, transcription, offer extraction, valuation refresh, alert dispatch. Contracts are versioned (`.v1` suffix) so payloads can evolve without breaking consumers.

```ts
export interface EventEnvelope<TType extends SpineEventType = SpineEventType, TPayload = unknown> {
  /** Producer-assigned UUID — unique per publish attempt. */
  event_id: string;
  type: TType;
  occurred_at: IsoTimestamp;
  /** Set when the event is already attributable to a deal. */
  deal_id?: string;
  /**
   * Dedupe anchor under at-least-once delivery. Derivation is fixed per type
   * (§5.3) — consumers treat two events with equal keys as the same fact.
   */
  idempotency_key: string;
  payload: TPayload;
}

export type SpineEventType =
  | 'comms.inbound.received.v1'
  | 'comms.transcription.requested.v1'
  | 'comms.transcription.completed.v1'
  | 'offer.extraction.requested.v1'
  | 'offer.extraction.completed.v1'
  | 'valuation.refresh.requested.v1'
  | 'valuation.refresh.completed.v1'
  | 'alert.dispatch.requested.v1';

// -- inbound comms (published by webhook handlers AFTER parse, BEFORE any heavy work)
export interface CommsInboundReceivedV1 {
  source: string;              // adapter id that parsed it
  inbound: InboundComms;       // §3.3
}

// -- transcription (calls; consumer policy = transcribe-only, no audio retention)
export interface TranscriptionRequestedV1 {
  deal_id: string;
  dealer_id: string;
  call_ref: string;
  provider_message_ref: string;
}
export interface TranscriptionCompletedV1 {
  deal_id: string;
  dealer_id: string;
  provider_message_ref: string;
  transcript: string;
}

// -- offer extraction (transcript/text/email → parsed Offer, specs/00)
export interface OfferExtractionRequestedV1 {
  deal_id: string;
  dealer_id: string;
  provider_message_ref: string;
  channel: MessageChannel;
  text: string;                // body or transcript
}
export interface OfferExtractionCompletedV1 {
  deal_id: string;
  dealer_id: string;
  provider_message_ref: string;
  /** Absent when the text contained no offer — a valid, terminal outcome. */
  offer?: Offer;
}

// -- valuation refresh (snapshot + cache, specs/00)
export interface ValuationRefreshRequestedV1 {
  deal_id: string;
  request: ValuationRequest;   // §3.2
}
export interface ValuationRefreshCompletedV1 {
  deal_id: string;
  snapshot: ValuationSnapshot;
}

// -- alert dispatch (flags, walk-away crossings → owner notification)
export interface AlertDispatchRequestedV1 {
  deal_id: string;
  kind: 'flag_raised' | 'offer_received' | 'message_received';
  flags?: OfferFlag[];
  summary: string;             // human-readable, PII-free
}

// Convenience union for typed consumers:
export type SpineEvent =
  | EventEnvelope<'comms.inbound.received.v1', CommsInboundReceivedV1>
  | EventEnvelope<'comms.transcription.requested.v1', TranscriptionRequestedV1>
  | EventEnvelope<'comms.transcription.completed.v1', TranscriptionCompletedV1>
  | EventEnvelope<'offer.extraction.requested.v1', OfferExtractionRequestedV1>
  | EventEnvelope<'offer.extraction.completed.v1', OfferExtractionCompletedV1>
  | EventEnvelope<'valuation.refresh.requested.v1', ValuationRefreshRequestedV1>
  | EventEnvelope<'valuation.refresh.completed.v1', ValuationRefreshCompletedV1>
```

Bus-neutral by design: envelopes are plain JSON-serializable objects; SQS/SNS vs Kafka vs managed queue (specs/00 leaves it open) is a downstream wiring choice that cannot leak into these types.

## 5. Error paths, retries, idempotency (per operation)

T-001 ships contracts, so this section is the **binding behavioral contract** each downstream implementation is designed against. Signatures in §3–§4 exist to make these rules expressible.

### 5.1 Outbound-feed adapter calls (valuation, VIN decode, recalls, history, prequal)

| Failure mode | Contract behavior | Retry / idempotency | Logged | Surfaces as |
|---|---|---|---|---|
| Provider timeout / 5xx | `{ok:false, code:'provider_unavailable', retryable:true}` | Caller retries with backoff; all reads are naturally idempotent | code, source, safe message | Stale cached `*Snapshot` (it's timestamped for exactly this) or "data unavailable" |
| Rate limit | `'rate_limited'`, retryable | Backoff + jitter, caller-side | code, source | Same as above |
| No data for vehicle/VIN | `'not_found'`, not retryable | None — terminal | code, source, VIN-less message | "No valuation/history available" |
| Bad input (mangled VIN) | `'invalid_input'`, not retryable | None — caller bug, fix upstream | code, source | Validation error to caller |
| Credential failure | `'auth'`, not retryable | None; operator alert | code, source | Degraded-feature state |
| Provider shape drift | `'malformed_response'`, not retryable | None; operator alert (mock fixture or contract broke) | code, source | Degraded-feature state |

Never logged, by contract: raw provider payloads, credit data, PII. `AdapterError.message` is defined as log-safe; there is no field on the type where a raw payload fits.

### 5.2 Webhook ingest (telephony/email inbound) — **ack-then-queue, binding**

specs/00 rule: "webhooks ack immediately, all heavy work (transcription, extraction) runs on the event bus. Provider timeouts must never drop a dealer message."

Handler sequence (T-009 implements; the contracts force this shape):

1. `adapter.parseInboundWebhook(payload)` — synchronous, pure (§3.3). No DB, no downstream calls, no transcription, no extraction before ack.
2. Wrap result in `comms.inbound.received.v1`, **durably enqueue**.
3. **Ack 2xx** — and 2xx means exactly "the event is durably enqueued", nothing more.

Failure paths:

| Failure | Behavior | Why |
|---|---|---|
| Parse fails (`malformed_response`) | Still **ack 2xx**; enqueue a `comms.inbound.received.v1` carrying the parse error marker and raw payload reference for quarantine/replay | A 5xx makes the provider retry the same unparseable payload forever, and giving up drops a dealer message — both violate the no-drop rule. Quarantine keeps the message. |
| Enqueue fails (bus down) | **5xx** — the one deliberate non-ack | Provider-side retry is then the durability mechanism; dedupe on `provider_message_ref` absorbs the redelivery |
| Provider redelivers (we acked too slowly / they retried) | Idempotency key `source + ':' + provider_message_ref` — consumer treats it as duplicate, no double thread entry | At-least-once end to end |

Logged at ingest: source, channel, `provider_message_ref`, outcome. Never logged: message bodies, phone numbers, email addresses.

### 5.3 Event consumption (all consumers)

- **Delivery:** at-least-once, unordered. Every consumer must be idempotent on `idempotency_key`.
- **Key derivation (fixed per type):** `comms.inbound.received.v1` → `source:provider_message_ref`. Transcription/extraction request+complete → `deal_id:provider_message_ref:<stage>`. Valuation → `deal_id:fetched-window`. Alert → `deal_id:kind:trigger-ref`. Producers own derivation; consumers only compare.
- **Retryable consumer failure** (downstream adapter `retryable:true`, transient store errors): redeliver with backoff, bounded attempts.
- **Poison message** (non-retryable error or attempts exhausted): dead-letter with envelope intact; operator alert. Never silently dropped — for comms events this is the receipt trail's feedstock.
- **Logged:** `event_id`, `type`, `deal_id`, attempt count, outcome. Never payload bodies.
- **Surfaces:** completed events update `DealerThread`/`current_offer` and trigger `alert.dispatch.requested.v1`; dead-lettered comms events surface as an operator queue, not a user-facing loss.

### 5.4 Outbound send (SMS/email)

- Caller generates `client_ref` **before** first attempt; retries reuse it; adapters dedupe on it → no double-texting a dealer.
- `retryable:true` errors: bounded caller retries. Terminal errors: surface as a failed-send state on the thread for the owner to act on; never silently swallowed (the receipt trail must reflect what was actually sent).
- Send receipts (`provider_message_ref`, `accepted_at`) are recorded for the receipt layer's append-only trail.

### 5.5 This task's own operations

`packages/core` itself performs no I/O — its only runtime failure modes are compile/test failures, which is the point: the smoke test (§6) plus `tsc --noEmit` are the entire operational surface.

## 6. Smoke test design (`packages/core/test/smoke.test.ts`)

Runs green with **no other package present** (AC-8), from root: `npx vitest run packages/core`.

1. **Import via alias:** `import { OFFER_FLAGS, type Deal, type SpineEvent } from '@core'` — proves tsconfig+vitest alias parity.
2. **Type-level assertions** (compile-time, using vitest's `expectTypeOf` or `satisfies`): a literal `Deal` with all spec fields typechecks; `Offer['flags'][number]` is exactly the ADR-002 union; `IdentityRef` has no provider field (`'provider' extends keyof IdentityRef` is false); `Message` accepts `recording_url: null`.
3. **Runtime:** `OFFER_FLAGS` contains `'payment_packing'` and not `'packing'`; an `EventEnvelope` literal for each of the eight event types round-trips `JSON.parse(JSON.stringify(...))` unchanged (bus-serializable).
