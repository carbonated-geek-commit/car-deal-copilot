## 0. Interpretive calls made by this design (drift trip-wire log)

Spec ambiguity resolved inside this design, none touching a frozen file. If a builder finds any insufficient, stop and escalate — do not improvise.

| # | Call | Basis |
|---|------|-------|
| D1 | **The blend is itself a `ValuationAdapter`** (composite). specs/00 says "Blend into wholesale vs trade-in vs retail" without naming a mechanism. Exposing the blend behind the same one interface means callers (valuation-refresh consumer, demos, tests) see exactly one shape whether they talk to a single source or the blend — the anti-corruption rule stays airtight. A pure `blendSnapshots` function is also exported so the merge is unit-testable without adapters. | specs/00 "Every external feed sits behind one internal interface"; task AC-1/AC-3. |
| D2 | **Partial-blend degradation.** One source fails → the blend still returns `ok` with the fields the surviving source supplied (`ValuationSnapshot.values` fields are optional in the spine for exactly this) and the `source` provenance string names only the contributing adapters. Both sources fail → one `AdapterError` chosen by the precedence rule in §4.3. The spine's `AdapterResult` carries a single error; no spine change needed or made. | specs/00 snapshot fields optional (T-001 §2); T-001 §5.1 "stale snapshot or data unavailable" surface. |
| D3 | **Blend `fetched_at` = oldest contributing `fetched_at`.** The blend is only as fresh as its stalest input; taking the minimum makes caller-side cache/staleness logic conservative rather than optimistic. | specs/00 "Snapshot + cache" — timestamp exists to drive cache decisions. |
| D4 | **Fixture match keys:** exact VIN (uppercased) first; else normalized `make|model|year` (case-insensitive, trimmed; `trim` field ignored for matching). A spec-keyed request with no `year` cannot match a fixture deterministically → `invalid_input`. A fixture row may instead declare a simulated `error` code so downstream tests can exercise every §4.1 failure path offline. | Task note "plausible per-VIN/spec fixtures"; AC-5 offline tests; T-001 §3.1 error taxonomy. |
| D5 | **Fixtures are TypeScript modules**, not JSON files — typechecked against the fixture row type, no `resolveJsonModule` addition to the frozen base tsconfig, imported statically (deterministic, offline). | T-001 §1.3 frozen `tsconfig.base.json`; ADR-001 one toolchain. |
| D6 | **No cache store in this package.** "Snapshot + cache" is read as: the adapter produces fresh, timestamped snapshots; caching them (Postgres later) is the caller's/consumer's concern. This package stays pure and storage-free. | specs/00 "Store" assigns persistence to the relational core, not the adapter layer; T-001 §5.1 stale-snapshot surface implies caller-held cache. |
| D7 | **Optional deterministic mileage adjustment** per fixture row (`baseline_mileage` + `cents_per_mile`, linear, floored at 0) so demo values respond plausibly to mileage. Static values remain valid; the adjustment is opt-in per row. No randomness anywhere. | Task note "plausible … so the blend view is meaningful in demos". |
| D8 | **Injectable clock** (`now?: () => IsoTimestamp`, default system clock) on every factory so tests pin `fetched_at` and stay fully deterministic. | AC-5 (deterministic offline tests); mirrors T-001's bus-serializable/deterministic posture. |
| D9 | **Private-party stays open, unstubbed.** The composite accepts an optional third `ValuationAdapter` slot; Epic 1 wires nothing into it and this package implements no private-party mock. | Task note ("leave the interface open to a third source, do not stub"). |

## 2. Exposed interface signatures (this task's public API)

Everything below is **this package's** surface. All capitalized types not defined here (`ValuationAdapter`, `ValuationRequest`, `ValuationSnapshot`, `AdapterResult`, `AdapterErrorCode`, `VehicleSpec`, `Vin`, `MoneyCents`, `IsoTimestamp`) are imported from `@core` (T-001 §§2–3) and are **referenced, never redefined**.

```ts
import type {
  ValuationAdapter, ValuationRequest, ValuationSnapshot,
  AdapterResult, AdapterErrorCode,
  MoneyCents, Vin, IsoTimestamp,
} from '@core';

// ---- adapter ids (provenance strings; the ONLY place provider names appear) ----
export const KBB_MOCK_SOURCE = 'mock-kbb';
export const MANHEIM_MOCK_SOURCE = 'mock-manheim';
/** Blend provenance: 'blend(' + contributing sources joined by '+' + ')' — e.g. "blend(mock-kbb+mock-manheim)". */
export const BLEND_SOURCE_PREFIX = 'blend(';

// ---- fixture shape (neutral: MoneyCents fields, NOT a provider payload shape) ----
export interface ValuationFixtureRow {
  /** Match key A: exact 17-char VIN (matched case-insensitively, stored uppercased). */
  vin?: Vin;
  /** Match key B: normalized make|model|year. At least one of vin/spec_key per row. */
  spec_key?: { make: string; model: string; year: number };
  /**
   * The values this mock source knows. KBB fixture rows populate trade_in/retail;
   * Manheim rows populate wholesale. The type does not enforce the split —
   * the default fixture files do (§3).
   */
  values?: {
    wholesale?: MoneyCents;
    trade_in?: MoneyCents;
    retail?: MoneyCents;
  };
  /** Opt-in deterministic mileage plausibility (D7): linear, floored at 0. */
  mileage_adjustment?: {
    baseline_mileage: number;
    cents_per_mile: number;   // subtracted per mile ABOVE baseline, added per mile below
  };
  /**
   * Simulated failure (D4): when set, the mock returns this AdapterErrorCode
   * instead of values — lets downstream tests exercise every error path offline.
   * A row has values XOR error.
   */
  error?: AdapterErrorCode;
}

export interface MockValuationOptions {
  /** Defaults to the package's built-in fixture set for that mock. */
  fixtures?: readonly ValuationFixtureRow[];
  /** Injectable clock for deterministic fetched_at (D8). Defaults to system UTC now. */
  now?: () => IsoTimestamp;
}

// ---- the two mocks (both return the ONE spine interface) ----
/** Retail / trade-in need (specs/00 Valuation table row 1). source === KBB_MOCK_SOURCE. */
export function createKbbMockAdapter(opts?: MockValuationOptions): ValuationAdapter;

/** Wholesale / auction (MMR) need (specs/00 Valuation table row 2). source === MANHEIM_MOCK_SOURCE. */
export function createManheimMockAdapter(opts?: MockValuationOptions): ValuationAdapter;

// ---- the blend ----
/**
 * Pure merge (no I/O): combines per-source snapshots into the spec's
 * wholesale vs trade-in vs retail view. Field precedence and timestamp
 * rules in §4.3. Non-empty tuple type: blending zero snapshots is a type error.
 */
export function blendSnapshots(
  snapshots: readonly [ValuationSnapshot, ...ValuationSnapshot[]],
): ValuationSnapshot;

/** Sources feeding the composite. Roles, not providers — anti-corruption holds. */
export interface BlendedValuationSources {
  /** KBB-mock in Epic 1; any ValuationAdapter later. */
  retail_trade_in: ValuationAdapter;
  /** Manheim-mock in Epic 1. */
  wholesale: ValuationAdapter;
  /** Deliberately open third slot (specs/00 row 3). NOT implemented in Epic 1 (D9). */
  private_party?: ValuationAdapter;
}

/**
 * Composite ValuationAdapter (D1): fans getValuation out to each wired source
 * concurrently, blends per §4.3, returns one AdapterResult<ValuationSnapshot>.
 * source is BLEND_SOURCE_PREFIX + contributing adapter ids.
 */
export function createBlendedValuationAdapter(
  sources: BlendedValuationSources,
): ValuationAdapter;

// ---- default fixtures (re-exported for test/demos) ----
export const KBB_DEFAULT_FIXTURES: readonly ValuationFixtureRow[];
export const MANHEIM_DEFAULT_FIXTURES: readonly ValuationFixtureRow[];
```

Notes:

- **No KBB- or Manheim-specific shape is exported or expressible** (AC-1). The factories return `ValuationAdapter`; `ValuationFixtureRow` is a neutral internal-currency shape (`MoneyCents`), not a provider payload. There is no `KbbResponse`/`ManheimMmr` type anywhere.
- The provider names exist only inside the `mock-*` source strings, filenames, and doc comments — exactly the posture T-001 §7 set ("strings in doc comments, never imports, endpoints, or credentials").
- `getValuation` is the only operation (spine contract, T-001 §3.2). This package adds no methods to the interface.

## 3. Data shapes & fixture content

All request/response traffic uses canonical spine types only:

- **In:** `ValuationRequest` — `{ vehicle: VehicleSpec | { vin: Vin }, mileage? }` (T-001 §3.2). This is the same `VehicleSpec` that sits on `Deal.target_vehicle` and the same `Vin` as `Deal.resolved_vehicle`, so a caller can value a deal pre- or post-VIN-resolution with no translation layer.
- **Out:** `ValuationSnapshot` (T-001 §2) — `vehicle`, `mileage?`, `values.{wholesale?,trade_in?,retail?,private_party?}`, `source`, `fetched_at`. Cached-and-timestamped semantics come from `fetched_at` (AC-4); this package always sets it from the injected clock at response time.
- **Relation to `Deal`/`DealerThread`/`Message`/`Offer`:** none direct — valuation never reads or writes the comms aggregate. Downstream, the valuation-refresh consumer (future service, T-001 §4) correlates a snapshot to a `Deal` via `ValuationRefreshRequestedV1.deal_id`; the flag engine (T-002) may compare `Offer.sale_price` against snapshot values. Both happen outside this package; this package's job ends at emitting the snapshot.

Default fixture content (deterministic, offline, plausible for demos):

- ~6–10 vehicles spanning common demo cases: a couple keyed by full VIN (matching T-004's demo VINs where sensible), the rest by `make|model|year`.
- Each vehicle appears in **both** fixture files with economically coherent numbers: `wholesale < trade_in < retail` (the spread view is the point — specs/02 calls it the pro's daily bread).
- KBB rows populate only `trade_in`/`retail`; Manheim rows only `wholesale`. Discipline lives in the fixture files, and a test asserts it (§6).
- At least one row per file carries a simulated `error` (`not_found` is implicit for unknown vehicles; explicit rows cover `provider_unavailable` and `rate_limited`) so retry-path tests exist offline.

## 4. Error paths per operation

The spine's uniform rules apply (T-001 §3.1, §5.1): **adapters never throw across the boundary**; every failure is an `AdapterResult` error with `code`, `retryable`, `source`, and a log-safe, payload-free `message`.

### 4.1 `getValuation` on each mock (KBB-mock, Manheim-mock)

| Failure mode | Result | Retry / idempotency | Logged (by caller) | Surfaces as |
|---|---|---|---|---|
| Request has neither a VIN nor a spec with make+model+year (D4); or VIN not 17 chars after trim/uppercase; or negative mileage | `invalid_input`, `retryable:false` | None — caller bug, fix upstream | code, source, safe message | Validation error to caller |
| No fixture row matches | `not_found`, `retryable:false` | None — terminal | code, source, VIN-less message | "No valuation available" |
| Fixture row simulates `provider_unavailable` | `provider_unavailable`, `retryable:true` | Caller retries with backoff; reads are pure → naturally idempotent, same input + same clock ⇒ same output | code, source | Stale cached snapshot (timestamped for exactly this) or "data unavailable" |
| Fixture row simulates `rate_limited` | `rate_limited`, `retryable:true` | Backoff + jitter, caller-side | code, source | Same as above |
| Fixture row simulates `auth` / `malformed_response` | that code, `retryable:false` | None; operator alert (in mock-land this means a broken fixture or contract drift) | code, source | Degraded-feature state |

- **Idempotency:** mocks are pure functions of (request, fixtures, clock). No state, no side effects, no I/O. Any caller retry policy is safe by construction.
- **Logging:** the mocks themselves do not log (zero deps, no logger). They uphold the contract that makes caller logging safe: `AdapterError.message` never contains fixture dumps, VINs, or PII — there is no field where a payload fits (T-001 §5.1).
- **Never present:** credentials, endpoints, HTTP. There is no network failure mode because there is no network path (mock_only structural enforcement).

### 4.2 `blendSnapshots` (pure function)

- Cannot fail at runtime by design: the non-empty-tuple parameter makes "blend of nothing" a **compile-time** error, and merging optional fields cannot throw. No error path exists to handle.

### 4.3 `createBlendedValuationAdapter(...).getValuation` (composite)

Fan-out is concurrent (`Promise.all` over wired sources — 2 in Epic 1, 3 when private-party lands).

| Outcome | Result | Notes |
|---|---|---|
| All wired sources ok | `ok` with blended snapshot | Field precedence: `wholesale` from the wholesale-role source, `trade_in`/`retail` from the retail_trade_in-role source, `private_party` from the third slot; if two snapshots ever supply the same field (mis-wired roles), the most recent `fetched_at` wins — deterministic, and a test pins it. `fetched_at` = **oldest** contributor (D3). `source` = `blend(mock-kbb+mock-manheim)`. `vehicle`/`mileage` echoed from the request. |
| Some fail, ≥1 ok | `ok`, **partial** snapshot (D2) | Only surviving sources' fields present; `source` names contributors only (e.g. `blend(mock-kbb)`), so provenance doubles as the degradation signal without touching the frozen snapshot shape. Caller may log the per-source errors it can't see here? No — the composite is the caller of the mocks: it is the one place per-source failures are visible, and it exposes them **only** via the narrowed `source` string; anything richer would require a spine change (escalation, not improvisation). |
| All wired sources fail | one `AdapterError` | Precedence: a `retryable:true` error wins over a terminal one (keeps the caller's retry loop alive when retrying could help); among equals, the retail_trade_in-role error wins (deterministic). `source` = the blend id; `message` names both codes (codes only — still log-safe). `retryable` = OR of contributors. |

### 4.4 Webhook / ack-then-queue posture

**This package contains no webhook handlers** — nothing here receives provider callbacks (there are no providers; mock_only), so the specs/00 "ack immediately, heavy work on the bus" rule has no handler to bind *in this package*. The design still honors the async backbone it plugs into:

- The adapter is invoked by the future **valuation-refresh consumer** of `valuation.refresh.requested.v1`, which emits `valuation.refresh.completed.v1` carrying the `ValuationSnapshot` (T-001 §4). That consumer, not this package, owns queue semantics.
- The consumer's at-least-once redelivery (T-001 §5.3, idempotency key `deal_id:fetched-window`) is safe against this adapter because the adapter is pure and idempotent: a redelivered request re-produces an equivalent snapshot; no double effects exist to guard.
- The blend never blocks a webhook path: valuation refresh is bus-driven by spec ("valuation refresh" is on the async backbone list), so even a slow future live adapter behind this same interface stays off the ack path. Nothing in this package's API invites being called inline from a webhook handler — it appears in no comms contract.

## 6. Test design (co-located, offline — AC-5)

`test/kbb-mock.test.ts`, `test/manheim-mock.test.ts`:
1. Known VIN fixture → `ok`, snapshot has the expected role fields only (KBB: `trade_in`+`retail`, no `wholesale`; Manheim: `wholesale` only), `source` is the mock id, `fetched_at` equals the pinned clock.
2. Spec-key match (case-insensitive make/model, trim ignored); spec without year → `invalid_input`.
3. Unknown vehicle → `not_found`, `retryable:false`; simulated-error rows → correct code + `retryable` per taxonomy.
4. Mileage adjustment: same row, two mileages → deterministic linear delta, floored at 0; no mileage → baseline values.
5. Purity/idempotency: two identical calls → deeply equal results.
6. Default fixture discipline: every KBB row lacks `wholesale`; every Manheim row has only `wholesale`; shared vehicles satisfy `wholesale < trade_in < retail`.

`test/blend.test.ts`:
1. Both mocks ok → blended snapshot with all three values, `source === 'blend(mock-kbb+mock-manheim)'`, `fetched_at` = older of the two, spread ordering holds for demo vehicles (AC-3).
2. One source failing (simulated `provider_unavailable` fixture) → `ok` partial snapshot, `source` names the survivor only.
3. Both failing → single error; retryable-beats-terminal precedence; `retryable` OR rule.
4. `blendSnapshots` pure-merge: field precedence and most-recent-wins collision rule.
5. Type-level: `createBlendedValuationAdapter` return type is exactly `ValuationAdapter` (`expectTypeOf`); the package's public API exports no type with a provider-shaped name.
6. Serialization: a blended `ValuationSnapshot` round-trips `JSON.parse(JSON.stringify(...))` unchanged (bus-ready for `valuation.refresh.completed.v1`).
