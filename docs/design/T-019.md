## 0. Interpretive calls made by this design (drift trip-wire log)

Every call below sits inside spec/ADR ambiguity or is a mechanical consequence of a frozen file. A builder who finds any of them insufficient **stops and messages the lead** — it does not improvise, does not add a dependency, does not widen a spine type, and does not edit a foreign file.

| # | Call | Basis / consequence |
|---|------|---------------------|
| **D1** | **The account context is resolved by a named `AccountContextResolver` port whose only E2 implementation reads a request header (`x-dc-account-id`). This is NOT authentication and the code says so in its own identifier: `poc-header`.** | AC-4 forbids selecting or wiring an auth provider; AC-2 requires an account context at the edge on every request. Something must produce the id in between. A *port with one deliberately weak implementation* is the honest shape: E3 registers an Auth0/Clerk/Cognito-backed resolver and **no other file changes**. The resolver is the ONLY module in the service permitted to read an identity off the wire (§5.2 static test); nothing downstream ever touches headers. Startup logs a `warn` naming the resolver, so an operator cannot mistake the PoC posture for a secured one. |
| **D2** | **A deal-addressed request cannot reach the store without passing the gate — enforced by the type system, not by discipline.** `DealHandle` carries a module-private `unique symbol` and is constructible only inside `src/auth/deal-gate.ts`. Every store-touching function takes a `DealHandle`, never a `deal_id: string`. | AC-2 ("no code path that reaches the store without one") and AC-3 (one choke point E3 edits). A convention ("remember to call `authorize`") is unverifiable; an unforgeable token makes the forgetful version *not compile*. Belt to that brace: a boot-time route-table audit (§2.10) fails startup if a route matching `:deal_id` was registered without the gate hook, so T-020 cannot add a bypass either. |
| **D3** | **Denial because the deal belongs to another account returns `404 not_found`, never `403 forbidden`.** `403` is reserved for role/grant denials *inside* an owned account (concierge controls 1 and 3), which are declared and unreachable in E2. | specs/00 "Dealership data tenancy" and specs/01 "Account model". A `403` on a deal id is an existence oracle: it tells an unauthorized caller that the id is real. The distinction has to exist *before* E3, because E3 would otherwise have to choose it while also writing the auth code, and the tempting choice is the leaky one. |
| **D4** | **One envelope means one envelope: Fastify's own 400/404/413/415/500 bodies are overwritten too.** `setErrorHandler` + `setNotFoundHandler` + `setSchemaErrorFormatter` + an `onSend` shape assertion. | AC-6 and ADR-001 ("defined once … and imported everywhere — no parallel type definitions"). The realistic failure mode is not an endpoint inventing a shape — it is the framework emitting `{statusCode, error, message}` for a route that was never reached. That body is a second error contract, and it leaks the framework. |
| **D5** | **`zod` schemas build their enums from `@core`'s frozen vocabulary arrays** (`MESSAGE_CHANNELS`, `MESSAGE_DIRECTIONS`, `MESSAGE_AUTHORS`, `VEHICLE_CONDITIONS`, `DEALERSHIP_CONTACT_ROLES`, `PROCESS_STEPS`, `OFFER_FLAGS`). `@core` exposes **no** array for `DealPath` or `DealStatus`, so this service declares those two locally **with a compile-time exhaustiveness guard against the `@core` union** (§2.6). | `packages/core/src/domain.ts` says the arrays exist so "validators import these rather than re-declaring the literals, which would be ADR-001's 'parallel type definition' in a different syntax" — but only 7 of the 9 spec-fixed enums got one. Editing `@core` is forbidden (T-010, complete). The guard makes drift a **build failure** rather than a silent divergence: add `leased` to `DealStatus` and this service stops compiling. Recorded as a note to the lead in §8.1 recommending `@core` gain `DEAL_PATHS` / `DEAL_STATUSES` in a task that owns it. |
| **D6** | **The webhook plane and the health plane are foundation, and live in `src/webhooks/**` and `src/http/**` — not `src/routes/**`.** | AC-7 makes webhook endpoints *this task's* deliverable, while the task notes reserve `src/routes/**` for T-020. Reconciled by the fact that they are genuinely different planes: a webhook has **no account context and no store access at all** (§2.9), and a health probe has neither. Putting them under `routes/` would also put them under a directory whose ownership forbids me from touching it. Flagged in §8.2. |
| **D7** | **`DATABASE_URL` and the object-store config are independent switches, and a configured-but-unreachable one fails fast at startup — the process exits non-zero and never degrades to in-memory.** Postgres-configured-without-object-store is **allowed with a `warn`**, and `/readyz` reports `raw_payload_durability: "volatile"`. | ADR-008 fixes the default and the fail-fast rule ("A configured-but-unreachable `DATABASE_URL` fails fast; it must never silently degrade to in-memory"), and `@db`'s `readDbConfigFromEnv` / `@object-store`'s `readObjectStoreConfig` already encode *absent ⇒ not configured* vs *partial ⇒ error*. ADR-008 gives no authority to **require** the pair, so requiring it would be invented policy; making the durability gap visible in the readiness body is the honest middle. §8.4 recommends the lead consider mandating the pair. |
| **D8** | **The API adds no request-level idempotency cache.** Idempotency is the spine's existing natural keys: the adapter-derived envelope key for webhooks (T-014), `client_note_ref` for notes, and `@store-pg`'s keyed writes (`ON CONFLICT DO NOTHING`) for everything durable. | An `Idempotency-Key` ledger needs durable storage; in the default in-memory mode it would be a cache that forgets on restart while *claiming* replay protection — a lie that is worse than the absence. The existing keys already cover every mutating path this epic exposes. |
| **D9** | **Responses never contain `null`.** An absent optional is an omitted key. | ADR-005: an absent input is **UNEVALUABLE**. `null` in a JSON body is read by every client as "known to be empty", which is precisely the "silently zero / not triggered" reading ADR-005 forbids. `exactOptionalPropertyTypes: true` already makes this the natural TS shape; an `onSend` assertion makes it checkable. |
| **D10** | **The API computes nothing the domain already owns.** No flag evaluation, no rollup merge, no valuation comparison, no offer extraction on the request path. | ADR-006 (rollup lives in `@comms/rollup.ts`, "the blast radius is rollup.ts alone"), ADR-007, specs/00 "Comms aggregation layer" ("all heavy work … runs on the event bus"). A second implementation in a route handler is exactly the parallel definition ADR-001 forbids. |
| **D11** | **No presigned URLs and no direct-to-store byte paths** — consistent with T-018 D8, and no new dependency is introduced to add one. | `@aws-sdk/s3-request-presigner` is a separate package ⇒ T-015-only ⇒ escalation. |
| **D12** | **JSON is the only accepted request content type.** A form-encoded provider webhook currently yields `415` through the envelope. | `@fastify/formbody` is a dependency edit (T-015-only, ADR-009). The comms adapters in this epic are fixtures, so nothing form-encoded exists to accept yet. Recorded as a real gap for the epic that wires Twilio/SES — §8.3. |
| **D13** | **No `node-shim.d.ts` in this service.** Verified empirically at design time. | `tsconfig.base.json` sets `"types": []`, which is why `services/comms` and `packages/object-store` hand-write shims. A probe compiled `fastify`, `zod`, `node:process`, `node:crypto`, `structuredClone`, `TextEncoder`, and `setTimeout` under `npx tsc -p services/api --noEmit` with **zero errors** — Fastify's typings carry the `node` types reference that the S3 SDK's do not (T-018's shim rationale inverted, for this program). The probe files were deleted; nothing was committed. If a builder hits `TS2307` for a builtin this design did not name, that is a §8 escalation, not a manifest edit. |

### 2.1 Configuration

```ts
/** The composition-root view of the environment. The ONLY env reader in the service. */
export interface ApiConfig {
  readonly host: string;                 // default '127.0.0.1' — not 0.0.0.0 by accident
  readonly port: number;                 // PORT, default 3000
  readonly body_limit_bytes: number;     // default 1_048_576
  readonly log_level: 'fatal' | 'error' | 'warn' | 'info' | 'debug';
  /** undefined ⇒ Postgres NOT configured (ADR-008: the normal PoC state). */
  readonly database?: DbConfig;
  /**
   * undefined  ⇒ object store NOT configured (default to in-memory)
   * { ok:false } ⇒ PARTIALLY configured — a misconfiguration; startup fails.
   * Passed through verbatim from `readObjectStoreConfig`; this service does not
   * re-interpret the distinction it already encodes.
   */
  readonly object_store?: ObjectStoreResult<ObjectStoreConfig>;
}

export type ApiConfigResult =
  | { ok: true; value: ApiConfig }
  | { ok: false; error: ApiError };      // §2.7 — startup failures use the same vocabulary

export function readApiConfig(env: Readonly<Record<string, string | undefined>>): ApiConfigResult;
```

`env` is a parameter, never `process.env` reached for internally (T-018 D10, T-015 §2.2 rule 4): every configuration branch is testable with no global mutation.

### 2.2 The storage plan — one pure decision, then no more branching

```ts
export type RelationalMode = 'memory' | 'postgres';
export type ObjectMode = 'memory' | 's3';

/**
 * The resolved posture. Computed ONCE, at startup, from `ApiConfig`. After this
 * point no module asks "are we on Postgres?" — every consumer holds a port.
 */
export interface StoragePlan {
  readonly relational: RelationalMode;
  readonly objects: ObjectMode;
  /**
   * TRUE when relational === 'postgres' && objects === 'memory' (D7): durable
   * rows will reference raw-payload bytes that do not survive a restart.
   * Surfaced in `/readyz` and logged `warn` at startup. Never silently true.
   */
  readonly raw_payload_durability: 'durable' | 'volatile';
}

export function resolveStoragePlan(config: ApiConfig): { ok: true; value: StoragePlan } | { ok: false; error: ApiError };
```

`{ ok: false }` here means **partially configured** — the `readObjectStoreConfig` `{ ok:false }` case. It is a startup abort, never a fallback (ADR-008; T-018 config header comment: "the caller FAILS FAST at startup and MUST NOT degrade to a volatile store").

### 2.4 Account context — resolved once, at the edge

```ts
export type ActorRole = 'owner' | 'concierge_agent';
```

### 2.5 The authorization choke point — and why nothing can go round it

```ts
export type DealAction = 'read' | 'write' | 'export';   // 'export' declared for concierge control 2

export type AuthzDenyReason =
  | 'not_owned'          // E2-reachable — the account does not own this deal
  | 'deal_not_found'     // E2-reachable
  | 'grant_expired'      // E3 (concierge control 3) — declared, unreachable today
  | 'role_not_permitted';// E3 (concierge controls 1 & 2) — declared, unreachable today

export type AuthzDecision =
  | { readonly outcome: 'permit'; readonly reason: 'account_owns_deal' }
  | { readonly outcome: 'deny'; readonly reason: AuthzDenyReason };

declare const DEAL_HANDLE_BRAND: unique symbol;   // module-private: NOT exported

/**
 * Proof that (a) an account context exists and (b) the gate permitted this
 * action on this deal. Unforgeable outside `auth/deal-gate.ts` because the brand
 * symbol is not exported. EVERY store-touching signature in this service takes
 * this instead of a `deal_id: string` (D2).
 */
export interface DealHandle {
  readonly [DEAL_HANDLE_BRAND]: true;
  readonly deal_id: string;
  readonly action: DealAction;
  readonly account: AccountContext;
  readonly scope: AccountScope;            // convenience: === account.scope
}

export interface DealAccessGate {
  readonly name: string;
  authorize(ctx: AccountContext, deal_id: string, action: DealAction): Promise<AuthzDecision>;
}

/**
 * E2 gate. Permits every action for a resolved context and records the decision.
 * It does NOT read the store: ownership is verified on the read path instead
 * (§2.6 `ScopedReadModel`, which re-checks `deal.owner_id`), so the gate stays a
 * pure policy function and E3 replaces exactly this one implementation.
 */
export function createPermissiveDealGate(): DealAccessGate;

/**
 * The `preHandler` factory every deal-addressed route MUST use. Reads `:deal_id`
 * from the already-validated params, calls the gate, and on `permit` mints the
 * handle onto the request. On `deny` it sends the envelope and never calls the
 * handler.
 *
 * The boot audit (§2.10) fails startup for any route whose URL contains
 * `:deal_id` and whose `preHandler` chain does not include this hook — so a
 * T-020 route cannot omit it even though T-020 owns that file.
 */
export function dealGate(gate: DealAccessGate, action: DealAction): FastifyPreHandlerHook;

/** Reads the minted handle. Throws `internal` if the gate did not run — unreachable via the audit. */
export function requireDealHandle(req: FastifyRequest): DealHandle;
```

### 2.6 The scoped store seam — the only door, and it has no unscoped side

```ts
/**
 * Reads, keyed by handle. `@comms`'s `CommsReadModel.getDeal(deal_id)` is
 * UNSCOPED by signature; this wrapper is the only permitted caller of it.
 *
 * Every read re-checks `deal.owner_id === handle.scope.account_id` and reports
 * `undefined` (⇒ 404) plus a `tenancy_reject` log line on mismatch. This is not
 * redundant: `InMemoryCommsStore` has no account column at all, so in the DEFAULT
 * PoC mode this check IS the tenancy enforcement (§5.1).
 *
 * There is deliberately NO `listQuarantined` and NO unscoped `listUnrouted`
 * here: `services/comms/src/ports.ts` states the unscoped call "must never be
 * reached from an account-scoped API (T-019/T-020 inherit this rule)", and
 * @store-pg §2.2 repeats it. The rule is kept by ABSENCE, not by a check.
 */
export interface ScopedReadModel {
  getDeal(handle: DealHandle): Promise<Deal | undefined>;
  getThread(handle: DealHandle, dealership_id: string): Promise<DealerThread | undefined>;
  /** The scoped half only — records attributed to THIS deal. */
  listUnrouted(handle: DealHandle): Promise<readonly UnroutedRecord[]>;
}

/**
 * A unit of work. In Postgres mode: one `PgCommsSession` over one transaction,
 * opened with `planForDeal(handle.deal_id)`. In memory mode: a pass-through over
 * the in-memory store whose `commit()` is a no-op. Handlers cannot tell which,
 * and that is the point (AC-8).
 */
export interface StoreSession {
  readonly handle: DealHandle;
  readonly store: CommsStore;              // @comms port, verbatim
  readonly raw_payloads: RawPayloadStore;  // @comms port, verbatim
  readonly receipts: ReceiptStore;         // @receipt port, verbatim, scope-bound
  commit(): Promise<ApiResult<void>>;
  rollback(): Promise<void>;
}

export interface StoreSessionFactory {
  /** No `forAccount()`, no `unscoped()`, no `raw()`. A handle or nothing. */
  forDeal(handle: DealHandle): Promise<ApiResult<StoreSession>>;
  /** open → run → commit, rollback on rejection. Never throws; failures are values. */
  withDeal<T>(handle: DealHandle, fn: (s: StoreSession) => Promise<T>): Promise<ApiResult<T>>;
}

export function createScopedReadModel(container: AppContainer): ScopedReadModel;
export function createStoreSessionFactory(container: AppContainer): StoreSessionFactory;
```

## 3. Data shapes

### 3.1 The error envelope on the wire

```jsonc
// 400
{ "error": { "code": "invalid_request", "message": "request body failed validation",
             "request_id": "01J…", "retryable": false,
             "details": [ { "path": "body.process_step",
                            "message": "expected one of: information_gather, deal_negotiation, deal_approval, financing, final_sale, pickup" } ] } }
// 404 — absent OR not owned. Byte-identical in both cases (D3).
{ "error": { "code": "not_found", "message": "deal not found", "request_id": "01J…", "retryable": false } }
// 503 — the webhook non-ack, and the only default-retryable code
{ "error": { "code": "unavailable", "message": "event could not be durably enqueued", "request_id": "01J…", "retryable": true } }
```

Constant across every response: `Content-Type: application/json; charset=utf-8`, header `x-request-id`. No stack, no SQL, no constraint name, no connection string, no rejected input value, no provider payload.

### 3.2 Response projections (the read side T-020 will serialize)

| View | Derived from | Deliberately absent | Why |
|---|---|---|---|
| `DealView` | `Deal` | — | `owner_id` is retained: it is the account's own id, never another's. |
| `DealerThreadView` | `DealerThread` | — | Carries `working_with` **only** inside an owner-scoped response (§5.1). |
| `MessageView` | `Message` | `recording_url`, `transcript`, any audio ref | `@core.Message` has no such field to project; the runtime guard is belt (§5.4). |
| `OfferView` | `Offer` | — | `flags[]` are copied from the domain, never recomputed (D10). `sale_price` absent stays absent (ADR-005, D9). |
| `DealershipPublicView` | `Dealership` | any contact field | Global read type. Contacts are structurally unrepresentable in it (§5.3). |
| `PrequalSummaryView` | `PrequalResult` | **`provider_token`** | specs/01 "Credit data residency": summary values only. The token is a capability into the provider's flow; summaries are `qualified_apr`, `approved_amount_max`, `fetched_at` (AC-9). |

### 3.3 Health and readiness

```jsonc
// GET /healthz — liveness. No dependency is touched; 200 whenever the process is up.
{ "status": "ok" }

// GET /readyz — 200 ready / 503 not ready. Names modes only; never a URL, host, bucket, or credential.
{ "status": "ready",
  "storage": { "relational": "postgres", "objects": "memory", "raw_payload_durability": "volatile" },
  "auth": { "resolver": "poc-header", "provider": "none" } }
```

`raw_payload_durability: "volatile"` and `provider: "none"` are stated out loud precisely because they are the two things an operator would otherwise assume were fine (D1, D7).

### 3.4 Request-scoped state

`AccountContext` and `DealHandle` are attached to the Fastify request via a declared module augmentation on `FastifyRequest` (`account_context?`, `deal_handle?`) and are read only through `requireAccountContext` / `requireDealHandle`. Both are optional on the type because the webhook plane genuinely has neither — a handler there that calls the reader gets a caught `internal`, not a silent `undefined`.

## 4. Error paths per operation

### 4.1 Startup

| Failure | Behaviour | Logged | Surfaces to caller |
|---|---|---|---|
| No `DATABASE_URL`, no `OBJECT_STORE_BUCKET` | **Normal.** In-memory both. Serves fully. | `info`: `storage=memory/memory` | — |
| `OBJECT_STORE_BUCKET` set, `OBJECT_STORE_REGION` absent | **Abort.** `readObjectStoreConfig` ⇒ `{ok:false}` ⇒ exit non-zero. **No degradation.** | `fatal`: code + which var is missing (never the value) | Process never listens |
| `DATABASE_URL` set but unreachable / wrong version | **Abort at preflight** (`handle.ping()`), before `listen`. | `fatal`: `db_preflight_failed`, SQLSTATE class only | Process never listens |
| `DATABASE_URL` malformed | Passed through by `readDbConfigFromEnv` on purpose; fails at handle creation ⇒ abort | `fatal` — never the string itself | Process never listens |
| Postgres configured, object store not | **Start**, `raw_payload_durability: 'volatile'` | `warn`: `raw_payload_store_volatile` | `/readyz` says so |
| Route audit finding (§2.10) | **Abort.** Registration-time throw. | `fatal`: finding kind + method + url template | Process never listens |
| Port in use | Abort | `fatal` | — |

The rule that carries the weight: **there is no code path from a Postgres failure to an in-memory store.** Not a guarded one — none. `createContainer` builds the in-memory pair only when `plan.relational === 'memory'`, and `plan` is computed before any I/O.

### 4.2 The per-request pipeline (order is the contract)

| # | Phase | Hook | On failure |
|---|---|---|---|
| 1 | Assign `request_id` | `genReqId` | — |
| 2 | Body limit + content type | Fastify core | `413` / `415` **through the envelope** (D4) |
| 3 | **Resolve account context** | `onRequest` | `401 unauthenticated` — **before** validation, so an unauthenticated caller learns nothing about the schema |
| 4 | **Validate** params → query → body | `preValidation` | `400 invalid_request` + `details[]` — **before any store call** (AC-5) |
| 5 | **Deal authorization gate** | `preHandler` | `404` (`not_owned`/`deal_not_found`) or `403` (E3 reasons) |
| 6 | Handler — the only place that opens a `StoreSession` | — | mapped per §4.3 |
| 7 | Projection + forbidden-field + no-`null` assertion | `preSerialization` | `500 internal` (a leak is a defect, never a response) |
| 8 | Error / not-found | `setErrorHandler`, `setNotFoundHandler` | the envelope, always |

Ordering 3 before 4 is deliberate and is a security property, not a preference. Ordering 4 before 5 is what makes "validation runs before any repository call" true even for the gate.

### 4.3 Per-operation posture

| Operation | Failure mode | Status / code | Retry & idempotency | Logged | Surfaced |
|---|---|---|---|---|---|
| Resolve context | header absent/blank | `401 unauthenticated` | client re-sends with context | `warn` `auth_unresolved` (no header value) | code + request_id |
| Validate | zod issues | `400 invalid_request` | not retryable | `info` count + paths | paths + expectation, **never the rejected value** |
| Validate | unknown key (`.strict()`) | `400 invalid_request` | not retryable | `info` | the key path |
| Gate | `not_owned` / `deal_not_found` | `404 not_found` (identical bodies) | not retryable | `warn` `tenancy_reject` w/ account_id + deal_id | generic "deal not found" |
| Gate | `grant_expired` / `role_not_permitted` (E3) | `403 forbidden` | not retryable | `warn` | code only |
| Open session (PG) | `DbError.retryable` | `503 unavailable` | **safe to retry** — nothing was written | `error` SQLSTATE class | code + `retryable:true` |
| Read deal | `owner_id` mismatch (in-memory mode) | `404 not_found` | not retryable | `warn` `tenancy_reject` | generic |
| Commit | `PgStoreError` `conflict` (23505) | `409 conflict` | retry only with a new natural key | `warn` constraint name (never values) | code |
| Commit | `unknown_reference` (23503) | `404 not_found` | not retryable | `warn` | generic |
| Commit | `tenancy_violation` / `scope_mismatch` | `404 not_found` + **`error` log** | not retryable | `error` — this is a **defect signal**, not a client error | generic |
| Commit | `unavailable` | `503 unavailable` | **retry safe**: `@store-pg` flushes as `ON CONFLICT DO NOTHING`, so a replay is a no-op | `error` | code + `retryable:true` |
| Commit | `unhydrated` / `store_bug` | `500 internal` | not retryable | `error` + the finding | bare code, nothing else |
| Note submit | `NoteSubmitOutcome` | status taken **verbatim** (`201`/`503`/`400`/`404`) | `client_note_ref` is the idempotency key: the keyed append no-ops and only the publish retries | `info` disposition | outcome-derived |
| Webhook | parse failure | `200` + `{ok:true}` | payload quarantined, replayable | `warn` `quarantined` + **ref prefix only** | `200` |
| Webhook | enqueue failure | `503 unavailable` | the provider's retry **is** the durability mechanism | `error` `enqueue_failed` | envelope, `retryable:true` |
| Object put | `AdapterError` `invalid_input` (content policy) | `415` or `422` | not retryable — a refusal is recorded, never a silent drop (T-018 D11) | `warn` kind + byte length | the refused content type |
| Object put | `AdapterError` `auth` | `503 unavailable` | operator alert; not client-fixable | `error` | code |
| Anything unexpected | thrown exception | `500 internal` | not retryable | `error` + stack **in-process only** | `{code:'internal', message:'internal error'}` and nothing more |

### 4.4 Idempotency posture, stated plainly

The API introduces **no new idempotency mechanism** (D8). What makes a retry safe is already in the spine: the adapter-derived envelope key for webhooks, `client_note_ref` for notes, `ON CONFLICT DO NOTHING` for every `@store-pg` flush, `attachExtractedOffer`'s fill-once, and the `processed_events` ledger. `503` responses are therefore retry-safe by construction, and this is asserted in tests rather than asserted in prose.

### 4.5 Logging — the allow list is the specification

**Logged:** `request_id`, method, **route template** (`/deals/:deal_id/…`, never the raw URL), status, `account_id`, `deal_id`, `dealership_id`, `message_ref`, error code, SQLSTATE class, constraint name, duration_ms, storage plan, resolver source, raw-payload **ref prefix** (first 12 hex — enough to correlate, not enough to address; T-018 §4.8).

**Never logged, at any level:** request or response bodies · message/note text · a rejected input value · `DATABASE_URL` or any part of it · object-store credentials or signatures · a raw webhook payload (`services/comms/src/ports.ts`: "The payload NEVER rides the bus or the logs") · `provider_token` · `qualified_apr` or any prequal amount · a `DealershipContact` name, phone, or email · any header value (Fastify `redact` covers `authorization`, `cookie`, `x-dc-account-id`).

Fastify's bundled logger is used via `app.log`; **no logging library is added** — that would be a dependency edit.

### 4.6 Shutdown order

`SIGTERM`/`SIGINT` → (1) `app.close()` — stop accepting, drain in-flight; (2) `S3RawPayloadStore.flush()` — drain the write-behind window (T-018 D5) and log `failedRefs()` at `error` if non-empty; (3) `DbHandle.close()`; (4) exit 0. Reversing (1) and (2) would flush a backlog that is still growing; skipping (2) discards payloads the process already told a provider it had accepted.

## 5. Invariant touchpoints, and how the design protects each

### 5.1 `Account` owns `Deals` — every store call is account-scoped (AC-2)

Three layers, each independently sufficient for a different failure:

1. **Type** — no store-touching signature accepts a bare `deal_id`; they take `DealHandle`, whose brand symbol is unexported (D2). Forgetting the scope does not compile.
2. **Query** — Postgres mode passes `AccountScope` into every `@store-pg` method, where it is a `WHERE` clause and a composite FK (T-017 §2.3).
3. **Response** — `ScopedReadModel` re-checks `deal.owner_id === scope.account_id` after every read. **This layer is not redundant:** `InMemoryCommsStore` has no account column, so in the ADR-008 default mode it is the *only* tenancy enforcement. A design that put tenancy solely in SQL would be tenancy-free in the mode the PoC actually runs.

Static test: no file outside `auth/` names `container.comms.read` or `session.store` directly.

### 5.2 One authorization choke point (AC-3, specs/01 concierge controls 1 & 3)

Every deal-addressed route passes `dealGate`. E3's entire diff is `createPermissiveDealGate` → a real gate: `AuthzDenyReason` already carries `grant_expired` and `role_not_permitted`, `DealAction` already carries `export` (control 2), and `AccountContext.role` already carries `concierge_agent` (control 1). No route, repository, or response type moves. The boot audit (§2.10) means a route that skips the gate cannot ship, including one T-020 writes.

### 5.3 Dealership data tenancy (AC-10)

`Dealership` is global; `DealershipContact` is account-private. Enforced on **both** paths, as the AC requires:
- **Query:** contacts are only ever read through a `DealHandle`-keyed thread read (`@comms` `bindThreadContact`/`resolveDealershipByContact` are already `deal_id`-first by construction, T-014 D9).
- **Response:** the global directory type is `DealershipPublicView = Pick<Dealership, 'id'|'name'|'state'|'city'|'zip_code'>`. A contact cannot be attached to it because the type has no place for one — the guarantee is structural, not a filter someone must remember to apply.

### 5.4 No audio, no transcript (AC-11)

`@core.Message` has no `recording_url` and no `transcript` — they were removed, not nulled (specs/01 consent posture). This service adds no field, and `FORBIDDEN_RESPONSE_KEYS` (`recording_url`, `transcript`, `audio_url`, `recording`, `media_url`) is asserted over every serialized body in `preSerialization`, mirroring `services/comms/test/fixtures/forbidden.ts`. `@object-store`'s `ArtifactKind` has no audio member, so no upload route can be written that stores one.

### 5.5 Credit data residency (AC-9, Q3)

`PrequalSummaryView` omits `provider_token` by `Pick`, so no response type can carry it. `@core` has no raw-credit type at all — there is nothing to serialize even by accident. `qualified_apr` and `approved_amount_max` are never logged (§4.5). No route accepts credit fields as input: no such schema exists in `validation/`.

### 5.6 One deal, one make/model (specs/00 "Cardinality invariants")

The foundation supplies the guard; T-020's write route calls it. `isTargetVehicleLocked(deal)` is **imported from `@core`**, never reimplemented (D10). A mutation of `target_vehicle.make`/`model` on a locked deal ⇒ `422 unprocessable` with a message naming the invariant, and the rejection is a receipt-trail event (specs/00: "The rejection is a receipt-trail event") — the foundation exposes the scope-bound `ReceiptStore` on `StoreSession` so that entry has somewhere to land without a second store lookup.

### 5.7 Budget ceiling vs. fair price stay two questions

No request or response type conflates them: `walk_away_number` is deal-level; every valuation-derived value is reached through a `VehicleInstance`. The API never derives `above_market` (ADR-007) or any other flag — `flags[]` are copied from the domain (D10). A thread with no `ValuationSnapshot` projects fair-price as **unevaluable**: the key is **absent**, never `0`, never `null` (ADR-005 + D9).

### 5.8 Append-only receipt trail

The route audit rejects `DELETE` on any path and `PUT`/`PATCH` on `/messages` or `/receipt` paths at registration time. `@receipt`'s `ReceiptStore` has no update or delete method to call, and `seq`/`appended_at` are database-assigned (T-017 §2.5), so ordering cannot be forged from here even with a bug.

### 5.9 Webhooks ack immediately (AC-7)

The webhook plugin's only call is `intake.ingest`, which is a sync-pure adapter parse plus a durable enqueue. The plane has no account context, no gate, and therefore no session — extraction, valuation, and notification are unreachable from it by construction, not by convention. Status is `WebhookIngestOutcome.http_status` verbatim; the API makes no ack decision of its own.

### 5.10 Infrastructure is a swap, not a rewrite (AC-8)

Handlers hold `CommsStore`, `RawPayloadStore`, `EventQueue`, `ObjectStore`, `ReceiptStore` — all ports declared elsewhere. `StoragePlan` is consulted exactly twice: once in `createContainer`, once in `/readyz`. No handler, hook, projection, or validator branches on the backing store.

## 6. Test plan

Run from the repo root: `npx vitest run services/api/test`. Typecheck: `npx tsc -p services/api --noEmit`.

- **Offline by default.** Every test in §1.2 except `storage-pg.db.test.ts` runs with no external service — that is the ADR-008 posture under test, not a convenience.
- **Fail-fast, provably.** The unreachable-`DATABASE_URL` case uses a closed loopback port: deterministic, offline, and it proves the *absence* of the fallback branch rather than the presence of a log line.
- **Skips are skips.** `storage-pg.db.test.ts` uses `describe.skipIf(!process.env['DATABASE_URL'])` and object-store cases additionally gate on `OBJECT_STORE_BUCKET`. Reported skipped, never passed (ADR-008).
- **Zero-store assertions.** Validation and webhook tests inject a `CommsStore` proxy that throws on **any** method call, so "before any repository call" is proven by the absence of a call rather than by ordering inspection.
- **Static tests** (no server): `as DealHandle` / `as unknown as DealHandle` appears nowhere in `src`; no module outside `context/` reads `req.headers`; no module outside `auth/` calls `listUnrouted()` unscoped or `listQuarantined`; the vocabulary arrays equal `@core`'s element-for-element.

## 8. Blockers / deviations

**None of the following is a stop.** No frozen-spine change, no unapproved integration, and no edit outside this task's ownership is required to build what is designed above.

### 8.1 `@core` has no `DEAL_PATHS` / `DEAL_STATUSES` (note)
Seven of the nine spec-fixed enums ship a frozen array explicitly "so validators import these rather than re-declaring the literals"; `DealPath` and `DealStatus` do not. `packages/core` is T-010 and complete, so this design declares them locally **with a compile-time exhaustiveness guard** against the `@core` union (D5) — drift becomes a build error, not a silent narrowing. **Recommendation to the lead:** a future task that owns `@core` adds the two arrays and this service deletes its locals.

### 8.2 Webhook and health endpoints live outside `src/routes/**` (note)
AC-7 makes webhook endpoints this task's deliverable while the task notes reserve `src/routes/**` for T-020. Resolved by plane, not by fiat: the webhook plane has no account context and no store access (D6, §2.9). Recorded so a reviewer reads the placement as deliberate.

### 8.3 Form-encoded webhook bodies are not accepted (note, real gap for a later epic)
JSON only, because `@fastify/formbody` is a dependency edit (T-015-only, ADR-009) and no form-encoded provider exists in this epic — the comms adapters are fixtures. **The epic that wires Twilio/SES must add that parser via T-015-equivalent ownership**; until then a real Twilio webhook would receive `415` through the envelope.

### 8.4 Postgres-without-object-store is allowed, and is a durability gap (note)
ADR-008 treats the two as independent presence switches and gives no authority to require the pair, so this design permits the combination, logs `warn`, and reports `raw_payload_durability: "volatile"` in `/readyz` (D7). **Recommendation to the lead:** decide whether durable relational rows referencing volatile raw-payload bytes should instead be a startup abort; that is an ADR-sized call, not a builder's.

### 8.5 What AC-12 proves without a database, stated honestly
With `DATABASE_URL` unset, `storage-pg.db.test.ts` **skips**, and skipped is reported as skipped (ADR-008). The offline suite still proves: the app starts and serves with zero external services; a partial object-store config aborts startup; an unreachable `DATABASE_URL` aborts startup rather than degrading. It does **not** prove the Postgres composition works — only running with a live database does, and this design does not let a green run claim otherwise.

### 8.6 `@store-pg` is designed but not yet built (note)
Every `@store-pg` signature used here (`AccountScope`, `PgSessionFactory.withSession`, `planForDeal`, `PgCommsSession`, `PgStoreError`) is taken **verbatim from `docs/design/T-017.md` §2**. If the built surface differs, the builder **stops and messages the lead** rather than adapting either side — a shim in `services/api` would be exactly the parallel definition ADR-001 forbids. In-memory mode has no such dependency, so the default posture builds and tests regardless.

### 8.7 The PoC account resolver is not security, and must not be mistaken for it (note — carried forward to E3)
`createPocHeaderResolver` trusts an unsigned request header. It exists so the scoping seam is exercised end to end before an auth provider is chosen (AC-4), it names itself `poc-header` in code, logs, and `/readyz`, and **this service must not be exposed to an untrusted network until E3 replaces it.** Default bind is `127.0.0.1` for that reason.

### 8.8 `@object-store`'s raw-payload write-behind window (inherited, T-018 D5)
`RawPayloadStore.stash` is synchronous, so an S3-backed implementation acknowledges before the durable PUT completes. The API's contribution is to make the window observable and bounded: `flush()` runs before the DB handle closes on shutdown, and a non-empty `failedRefs()` is logged at `error` (§4.6). The underlying port-shape fix is T-018's recommendation, not this task's to make.
