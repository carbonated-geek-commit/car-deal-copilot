# Design — T-012: Offer-extraction + receipt layer realigned to v0.5 (`packages/offer-extraction`, `packages/receipt`)

- **Task:** `tasks/T-012-extraction-receipt-v05-realignment.md`
- **Spec basis (authoritative, v0.5):** `specs/00-shared-core-architecture.md` — "Core domain model", "Cardinality invariants (structurally enforced)", "Budget ceiling vs. fair price — two different questions", "Dealership data tenancy", "Comms aggregation layer (provider-agnostic — shared)", "Receipt layer (trust engine)"; `specs/01-consumer-product-spec.md` — "Consent & recording posture *(resolved 2026-08-07)*", "Concierge tier (consumer-only)"
- **Decisions honored:** `decisions/OPEN-QUESTIONS.md` Q14 (transcription dropped), Q17 (concierge deliverable comparative, not forensic), Q22 (`Message` RATIFIED); ADR-001 (Node/TS, spine defined once, no parallel type definitions), ADR-005 (`sale_price` optional; missing input ⇒ **unevaluable**, never zero, never "not triggered"), ADR-008 (Epic-2 libraries; API defaults to in-memory), ADR-009 (dependency edits are T-015-only)
- **Predecessor designs:** `docs/design/T-007.md` (offer-extraction) and `docs/design/T-008.md` (receipt) remain the behavioral baseline. **This document supersedes them where they differ**, and only inside `packages/offer-extraction/**` and `packages/receipt/**`. `docs/design/T-010.md` §2.6 (ratified `Message`) and §5 are upstream and binding — this design consumes them, never restates them.
- **Stage:** design → build
- **Scope:** two pure packages. No I/O, no HTTP, no persistence, no provider SDK, no new dependency, no root-config edit, no `package.json` edit (ADR-009 confines dependency edits to T-015 and per-package `typecheck` scripts to T-016…T-019; T-012 is in neither set).

**Ownership boundary.** Writes are confined to `packages/offer-extraction/**`, `packages/receipt/**`, plus `tasks/T-012-*.md` and this file. `packages/core` is frozen and imported. `packages/flag-engine`, `packages/adapters/*`, and `services/comms` are red against the v0.5 spine by design — T-011/T-013/T-014 repair them. **A builder on this task must not touch them and must not report their breakage as a finding.**

**Starting state (measured, not assumed — 2026-08-07).** `npx tsc -p packages/offer-extraction --noEmit` and `npx tsc -p packages/receipt --noEmit` both pass **today**. Neither package is compile-broken; both are **semantically stale**, which is worse than red because it is silent:

- `extractOffer` narrows `channel` with a hand-written literal test that lists `call | email | sms` only, so the v0.5 `note` channel **falls through to the `sms` fallback**. Notes — the *primary* v0.5 extraction input — are today processed as a mislabelled SMS, and nothing fails.
- `packages/receipt` still exports `recording_ref` and `transcript` entry kinds, and no receipt entry carries an `author` at all.

The absence of a compiler error is the reason this task exists as a task rather than a fix loop.

## 0. Interpretive calls made by this design (drift trip-wire log)

Every call below sits inside spec ambiguity or is a mechanical consequence of a v0.5 spec line. None touches a protected path, none adds an integration, none amends the frozen spine. **A builder who finds any insufficient must stop and escalate — do not improvise an alternative.**

| # | Call | Basis |
|---|------|-------|
| **D1** | The extractor's per-channel text cleanup is re-keyed from `MessageChannel` to an internal `NormalizationProfile` (`plain` \| `email` \| `spoken`). `channel` maps to a profile through one exhaustive `Record<MessageChannel, NormalizationProfile>`; the rule core never sees a channel. | AC-1 ("channel-agnostic … never depends on how the text was produced"). Today the channel value is threaded into `normalizeText` and compared against literals, so "channel-agnostic" is a claim in a comment rather than a property of the code. A profile indirection makes it structural: there is no channel value inside the rules to depend on. The `Record<MessageChannel, …>` makes the map **exhaustive** — a future spine channel fails to compile here, which is the trip-wire that would otherwise be a silent fallback (exactly the `note` bug above). |
| **D2** | Profile assignment: `note → spoken`, `email → email`, `sms → plain`, `call → plain`. | `note`: AC-3 requires the ex-transcript corpus to keep its parsing coverage after re-basing as buyer notes, and that corpus is entirely colloquial spoken forms ("twenty nine thousand five hundred", "four fifty a month", "six point nine percent"). specs/01: "The buyer types what the dealer said, **in their own words**" — a note is speech retold in typing, so the spoken-form cleanup follows the text, not the transcript. `call`: under v0.5 a call message carries **no text** (`Message.body` "Absent for a bare call record", T-010 D16); defining a call-text cleanup profile would re-create the transcript path in spirit, so `call` gets the least-transformative profile. See §1.3 for why this does not make `note` a special case. |
| **D3** | An unrecognized runtime `channel` value falls back to the **`plain` profile**, not to `'sms'`. | The current `: 'sms'` fallback silently asserts a channel the caller did not send, and it is what demoted `note`. A profile fallback keeps totality (D4 of T-007, still binding) without ever fabricating a channel. The `sms` literal disappears from control flow entirely. |
| **D4** | Receipt entry kinds become the closed set `note` \| `sms` \| `email` \| `call_meta`. `recording_ref` and `transcript` are **deleted** — not deprecated, not aliased, not commented out. | specs/00 "Receipt layer": "Every **buyer note, SMS, email, and call-metadata record** is append-only, timestamped, exportable. (No recordings or transcripts exist …)". Q14. Task AC-5. T-010 already deleted the corresponding spine fields with no shim; a shim here would re-open what core closed. |
| **D5** | `author: MessageAuthor` is a **required** field on the receipt entry input base — no default, no derivation from `kind`, `direction`, or provider metadata. | specs/00 "Receipt layer": "Each entry carries its **author** … so self-authored evidence is never presented as if it came from the dealer"; core `domain.ts`: "Who produced this text — **NEVER inferred**". Q22, Q17. A default would be an inference wearing a different hat: the one failure mode this field exists to prevent is a self-authored entry acquiring a `dealer` label by omission. |
| **D6** | Author/direction coherence is enforced **at the type level first**, runtime second: `NoteEntryInput` fixes `direction: 'internal'` and `author: Exclude<MessageAuthor, 'dealer'>`; `sms`/`email`/`call_meta` fix `direction: Exclude<MessageDirection, 'internal'>`. | specs/00 `Message`: "`internal` = the buyer's/operator's own record"; core `domain.ts` line 36: "`note` = text the buyer/operator authored". A dealer-authored `internal` record and a dealer-authored note are both **contradictions of the spec's own gloss**, so making them unrepresentable is enforcement of a spec line, not new policy. `Exclude<…>` narrows the spine type by reference; it declares no parallel type (ADR-001). If the chief judges this over-tight, the fix is deleting two `Exclude` wrappers — the runtime checks stay either way. |
| **D7** | `CallMetaEntryInput.author` is `Exclude<MessageAuthor, 'dealer'>` and means *who logged the call on the account side*, not *who spoke*. `direction` carries who called whom. | A call-metadata record has no text, so "who produced this text" needs a stated reading rather than a silent one. specs/01 concierge control 4: "every agent action (view, send, **call**) lands in the deal's append-only receipt trail, visible to the customer" — the reader's question is *did the buyer or the operator take this call*, and `direction` already answers *inbound or outbound*. A dealer never writes into this trail, so `dealer` is unrepresentable here. |
| **D8** | `CallMetaEntryInput` carries the `@core` `CallMeta` type verbatim (`call_meta: CallMeta`) rather than flattening `started_at`/`duration_seconds`/`party` onto the entry. | ADR-001 single definition: `CallMeta` already exists in the spine (T-010 D9) with the exact three fields specs/00 names ("log call metadata (time, direction, party)"). Reusing it makes AC-7 **structural**: there is no field on `CallMeta` where an audio pointer or transcript string could sit, so "contains no audio pointer and no transcript text" is a property of the type rather than a rule someone must remember. |
| **D9** | `provider_message_ref?` moves off the shared base onto the three provider-originated variants; `NoteEntryInput` has no such field. | T-010 D10: "v0.5 runs extraction on **notes** … and a note has no provider id." Leaving the field on the base invites a fabricated correlation id on an in-app-authored entry — fabricated provenance in the one structure whose value is that it is not fabricated. |
| **D10** | Dedupe keeps **first-write-wins** semantics: a repeat `dedupe_key` returns the existing frozen entry with `deduplicated: true`, even if the new payload differs. No conflict error is raised. | T-008 R6, retained. Comparing payloads to detect a conflict would require either putting body text in an error message (breaking the log-safety contract, §4.5) or hashing content the store has no mandate to hash. First-write-wins is the only rule that keeps the trail append-only under at-least-once redelivery: the alternative — reporting a conflict — invites a caller to "fix" it with an overwrite that the interface deliberately does not offer. |
| **D11** | `DealDossier` gains **no new field**. Author reaches the export by riding on `ReceiptEntry`, and the design fixes a forward constraint on the still-stubbed renderer instead. | AC-9 asks that the export *structure* carry the author. It does, by construction (`DealDossier.entries: readonly ReceiptEntry[]`, and `author` is required on every entry). A summary/count field would be a presentation decision with no spec line — CLAUDE.md invariant 3. The forward constraint (§3.3) is where the "reader can distinguish" half is actually owed, and rendering belongs to a later epic (task Notes; T-018 owns durable dossier storage). |
| **D12** | The fixture corpus group `transcripts/` is **renamed** to `notes/`, file-by-file, preserving every `expected` block byte-for-byte; only `name`, `channel`, and the narrative framing of `text` change. | AC-3: "re-based as a **buyer-note** corpus … preserving the parsing coverage it provided"; task Notes: "Keep the assertions, change the provenance." A rewrite that also changed expectations would destroy the regression evidence the rebase exists to preserve. §1.5 fixes the exact per-file mapping so the builder cannot drift. |
| **D13** | The corpus loader validates `channel` against `MESSAGE_CHANNELS` imported from `@core` rather than a locally-declared `Set`. | The loader's current hand-written `new Set(['call','sms','email'])` is a parallel enum declaration (ADR-001 in a different syntax) and is the reason a `note` fixture would have been rejected by the test harness rather than caught by the extractor. T-010 D13 shipped the frozen vocabulary arrays precisely for this. |

## 1. `packages/offer-extraction` — exact TypeScript signatures

### 1.1 Public API — `src/index.ts`

Unchanged surface, one entry point, still pure/sync/total. Everything shared is imported from `@core`; nothing spine-shaped is declared here.

```ts
export type { ExtractedOffer, ExtractionInput, ExtractionResult } from './extract.js';
export { extractOffer } from './extract.js';
```

`NormalizationProfile` and `normalizeText` are **internal** — not exported from `index.ts`. The profile is an implementation detail of "channel-agnostic"; exporting it would let a caller pick a profile independently of the channel, which is precisely the provider/channel coupling AC-1 forbids.

### 1.2 Types — `src/extract.ts`

```ts
import type { MessageChannel, Offer } from '@core';

/**
 * ADR-005 collapsed the partial-offer projection onto the spine type: an Offer
 * with `sale_price` absent means the dealer stated no price. This IS the `@core`
 * Offer (ADR-001: no parallel type); the alias exists so the public API reads as
 * the design specifies.
 */
export type ExtractedOffer = Offer;

/**
 * Channel-agnostic extraction input (AC-1). ONE entry point for all four v0.5
 * channels. `text` is whatever the Message carries:
 *   note  → Message.body (buyer- or concierge-authored)
 *   sms   → Message.body (verbatim)
 *   email → Message.body (verbatim)
 *   call  → normally ABSENT — a call message carries call_meta, not text
 * `channel` selects a text-cleanup profile only (§1.3). It never routes to a
 * different extractor, never gates which fields are extractable, and never
 * carries provider knowledge.
 */
export interface ExtractionInput {
  channel: MessageChannel;
  text: string;
}

/**
 * Discriminated outcome. `found: false` is a valid terminal result — the text
 * contained no offer — never an error.
 */
export type ExtractionResult =
  | { readonly found: true; readonly offer: ExtractedOffer }
  | { readonly found: false };

export function extractOffer(input: ExtractionInput): ExtractionResult;
```

**Deleted from this file:** the doc-comment line `call → Message.transcript` (AC-2 — a transcript *parameter* is gone from core, and the last reference to one must go with it), and the `input?.channel === 'call' || … : 'sms'` literal chain (D3).

### 1.3 Normalization profiles — `src/normalize.ts` (internal)

```ts
import type { MessageChannel } from '@core';

/**
 * How the text was PRODUCED, as far as cleanup is concerned. Deliberately not a
 * channel: the rule core below normalization sees only a profile, so no rule can
 * branch on channel (AC-1, D1).
 */
export type NormalizationProfile = 'plain' | 'email' | 'spoken';

/**
 * Exhaustive by construction: adding a channel to the spine fails to compile
 * here rather than silently falling back (D1).
 */
export const PROFILE_BY_CHANNEL: Readonly<Record<MessageChannel, NormalizationProfile>>;

/** Total: any string in, a (possibly empty) string out. Never throws. */
export function normalizeText(raw: string, profile: NormalizationProfile): string;
```

Profile behavior (each is deterministic, locale-free, linear-time — T-007 §4.3, still binding):

| Profile | Channels | Transform |
|---|---|---|
| `plain` | `sms`, `call`, and the unrecognized-channel fallback (D3) | Shared cleanup only: CRLF → LF, `&nbsp;` → space, horizontal-whitespace collapse, blank-line collapse, trim. |
| `email` | `email` | Quoted-reply-chain and signature stripping, then shared cleanup. Prevents a stale offer quoted back by the buyer re-extracting as the dealer's new offer. |
| `spoken` | `note` | Colloquial-speech cleanup — filler-word removal, spelled-out number joining (`twenty nine thousand five hundred` → `2950000`¢ via `29500`), `29 grand`/`29 thousand` → `29000`, `six point nine` → `6.9`, `percent` → `%` — then shared cleanup. |

**Why `note` having its own profile does not contradict "treat `note` exactly like sms/email" (task EXTRA).** `note` is first-class in every way the EXTRA is about: one entry point, one rule core, one gate, one result type, one set of extractable fields, and no note-specific branch anywhere below normalization. What differs is only *text cleanup* — and that already differs between `sms` and `email` today (email strips quote chains, sms does not) without either being second-class. The profile handles the shape of the typed characters, not the standing of the channel. **A builder must not add a `note` branch in `extract.ts`, in any rule under `src/rules/**`, or in the gate.**

**Renamed for AC-2:** `normalizeTranscript` → `normalizeSpokenForm`; the section banner `// ---- call transcripts: …` → `// ---- spoken-form prose (typed notes): …`. After the build, `grep -rin "transcript\|recording" packages/offer-extraction` must return **zero** hits, including comments and fixture filenames.

### 1.4 Pipeline (unchanged shape, restated so the builder does not "improve" it)

`normalize → labeled fees (claim spans) → monthly (claim span) → APR → term → sale price (over unclaimed spans) → gate → build offer`.

- Rule order is load-bearing for span claiming; do not reorder.
- The gate is "at least one extracted field, else `{ found: false }`".
- Every result is a **fresh** object; absent fields stay **absent**, never `undefined`-valued, never `0` (ADR-005; the corpus asserts omission by deep equality).
- `flags` is **always `[]`** — see §4.4, this is an ADR-005 touchpoint, not a stylistic default.

### 1.5 Corpus rebase — `test/fixtures/transcripts/` → `test/fixtures/notes/` (AC-3, D12)

Directory renamed; group list in `corpus.test.ts` becomes `['notes', 'sms', 'email', 'hostile']`. For each file: `channel` becomes `"note"`, `name` loses the `transcript-` prefix, `text` is reframed as the buyer typing what the dealer said, and **`expected` is copied unchanged**.

| Old file | New file | Reframing rule | `expected` |
|---|---|---|---|
| `transcript-full-offer.json` | `notes/note-full-offer.json` | First person, buyer reporting: "He said they can do the car at twenty nine thousand five hundred, financing at six point nine percent APR for seventy two months, puts me right around four twenty five a month." | byte-identical |
| `transcript-grand-otd.json` | `notes/note-grand-otd.json` | "He said he can let it go for twenty nine grand out the door, today only." | byte-identical |
| `transcript-spoken-monthly.json` | `notes/note-spoken-monthly.json` | "He said he talked to his manager and thinks they can get me to four fifty a month on that trim." | byte-identical |
| `transcript-garbled.json` | `notes/note-vague-no-numbers.json` | A buyer's own hedging recollection with no figures in it — keep the filler words (buyers do type "he was like, uh, maybe"), drop the ASR-artifact framing. | byte-identical (`found: false`) |
| `transcript-no-offer-scheduling.json` | `notes/note-scheduling-no-offer.json` | "Sam called to confirm my test drive tomorrow afternoon, ask for him at the front desk." | byte-identical (`found: false`) |

**Binding:** the number *forms* in each `text` (spelled-out, `grand`, `point`, `percent`) must survive the reframing. They are the coverage. A rewrite that quietly turns `twenty nine grand` into `$29,000` deletes the regression the fixture exists for and passes anyway — the reviewer's check is that every new `notes/` file still contains at least one non-digit number form except `note-scheduling-no-offer`.

### 1.6 New test — channel-swap invariance (AC-1 made falsifiable)

A small set of **neutral** texts (digit-form amounts, no spelled numbers, no filler words, no quote markers) is extracted under all four channels and asserted `toStrictEqual` across them. This is the property "the extractor never depends on how the text was produced", stated as a test rather than a comment. Fixtures with spoken forms are deliberately excluded — profiles exist precisely because those texts are not channel-neutral, and asserting otherwise would encode a false invariant.

## 2. `packages/receipt` — exact TypeScript signatures

### 2.1 Entry inputs — `src/contract.ts`

```ts
import type {
  CallMeta,
  IsoTimestamp,
  MessageAuthor,
  MessageChannel,
  MessageDirection,
} from '@core';

/**
 * specs/00 "Receipt layer": buyer note, SMS, email, call-metadata record —
 * closed set. `recording_ref` and `transcript` are REMOVED (Q14; specs/01
 * "Consent & recording posture": no recordings or transcripts exist).
 */
export type ReceiptEntryKind = 'note' | 'sms' | 'email' | 'call_meta';

interface ReceiptEntryInputBase {
  kind: ReceiptEntryKind;
  /**
   * Who produced this entry. REQUIRED, never inferred, never defaulted (D5).
   * specs/00 "Receipt layer"; core Message.author (Q22).
   */
  author: MessageAuthor;
  direction: MessageDirection;
  /** When the underlying communication happened (maps to Message.timestamp). */
  occurred_at: IsoTimestamp;
  /** Idempotency anchor for at-least-once writers. Convention: event idempotency_key. */
  dedupe_key?: string;
}

/** Arrived through a provider — so it has a provider correlation id and a real direction (D9). */
interface ProviderOriginatedEntryInputBase extends ReceiptEntryInputBase {
  direction: Exclude<MessageDirection, 'internal'>;
  provider_message_ref?: string;
}

/**
 * The buyer's or operator's own written record (core: "`note` = text the
 * buyer/operator authored"; "`internal` = the buyer's/operator's own record").
 * A dealer-authored note is a contradiction of that gloss, so it is
 * unrepresentable rather than merely rejected (D6).
 */
export interface NoteEntryInput extends ReceiptEntryInputBase {
  kind: 'note';
  direction: 'internal';
  author: Exclude<MessageAuthor, 'dealer'>;
  body: string;
}

export interface SmsEntryInput extends ProviderOriginatedEntryInputBase {
  kind: 'sms';
  body: string;
}

export interface EmailEntryInput extends ProviderOriginatedEntryInputBase {
  kind: 'email';
  subject?: string;
  body: string;
}

/**
 * Call METADATA only — time, direction, party (specs/00 "Comms aggregation
 * layer"). `CallMeta` is the @core type (ADR-001), and it has no field where an
 * audio pointer or transcript string could sit: AC-7 is structural, not a rule
 * (D8). `author` = who logged the call on the account side (D7).
 */
export interface CallMetaEntryInput extends ProviderOriginatedEntryInputBase {
  kind: 'call_meta';
  author: Exclude<MessageAuthor, 'dealer'>;
  call_meta: CallMeta;
}

export type ReceiptEntryInput =
  | NoteEntryInput
  | SmsEntryInput
  | EmailEntryInput
  | CallMetaEntryInput;
```

**Deleted:** `RecordingRefEntryInput`, `TranscriptEntryInput`, and both members of the union and of the `index.ts` export list. `grep -rin "transcript\|recording" packages/receipt` must return **zero** hits after the build.

### 2.2 Stamp, stored entry, results — `src/contract.ts`

```ts
/** Store-assigned at append time; never caller-supplied. */
export interface ReceiptEntryStamp {
  /** Per-bundle monotonic sequence — append order, total and gap-tolerant. */
  seq: number;
  /** When the store accepted the entry (distinct from occurred_at). */
  appended_at: IsoTimestamp;
  /** Derived from kind — 1:1 under v0.5 (§2.3). */
  channel: MessageChannel;
}

/** Caller input + store stamp, DEEPLY READONLY. */
export type ReceiptEntry = Readonly<ReceiptEntryInput & ReceiptEntryStamp>;

export type ReceiptErrorCode =
  | 'invalid_input'      // caller bug — not retryable
  | 'store_unavailable'  // durable-backend outage — retryable; in-memory impl never emits it
  | 'not_implemented';   // dossier render/publish stubs — not retryable

export interface ReceiptError {
  code: ReceiptErrorCode;
  /** True only for store_unavailable. Stated explicitly so callers never guess. */
  retryable: boolean;
  /**
   * Log-safe by contract: never contains note/sms/email bodies, email subjects,
   * call_meta.party, phone numbers, or email addresses. Codes, kinds, author
   * labels, and field names only (§4.5).
   */
  message: string;
}

export type ReceiptResult<T> = { ok: true; value: T } | { ok: false; error: ReceiptError };

export interface AppendOutcome {
  entry: ReceiptEntry;
  /** True when dedupe_key matched an existing entry and nothing new was written (D10). */
  deduplicated: boolean;
}

/** Injectable clock for deterministic tests; defaults to system UTC now. */
export type ReceiptClock = () => IsoTimestamp;
```

`ReceiptErrorCode` is **unchanged** — no `invalid_author` or `authorship_conflict` code is added. Both are caller bugs of exactly the `invalid_input` species, and a new code would push per-code branching into every caller (T-014, T-020) for no behavioral difference.

### 2.3 Kind → channel derivation (1:1 under v0.5)

| `kind` | `channel` |
|---|---|
| `note` | `note` |
| `sms` | `sms` |
| `email` | `email` |
| `call_meta` | `call` |

Under v0.4 two kinds mapped onto `call` (`recording_ref`, `transcript`); with both deleted the map is a bijection, so a mismatched kind/channel pair is inexpressible. The table is a `Readonly<Record<ReceiptEntryKind, MessageChannel>>` — exhaustive, so a future kind cannot be added without deciding its channel.

### 2.4 Store contract — structurally append-only (AC-8)

```ts
/**
 * Append-only, timestamped store keyed by Deal.receipt_bundle_id (AC-10).
 * These TWO methods are the entire surface. No update, delete, overwrite,
 * truncate, upsert, or patch operation exists on this or any exported type —
 * and none may be added (specs/00 "Receipt layer": append-only).
 */
export interface ReceiptStore {
  append(
    receipt_bundle_id: string,
    input: ReceiptEntryInput,
  ): Promise<ReceiptResult<AppendOutcome>>;

  /** Chronological read-back: occurred_at ascending, ties broken by seq. */
  read(receipt_bundle_id: string): Promise<ReceiptResult<readonly ReceiptEntry[]>>;
}

export function createInMemoryReceiptStore(clock?: ReceiptClock): ReceiptStore;
```

Behavioral contract (binding; the durable T-017 implementation inherits every rule unchanged):

1. `append` validates (§4.1), derives `channel` from `kind`, assigns `seq` (per-bundle, from 1) and `appended_at` (from the clock), **defensively copies** the input, **deep-freezes**, stores.
2. Dedupe is per-bundle on `dedupe_key`; a hit returns the **existing frozen entry** with `deduplicated: true` — no new entry, no mutation, first write wins (D10).
3. `read` returns a fresh array each call (array is the caller's; entries are frozen singletons). Unknown bundle → `{ ok: true, value: [] }`.
4. The internal bundle log only ever **gains** entries. Nothing reassigns or removes one.

### 2.5 Dossier export — `src/dossier.ts` (shape unchanged; rendering still stubbed)

```ts
export interface DealDossier {

  receipt_bundle_id: string;
  generated_at: IsoTimestamp;
  entry_count: number;

  first_entry_at?: IsoTimestamp;
  last_entry_at?: IsoTimestamp;
  /**
   * Ordered, verbatim, frozen entries. Every element carries its required

}

export interface DossierArtifactRef {
  kind: 'pdf' | 'web_link';
  ref: string;
  generated_at: IsoTimestamp;
}

export interface DossierExporter {
  /** REAL. Assembles the bundle's entries into the exportable structure. */
  assemble(receipt_bundle_id: string): Promise<ReceiptResult<DealDossier>>;
  /** STUB: always not_implemented. Signature is final; T-018 owns durable storage. */
  renderPdf(dossier: DealDossier): Promise<ReceiptResult<DossierArtifactRef>>;
  /** STUB: always not_implemented. Signature is final. */
  publishWebLink(dossier: DealDossier): Promise<ReceiptResult<DossierArtifactRef>>;

export function createDossierExporter(
  store: ReceiptStore,
  clock?: ReceiptClock,

```

**Forward constraint, binding on whoever implements rendering (D11).** The rendered dossier MUST print each entry's author label beside its content, and MUST NOT render a concierge- or buyer-authored entry in a way a reader could take for a dealer statement. specs/01 accepts a known risk here (losing threads are operator-authored and not independently checkable) explicitly *because* the author label is in force as a mitigation; a renderer that drops the label voids the mitigation the risk acceptance depends on. This is stated here, in the epic that owns the type, so the epic that owns the renderer inherits it rather than re-deciding it.

## 3. Data shapes — how the pieces sit together

### 3.1 v0.5 message flow through both packages

```
inbound SMS / email  ──webhook──▶ [ack] ──event bus──▶ consumer
                                                          ├─▶ Message{channel, direction:in, author:'dealer', body}
                                                          ├─▶ extractOffer({channel, text: body}) ─▶ Message.extracted_offer
                                                          │                                          └─▶ DealerThread.current_offer (ADR-006)
                                                          └─▶ ReceiptStore.append(bundle, {kind:'sms'|'email', author:'dealer', direction:'in', …})

inbound call         ──webhook──▶ [ack] ──event bus──▶ consumer
                                                          ├─▶ Message{channel:'call', call_meta, body ABSENT}
                                                          ├─▶ ReceiptStore.append(bundle, {kind:'call_meta', author:'buyer'|'concierge', direction:'in', call_meta})
                                                          └─▶ notify owner ──▶ owner writes a NOTE ──▶ (note path below)
                                                              ^ no audio, no ASR, no transcript anywhere on this line

buyer/operator note  ──in-app──▶ Message{channel:'note', direction:'internal', author:'buyer'|'concierge', body}
                                    ├─▶ extractOffer({channel:'note', text: body})   ← same entry point, same rules
                                    └─▶ ReceiptStore.append(bundle, {kind:'note', author, direction:'internal', body})

any bundle           ──▶ DossierExporter.assemble(receipt_bundle_id) ─▶ DealDossier{entries[] each carrying author}
```

The two packages never call each other and share no module. Their only common vocabulary is `@core`.

### 3.2 Where each field comes from

| Receipt entry field | Source | Never |
|---|---|---|
| `kind` | caller (the flow that produced the entry) | inferred from body content |
| `author` | the authenticated actor on the write path (T-020) — buyer session, concierge operator session, or "the counterparty of an inbound provider message" | defaulted, derived from `direction`, or derived from `channel` (D5) |
| `direction` | provider metadata for sms/email/call; fixed `'internal'` for notes | guessed |
| `occurred_at` | provider timestamp; for `call_meta` the caller sets it to `call_meta.started_at` | synthesized by the store |
| `provider_message_ref` | provider payload | present on a note (D9 — structurally absent) |
| `dedupe_key` | the event envelope's `idempotency_key` | random per attempt (that would defeat idempotency) |
| `seq`, `appended_at`, `channel` | **store-assigned** | caller-supplied |

### 3.3 Extraction data shape

`ExtractionInput{channel, text}` → `ExtractionResult`. On `found: true` the offer is a `@core` `Offer` with `fees` and `flags` always present (`flags` always empty), and `sale_price` / `apr` / `term_months` / `monthly` present **only when confidently extracted**. Money is integer cents (`MoneyCents`); APR is a plain number (`6.9`), term a plain integer month count.

## 4. Error paths per operation

Both packages perform no I/O and own **no** webhook handler or HTTP surface. Neither writes to a logger: the extractor handles PII-laden message text and a library that cannot log cannot leak (T-007 §5.3, retained); the receipt store returns log-safe errors and leaves logging to its caller.

### 4.1 `extractOffer(input)` — total, never throws

| Failure mode | Result | Retry / idempotency | Logged | Surfaces as |
|---|---|---|---|---|
| `text` is not a string (hostile/JS caller) | Treated as `''` → `{ found: false }` | Pure ⇒ re-running is byte-identical; safe under at-least-once redelivery | nothing (by design) | "no offer in this message" |
| `channel` missing / not a `MessageChannel` | `plain` profile, extraction proceeds (D3) | same | nothing | Normal result; no channel is fabricated |
| `channel: 'call'` with empty body (the v0.5 norm) | `{ found: false }` | same | nothing | Call logged, no offer — the state the owner-notify exists to resolve |
| Text contains no offer terms | `{ found: false }` — a **valid terminal outcome**, not an error | same | nothing | `OfferExtractionCompletedV1.offer` absent |
| Garbage / binary / digit-soup text | `{ found: false }` via the precision gate | same | nothing | Same as above; the `hostile/` corpus is the standing proof |
| Very large text | Linear-time, bounded rules; no truncation, no cap introduced | same | nothing | Normal result |

**There is no error channel and no thrown exception.** The caller is an at-least-once bus consumer; a throwing extractor turns one weird dealer message into a poison message that blocks a queue. Determinism **is** the idempotency posture: re-extraction after redelivery cannot produce a different offer, so no dedupe key is needed on this path.

**No cap on input length is introduced.** Truncating would silently drop offer terms from a long email and report `found: false` — a false negative in the one place the product's promise lives. Bounding message size is the comms boundary's job (T-014).

### 4.2 `ReceiptStore.append`

| Failure mode | Result | Retry / idempotency | Logged (by caller) | Surfaces as |
|---|---|---|---|---|
| Blank `receipt_bundle_id` | `invalid_input`, not retryable | none — caller bug | code, kind | Programming-error state; never user-facing |
| Unknown / missing `kind` | `invalid_input` | none | code | Same |
| **Missing or unknown `author`** (AC-6) | `invalid_input`, not retryable, message `author must be one of dealer\|buyer\|concierge (kind: <kind>)` | none | code, kind | Same — **nothing is written**; an authorless entry can never enter the trail |
| **Authorship-coherence violation** — `direction: 'internal'` with `author: 'dealer'`, or `kind: 'note'` with `author: 'dealer'` / `direction ≠ 'internal'`, or `kind: 'call_meta'` with `author: 'dealer'` (D6, D7) | `invalid_input`, not retryable | none | code, kind, **author label** (an enum, log-safe) | Same. Unreachable from TypeScript callers (the types forbid it); the check exists for JS/JSON boundaries |
| Missing / non-object `call_meta`, or `call_meta.started_at` not ISO-8601 | `invalid_input` | none | code, kind | Same |
| Blank `body` for `note`/`sms`/`email` | `invalid_input` | none | code, kind | Same |
| Malformed `occurred_at` | `invalid_input` | none | code, kind | Same |
| Duplicate `dedupe_key` in bundle | **`ok: true`**, `deduplicated: true`, existing entry returned, nothing written (D10) | **This is the idempotency mechanism** — safe under at-least-once redelivery and consumer retry | bundle id, seq, `deduplicated=true` | Nothing — duplicates absorbed silently and correctly |
| Duplicate `dedupe_key`, **different payload** | Same as above: original entry returned unchanged | First write wins; the second payload is never persisted and never overwrites | bundle id, seq, `deduplicated=true` | Nothing. Reporting a conflict would require comparing bodies (PII in errors) and would invite an overwrite the interface does not offer (D10) |
| Durable backend down (T-017 impl only) | `store_unavailable`, **retryable** | Caller retries with backoff **reusing the same `dedupe_key`** — a retry after a partial write is absorbed by dedupe, so append is exactly-once-effective | code, bundle id, attempt count | Event-consumer redelivery; dead-letter + operator alert on exhaustion |

### 4.3 `ReceiptStore.read`

| Failure mode | Result | Retry / idempotency | Logged | Surfaces as |
|---|---|---|---|---|
| Blank `receipt_bundle_id` | `invalid_input` | none | code | Programming-error state |
| Unknown / never-appended bundle | `ok: true, value: []` | Naturally idempotent (pure read) | bundle id, count=0 | Empty trail — a valid state for a fresh deal |
| Durable backend down (future) | `store_unavailable`, retryable | Backoff; reads are idempotent | code, bundle id | Stale/unavailable trail view, **never fabricated data** |

### 4.4 `DossierExporter.assemble` / `renderPdf` / `publishWebLink`

| Operation | Failure mode | Result | Retry | Logged | Surfaces as |
|---|---|---|---|---|---|
| `assemble` | underlying `read` fails | Propagates the store's `ReceiptError` **unchanged** | per the propagated `retryable` | bundle id, outcome | "Dossier unavailable" — never a partial dossier |
| `assemble` | empty bundle | `ok: true`, empty dossier, no `first/last_entry_at` | — | bundle id, count=0 | Empty-but-valid dossier |
| `renderPdf` | always (this epic) | `not_implemented`, not retryable | none — terminal by design | operation name | Feature-not-available; callers must branch on `ok`, so the stub cannot be mistaken for success |
| `publishWebLink` | always (this epic) | `not_implemented`, not retryable | none | operation name | Same |

A stub that fabricated a URL or an S3 key would leak into product code as if hosting existed. It fails loudly instead.

### 4.5 What is never logged (contract)

`ReceiptError.message` is log-safe **by contract**: note/sms/email bodies, email subjects, `call_meta.party` (a phone number or a person's name), phone numbers, and email addresses never appear in it. Only error codes, entry kinds, field names, and the `author` enum label may. The receipt trail *stores* PII — its errors and its callers' logs must not re-emit it.

### 4.6 Webhook boundary — ack-then-queue (binding on callers, restated)

Neither package exposes an HTTP surface. specs/00 ("webhooks ack immediately, all heavy work runs on the event bus; provider timeouts must never drop a dealer message") reaches these packages as constraints on their callers (T-014, T-020):

1. **No `append` call may run inside a webhook handler before the 2xx ack.** Parse, durably enqueue, ack; a consumer appends afterwards.
2. **Writers set `dedupe_key` from the event envelope's `idempotency_key`.** Provider redelivery cannot then double-write the trail.
3. A failed append inside a consumer is a **consumer** failure: retryable → redeliver with backoff; exhausted → dead-letter with the envelope intact + operator alert. Never silently dropped — dead-lettered comms events are the trail's feedstock, and losing one falsifies the trail.
4. Outbound sends append their entry only **after** the adapter accepts the send, with `dedupe_key` from `client_ref`: the trail records what was sent, not what was attempted.
5. **`author` is taken from the authenticated session on the write path, never from the request body.** A client-supplied author label is a forgery vector against exactly the guarantee AC-6 exists to provide.

## 5. Invariant touchpoints — what could break, and what stops it

| Invariant (source) | How this task could break it | How this design protects it |
|---|---|---|
| **Receipt trail is append-only, timestamped, exportable** (specs/00 "Receipt layer"; AC-8) | An update/delete/clear method; a mutable read-back; dedupe drifting into upsert | **Structural:** `ReceiptStore` has exactly two members (§2.4); entries are defensively copied and deep-frozen; dedupe returns the existing entry untouched, first-write-wins (D10); every entry carries `occurred_at` + `appended_at` + `seq`. Type-level test asserts `Exclude<keyof ReceiptStore, 'append' \| 'read'>` is `never` (§6) |
| **No recordings or transcripts exist** (specs/01 "Consent & recording posture"; Q14; AC-2, AC-5, AC-7) | A `transcript` kind kept "for the shared layer"; a `recording_ref` left as a deprecated alias; a call-text normalization profile; a `body` on the call-metadata entry | Both kinds and both input types **deleted**, not deprecated (D4). `CallMetaEntryInput` carries `@core` `CallMeta`, which has **no field** an audio pointer or transcript could occupy (D8), and no `body`. `call → plain` profile, `normalizeTranscript` renamed (D2). Standing gate: `grep -rin "transcript\|recording"` over both packages returns zero |
| **Author is never inferred** (specs/00 "Receipt layer"; core `domain.ts`; Q22; AC-6) | A default author; deriving author from `direction` or `channel`; an optional `author?` | Required field, no default anywhere (D5); runtime rejection with `invalid_input` when missing or unknown (§4.2); type-level narrowing makes dealer-authored self-authored entries unrepresentable (D6, D7); §4.6 rule 5 forbids taking the label from a request body |
| **Self-authored evidence is never presented as the dealer's** (specs/00; specs/01 "Concierge tier"; Q17; AC-9) | Author dropped between store and export; a renderer that omits the label | `DealDossier.entries` are `ReceiptEntry`, on which `author` is required — carry-through is structural (D11). | **Extractor is channel-agnostic** (specs/00 "Comms aggregation layer"; AC-1) | A `note` branch in the rules; per-channel entry points; a channel value reaching the rule core; a silent fallback demoting an unknown channel | One entry point; the profile indirection removes the channel from everything below normalization (D1); the profile map is exhaustive over `MessageChannel`, so a new channel is a compile error not a fallback (D1, D3); channel-swap invariance test (§1.6) |

Standing gate: no `interface (Deal\|DealerThread\|Message\|Offer)\b` outside `packages/core` |

| **Dealership data tenancy — the people are private** (specs/00) | A receipt entry carrying a `DealershipContact` or a global contact id | Entries carry no dealership fields at all; they are bundle-scoped, and the bundle is the account-owned `Deal`'s. `call_meta.party` is free text belonging to that deal's trail and is on the never-logged list (§4.5) |
| **Budget ceiling ≠ fair price; one deal, one make/model** (specs/00 "Cardinality invariants", "Budget ceiling vs. fair price") | The extractor inferring a vehicle, a valuation, or a walk-away comparison from message text | The extractor's output is an `Offer` and nothing else — it has no vehicle input, no valuation input, and no deal context, so neither comparison is expressible here. ## 6. Test plan (both packages own their own tests)

Run from root: `npx vitest run packages/offer-extraction packages/receipt`. Typecheck: `npx tsc -p packages/offer-extraction --noEmit`, `npx tsc -p packages/receipt --noEmit`. Deterministic throughout via the injected `ReceiptClock`; no network, no timers, no filesystem beyond the checked-in fixtures.

**`packages/offer-extraction/test`**

1. **Corpus (data-driven, unchanged runner):** groups `notes | sms | email | hostile`, full-result deep equality, absent-means-absent, determinism (re-run byte-identical), fresh-object-per-call, `flags` always `[]`.
2. **Rebased notes group:** all five ex-transcript cases pass with their original `expected` blocks (AC-3). A drop in this group's pass count is a regression in parsing coverage, not a fixture-naming detail.
3. **Channel-swap invariance:** neutral digit-form texts give identical results across all four channels (§1.6, AC-1).
4. **`note` is not the fallback:** a fixture whose spoken-form parse succeeds under `note` and, under `sms`, does **not** — the standing proof that `note` reaches its own profile rather than the old `sms` fallback. (This is the test that would have caught today's bug.)
5. **Unknown-channel totality:** a bogus channel value at runtime yields a result, never a throw, and applies the `plain` profile (D3).
6. **Transcript-free surface:** a source-text scan asserts no `transcript`/`recording` token exists under `packages/offer-extraction/**` (AC-2).

**`packages/receipt/test`**

7. **Append + stamp** for all four kinds: derived `channel` per §2.3, `seq` from 1 and per-bundle independent, `appended_at` from the injected clock.
8. **Author is mandatory (AC-6):** append with `author` missing / `''` / `'operator'` / `'system'` → `invalid_input`, not retryable, **and `read` confirms nothing was written**. Type-level assertion that `author` is non-optional on every member of `ReceiptEntryInput`.
9. **Authorship coherence (D6, D7):** `direction:'internal'` + `author:'dealer'`, `kind:'note'` + `author:'dealer'`, `kind:'call_meta'` + `author:'dealer'` all rejected at runtime; `expectTypeOf` asserts each is also a compile error.
10. **Call-metadata purity (AC-7):** a `call_meta` entry round-trips `started_at`/`duration_seconds`/`party`; type-level assertion that `CallMetaEntryInput` has no `body`, no `transcript`, no `recording_ref`, and no other string payload field.
11. **Kinds removed (AC-5):** the exported surface has no `recording_ref`/`transcript` kind, no `RecordingRefEntryInput`/`TranscriptEntryInput`; a source-text scan over `packages/receipt/**` finds neither token.
12. **Structural append-only (AC-8):** type-level `Exclude<keyof ReceiptStore, 'append' | 'read'>` is `never`; runtime assertion that the store object exposes no other own function property; a scan of the public API surface for `update`/`delete`/`remove`/`clear`/`truncate`/`patch`/`upsert`-named members finds none.
13. **Immutability:** mutating the input after append does not change the stored entry; stored entries are frozen including nested `call_meta`; mutating a `read` result array does not affect a later `read`.
14. **Idempotent dedupe (D10):** same key twice → `deduplicated: true`, same `seq`, one entry; same key with a **different body** → the **original** entry is returned and `read` still shows the original content.
15. **Validation + bundle isolation:** blank bundle id, blank body, malformed `occurred_at`, malformed `call_meta.started_at` → `invalid_input` with nothing written; entries never land in or read from the wrong bundle.
16. **Dossier (AC-9):** `assemble` returns ordered entries with correct `entry_count` and `first/last_entry_at`; **every exported entry carries its author**, and a bundle mixing `dealer`, `buyer`, and `concierge` entries exports all three labels distinctly; empty bundle → valid empty dossier; `renderPdf`/`publishWebLink` → `not_implemented`, `retryable: false`.
17. **Error-message hygiene (§4.5):** no `ReceiptError.message` produced anywhere in the suite contains any body, subject, `party`, phone, or email fixture string.

## 8. Deviations and blockers

**Blocked: no.** This design needs no change to the frozen spine (every shared type is imported or narrowed by reference, never amended), no unapproved integration (no ASR, no PDF engine, no storage SDK, no hosting), no dependency change (ADR-009 keeps those in T-015), and no edit outside the task's ownership globs.

Deviations resolved by the designer and logged rather than escalated:

1. **D6/D7 — type-level authorship narrowing.** Making `kind:'note' + author:'dealer'` and `direction:'internal' + author:'dealer'` unrepresentable is stricter than the ACs literally require. It is enforcement of the spec's own gloss on `internal` and `note`, and it runs the concierge honesty guarantee in the second direction (nothing self-authored acquires a dealer label). Reversal, if the chief prefers looser typing, is deleting two `Exclude<…>` wrappers; the runtime checks and every AC survive that change.
2. **D2 — `call → plain` profile.** The spoken-form cleanup follows the *note* channel, not the *call* channel, because under v0.5 a call message carries no text at all. This is the anti-drift reading of "remove every transcript reference"; the alternative (mapping `call` to the spoken profile) would preserve a call-text path with nothing to put in it.
3. **D9 — `provider_message_ref` removed from note entries.** Slightly narrower than T-008's shared base, and it follows T-010 D10 ("a note has no provider id"). No caller is known to set one on a note.
4. **D11 — no new dossier field.** AC-9 is met structurally; the missing half (a reader *seeing* the label) is a rendering concern, recorded as a binding forward constraint in §2.5 rather than solved with a field this epic cannot render.
5. **Forward note for T-016/T-017 (not this task's files):** the receipt schema must not carry `recording_ref` or `transcript` columns/kinds, must make `author` `NOT NULL` with a CHECK against the three-value set, and must enforce append-only at the grant level (no UPDATE/DELETE for the application role). Stated here so the persistence tasks inherit it; **no migration file is written by T-012.**
