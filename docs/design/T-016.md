## 0. Interpretive calls made by this design (drift trip-wire log)

Each stays inside spec/ADR ambiguity or is a mechanical consequence of Postgres. None touches a protected path. A builder that finds any insufficient **stops and messages the lead** — it does not improvise, and above all it does not add a dependency, edit a foreign file, or reach for an ORM.

| # | Call | Basis / consequence |
|---|------|---------------------|
| **D1** | **`VehicleTarget` is columns on `deals`, not a table.** `target_make`, `target_model`, `target_year_from`, `target_year_to` live on the deal row. There is no `vehicle_targets` table and no `deals.target_vehicle_id`. | specs/00 models `VehicleTarget` as an embedded value object with no `id`, and `@core`'s `VehicleTarget` has none. Consequence: **"exactly one vehicle target per deal" is not a constraint that can be violated — it is arity.** A second target is unrepresentable rather than rejected, which is strictly stronger than `UNIQUE (deal_id)` on a child table (that still allows delete-and-replace and a nullable 0-row state). AC-8's "exactly one" costs zero enforcement code. |
| **D2** | **Tenancy is enforced by foreign-key composition, NOT by row-level security.** Every account-owned table carries `account_id NOT NULL`, every parent has a `UNIQUE (account_id, id)`, and every child FK is the composite pair. | AC-4 names "foreign-key composition, row-level security, or equivalent" and the task Notes say choosing RLS is a **chief-level ADR** because it reshapes every T-017 call (`SET LOCAL app.account_id` on every checkout, plus a `BYPASSRLS` story for migrations and tests). FK composition needs no ADR, no session variable, no change to any port signature, and is visible in `\d` output. §5.5 states exactly what it does and does not guarantee — this design does not overclaim. RLS remains available later **with no schema change**, because `account_id` is already on every row; that is E3's call, not this task's. |
| **D3** | **`Deal.owner_id` IS `deals.account_id`.** One column, projected onto `owner_id` on read. There is no separate `owner_id` column. | specs/01 "Account model": "`Account` owns `Deals`". A second, independently-writable owner column would let `owner_id ≠ account_id` exist, which is precisely the cross-account hole AC-5 exists to close. B2B's Org/Seat split (specs/00 "owner = … Org/Seat in B2B") would add a `seat_id` **beside** the account scope in a later epic; it would not re-key tenancy. |
| **D4** | **Append-only is enforced in three independent layers**, not one: (a) the app role is granted `SELECT, INSERT` only on `receipt_entries`; (b) `BEFORE UPDATE / DELETE / TRUNCATE` triggers raise `DC001`; (c) no FK anywhere uses `ON DELETE CASCADE`, so no parent delete can reach the trail. | AC-6 asks for grant **and** trigger ("a trigger or equivalent rejects any attempt, so immutability does not depend on application discipline"). The layers cover different attackers: grants stop the application, triggers stop a privileged session (the table owner, a migration, a psql operator), and the absence of cascades stops the accident nobody tests for — deleting a deal and silently taking its evidence with it. |
| **D5** | **Nothing in this schema is ever deleted. All FKs are `ON DELETE RESTRICT`.** | specs/01 number lifecycle: on burn "the thread is **archived (never deleted)**". `Deal.status` already carries `closed`/`burned` and `Deal.burned_at` records the moment. A `DELETE` path is therefore not a missing feature — it is a contradiction of the receipt promise, and `RESTRICT` makes the contradiction fail loudly instead of cascading. |
| **D6** | **Three project-specific SQLSTATEs are defined: `DC001` (receipt append-only), `DC002` (target vehicle write-once), `DC003` (reserved: cross-account reference caught by a trigger rather than an FK).** | PL/pgSQL's default `P0001` is indistinguishable from any other `RAISE`, so a caller could not tell "you tried to edit the receipt trail" from "a check failed". Class `DC` collides with no standard SQLSTATE class and with none of PL/pgSQL's `P00xx`. `@db` owns the SQLSTATE → `DbErrorCode` map (§2.3) so T-017 never string-matches on a message. |
| **D7** | **`receipt_entries.seq` and `appended_at` are assigned by a `BEFORE INSERT` trigger from a per-bundle counter row, never by the caller.** `channel` is a `GENERATED ALWAYS … STORED` column derived from `kind`. | `@receipt`'s `ReceiptEntryStamp` says "Store-assigned at append time; **never caller-supplied**" and calls `channel` "derived from kind — a bijection under v0.5". Putting both in the schema means the durable store cannot forge ordering or mislabel a channel even if T-017 has a bug, and the counter row's lock serializes concurrent appends without an advisory lock or a `max(seq)+1` race. |
| **D8** | **A blank/whitespace `dedupe_key` is normalized to `NULL` by trigger and the uniqueness index is partial (`WHERE dedupe_key IS NOT NULL`). It is never rejected.** | `@receipt` `contract.ts` is explicit and BINDING on the durable implementation: a degenerate key "means *no anchor was supplied* … it appends normally", because "the safe failure direction for a trail whose value is completeness is a possible duplicate … never a loss". A `CHECK` that rejected `''` would turn an append into an error and drop a receipt entry — the one outcome the trail may not have. |
| **D9** | **PostgreSQL 14+ is the floor and no extension is installed.** The runner preflights `server_version_num >= 140000`. | `gen_random_uuid()` is core since PG13, so `pgcrypto`/`uuid-ossp` are unnecessary — and an extension is a new moving part on an approved integration, which is exactly the kind of quiet addition CLAUDE.md invariant 2 exists to catch. 14 (not 13) gives headroom and is universally available; the floor is asserted rather than assumed so the failure is one clear message instead of a confusing DDL error. |
| **D10** | **`@db` exports the schema's *vocabulary* (table names, pg enum type names and their label tuples, stable constraint names) but no row interfaces.** | T-015 §2.2 rule 5: "Row shapes stay inside `@store-pg`." The task Notes allow "any generated schema types" in `packages/db/src/**`; the reconciliation is that `@db` publishes **identifiers**, not shapes. This buys the one test that makes AC-2 mechanical: every pg enum's labels are compared against the corresponding frozen array in `@core` (`OFFER_FLAGS`, `MESSAGE_CHANNELS`, …), so a spine enum change breaks the DB suite instead of silently diverging. |
| **D11** | **No `migrate` npm script is added.** Migrations run programmatically via `runMigrations()`. | ADR-009 grants exactly one script key (`typecheck`) to this task's manifest. A second key is a manifest edit outside the grant. `runMigrations()` is what the DB tests call and what T-019's composition root will call at startup; if a CLI entry point is genuinely wanted, that is a lead escalation, not a unilateral edit (§8, item 2). |
| **D12** | **Identity resolution is globally unique among *active* bindings, deliberately crossing the account boundary.** `deal_identities` has partial unique indexes on the normalized phone / email / identity id `WHERE released_at IS NULL`. | Inbound routing happens **before** any account is known — a webhook arrives addressed to a number, and the store must answer "whose deal is this?" (`resolveDealByIdentity` takes no account argument, by necessity). Global active-uniqueness is also the schema-side expression of Q9: a live number belongs to at most one deal platform-wide, so "a dealer reaches a stranger" is unrepresentable. `released_at` is what lets Burn/Keep/**Re-use** (Q2) rebind the same number to a later deal without ever double-binding it. The lifecycle itself is not implemented here — only the column and the index that make it possible without a schema change. |
| **D13** | **`object_refs` carries `CHECK (content_type IS NULL OR content_type NOT LIKE 'audio/%')`.** | specs/00 Store: "No audio is stored"; specs/01 consent posture. `object_refs` is the only place in the system where stored bytes are addressable, so it is the only place the rule can be made structural rather than remembered. Video is deliberately **not** blocked: no spec line addresses it and inventing one would be drift (§8, item 3). |

Rules binding on every `.sql` file, checked by a static test that needs no database (§6.2):

1. Filename matches `^\d{4}_[a-z0-9_]+\.sql$`; versions are unique and contiguous from `0001`.
2. **No transaction control inside a file** (`BEGIN`, `COMMIT`, `ROLLBACK`, `SAVEPOINT`). The runner wraps each file in one transaction (§2.4). Consequence: no `CREATE INDEX CONCURRENTLY` — at PoC scale it buys nothing and cannot run in a transaction.
3. **No `DROP TABLE`, no `DROP COLUMN`, no `TRUNCATE`, no `DELETE FROM`.** Forward-only means a mistake is corrected by a new migration, never by rewriting an applied one.
4. **No `ON DELETE CASCADE` / `ON DELETE SET NULL` anywhere** (D5).
5. **No `bytea` column anywhere** (AC-13: bytes live in the object store).
6. Every migration that creates a table ends with that table's `GRANT` statements. Forgetting is caught by the privilege-matrix test (§6.1 T13), not by review alone.

### 2.2 The query seam

No `pg` type crosses this boundary — not `Pool`, not `PoolClient`, not `QueryResult`.

```ts
export interface QueryOutcome<R> {
  readonly rows: readonly R[];
  /** Rows affected for INSERT/UPDATE/DELETE; rows returned for SELECT. */
  readonly row_count: number;
}

export interface Queryable {
  /**
   * Parameterized only. `sql` is static text; every value travels in `params`.
   * Never throws — failure is a value (house style, `@core` AdapterResult).
   */
  query<R extends Record<string, unknown> = Record<string, unknown>>(
    sql: string,
    params?: readonly unknown[],
  ): Promise<DbResult<QueryOutcome<R>>>;
}

export interface DbHandle extends Queryable {
  /**
   * One connection, one transaction. COMMIT iff the callback resolves ok:true;
   * ROLLBACK on ok:false AND on a thrown exception (which is caught and mapped,
   * so `transaction` itself never throws either).
   */
  transaction<T>(fn: (tx: Queryable) => Promise<DbResult<T>>): Promise<DbResult<T>>;
  /** Liveness + server-version preflight. */
  ping(): Promise<DbResult<{ server_version_num: number }>>;
  /** Idempotent; safe to call on an already-closed handle. */
  close(): Promise<void>;
}

/** Creates a pool. Lazy — no socket is opened until the first query or ping. */
export function createDbHandle(config: DbConfig, logger?: DbLogger): DbHandle;
```

The load-bearing property: **`Queryable` is what T-017 receives.** A repository takes a `Queryable`, so the same code runs on the pool and inside a transaction, and `@store-pg` never reads `DATABASE_URL` (T-015 §2.2 rule 4).

### 2.3 Errors — one vocabulary, one mapping

```ts
export type DbErrorCode =
  | 'not_configured'         // DATABASE_URL absent — a state, not a fault (ADR-008)
  | 'connection_failed'      // could not reach / authenticate
  | 'server_too_old'         // server_version_num < MIN_SERVER_VERSION_NUM
  | 'permission_denied'      // 42501 — includes UPDATE/DELETE on receipt_entries
  | 'unique_violation'       // 23505
  | 'foreign_key_violation'  // 23503 — includes the cross-account composite FK
  | 'not_null_violation'     // 23502
  | 'check_violation'        // 23514, 22P02, 22003
  | 'append_only_violation'  // DC001 — the receipt trail was written against
  | 'write_once_violation'   // DC002 — target make/model changed after lock
  | 'tenancy_violation'      // DC003 — reserved trigger-side cross-account catch
  | 'serialization_failure'  // 40001 / 40P01 — retryable
  | 'statement_timeout'      // 57014
  | 'migration_conflict'     // checksum drift, gap, duplicate version
  | 'unavailable'            // 57P01, 53300, 08xxx after connect
  | 'unknown';

export interface DbError {
  code: DbErrorCode;
  /** Stated explicitly so a caller never has to guess (§4.7). */
  retryable: boolean;
  /**
   * Log-safe BY CONTRACT: codes, SQLSTATEs, table names, constraint names,
   * column names, migration versions. NEVER a bound parameter, a row value, a
   * message body, an email address, a phone number, a VIN, or the connection
   * string.
   */
  message: string;
  sqlstate?: string;
  table?: string;
  constraint?: string;
}

export type DbResult<T> = { ok: true; value: T } | { ok: false; error: DbError };

/** Pure, total, exported so T-017 tests can assert the mapping directly. */
export function classifySqlstate(sqlstate: string): { code: DbErrorCode; retryable: boolean };
```

Note for the builder: the toolchain sets `exactOptionalPropertyTypes`. Build `DbError` by conditionally spreading (`...(constraint !== undefined && { constraint })`), never by assigning `constraint: undefined`.

### 3.2 The tenancy split, in DDL (AC-3, AC-4)

`dealerships` is global. It has **no** account, owner, or tenant column, and none may be added:

```sql
CREATE TABLE dealerships (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name       text NOT NULL,
  state      text NOT NULL,
  city       text NOT NULL,
  zip_code   text NOT NULL,          -- text: leading zeros are real ZIPs
  created_at timestamptz NOT NULL DEFAULT now()
);

-- Batch-load key (specs/01 backlog 5, Q13): makes a later bulk import an
-- idempotent `INSERT … ON CONFLICT DO NOTHING` rather than a dedupe project.
CREATE UNIQUE INDEX dealerships_natural_uidx
  ON dealerships (lower(name), upper(state), lower(city), zip_code);
```

`dealership_contacts` is account-private, and the `UNIQUE (account_id, id)` is what makes the composite FK below possible:

```sql
CREATE TABLE dealership_contacts (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  account_id    uuid NOT NULL REFERENCES accounts (id),
  dealership_id uuid NOT NULL REFERENCES dealerships (id),
  name          text NOT NULL,
  role          dealership_contact_role NOT NULL,
  phone         text,
  email         text,
  created_at    timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT dealership_contacts_account_id_uk UNIQUE (account_id, id)
);
```

The enforcement is on the referencing side. A thread carries its own `account_id` (itself pinned to its deal's account by the same trick), and the contact reference is the **pair**:

```sql
CONSTRAINT dealer_threads_contact_fk
  FOREIGN KEY (account_id, working_with_contact_id)
  REFERENCES dealership_contacts (account_id, id)
```

Two properties make this work, and both are deliberate:

- **MATCH SIMPLE (the default) is exactly right here.** `working_with_contact_id` is nullable — a thread has no contact until the buyer is handed to a person (`@core`: "Optional — absent until handed to a person"). Under MATCH SIMPLE a composite FK with any NULL column is satisfied, so "no contact yet" is legal and "a contact from another account" is a `23503`.
- **The account on the referencing row is not free.** `dealer_threads.account_id` is itself half of `FOREIGN KEY (account_id, deal_id) REFERENCES deals (account_id, id)`, so it cannot be set to a stranger's account in order to reach a stranger's contact — the row would then dangle off a deal that account does not own.

The same pattern chains all the way down: `messages` → `dealer_threads` → `deals` → `accounts`, each hop carrying `account_id` in the FK. **A cross-account row cannot be joined into existence because it cannot be inserted** (AC-5).

### 3.3 Deals — one target, by arity (AC-8, D1)

```sql
CREATE TABLE deals (
  id                uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  account_id        uuid NOT NULL REFERENCES accounts (id),   -- IS Deal.owner_id (D3)
  path              deal_path   NOT NULL,
  status            deal_status NOT NULL DEFAULT 'draft',

  -- VehicleTarget, embedded. There is no vehicle_targets table (D1).
  target_make       text NOT NULL,
  target_model      text NOT NULL,
  target_year_from  int,
  target_year_to    int,

  budget_cents      bigint NOT NULL,
  walk_away_cents   bigint NOT NULL,   -- Q20: the BUDGET CEILING, not a price verdict
  receipt_bundle_id uuid REFERENCES receipt_bundles (id),
  created_at        timestamptz NOT NULL DEFAULT now(),
  burned_at         timestamptz,

  CONSTRAINT deals_account_id_uk UNIQUE (account_id, id),
  -- YearRange has BOTH fields required in @core: both or neither.
  CONSTRAINT deals_year_range_paired
    CHECK ((target_year_from IS NULL) = (target_year_to IS NULL)),
  CONSTRAINT deals_year_range_ordered
    CHECK (target_year_from IS NULL OR target_year_from <= target_year_to),
  CONSTRAINT deals_burned_at_only_when_burned
    CHECK (burned_at IS NULL OR status = 'burned'),
  CONSTRAINT deals_money_nonneg
    CHECK (budget_cents >= 0 AND walk_away_cents >= 0)
);
```

`deals_year_range_ordered` constrains the **range's own well-formedness** and nothing else. There is deliberately **no** constraint anywhere relating `vehicle_instances.year` to these columns — the year span is a soft guide (AC-10, Q16), and §6.1 T9 proves an out-of-range instance inserts cleanly.

Write-once (AC-8) mirrors `@core`'s `isTargetVehicleLocked` condition for condition — one predicate, two enforcement sites:

```sql
CREATE FUNCTION deals_target_vehicle_write_once() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  IF NEW.target_make  IS DISTINCT FROM OLD.target_make
  OR NEW.target_model IS DISTINCT FROM OLD.target_model THEN
    IF OLD.status <> 'draft'
    OR EXISTS (SELECT 1 FROM offers o WHERE o.deal_id = OLD.id)
    OR EXISTS (SELECT 1 FROM dealer_threads t
                WHERE t.deal_id = OLD.id AND t.current_offer_id IS NOT NULL) THEN
      RAISE EXCEPTION
        'deal % target make/model is write-once once the deal has left draft or any offer is attached', OLD.id
        USING ERRCODE = 'DC002', TABLE = 'deals', COLUMN = 'target_make';
    END IF;
  END IF;
  RETURN NEW;
END;
$$;

CREATE TRIGGER deals_target_vehicle_write_once
  BEFORE UPDATE ON deals FOR EACH ROW
  EXECUTE FUNCTION deals_target_vehicle_write_once();
```

The three disjuncts are `isTargetVehicleLocked`'s three disjuncts, in the same order. §6.1 T8 runs a shared case table through **both** the TypeScript predicate and the trigger and asserts they agree — the drift this protects against is the API saying "locked" while the schema says "fine", which would let the one-vehicle anchor rot from the inside.

### 3.6 The receipt trail — append-only in three layers (AC-6, AC-7, D4, D7, D8)

```sql
CREATE TABLE receipt_bundles (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  account_id uuid NOT NULL REFERENCES accounts (id),
  next_seq   bigint NOT NULL DEFAULT 1,
  created_at timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT receipt_bundles_account_id_uk UNIQUE (account_id, id)
);

CREATE TABLE receipt_entries (
  id                   uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  account_id           uuid NOT NULL,
  receipt_bundle_id    uuid NOT NULL,
  seq                  bigint NOT NULL,          -- trigger-assigned (D7)
  kind                 receipt_entry_kind NOT NULL,
  author               message_author     NOT NULL,   -- AC-7: never inferred, never defaulted
  direction            message_direction  NOT NULL,
  channel              message_channel GENERATED ALWAYS AS (
                         CASE kind WHEN 'note' THEN 'note'::message_channel
                                   WHEN 'sms'  THEN 'sms'::message_channel
                                   WHEN 'email' THEN 'email'::message_channel
                                   ELSE 'call'::message_channel END) STORED,
  occurred_at          timestamptz NOT NULL,
  appended_at          timestamptz NOT NULL,     -- trigger-assigned (D7)
  body                 text,
  subject              text,
  call_started_at      timestamptz,
  call_duration_seconds int,
  call_party           text,
  provider_message_ref text,
  dedupe_key           text,

  CONSTRAINT receipt_entries_bundle_fk
    FOREIGN KEY (account_id, receipt_bundle_id) REFERENCES receipt_bundles (account_id, id),
  CONSTRAINT receipt_entries_bundle_seq_uk UNIQUE (receipt_bundle_id, seq),
  CONSTRAINT receipt_entries_note_shape
    CHECK (kind <> 'note' OR (direction = 'internal' AND author <> 'dealer'
                              AND provider_message_ref IS NULL AND body IS NOT NULL)),
  CONSTRAINT receipt_entries_call_shape
    CHECK (kind = 'call_meta' OR (call_started_at IS NULL AND call_duration_seconds IS NULL
                                  AND call_party IS NULL)),
  CONSTRAINT receipt_entries_call_author
    CHECK (kind <> 'call_meta' OR author <> 'dealer')
);

-- D8: only a NON-BLANK key anchors. A blank one is normalized to NULL on insert
-- and is never rejected — a rejected append is a lost receipt entry.
CREATE UNIQUE INDEX receipt_entries_bundle_dedupe_uidx
  ON receipt_entries (receipt_bundle_id, dedupe_key) WHERE dedupe_key IS NOT NULL;
```

Insert-side trigger (D7/D8) — assigns `seq` from the bundle counter (the `UPDATE` takes the row lock, so concurrent appends serialize with no gap and no race), stamps `appended_at`, and normalizes the dedupe key:

```sql
CREATE FUNCTION receipt_entries_stamp() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  UPDATE receipt_bundles SET next_seq = next_seq + 1
   WHERE id = NEW.receipt_bundle_id
  RETURNING next_seq - 1 INTO NEW.seq;
  IF NOT FOUND THEN
    RAISE EXCEPTION 'unknown receipt bundle' USING ERRCODE = '23503', TABLE = 'receipt_entries';
  END IF;
  NEW.appended_at := now();
  IF btrim(coalesce(NEW.dedupe_key, '')) = '' THEN NEW.dedupe_key := NULL; END IF;
  RETURN NEW;
END;
$$;
CREATE TRIGGER receipt_entries_stamp BEFORE INSERT ON receipt_entries
  FOR EACH ROW EXECUTE FUNCTION receipt_entries_stamp();
```

Layer (a) — **privilege.** The application literally does not hold the verbs:

```sql
GRANT SELECT, INSERT ON receipt_entries TO deal_copilot_app;
REVOKE UPDATE, DELETE, TRUNCATE ON receipt_entries FROM deal_copilot_app, PUBLIC;
```

Layer (b) — **trigger**, which also binds the table owner, a migration, and a psql operator (grants do not):

```sql
CREATE FUNCTION receipt_entries_append_only() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  RAISE EXCEPTION 'receipt_entries is append-only: % is not permitted', TG_OP
    USING ERRCODE = 'DC001', TABLE = 'receipt_entries';
END;
$$;
CREATE TRIGGER receipt_entries_no_update BEFORE UPDATE ON receipt_entries
  FOR EACH ROW EXECUTE FUNCTION receipt_entries_append_only();
CREATE TRIGGER receipt_entries_no_delete BEFORE DELETE ON receipt_entries
  FOR EACH ROW EXECUTE FUNCTION receipt_entries_append_only();
CREATE TRIGGER receipt_entries_no_truncate BEFORE TRUNCATE ON receipt_entries
  FOR EACH STATEMENT EXECUTE FUNCTION receipt_entries_append_only();
```

Layer (c) — **no cascade.** `receipt_bundles.id` is referenced by `deals.receipt_bundle_id` with `RESTRICT`, and nothing cascades to `receipt_entries`. A cascading delete fires the child's `BEFORE DELETE` trigger, so layer (b) would catch it anyway; `RESTRICT` makes the failure a clean `23503` at the parent instead of a confusing `DC001` from three tables away.

There is **no** `recording_url`, `transcript`, `audio_ref`, `duration_bytes`, or `bytea` column here or anywhere (AC-12, Q14) — the fields were removed from the spine rather than left null, and this schema does not resurrect them.

## 4. Error paths per operation

House rule for every entry point: **failure is a value, never an exception.** `DbError.message` is log-safe by contract (§2.3) — codes, SQLSTATEs, identifiers, migration versions. No parameter value, no row content, no connection string ever appears in it.

### 4.1 `readDbConfigFromEnv`

| Failure | Retry / idempotency | Logged | Surfaces as |
|---|---|---|---|
| `DATABASE_URL` absent | Pure function; idempotent | nothing | `undefined` — **not an error.** ADR-008's default PoC path. The caller composes the in-memory store. A fabricated `postgres://localhost/…` default would turn "not configured" into "misconfigured" and is forbidden. |
| `DATABASE_URL` present but unparseable | Not retryable | nothing (the value would leak a password) | `undefined` is **not** returned; the caller gets a `DbError{ code:'connection_failed' }` at handle creation. Silent fallback to in-memory here would be the exact degradation T-015 §4.4 forbids. |

### 4.2 `createDbHandle` / first connection

| Failure | Retry / idempotency | Logged | Surfaces as |
|---|---|---|---|
| Host unreachable, auth failure, TLS refusal (`08001`, `08006`, `28P01`) | `retryable: true` at the *statement* level, but the composition root **fails fast and exits non-zero** at startup — never falls back to in-memory (T-015 §4.4). A configured-but-unreachable DB that degrades silently would 2xx a dealer webhook and lose the message. | `pool_opened` / `query_failed` with SQLSTATE only | `DbResult` `{ code:'connection_failed', retryable:true }` |
| `server_version_num < 140000` | Not retryable | `error` once | `{ code:'server_too_old' }` naming the required and actual version numbers (D9) |
| Pool exhausted / `53300 too_many_connections` | Retryable after backoff — **caller's** backoff; `@db` implements none (§4.7) | `query_failed` | `{ code:'unavailable', retryable:true }` |

`createDbHandle` itself never throws and opens no socket; the first `ping()`/`query()` is where connection errors surface. `close()` is idempotent.

### 4.3 `query`

| Failure | SQLSTATE → code | Retryable | Surfaces to T-017 as |
|---|---|---|---|
| Duplicate `(deal_id, message_ref)` | `23505` → `unique_violation`, `constraint: 'messages_deal_message_ref_uk'` | no | `appendMessage` ⇒ `'duplicate'`. Expected traffic under at-least-once redelivery, not an incident — T-017 uses `ON CONFLICT DO NOTHING` and reads `row_count === 0`. |
| Duplicate receipt `dedupe_key` | `23505`, `constraint: 'receipt_entries_bundle_dedupe_uidx'` | no | `AppendOutcome.deduplicated = true`, first-write-wins (`@receipt` D10). |
| Duplicate `(consumer, idempotency_key)` | `23505`, `constraint: 'processed_events_pkey'` | no | `markProcessed` ⇒ `'duplicate'`. |
| **Cross-account contact reference** | `23503`, `constraint: 'dealer_threads_contact_fk'` | no | `{ code:'foreign_key_violation' }`. This is a **tenancy breach attempt** — T-017/T-020 must surface it as a not-found/forbidden, never echo the foreign id, and it is worth an `error` log line (identifiers only). |
| UPDATE/DELETE on `receipt_entries` | `DC001` → `append_only_violation` (or `42501 → permission_denied` when the app role hits the grant wall first) | no | A **caller bug by construction** — `ReceiptStore` exposes no such operation. Log `error`, fail the request; never retry, never "fix up" by inserting a compensating row. |
| Target make/model changed after lock | `DC002` → `write_once_violation` | no | T-020 renders the spec's UX: reject the entry, highlight the vehicle in red against its VIN, offer a new deal — **and record the rejection as a receipt event** (specs/00; Q11). The receipt write is a separate INSERT and must not be inside the aborted transaction. |
| `NOT NULL` on `receipt_entries.author` | `23502` → `not_null_violation` | no | Caller bug. `author` is never defaulted or inferred (AC-7) — a default would be an inference wearing a different hat. |
| Serialization failure / deadlock | `40001` / `40P01` → `serialization_failure` | **yes** | Retry the whole transaction. Safe because every write that must not double-apply is protected by a unique key, not by luck. |
| `statement_timeout` | `57014` → `statement_timeout` | **no** | Deliberate: re-running a query that already blew its budget reproduces the cost. Surfaces as a 5xx / operator alert. |
| Admin shutdown, crash-recovery | `57P01` → `unavailable` | yes | Retry with backoff at the caller. |
| Anything unmapped | → `unknown`, `retryable:false` | | Never guessed as retryable. Guessing "retryable" on an unknown failure is how a non-idempotent write gets applied twice. |

### 4.4 `transaction`

- Callback returns `ok:true` ⇒ `COMMIT`; `ok:false` ⇒ `ROLLBACK`, and the callback's own error is returned unchanged.
- Callback **throws** ⇒ `ROLLBACK`, mapped to `{ code:'unknown', retryable:false }`, logged as `transaction_rolled_back`. `transaction` still does not throw.
- `COMMIT` itself fails ⇒ the error is returned; the client is destroyed rather than returned to the pool, because its transaction state is unknown.
- The client is **always** released — `finally`, no exceptions. A leaked client is a pool that dies slowly under load, and it presents as a mysterious timeout ten minutes later.
- Idempotency of a *retried* transaction is not the transaction's property; it is the schema's, via the unique keys in §3.4/§3.6/§3.8. This is the whole reason ADR-008 chose visible SQL over an ORM.

### 4.5 `runMigrations`

Sequence: acquire `pg_advisory_lock(8160160160160160)` → `CREATE TABLE IF NOT EXISTS schema_migrations` → read the ledger → for each pending file in version order, in **its own transaction**: run the SQL, insert the ledger row, `COMMIT` → release the lock.

| Failure | Retry / idempotency | Logged | Surfaces as |
|---|---|---|---|
| Another runner holds the advisory lock | Blocks, then proceeds; with `dir` unchanged the second runner finds everything applied and reports `applied: []` | `info` | success with an empty `applied` list. Concurrent test files and a concurrently-starting API cannot half-apply a migration. |
| Checksum of an already-applied file differs | **Not retryable, not auto-repaired** | `migration_failed` with the version | `{ code:'migration_conflict' }` naming the version. Someone edited an applied migration; the fix is a **new** migration, never a rewritten one. Auto-repair here would let a schema silently diverge from its history — the same class of dishonesty as a silently-green DB test. |
| Version gap or duplicate version on disk | Not retryable | `migration_failed` | `{ code:'migration_conflict' }` |
| A file's DDL fails | Not retryable | `migration_failed` with version + SQLSTATE | mapped `DbError`. That file's transaction rolls back **whole**, its ledger row is not written, and no later file runs. The database is left at the last fully-applied version — never half a migration. |
| Migrating role lacks `CREATEROLE` (migration `0001`) | Not retryable | `migration_failed` | `{ code:'permission_denied' }` with an actionable message naming `APP_ROLE`. **Not skipped, not warned-past**: AC-6 requires the app role to lack UPDATE/DELETE, and a schema that quietly skipped its grants would claim an immutability it does not have. |
| Server too old | Not retryable | `error` | `{ code:'server_too_old' }` (preflight, before the lock) |
| Process dies mid-run | Advisory locks are session-scoped and released on disconnect; re-running resumes at the first unapplied version | — | Safe by construction — the ledger insert shares the file's transaction, so a version is either fully applied and recorded, or neither. |

Re-run on an up-to-date database: no DDL executes, `applied` is empty, `already_applied` lists every version. That is AC-15's "re-runnable without effect", and it is a *property of the ledger*, not of `IF NOT EXISTS` sprinkled through the files.

### 4.6 `loadMigrations`

Directory missing, unreadable, empty, or a filename that violates §1.1 rule 1 ⇒ `{ code:'migration_conflict' }` naming the offending filename. Not retryable; nothing is logged beyond the error. Path resolution is `new URL('../migrations/', import.meta.url)`, which is correct under both vitest and Node's native type-stripping because there is no emit step (T-001 D5).

### 4.7 Retry posture, stated once

`@db` **implements no retries and no backoff.** It classifies; the caller decides. A generic retry loop inside the driver layer would re-execute a non-idempotent `INSERT` and duplicate a dealer message — the one failure specs/00 names outright. Idempotency is a property of the *schema* (unique keys) and of the *caller* (`ON CONFLICT`), never of a hidden retry.

### 4.8 What is logged

Emitted only when a `DbLogger` is supplied: `pool_opened`/`pool_closed`, `migration_applied`/`migration_skipped`/`migration_failed`, `query_failed`, `transaction_rolled_back`. Each carries level, event, a static message, and optionally migration version, duration, SQLSTATE, table, constraint.

**Never logged, at any level:** bound parameters, row values, message bodies, email subjects, `call_party`, phone numbers, email addresses, VINs, prices, the connection string, or a raw provider payload. This is not politeness — the receipt trail is evidence, and a log that mirrors it is an uncontrolled second copy of the very PII the tenancy split exists to contain.

## 5. Invariant touchpoints

| # | Invariant | Source | How this design protects it |
|---|---|---|---|
| 5.1 | **One deal, one make/model — always** | specs/00 "Cardinality invariants"; Q11 AMENDED | D1: the target is *columns on the deal*. Two targets are not rejected, they are **unrepresentable**. `vehicle_instances` carries no make/model, so a thread cannot contradict the anchor either. |
| 5.2 | **`target_vehicle.make`/`model` are write-once** | specs/00 "Enforcement"; Q11 | §3.3 trigger, whose three disjuncts are `isTargetVehicleLocked`'s three disjuncts. §6.1 T8 runs one case table through both and asserts agreement, so the API and the schema cannot drift into disagreeing about "locked". Violation surfaces as `DC002`, and T-020 records the rejection as a receipt event. |
| 5.3 | **Each thread carries its own `VehicleInstance`** | specs/00 "Cardinality invariants" | `vehicle_instances.thread_id` is `UNIQUE` and the instance row *is* owned by the thread. No instance is shared, no instance hangs off a deal. |
| 5.4 | **Fair price is per-instance; budget ceiling is per-deal** | specs/00 "Budget ceiling vs. fair price"; Q20; ADR-007 | `valuation_snapshots` and `vehicle_data` key on `vehicle_instance_id` with **no `deal_id` column and no deal-level valuation table** — a make/model-level price is unrepresentable, which is the schema-side form of "make + model alone is not priceable". `deals.walk_away_cents` is documented as the budget ceiling and is compared to nothing in SQL. A thread with no snapshot has *no row*, which is how "unevaluable" survives the round trip (never a 0). |
| 5.5 | **Dealerships global, contacts account-private** | specs/00 "Dealership data tenancy"; Q12 AMENDED | `dealerships` has no account column and a natural-key index for batch load. `dealership_contacts` has `account_id NOT NULL` + `UNIQUE (account_id, id)`, and every reference to it is a composite FK carrying the referrer's account (§3.2). **What this guarantees:** no row belonging to account A can *point at*, join to, or cascade into a contact of account B — a cross-account object graph cannot be inserted. **What it does not guarantee:** a caller that issues an unscoped `SELECT * FROM dealership_contacts` still sees rows. That last mile is T-017's mandatory account-scope argument plus E3's authorization; stating the boundary is deliberate, because a schema claim that overreaches is worse than one that is precise. RLS remains available later with no schema change (D2). |
| 5.6 | **Every account-owned table carries an account scope** | specs/00 tenancy; specs/01 "Account model" | §3.9 enumerates both lists, `ACCOUNT_SCOPED_TABLES` is exported, and §6.1 T14 asserts against `information_schema` that every listed table has a NOT NULL `account_id` in a composite FK — so a *future* table added without a scope fails the suite instead of passing review. D3 removes the `owner_id ≠ account_id` hole entirely. |
| 5.7 | **Receipt entries are append-only** | specs/00 "Receipt layer" | Three independent layers (D4, §3.6): grant, trigger, no-cascade. Grants stop the app; triggers stop a privileged session; the absence of `ON DELETE CASCADE` stops the accident. Tested from both roles (§6.1 T5). |
| 5.8 | **Each entry carries its author** | specs/00 "Receipt layer"; Q21 mitigation | `receipt_entries.author message_author NOT NULL` with **no default**. `kind='note' ⇒ author <> 'dealer'` and `kind='call_meta' ⇒ author <> 'dealer'` make fabricated dealer provenance unrepresentable — the concierge honesty guarantee rests on this column, so it is the last one that may acquire a default. |
| 5.9 | **No audio, no recording, no transcript** | specs/01 consent posture; Q14; specs/00 Store | No such column exists anywhere; §6.1 T3 scans `information_schema.columns` for `%recording%`/`%transcript%`/`%audio%` and asserts zero, and §6.2 scans the `.sql` files for `bytea`. `object_refs` additionally rejects `audio/%` content types (D13) — the only place bytes are addressable is the only place the rule can bite. |
| 5.10 | **Bytes live in the object store** | specs/00 Store | `object_refs` + three join tables; no `bytea` column anywhere; the quarantine table holds a `raw_payload_ref`, never the payload. |
| 5.11 | **`sale_price` optional; missing input ⇒ UNEVALUABLE, never zero** | ADR-005 | `offers.sale_price_cents`, `apr`, `term_months`, `monthly_cents` are nullable **with no `DEFAULT`**. All four valuation bands likewise. A `DEFAULT 0` anywhere in this schema is a review reject — it is exactly the "silently passed flag" ADR-005 forbids, expressed in DDL. |
| 5.12 | **`payment_packing` is canonical; `above_market` exists** | ADR-002; ADR-007 | The `offer_flag` enum's five labels, compared against `@core`'s `OFFER_FLAGS` by test (§6.1 T2). A label like `packed_payment` cannot enter the DB because it is not in the type. |
| 5.13 | **`current_offer` is per-field newest-wins** | ADR-006 | `dealer_threads.rollup_state jsonb` stores the policy's *output* (`@comms` `RollupState`). **No SQL recomputes the merge** — no trigger, no view, no generated column touches `current_offer_id`. A second implementation in SQL would be ADR-001's parallel definition in a different language. |
| 5.14 | **A dealer message is never dropped** | specs/00 "Comms aggregation layer" | `UNIQUE (deal_id, message_ref)` makes the append keyed and redelivery-safe; `processed_events` PK backs the consumer ledger; `quarantined_payloads` and `unrouted_inbound` are *no-drop holding areas* with no delete path. Unrouted inbound is held **whole** as jsonb, replayable — never guessed onto a thread and never minted into a new global `Dealership`. |
| 5.15 | **Year drift is a soft guide** | specs/00 "Year drift"; Q16 | There is no constraint of any kind between `vehicle_instances.year` and `deals.target_year_*`. §6.1 T9 inserts an instance a decade outside the range and asserts success — a *positive* test, because the invariant here is the absence of a rule and absences rot silently. |
| 5.16 | **VIN is user-entered and unvalidated** | Q16; specs/01 backlog 4 | `vin text`, nullable, no length check, no regex, no checksum, no uniqueness. §6.1 T10 inserts `'not-a-vin'` and asserts success. |
| 5.17 | **Deals are archived, never deleted** | specs/01 number lifecycle | D5: every FK is `RESTRICT`; migrations may not contain `DROP TABLE`/`DELETE FROM`/`TRUNCATE` (§1.1 rule 3, statically checked). `status='burned'` + `burned_at` is the archive, and `deal_identities.released_at` retires an identity without deleting the binding. |
| 5.18 | **No unapproved integration or spend** | CLAUDE.md invariant 2 | Zero new dependencies (§1.3 — `dependencies` untouched), zero Postgres extensions (D9: `gen_random_uuid()` is core), no ORM, no query builder, no migration framework, no test-container library. The schema references no external service: KBB/Manheim/Carfax/AutoCheck/credit appear only as opaque `source` **text** on a snapshot row — an adapter id, never a credential, never an endpoint. |
| 5.19 | **No silent interpretive drift** | CLAUDE.md invariant 3 | D1–D13 log every call. The one decision that would have required a chief ADR — RLS for tenancy — was **not** taken (D2), and the reason is recorded rather than left implicit. |
| 5.20 | **Spine defined once, imported everywhere** | ADR-001 | `@db` imports `IsoTimestamp` from `@core` and declares no spine type. D10 exports identifiers, not row shapes; row shapes stay in `@store-pg` (T-015 §2.2 rule 5). The enum-parity test makes "the DB is a second definition of the spine" a testable falsehood rather than an accepted fact of life. |
| 5.21 | **Core services never see a provider's shape** | specs/00 anti-corruption layer | `pg` is imported in exactly one file and appears in **no** exported signature (§2.2). `Queryable`/`DbHandle`/`QueryOutcome` are ours. Swapping the driver would not change one line of `@store-pg`. |

## 8. Blockers / deviations

**Not blocked.** Four notes, all resolved inside this design or handed on explicitly.

1. **RLS was considered and deliberately not chosen (D2).** The task Notes make RLS a chief-level ADR because it reshapes every T-017 call. Composite-FK tenancy is one of the two options AC-4 names, needs no ADR, and changes no port signature. §5.5 states the residual precisely rather than claiming more than the schema delivers. If the lead prefers RLS as defence in depth, it is additive — `account_id` is already on every row — and it is an ADR + a T-017 re-scope, not an edit here.
2. **No `migrate` npm script (D11).** ADR-009 grants this task exactly one script key. Migrations run via `runMigrations()`, which is what the DB tests and T-019's composition root call. A CLI entry point, if wanted, is a lead escalation.
3. **`object_refs` blocks `audio/%` but not `video/%` (D13).** specs/01 forbids audio capture; no spec line addresses video, and inventing one would be drift. Recorded so the gap is a decision rather than an oversight.
4. **The migrating role needs `CREATEROLE`.** Migration `0001` creates `deal_copilot_app`. On an instance where the migrating role lacks it, `runMigrations` fails with `permission_denied` and an actionable message — it does **not** skip the grants and continue, because AC-6's guarantee would then be false while the suite looked green. The trigger layer still holds independently of grants, which is precisely why there are three layers.

**Handed to T-017 as binding consequences of this schema:** the constraint names in `CONSTRAINTS` are an interface (renaming one breaks callers); NULL maps to `undefined`, never `0`; `seq`, `appended_at`, and `channel` on `receipt_entries` are never supplied by the caller; identity and contact-point values are normalized **before** they reach SQL; and every repository method carries an account scope, because the schema stops cross-account *linkage*, not an unscoped `SELECT`.
