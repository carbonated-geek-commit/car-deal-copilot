# Design — T-002: Flag engine (`packages/flag-engine`)

- **Task:** `tasks/T-002-flag-engine.md`
- **Spec basis:** `specs/00-shared-core-architecture.md` — "Flag engine (shared)", "Core domain model" (Offer + flags enum), "Async backbone (shared)" (where callers live); `specs/01` — flags are foregrounded on W2/A3/A4 surfaces, prequal supplies the qualified rate (shape constraints only); `specs/02` — flags advisory for B2B (presentation-only divergence, explicitly out of scope here)
- **ADRs honored:** ADR-001 (Node/TS, spine defined once, no parallel types), ADR-002 (`payment_packing` canonical), ADR-003 (npm workspaces — no per-package installs, aliases predeclared by T-001)
- **Spine reference:** `docs/design/T-001.md` + the as-built `packages/core` (verified identical for every type used here). This doc **references** the spine via `@core`; it redefines nothing.
- **Stage:** design → build
- **Scope:** one pure, provider-agnostic function + its context/config types + co-located vitest fixtures. No I/O, no async, no persistence, no provider knowledge, no UI.

## 0. Interpretive calls made by this design (drift trip-wire log)

Every call below is a mapping inside spec ambiguity the task file already delegates to the designer ("thresholds … not numerically specified … design them as injectable parameters"; "pick one canonical wire value" — already resolved by ADR-002). None requires changing a frozen file; none is blocking.

| # | Call | Basis |
|---|------|-------|
| D1 | **Config is required and has no baked-in defaults.** Any numeric default (e.g. `stretched_term_min_months = 72`) would be an uncited business constant. The spec's "72/84 mo" appears only as *fixture values in tests*, cited to specs/00's own example. | Task note: "design them as injectable parameters/config … so no uncited scope is invented." |
| D2 | **`over_walkaway` total = `sale_price + Σ fees[].amount`.** "The total crosses the deal's walk-away number" (specs/00) — the only totals expressible from the spine `Offer` are price-and-fees; financed interest is not representable (`Offer` has no financed-total field, D2 of T-001 forbids adding one here). Out-the-door price is the operational reading. | specs/00 Offer shape; ADR-001 no-parallel-types (can't extend `Offer`). |
| D3 | **Missing inputs mean "not assessed", never "throw" and never "fire".** `apr` absent (cash deal) or `qualified_apr` absent (no prequal) → `rate_markup` cannot fire; `term_months` absent → `payment_packing` cannot fire. The engine is a *total* function: any well-typed input yields a flag array. Absence of evidence is not a finding. | Purity requirement (specs/00 "pure function"); spine marks `apr`/`term_months`/`monthly` optional. |
| D4 | **Boundary semantics:** `payment_packing` fires at `term_months >= stretched_term_min_months` (72 itself is stretched per the spec's own "72/84 mo" example); `rate_markup`, `junk_fee`, `over_walkaway` fire on **strict** excess (`>`) — the spec words are "above" and "crosses", and equal-to is neither. | specs/00 "Flag engine (shared)" wording, transcribed. |
| D5 | **The engine ignores `offer.flags` on input and returns the full recomputed set.** Callers *replace* an offer's flags with the result; they never merge. Re-evaluation is therefore deterministic and idempotent regardless of what a redelivered event already carried. | specs/00 "pure function of `Offer` + qualified-rate + walk-away" — output depends on economics, not prior annotations. |
| D6 | **`junk_fee` fair value is a per-fee-name cap table** (normalized name → max cents) with an optional catch-all cap for unmatched names; omitted catch-all = unmatched fees never flag. Config-as-data (not an injected callback) keeps the engine serializable, fixture-testable, and free of hidden logic. | Task note (injectable config); specs/00 "add-ons / fees above fair value" — per-fee is the smallest faithful reading. |
| D7 | **Result ordering is fixed to `OFFER_FLAGS` order** (`@core` const) and duplicate-free, so equality checks in tests, event dedupe comparisons, and UI snapshots are stable. | ADR-002 consequence (`packages/core` enum is the flag vocabulary); determinism. |

## 2. Public interface (exact signatures)

All spine types come from `@core` — `Offer`, `OfferFee`, `OfferFlag`, `OFFER_FLAGS`, `MoneyCents`. This package defines **only** the types below (its own inputs), and no type named `Deal`, `DealerThread`, `Message`, `Offer`, or any flag union — that vocabulary already exists (ADR-001/ADR-002).

```ts
import type { MoneyCents, Offer, OfferFlag } from '@core';

/**
 * The buyer/deal side of the evaluation — the "qualified-rate + walk-away"
 * of specs/00 "Flag engine (shared)". Field names mirror the spine sources
 * they are read from; this type is a projection, not a parallel model.
 */
export interface FlagContext {
  /**
   * Buyer's qualified APR, same units as Offer.apr (e.g. 6.9).
   * Sourced from PrequalResult.qualified_apr (@core, specs/01 credit residency:
   * derived number only — no credit payload can pass through this field).
   * Absent when the buyer has no prequal → rate_markup is not assessed (D3).
   */
  qualified_apr?: number;
  /** Deal.walk_away_number (@core), integer USD cents. */
  walk_away_number: MoneyCents;
}

/**
 * Injectable thresholds (D1 — required, no defaults; business constants are
 * the caller's to cite, not this engine's to invent).
 */
export interface FlagEngineConfig {
  /** Term at/above which the term counts as stretched (>=, D4). Spec example: 72. */
  stretched_term_min_months: number;
  /**
   * APR points of excess over qualified_apr tolerated before rate_markup
   * fires (strict >, D4). 0 = any excess flags.
   */
  rate_markup_tolerance_points: number;
  /** Fair-value caps per fee (D6). A fee whose amount strictly exceeds its cap is junk. */
  fee_fair_caps: readonly FeeFairCap[];
  /**
   * Cap applied to fees matching no entry in fee_fair_caps.
   * Omitted = unmatched fees never flag (D6).
   */
  unmatched_fee_cap?: MoneyCents;
}

export interface FeeFairCap {
  /** Matched against OfferFee.name after normalization: trim + lowercase, exact match. */
  name: string;
  max_amount: MoneyCents;
}

/**
 * THE flag engine (specs/00 "Flag engine (shared)"): pure, provider-agnostic,
 * synchronous, total. No I/O, no clock, no randomness, no mutation of any
 * argument, no exceptions on well-typed input. Ignores offer.flags (D5).
 *
 * Returns a duplicate-free OfferFlag[] in OFFER_FLAGS order (D7):
 *  - payment_packing: term_months present && >= config.stretched_term_min_months
 *  - rate_markup:     apr && qualified_apr present && apr > qualified_apr + tolerance
 *  - junk_fee:        any fee.amount > its matched cap (fee_fair_caps, else unmatched_fee_cap)
 *  - over_walkaway:   sale_price + Σ fees[].amount > walk_away_number   (D2)
 */
export declare function evaluateOffer(
  offer: Offer,
  context: FlagContext,
  config: FlagEngineConfig,
): OfferFlag[];
```

That is the entire public API: one function, three input types. Deliberately **not** exported: per-flag predicates (internal detail; testing goes through the public surface), an "attach flags to offer" helper (callers spread: `{ ...offer, flags: evaluateOffer(offer, ctx, cfg) }` — keeping the replace-not-merge rule (D5) visibly in caller code), and any re-export of `@core` types (consumers import the spine from `@core`, never transitively).

## 3. Data shapes (canonical spine, referenced not redefined)

| Shape | Role here | Source of truth |
|---|---|---|
| `Offer` (`sale_price`, `fees[]`, `apr?`, `term_months?`, `monthly?`, `flags[]`) | Sole subject of evaluation; input untouched, `flags` on input ignored (D5) | `@core` domain — specs/00 "Core domain model" |
| `OfferFlag` / `OFFER_FLAGS` | The **only** flag vocabulary; the return type is `OfferFlag[]` — AC-6's "no parallel flag type" holds by construction because this package cannot name a flag `@core` doesn't define | `@core` — ADR-002 |
| `OfferFee` | Matched against `FeeFairCap` for `junk_fee` | `@core` |
| `MoneyCents` | All money in `FlagContext`/`FlagEngineConfig` is integer cents — arithmetic (`Σ fees`, walk-away comparison) never touches floats | `@core` scalar |
| `Deal.walk_away_number` | Where callers read `FlagContext.walk_away_number` from | `@core` `Deal` |
| `PrequalResult.qualified_apr` | Where callers read `FlagContext.qualified_apr` from (derived number only — specs/01 residency) | `@core` adapter contract |
| `DealerThread.current_offer`, `Message.extracted_offer` | Where flagged offers land downstream — this engine never touches threads/messages itself; callers own attachment | `@core` |
| `AlertDispatchRequestedV1.flags?: OfferFlag[]` | The event by which emitted flags reach owners — same vocabulary end-to-end | `@core` events |

The engine takes no `Deal`, no `DealerThread`, no `Message`, no event envelope — only the three-argument projection above. That narrowness is what makes it shared verbatim across consumer and B2B (specs/00: divergence is presentation-layer only; there is no product/tenant parameter in the signature and there must never be one).

## 4. Error paths per operation

The engine has exactly one operation, and it is pure. Most failure machinery is therefore *provably absent* rather than handled — which is itself the design.

### 4.1 `evaluateOffer` (the only operation)

| Failure mode | Behavior | Retry / idempotency | Logged | Surfaces as |
|---|---|---|---|---|
| Missing optional inputs (`apr`, `term_months`, `qualified_apr` absent) | Affected flag **not assessed** — cannot fire (D3). Not an error. | n/a — deterministic | Nothing (engine never logs) | Fewer flags; callers needing "insufficient data" UX derive it from input presence, not from this engine |
| Nonsense numerics slipping past upstream (NaN, negative cents) | Total function: comparisons with NaN are false → flags conservatively do not fire; no throw. Input validation is upstream's job (offer-extraction T-008 / API edge), not the flag engine's | n/a | Nothing | Silently conservative — acceptable because a NaN offer is already an upstream contract violation the validator/test layer catches |
| Malformed **config** (e.g. negative threshold) | Same: total, no throw. Config is operator-supplied, versioned with the caller, and exercised by that caller's own tests — the pure engine does not police its caller | n/a | Nothing | Caller-side test failure |
| Provider outage, timeout, rate limit, auth | **Impossible.** No I/O exists in this package — no adapter import, no fetch, no queue client, no clock | — | — | — |
| Exception escaping the engine | None on well-typed input, by contract; a throw observed in practice is a defect (test escape), not a handled path | — | — | — |

**Idempotency:** referential transparency *is* the idempotency story. Same `(offer, context, config)` → identical `OfferFlag[]`, always. Under the bus's at-least-once, unordered delivery (T-001 §5.3), a consumer that re-runs evaluation on a redelivered event produces the same flags and, per D5 replace-not-merge, writing them again is a no-op. No idempotency key is needed *inside* the engine; the enclosing event's `idempotency_key` (already specified in T-001 §5.3) covers the write.

**Logging:** the engine logs nothing — purity means no logger dependency, and there is nowhere for PII to leak from a function that cannot perform output. Observability of flag emission belongs to callers: the alert path logs `deal_id`, `kind: 'flag_raised'`, and the `flags[]` array (flag names are PII-free enum literals), never offer bodies — consistent with T-001 §5.3's "never payload bodies".

### 4.2 Webhook posture (binding on callers; stated here because the task requires it)

This package exposes **no webhook, HTTP, or queue surface** — nothing to ack. The binding spine rule (specs/00: "webhooks ack immediately, all heavy work … runs on the event bus") is honored *around* the engine as follows:

- The engine is never called inside a webhook handler's pre-ack window. Its callers are **event consumers** — canonically the `offer.extraction.completed.v1` consumer (T-008/T-009 territory), which receives a parsed `Offer`, reads `walk_away_number` off the `Deal` and `qualified_apr` off stored prequal, calls `evaluateOffer`, writes `{ ...offer, flags }` onto the thread's `current_offer`, and (when flags are non-empty) publishes `alert.dispatch.requested.v1`. Ack-then-queue happened long before, at ingest (T-001 §5.2).
- The engine is structurally *incapable* of violating the rule even if misused: it is synchronous, allocation-cheap (a handful of comparisons and one fee sum), and does no I/O — it cannot block an ack, hold a connection, or drop a dealer message. There is no retry policy to design because there is nothing that can transiently fail.
- Failure in the *enclosing consumer* (store write fails after evaluation, etc.) follows T-001 §5.3 unchanged: redeliver with backoff, dead-letter on exhaustion — and re-evaluation on redelivery is safe per the idempotency note above.

### 4.3 What surfaces where (end-to-end, for traceability)

`flags[]` → written into `Offer.flags` by the caller → visible on `DealerThread.current_offer` → consumer UI foregrounds them (specs/01 W2 flags column, A3 instant flags, A4 push alerts via `alert.dispatch.requested.v1`); B2B renders the same values as advisory (specs/02). Nothing in this package knows or encodes that difference.

## 5. Test design (`packages/flag-engine/test/`, AC-7)

Fixture config (in `fixtures.ts`, values cited to the spec's own examples — D1): `stretched_term_min_months: 72` (specs/00 "72/84 mo"), `rate_markup_tolerance_points: 0`, a small `fee_fair_caps` table (e.g. doc fee capped), `unmatched_fee_cap` set in some fixtures and omitted in others. Fixture offers are plain `Offer` literals importing the type from `@core`.

| Suite | Cases |
|---|---|
| Per-flag firing / not firing (AC-2..5) | For each of the four flags: one fixture where it fires, one where it does not, all other inputs held benign — 8 core cases |
| Boundaries (D4) | term = 72 fires, 71 does not; apr = qualified + tolerance does **not** fire, +ε does; fee = cap does not fire, cap+1¢ does; total = walk-away does not fire, +1¢ does |
| Missing inputs (D3) | no `apr` / no `qualified_apr` / no `term_months` → respective flag absent, other flags unaffected |
| Vocabulary (AC-6, ADR-002) | Result values ⊆ `OFFER_FLAGS`; `'packing'` never appears; type-level: return type assignable to `OfferFlag[]` and *not* to any wider string union |
| Purity & determinism (AC-1, D5, D7) | Input offer deep-equal before/after call (no mutation); `offer.flags` prepopulated with garbage-but-valid flags does not affect output; two calls with equal inputs are `deepEqual`; multi-flag fixture returns flags in `OFFER_FLAGS` order, no duplicates |
| Combined | One "everything wrong" offer emits all four; one clean offer emits `[]` |

All tests run from root: `npx vitest run packages/flag-engine`, green with only `packages/core` and this package present.

## 6. Invariant touchpoints

| Invariant (source) | How this component could break it | How the design protects it |
|---|---|---|
| No parallel type definitions; spine defined once (ADR-001) | Re-declaring `Offer` or a local flag union "for convenience" | §2 imports every spine type from `@core`; the only defined types are the engine's own inputs (`FlagContext`, `FlagEngineConfig`, `FeeFairCap`); return type is `@core`'s `OfferFlag[]`; T-001 §7's grep rule (`interface (Deal\|DealerThread\|Message\|Offer)\b` outside core) stays clean |
| `payment_packing` canonical, no new flag names (ADR-002) | Emitting `'packing'` or inventing a fifth flag | The return type makes non-`OfferFlag` strings a compile error; vocabulary suite (§5) asserts `'packing'` never appears and results ⊆ `OFFER_FLAGS` |
| No unapproved integration or spend (CLAUDE.md #2) | A dep sneaking into the package; provider logic entering "fair value" | `package.json` has zero dep keys (§1); config is data, not code (D6); no import may resolve outside `@core`/vitest — reviewer greps imports |
| No silent interpretive drift (CLAUDE.md #3) | Hard-coded thresholds = uncited business constants; unlogged readings of "total"/"above"/"crosses" | D1 (no defaults, config required), D2/D4 log the readings with spec basis; fixtures cite specs/00's own example values |
| Flag engine is pure and provider-agnostic (specs/00, AC-1) | I/O, clock, randomness, or a provider/product parameter creeping into the signature | §2 signature is closed: three data arguments, sync return; no async, no logger, no tenant/product flag — B2B/consumer divergence stays presentation-layer (§3, §4.3) |
| Webhooks ack immediately; no dropped dealer message (specs/00) | Heavy or blocking work invoked pre-ack | No webhook surface exists here (§4.2); engine is sync + cheap + I/O-free, so it cannot block an ack even if called in the wrong place; heavy work remains event-bus-only per T-001 §5.2–5.3 |
| Credit data pass-through only (specs/01) | Credit payloads flowing into flag evaluation | `FlagContext.qualified_apr` is a single derived number — the same shape `PrequalResult` already restricts to; no field of any engine type can hold a credit payload |
| Receipt trail append-only (specs/00) | Mutating stored offers/messages | The engine mutates nothing (purity test, §5); D5's replace-not-merge applies to the caller's *new* write of `current_offer`, and message history is untouched by design |
| File ownership (CLAUDE.md) | Touching root configs or other packages | All created files are under `packages/flag-engine/**` (§1); aliases and test globs were predeclared by T-001 — zero root edits needed |
