# Design — T-008: Receipt layer — append-only store contract + dossier export stub (`packages/receipt`)

- **Task:** `tasks/T-008-receipt-layer.md`
- **Spec basis:** `specs/00-shared-core-architecture.md` — "Receipt layer (trust engine)", "Core domain model" (Store, `receipt_bundle_id`), "Async backbone (shared)"; `specs/01-consumer-product-spec.md` — "Consent & recording posture" (transcribe-only, no audio retention; shape constraint only); `specs/02-b2b-product-spec.md` — receipt trail as audit/handoff artifact (emphasis only, no model change)
- **ADRs honored:** ADR-001 (Node/TS, spine defined once, vitest one toolchain), ADR-002 (flag vocabulary — no receipt impact beyond importing spine types unchanged), ADR-003 (npm workspaces)
- **Spine reference:** all shared types are **imported from `@core`** (`docs/design/T-001.md` §2–§4). This document defines only receipt-package-local types; it never redefines `Deal`, `DealerThread`, `Message`, `Offer`, or any core scalar/enum.
- **Stage:** design → build
- **Scope:** contract types + in-memory reference implementation + dossier-export stub + co-located vitest tests. No persistence, no PDF engine, no hosting, no HTTP, no new dependencies.

## 0. Interpretive calls made by this design (drift trip-wire log)

Every call stays inside spec ambiguity or T-001's binding contracts; none touches a frozen file and none requires an unapproved integration. If a builder finds any insufficient, stop and escalate — do not improvise.

| # | Call | Basis |
|---|------|-------|
| R1 | **Receipt entries are package-local types, not spine types.** `ReceiptEntry` carries store-assigned `seq` + `appended_at` and an optional caller-supplied `dedupe_key`. This does **not** add fields to core `Message` (T-001 D2 forbids that without an ADR): correlation to a message rides on the already-existing `provider_message_ref` (the spine's idempotency anchor, T-001 §5.3), so no synthetic `Message.id` is needed. | T-001 D2 ("correlation/idempotency identifiers live in the event envelope, not the domain model"); ADR-001 (spine defined once — so receipt shapes must live outside it, referencing it). |
| R2 | **Entry kinds are closed to the spec's four:** `recording_ref`, `transcript`, `sms`, `email`. The specs/01 concierge audit-log entries ("every agent action lands in the append-only receipt trail") are a consumer-product concern for a later epic; adding an `audit` kind is an ADR + task, not a quiet union extension here. One shared layer, no product branching (task note). | specs/00 "Receipt layer" names exactly recording/transcript/SMS/email; task Notes ("does not change the model — build one shared layer"). |
| R3 | **Bundles are implicit — no create/open operation.** `receipt_bundle_id` is issued by whoever owns the `Deal` aggregate (it is a `Deal` field, specs/00 "Core domain model"); the store treats any well-formed id as an existing, possibly-empty bundle. Reading or assembling a never-appended bundle returns an empty entry list / empty dossier, not an error — the store cannot know which ids are "real" without reaching into the Deal store, which is outside this package's boundary. | specs/00 `Deal.receipt_bundle_id`; task AC-3 (bundles are *addressed by* the deal's id — addressing, not lifecycle). |
| R4 | **Channel is derived, not supplied.** Callers do not pass `channel`; the store derives it from `kind` (`recording_ref`/`transcript` → `call`, `sms` → `sms`, `email` → `email`). An inconsistent state (`kind: 'sms'`, `channel: 'email'`) is inexpressible — same structural-enforcement philosophy as the append-only surface itself. | specs/00 `Message.channel` enum (imported from `@core`); task Objective ("immutability is enforced by the API surface, not by convention") applied to consistency too. |
| R5 | **Read-back and dossier order = `occurred_at` ascending, tie-broken by `seq`.** Append order and event-time order can differ (a transcript completes minutes after the SMS that followed the call); the trust artifact must read chronologically, so `occurred_at` wins and the per-bundle monotonic `seq` makes ordering total and deterministic. | task AC-5 ("chronological read-back"); specs/00 ("timestamped, exportable" — a dossier is read as a timeline). |
| R6 | **Idempotent append via optional `dedupe_key`, resolved append-only.** Under at-least-once event delivery (T-001 §5.3) the same fact may be appended twice. If `dedupe_key` matches an existing entry in the same bundle, append returns the existing entry marked `deduplicated: true` — no new entry, **no mutation of the existing one**. Entries without a `dedupe_key` always append. Convention for event-driven writers: `dedupe_key` := the event envelope's `idempotency_key`. | T-001 §5.3 (at-least-once, consumers idempotent on `idempotency_key`); specs/00 append-only (dedupe must not become upsert). |
| R7 | **Interface is `Promise`-async even though Epic 1 is in-memory.** A Postgres/S3 implementation must slot in behind the identical interface (task Notes); a synchronous surface would force that future implementation to change the contract. The in-memory reference resolves immediately. | task Notes ("Design the store contract so a Postgres/S3 implementation can slot in… without changing it"). |
| R8 | **Stubs fail loudly with `not_implemented`.** `renderPdf` / `publishWebLink` keep their real future signatures (returning an artifact ref) but always return `{ ok: false, code: 'not_implemented' }` in Epic 1. A stub that fabricates a fake URL would leak into product code as if hosting existed. | task AC-4 ("actual PDF rendering and web-link hosting are stubbed"); CLAUDE.md invariant 2 (no hosting endpoint may exist yet anyway). |
| R9 | **Package-local `ReceiptResult`/`ReceiptError`, not core's `AdapterResult`.** The receipt store is internal infrastructure, not an anti-corruption adapter over an external provider; core's `AdapterErrorCode` vocabulary (`auth`, `rate_limited`, `malformed_response`) describes provider failure, which cannot occur here. Shape mirrors `AdapterResult` (discriminated `ok`, explicit `retryable`, log-safe `message`) so callers handle both identically. | T-001 §3.1 (adapter contract is for external feeds); specs/00 "Every external feed sits behind one internal interface" — the receipt store is not a feed. |

## 2. Receipt entry shapes (`src/contract.ts`)

References canonical spine types — `IsoTimestamp`, `MessageChannel`, `MessageDirection` from `@core`. The entry mirrors the receipt-relevant projection of the canonical `Message` (`channel`, `direction`, `body | recording_url | transcript`, `timestamp` — specs/00 "Core domain model") without redefining `Message` itself.

```ts
import type { IsoTimestamp, MessageChannel, MessageDirection } from '@core';

/** specs/00 "Receipt layer": recording, transcript, SMS, email — closed set (R2). */
export type ReceiptEntryKind = 'recording_ref' | 'transcript' | 'sms' | 'email';

interface ReceiptEntryInputBase {
  kind: ReceiptEntryKind;
  direction: MessageDirection;                 // @core — in | out
  /** When the underlying communication happened (maps to Message.timestamp). */
  occurred_at: IsoTimestamp;
  /** Correlation to the originating message/event — the spine's existing anchor (R1). */
  provider_message_ref?: string;
  /** Idempotency anchor for at-least-once writers (R6). Convention: event idempotency_key. */
  dedupe_key?: string;
}

/**
 * A POINTER to a recording (provider handle or future object-store key) —
 * never audio bytes. Consumer product policy (specs/01 transcribe-only)
 * simply never appends this kind; the kind exists because the layer is shared.
 */
export interface RecordingRefEntryInput extends ReceiptEntryInputBase {
  kind: 'recording_ref';
  recording_ref: string;
}

export interface TranscriptEntryInput extends ReceiptEntryInputBase {
  kind: 'transcript';
  transcript: string;
}

export interface SmsEntryInput extends ReceiptEntryInputBase {
  kind: 'sms';
  body: string;
}

export interface EmailEntryInput extends ReceiptEntryInputBase {
  kind: 'email';
  subject?: string;
  body: string;
}

export type ReceiptEntryInput =
  | RecordingRefEntryInput
  | TranscriptEntryInput
  | SmsEntryInput
  | EmailEntryInput;

/** Store-assigned at append time; never caller-supplied. */
export interface ReceiptEntryStamp {
  /** Per-bundle monotonic sequence — append order, total and gap-tolerant. */
  seq: number;
  /** When the store accepted the entry (distinct from occurred_at). */
  appended_at: IsoTimestamp;
  /** Derived from kind (R4): recording_ref/transcript → 'call', sms → 'sms', email → 'email'. */
  channel: MessageChannel;
}

/**
 * A stored entry: caller input + store stamp, DEEPLY READONLY.
 * The reference implementation defensively copies the input and deep-freezes
 * the stored object, so neither later caller mutation of the input nor
 * mutation of a read-back result can alter the trail.
 */
export type ReceiptEntry = Readonly<ReceiptEntryInput & ReceiptEntryStamp>;
```

## 3. Store contract (`src/contract.ts`) — structurally append-only

The interface exposes **append and read only**. There is no `update`, `delete`, `overwrite`, `truncate`, `clear`, or setter of any name on any exported type — task AC-2 makes the *type surface* the enforcement mechanism.

```ts
export type ReceiptErrorCode =
  | 'invalid_input'       // caller bug (empty bundle id, empty payload) — not retryable
  | 'store_unavailable'   // durable-backend outage — retryable; in-memory impl never emits it
  | 'not_implemented';    // Epic 1 stubs (renderPdf, publishWebLink) — not retryable

export interface ReceiptError {
  code: ReceiptErrorCode;
  /** True only for store_unavailable. Stated explicitly so callers never guess. */
  retryable: boolean;
  /** Log-safe: never contains bodies, transcripts, phone numbers, or email addresses. */
  message: string;
}

export type ReceiptResult<T> = { ok: true; value: T } | { ok: false; error: ReceiptError };

export interface AppendOutcome {
  entry: ReceiptEntry;
  /** True when dedupe_key matched an existing entry and no new entry was written (R6). */
  deduplicated: boolean;
}

/**
 * Append-only, timestamped store for receipt entries, keyed by the Deal's
 * receipt_bundle_id (specs/00 "Core domain model"). specs/00 "Receipt layer":
 * append-only, timestamped, exportable. Epic 1 ships the in-memory reference;
 * a Postgres/S3 implementation must satisfy THIS interface unchanged (R7).
 */
export interface ReceiptStore {
  append(receipt_bundle_id: string, input: ReceiptEntryInput): Promise<ReceiptResult<AppendOutcome>>;
  /** Chronological read-back: occurred_at ascending, ties broken by seq (R5). */
  read(receipt_bundle_id: string): Promise<ReceiptResult<readonly ReceiptEntry[]>>;
}

/** Injectable clock for deterministic tests; defaults to system UTC now. */
export type ReceiptClock = () => IsoTimestamp;
```

Reference implementation factory (in `memory-store.ts`, exported via `index.ts`):

```ts
export function createInMemoryReceiptStore(clock?: ReceiptClock): ReceiptStore;
```

Behavioral contract of the reference implementation (binding on the builder; the durable implementation inherits every rule):

- `append` validates input (§5.1), derives `channel`, assigns `seq` (per-bundle counter starting at 1) and `appended_at` (from the clock), defensively copies, deep-freezes, stores.
- Dedupe check is per-bundle on `dedupe_key`; a hit returns the **existing frozen entry** with `deduplicated: true`.
- `read` returns a **fresh array** each call (the array is the caller's; the entries are frozen singletons), sorted per R5. Unknown bundle → `{ ok: true, value: [] }` (R3).
- Nothing in the implementation ever reassigns or removes a stored entry — there is no code path to (the internal map only ever gains entries), matching the interface's promise.

## 4. Dossier export (`src/dossier.ts`) — assembler real, rendering/hosting stubbed

specs/00 "Receipt layer": "Generates a shareable **deal dossier** (PDF + web link)." Epic 1 ships the *structure*; PDF and hosting are stubbed (task AC-4, R8).

```ts
export interface DealDossier {
  /** The Deal's receipt_bundle_id — the dossier's address (task AC-3). */
  receipt_bundle_id: string;
  generated_at: IsoTimestamp;
  entry_count: number;
  /** Absent when the bundle is empty. */
  first_entry_at?: IsoTimestamp;
  last_entry_at?: IsoTimestamp;
  /** Ordered per R5 — the shareable timeline, verbatim frozen entries. */
  entries: readonly ReceiptEntry[];
}

/** Future artifact pointer (S3 key / hosted URL). Epic 1: never produced. */
export interface DossierArtifactRef {
  kind: 'pdf' | 'web_link';
  /** Opaque ref — object-store key or URL, per the later durable epic. */
  ref: string;
  generated_at: IsoTimestamp;
}

export interface DossierExporter {
  /** Assembles the bundle's entries into the exportable dossier structure. REAL in Epic 1. */
  assemble(receipt_bundle_id: string): Promise<ReceiptResult<DealDossier>>;
  /** STUB in Epic 1: always { ok: false, code: 'not_implemented' } (R8). Signature is final. */
  renderPdf(dossier: DealDossier): Promise<ReceiptResult<DossierArtifactRef>>;
  /** STUB in Epic 1: always { ok: false, code: 'not_implemented' } (R8). Signature is final. */
  publishWebLink(dossier: DealDossier): Promise<ReceiptResult<DossierArtifactRef>>;
}

export function createDossierExporter(store: ReceiptStore, clock?: ReceiptClock): DossierExporter;
```

- `assemble` reads through the injected `ReceiptStore` — it has no private access to storage, so a durable store slots in without touching the exporter.
- Empty bundle → valid empty dossier (`entry_count: 0`, no `first/last_entry_at`) — R3.
- No PDF library, no HTTP, no hosting code appears anywhere — the stubs are error-returning bodies, not half-implementations.

## 5. Error paths per operation (failure modes, retry/idempotency, logging, surfacing)

This package performs no I/O in Epic 1 and owns **no webhook handler** — but its writers do, so §5.4 fixes how the ack-then-queue rule reaches this layer.

### 5.1 `ReceiptStore.append`

| Failure mode | Result | Retry / idempotency | Logged (by caller/impl) | Surfaces as |
|---|---|---|---|---|
| Empty/blank `receipt_bundle_id` | `invalid_input`, not retryable | None — caller bug, fix upstream | code, kind | Programming-error state to caller; never user-facing |
| Empty payload for kind (blank `body`/`transcript`/`recording_ref`) | `invalid_input`, not retryable | None | code, kind, bundle id | Same |
| Malformed `occurred_at` (non-ISO-8601) | `invalid_input`, not retryable | None | code, kind, bundle id | Same |
| Duplicate `dedupe_key` in bundle | **`ok: true`**, `deduplicated: true`, existing entry returned | This IS the idempotency mechanism (R6) — safe under at-least-once redelivery | bundle id, seq, `deduplicated=true` | Nothing — duplicates are absorbed silently and correctly |
| Durable backend down (future impl only) | `store_unavailable`, retryable | Caller retries with backoff **reusing the same `dedupe_key`** — retry-after-partial-write is absorbed by dedupe, so append is exactly-once-effective | code, bundle id, attempt count | Event consumer redelivery path (T-001 §5.3); operator alert on dead-letter |

**Never logged, by contract:** entry bodies, transcripts, subjects, phone numbers, email addresses, recording refs. `ReceiptError.message` is defined log-safe (§3); log lines carry ids, kinds, seq, outcome only. The receipt trail *stores* PII — its logs must not leak it.

### 5.2 `ReceiptStore.read`

| Failure mode | Result | Retry / idempotency | Logged | Surfaces as |
|---|---|---|---|---|
| Empty/blank `receipt_bundle_id` | `invalid_input` | None | code | Programming-error state |
| Unknown / never-appended bundle | `ok: true, value: []` (R3) | Naturally idempotent (pure read) | bundle id, count=0 | Empty trail view / empty dossier — a valid state for a fresh deal |
| Durable backend down (future) | `store_unavailable`, retryable | Backoff; reads are idempotent | code, bundle id | Stale/unavailable trail view, never fabricated data |

### 5.3 `DossierExporter.assemble` / `renderPdf` / `publishWebLink`

| Operation | Failure mode | Result | Retry | Logged | Surfaces as |
|---|---|---|---|---|---|
| `assemble` | Underlying `read` fails | Propagates the store's `ReceiptError` unchanged | Per the propagated `retryable` flag | bundle id, outcome | "Dossier unavailable" — never a partial dossier |
| `assemble` | Empty bundle | `ok: true`, empty dossier | — | bundle id, count=0 | Empty-but-valid dossier |
| `renderPdf` | Always (Epic 1) | `not_implemented`, not retryable | None — terminal by design | operation name | Feature-not-available state; callers must branch on `ok`, so the stub cannot be mistaken for success (R8) |
| `publishWebLink` | Always (Epic 1) | `not_implemented`, not retryable | None | operation name | Same |

### 5.4 Webhook boundary — **ack-then-queue, binding on all writers**

This package deliberately exposes **no webhook handler and no HTTP surface**. The specs/00 rule ("webhooks ack immediately, all heavy work runs on the event bus; provider timeouts must never drop a dealer message") reaches the receipt layer as a constraint on its callers, fixed here so T-009 cannot mis-wire it:

1. **No `ReceiptStore.append` call may run inside a webhook handler before the 2xx ack.** Appends are event-consumer work: the handler parses (sync, pure — T-001 §3.3), durably enqueues `comms.inbound.received.v1`, acks; a consumer later appends the receipt entry alongside threading the `Message`.
2. **Writers set `dedupe_key` to the event envelope's `idempotency_key`** (e.g. `source:provider_message_ref` for inbound comms — T-001 §5.3). Provider redelivery or consumer retry then cannot double-write the trail (R6).
3. **A failed append inside a consumer is a consumer failure**, handled by T-001 §5.3: retryable → redeliver with backoff; exhausted → dead-letter with envelope intact + operator alert. Never silently dropped — dead-lettered comms events are the receipt trail's feedstock, and losing one silently falsifies the trail.
4. Outbound sends (T-001 §5.4) append their receipt entry only after the adapter accepts the send (`ProviderSendReceipt`), with `dedupe_key` derived from `client_ref` — the trail records what was actually sent, not what was attempted.

## 7. Test design (`packages/receipt/test/receipt.test.ts`) — AC-5

Run from root: `npx vitest run packages/receipt`. Deterministic via injected `ReceiptClock`.

1. **Append + stamp:** appending each of the four kinds returns `ok` with derived `channel` (R4), `seq` starting at 1 and incrementing per bundle, `appended_at` from the clock; separate bundles have independent `seq` sequences.
2. **Chronological read-back:** entries appended out of event-time order read back sorted by `occurred_at` asc with `seq` tiebreak (R5); unknown bundle reads back `[]`.
3. **Structural append-only (type surface):** compile-time assertion (`expectTypeOf`) that `keyof ReceiptStore` is exactly `'append' | 'read'`, and that no exported type has an `update`/`delete`/`clear`-named member; runtime assertion that the store object exposes no other own function properties.
4. **Immutability:** mutating the input object after append does not change the stored entry (defensive copy); stored entries are frozen (`Object.isFrozen`, including nested); mutating a `read` result array does not affect a subsequent `read`.
5. **Idempotent dedupe:** same `dedupe_key` twice → second append `ok` with `deduplicated: true`, same `seq`, `read` shows one entry; different keys and keyless appends always add.
6. **Validation:** blank bundle id / empty payload / malformed timestamp → `invalid_input`, not retryable, and `read` confirms nothing was written.
7. **Dossier assembly:** `assemble` returns ordered entries, correct `entry_count`, `first/last_entry_at`; empty bundle → valid empty dossier; `renderPdf` and `publishWebLink` return `not_implemented` with `retryable: false`.
8. **Error message hygiene:** every `ReceiptError.message` produced in the above contains none of the test's body/transcript/phone/email fixture strings.
