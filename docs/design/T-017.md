## 0. Interpretive calls made by this design (drift trip-wire log)

Each stays inside spec/ADR ambiguity or is a mechanical consequence of Postgres. None touches a protected path. A builder who finds any of these insufficient **stops and messages the lead** — it does not improvise, and above all it does not edit a port, a migration, or a manifest dependency.

| # | Call | Basis / consequence |
|---|------|---------------------|
| **D1** | **The synchronous `CommsStore` port is satisfied by a transaction-scoped UNIT OF WORK, not by per-call I/O.** A `PgCommsSession` hydrates asynchronously, hands out a *synchronous* `CommsStore` backed by the hydrated working set, journals every mutation, and flushes the journal inside the same transaction on `commit()`. | `CommsStore` and `RawPayloadStore` return plain values (`Deal \| undefined`, `'appended' \| 'duplicate'`, `string`); `pg` is asynchronous, and no synchronous Postgres client exists in the approved dependency set. The three ways out are: change the port (forbidden — AC-1 and the task Notes make it a T-014 re-scope), block the event loop (a worker + `Atomics.wait` is an unapproved architecture change and would stall a Fastify process), or make the *unit of work* the async boundary. Only the third leaves every signature untouched. Note the asymmetry that proves the point: `@receipt`'s `ReceiptStore` is **already** `Promise`-returning (T-008 designed it for a durable backend), so it needs none of this — §2.5 implements it directly. §8.2 recommends the port re-scope to the lead without acting on it. |
| **D2** | **The hydration plan is DERIVED from the event or request, never guessed.** `planForEvent(event: SpineEvent)` and `planForDeal(deal_id)` are pure functions in `@store-pg`; `open(plan)` resolves identities → deal ids → full aggregates before the handler runs. | Otherwise the inbound path deadlocks on its own chicken-and-egg: `resolveDealByIdentity` must answer synchronously, but the deal it names is not known until it has answered. The envelope already carries `to_identity`, so the resolution is an *async* step at `open()` and a *lookup* inside the handler. Preloading a global identity cache instead was rejected: it is a distributed cache with no invalidation, and a binding written by one process would be invisible to another — messages would go to `unrouted` for reasons no operator could reproduce. |
| **D3** | **Under-hydration is a loud error, never a silent miss.** Any port call naming a `deal_id` outside the session's hydration set throws `PgStoreUnhydratedError`. | The failure mode this closes is the worst one available: the in-memory engine would otherwise answer "unknown deal" for a deal that exists, and a consumer would classify that as `retry` → dead-letter, i.e. a dealer message held forever for a cache bug. A distinct error makes the bug a one-line log entry instead of an archaeology project. |
| **D4** | **"Repository" and "port" are two layers, and only the repository is account-scoped by signature.** `CommsRepository` (§2.3) takes `AccountScope` on every method; `PgCommsSession` is *constructed* against one scope and is what implements the unchanged `CommsStore`. | This is how AC-1 ("no port signature is modified") and AC-2 ("every repository method takes an account scope") are both true rather than in conflict. The port cannot grow an account argument; the layer beneath it cannot lose one. E3's authorization attaches at `open()` — one place, already parameterized. |
| **D5** | **Every scoped statement carries `account_id = $1` IN ADDITION to its id predicate**, even where the id is already unique. | T-016 §5.5 states its own limit precisely: composite FKs stop cross-account *linkage*, not an unscoped `SELECT`. That last mile is this task's, and it is bought with a redundant predicate rather than a promise. A repository method that omits it is a review reject; §6.2 asserts it statically over the SQL text. |
| **D6** | **A cross-account read returns exactly what a missing row returns — `undefined` / an empty list — never a distinguishing error, and never an echo of the foreign id.** | Distinguishing "not yours" from "does not exist" turns the store into an existence oracle: an attacker learns which deal ids are real by the shape of the refusal. AC-11's test asserts the two cases are observably identical. Cross-account *writes* are a different matter — those are caught by the FK (`23503`) or `DC003` and logged, because a write attempt is evidence of a caller bug or an attack, not a probe to be answered politely. |
| **D7** | **The ADR-006 merge is IMPORTED (`mergeCurrentOffer` from `@comms`) and never reimplemented — not in TypeScript here, not in SQL.** `dealer_threads.rollup_state` stores the policy's output verbatim. | ADR-006's blast radius is `services/comms/src/rollup.ts` alone. A second merge in this package would be ADR-001's parallel definition wearing a persistence hat, and the two would drift the first time a tie-break changed. T-016 §5.13 already forbids the SQL half. |
| **D8** | **`current_offer` is ONE `offers` row per thread, updated in place; `extracted_offer` is one row per message, fill-once and never updated.** `Deal.offers[]` is exactly `offers WHERE deal_id = $ AND thread_id IS NULL`. | `@core`'s `Offer` has **no `id`**, so offer identity is store-internal and must never leak onto a returned spine object. Inserting a fresh row per rollup was rejected: superseded rows would become unreferenced and leak into `Deal.offers`. `thread_id IS NULL` is the discriminator T-016 already gave us (`offers.thread_id` is nullable); a `NOT EXISTS` over both pointer columns was rejected as fragile. Nothing evidentiary is lost — the contributions are the `messages.extracted_offer_id` rows and the receipt trail, and `rollup_state` records per-field provenance. |
| **D9** | **`DealershipContact` is found-or-created by `(account_id, dealership_id, lower(name), role)`.** | `@core`'s `DealershipContact` has no `id`; the table does. The store may not invent identity beyond what the spine gives it, and it may not create a second row for a redelivered `putThread` (that would be a fabricated person in a private index). Residual, stated rather than hidden: two genuinely different people with the same name and role at one dealership inside one account collapse to one row. A natural-key unique index would make this an `ON CONFLICT` instead of a `SELECT`-then-`INSERT`; that is a T-016 addition (§8.5), not an edit here. |
| **D10** | **`putDeal` / `putThread` are idempotent UPSERTS of the parent row only. They never delete, never truncate a child collection, and never reset an existing thread.** | The in-memory implementation *replaces* the record; over Postgres a replace would delete messages, which T-016 D5 forbids outright and which the append-only promise forbids in principle. The observable divergence is narrow and stated: re-seeding a deal with fewer threads leaves the older threads present in Postgres. No behavioural test exercises that path (`seedDeal` runs once per deal), and the durable direction is the safe one — a spurious extra thread is visible, a deleted message is not. |
| **D11** | **Normalization is re-expressed here and proved equal by test, not shared by import.** `normalizePhone`/`normalizeEmail` are private to `services/comms/src/store/in-memory-store.ts`. | Exporting them is a `@comms` edit this task may not make. The risk — a near-miss identity that routes in one store and not the other — is closed by a **normalization parity suite** (§6.1 T3) that drives one adversarial value table through *both* stores' bind-then-resolve and asserts identical verdicts. §8.4 recommends the one-line export that would delete the duplicate. |
| **D12** | **`RawPayloadStore` over Postgres persists the REF, never the bytes.** `stash()` computes a sha-256 of canonical JSON synchronously (`node:crypto`, no new dependency), returns it, and journals both an `object_refs` row (`kind='raw_payload'`) and a byte write to an injected `RawByteSink`. | AC-8 and specs/00 Store: bytes live in the object store. `@store-pg` must not import `@object-store` (no dependency edge, and T-018 owns it), so the sink is a narrow **structural** interface that T-018's adapter satisfies without either package knowing about the other. The sink is required at construction — a missing sink fails loudly at composition rather than silently storing nothing. |
| **D13** | **The holding areas dedupe with a guarded `INSERT … WHERE NOT EXISTS` / conditional `UPDATE`, because no unique index exists for them.** | The in-memory store dedupes quarantine on `(source, raw_payload_ref)` and unrouted on `(source, inbound.provider_message_ref)` — but T-016 shipped neither table with a matching constraint. The guard reproduces the behaviour; the residual is a concurrent race that can produce a **duplicate held record**, never a lost one. That direction is the correct one for a no-drop holding area, and the fix is an additive index (§8.3). |
| **D14** | **AC-10 is satisfied by re-running the behavioural CONTRACT, not by re-executing `services/comms/test/*.ts`.** | Those files are foreign, and they hard-wire the concrete `InMemoryCommsStore` (`Harness.store: InMemoryCommsStore`, `HarnessOpts.consent: (store: InMemoryCommsStore) => ConsentHook`). They also use non-uuid ids (`'deal-a'`, `'dealership-synthetic-motors'`), which Postgres rejects as `22P02`. `packages/store-pg/test/` therefore builds a harness that injects `PgCommsSession.store` into the same `createCommsService(...)` and drives the same scenarios with uuid fixtures — a **table-driven suite parameterized over both stores** (§6.1 T1), so parity is asserted rather than asserted-about. |
| **D15** | **`@store-pg` never creates an `accounts` row and never mints a `Dealership`.** | Account provisioning is an API/E3 concern; minting a dealership from an unrecognised sender is the exact injection into a globally shared namespace that T-014 D9/D10 and specs/00 "Dealership data tenancy" forbid. Both are the caller's (or the test harness's) responsibility, and an unknown reference surfaces as `23503` rather than being papered over. |

Rules binding on every file, checked by §6.2 (no database required):

1. **Every SQL statement is a string literal with `$n` placeholders.** No interpolation of any value, ever — not an id, not a table name. No ORM, no query builder, no template-built `WHERE`.
2. **`pg` is never imported here.** The only handle is `Queryable` from `@db`. `DATABASE_URL` is never read in this package (T-015 §2.2 rule 4).
3. **Every statement that touches an `ACCOUNT_SCOPED_TABLES` table names `account_id` in its predicate** (D5).
4. **No `DELETE`, no `TRUNCATE`, no `DROP`** anywhere in this package. Not on messages, not on receipt entries, not on holding areas, not in test teardown SQL.
5. **No `UPDATE` against `receipt_entries`.** The role does not hold the verb and the trigger would reject it; the statement must not exist to be reviewed in the first place.
6. **Every exported function returns a value on failure.** No exported entry point throws, with exactly one deliberate exception: the synchronous port methods, which have no error channel — see §4.1.
7. **Constraint names come from `CONSTRAINTS` in `@db`**, never typed as literals (T-016 made them an interface).

### 2.2 The unscoped-operation register

Four repository operations take no `AccountScope`. Each is enumerated here so the omission is a decision a reviewer can weigh, never a gap, and §6.2 asserts the list is exhaustive by comparing it against the repository's own method signatures.

| Operation | Why it cannot be scoped |
|---|---|
| `resolveIdentity` | Inbound routing runs **before** any account is known — a webhook arrives addressed to a number and the store must answer "whose deal is this?". T-016 D12 made active identity bindings globally unique for exactly this reason; the answer *establishes* the scope rather than presupposing it. |
| `hasProcessed` / `markProcessed` | `processed_events` is a platform-wide ledger over opaque consumer keys that arrive before attribution. T-016 §3.9 lists it as deliberately account-free. |
| `listQuarantined` | An unparseable payload is by definition unattributable — there is no account to scope to. Operator surface only. |
| `listUnroutedAll` | The unscoped half of `listUnrouted()`. `no_identity_match` records belong to no account. **This method must never be reachable from an account-scoped API** (T-019/T-020 inherit the rule from `@comms`); the scoped half is `listUnroutedForDeal(scope, deal_id)`. |

### 2.4 `PgCommsSession` — the unit of work that satisfies the unchanged port (D1)

```ts
/** What must be resident before the synchronous port can answer (D2). */
export interface HydrationPlan {
  readonly identities: readonly { phone_number?: string; email_alias?: string }[];
  readonly deal_ids: readonly string[];
  readonly raw_payload_refs: readonly string[];
  readonly processed: readonly { consumer: string; idempotency_key: string }[];
}

/** Pure. Derives the plan from the envelope the consumer is about to handle. */
export function planForEvent(event: SpineEvent): HydrationPlan;
/** Pure. The API/read path: one deal, no identity resolution needed. */
export function planForDeal(deal_id: string): HydrationPlan;

/**
 * A durable outcome that differed from the optimistic in-session verdict.
 * Only ever in the SAFE direction: the session said 'appended'/'first' and the
 * database already held the row. The inverse cannot occur — the working set
 * says 'duplicate' only for rows it read out of the database.
 */
export type SessionDivergence =
  | { kind: 'message_already_durable'; deal_id: string; message_ref: string }
  | { kind: 'thread_already_durable'; deal_id: string; dealership_id: string }
  | { kind: 'processed_already_durable'; consumer: string };

export interface SessionReport {
  readonly statements: number;
  readonly divergences: readonly SessionDivergence[];
}

export interface PgCommsSession {
  /** Pinned at open(); undefined only for an operator session over no deal. */
  readonly scope: AccountScope | undefined;
  /** The UNCHANGED @comms port. Synchronous, reads its own writes. */
  readonly store: CommsStore;
  /** The UNCHANGED @comms port. */
  readonly raw_payloads: RawPayloadStore;
  /** Flushes the journal inside the open transaction, then COMMITs. */
  commit(): Promise<DbResult<SessionReport>>;
  /** ROLLBACK. Idempotent; safe after commit() (then a no-op). */
  rollback(): Promise<void>;
}

export interface PgSessionFactoryDeps {
  handle: DbHandle;
  byte_sink: RawByteSink;          // D12 — T-018's adapter satisfies this structurally
  now?: () => IsoTimestamp;        // injectable clock (test determinism)
  logger?: PgStoreLogger;
}

export interface PgSessionFactory {
  open(plan: HydrationPlan): Promise<DbResult<PgCommsSession>>;
  /**
   * open → run → commit, with rollback on a thrown callback (which is caught
   * and mapped, so this never throws). The shape a consumer wrapper uses.
   */
  withSession<T>(plan: HydrationPlan, fn: (s: PgCommsSession) => T | Promise<T>): Promise<DbResult<{ value: T; report: SessionReport }>>;
}

export function createPgSessionFactory(deps: PgSessionFactoryDeps): PgSessionFactory;
```

**The load-bearing properties, stated so nobody has to infer them:**

- One session = one `DbHandle.transaction` = one consumer invocation or one API request. Reads come from a snapshot taken inside that transaction; writes land inside it; nothing is visible to another process until `commit()`.
- **Read-your-own-writes** inside the session is total — the working set is the same object the port wrote to.
- **Uniqueness is the database's, not the cache's.** Every journalled write flushes as `INSERT … ON CONFLICT DO NOTHING` (or a conditional `UPDATE`), so the durable state is correct regardless of what the optimistic verdict was. A divergence is reported and logged, never swallowed.
- **The safe direction is guaranteed.** A divergence can only mean "we said new, it was already there" — which costs one redundant downstream event on a bus that is at-least-once by construction, and which the extraction worker's ledger plus `attachExtractedOffer`'s fill-once already absorb. The opposite ("we said duplicate, it was actually new") is unreachable: the working set only reports `duplicate` for refs it hydrated out of Postgres.

### 2.7 Errors and logging

```ts
export type PgStoreErrorCode =
  | 'unhydrated'          // D3 — a deal outside the session's plan was named
  | 'scope_mismatch'      // a spine object whose owner_id ≠ the session scope
  | 'unknown_reference'   // 23503 — unknown account, dealership, deal, or thread
  | 'tenancy_violation'   // DC003 / a composite-FK 23503 across accounts
  | 'conflict'            // 23505 on a key the caller was expected to own
  | 'unavailable'         // mapped from DbError.retryable === true
  | 'store_bug';          // append-only / write-once violation reached from here

export interface PgStoreError {
  code: PgStoreErrorCode;
  retryable: boolean;
  /**
   * Log-safe BY CONTRACT — codes, SQLSTATEs, table names, constraint names,
   * column names, deal/dealership/account ids, message_ref. NEVER a message
   * body, an email subject, a phone number, an email address, a VIN, a price,
   * a raw payload, or a connection string.
   */
  message: string;
  cause?: DbError;
}

/** Thrown ONLY from the synchronous port methods, which have no error channel (§4.1). */
export class PgStoreUnhydratedError extends Error {}

export type PgStoreLogEvent = {
  level: 'info' | 'warn' | 'error';
  event: 'session_opened' | 'session_committed' | 'session_rolled_back'
       | 'flush_divergence' | 'tenancy_denied' | 'statement_failed';
  message: string;
  deal_id?: string;
  dealership_id?: string;
  message_ref?: string;
  sqlstate?: string;
  constraint?: string;
  statements?: number;
};
export type PgStoreLogger = (e: PgStoreLogEvent) => void;
```

Nothing is written anywhere unless a logger is supplied — no `console`, no global. Silence is the default so a library cannot leak into a caller's log stream.

## 3. Data shapes — spine ⇄ rows

Conventions inherited from T-016: ids are `uuid`; money is `bigint` **integer cents** (`MoneyCents`, no floats); time is `timestamptz`, rendered as UTC ISO-8601 on read. Mapping lives in `src/mapping.ts` and runs in exactly one direction per function — no bidirectional "sync" helper, because those are where silent field drops live.

### 3.1 The three rules that govern every mapping

1. **`NULL` maps to `undefined`, never to `0`, `''`, or `[]`.** ADR-005: absence is a first-class state. A `sale_price_cents IS NULL` becomes an `Offer` with **no `sale_price` key at all** (`exactOptionalPropertyTypes` is on — build optional fields by conditional spread, never by assigning `undefined`). The flag engine must be able to see UNEVALUABLE, and a zero would read as "free".
2. **Row shapes never escape.** Every read returns a `@core` aggregate. No `pg` type, no `snake_case` row object, no synthesized `id` on an `Offer`, no `account_id` bolted onto a `Deal` (it is projected onto `owner_id`, T-016 D3). AC-9, ADR-001.
3. **Ids are the caller's.** `@store-pg` generates no spine id and validates none. A non-uuid id (`'deal-a'`) surfaces as `22P02` → `check_violation`, i.e. a loud caller error, never a silent miss. The `@store-pg` test fixtures therefore use uuids (D14).

### 3.2 Aggregate assembly — `loadDealAggregate`

One query per level, five round trips, assembled in memory (a single wide join would multiply message rows by fee rows and make ordering a guessing game):

| # | Statement | Notes |
|---|---|---|
| 1 | `SELECT … FROM deals WHERE account_id = $1 AND id = $2` | 0 rows ⇒ `undefined` — identical for absent and foreign (D6) |
| 2 | `SELECT … FROM dealer_threads t LEFT JOIN vehicle_instances vi ON … LEFT JOIN dealership_contacts c ON … WHERE t.account_id = $1 AND t.deal_id = $2 ORDER BY t.created_at, t.id` | thread + its instance + `working_with` in one pass; `LEFT JOIN` because both are legitimately absent |
| 3 | `SELECT … FROM messages WHERE account_id = $1 AND deal_id = $2 ORDER BY occurred_at, id` | builds `messages[]`, `messages_by_ref`, `thread_by_ref` |
| 4 | `SELECT … FROM offers o LEFT JOIN offer_fees f … LEFT JOIN offer_flags fl … WHERE o.account_id = $1 AND o.deal_id = $2 ORDER BY f.idx` | one pass for deal-level (`thread_id IS NULL`), thread-current, and per-message extracted offers; distributed by pointer (D8) |
| 5 | `SELECT point_kind, point_value, dealership_id FROM thread_contact_points WHERE account_id = $1 AND deal_id = $2` | the account-private contact index |

`Deal.dealer_threads[]` is thread order by `created_at`; `DealerThread.messages[]` is `occurred_at` ascending, ties broken by row id — the same total order the in-memory store produces by push order for any single-writer sequence.

### 3.3 Field maps that carry meaning

| Spine | Row | Rule |
|---|---|---|
| `Deal.owner_id` | `deals.account_id` | One column (T-016 D3). `upsertDeal` **rejects** `deal.owner_id !== scope.account_id` with `scope_mismatch` before issuing SQL — the cheapest possible place to catch a cross-account write. |
| `Deal.budget` / `walk_away_number` | `budget_cents` / `walk_away_cents` | `walk_away_number` is the **budget ceiling** (specs/00 "Budget ceiling vs. fair price"; Q20), compared to nothing in SQL. |
| `Deal.target_vehicle` | `target_make`, `target_model`, `target_year_from/to` | Embedded, by arity (T-016 D1). `year_range` maps both-or-neither. An `UPDATE` that changes make/model after lock raises `DC002`; §4.4 says what surfaces. |
| `Deal.offers[]` | `offers WHERE thread_id IS NULL` | D8. |
| `DealerThread` (no `id` in the spine) | `dealer_threads.id`, keyed by `UNIQUE (deal_id, dealership_id)` | The natural key **is** the port's key, which is why `resolveOrCreateThread` is idempotent for free (`CONSTRAINTS.thread_per_dealership`). |
| `DealerThread.current_offer` | `offers` row pointed at by `dealer_threads.current_offer_id` | One row per thread, updated in place (D8). |
| `DealerThread.vehicle_instance` | `vehicle_instances` (`UNIQUE (thread_id)`) | Absent instance = **no row**. No make/model column exists — a thread cannot contradict the deal anchor. |
| `DealerThread.working_with` | `dealership_contacts` via `(account_id, working_with_contact_id)` | D9. NULL is legal and normal (MATCH SIMPLE); a foreign account's contact is `23503`. |
| `Message.call_meta` | `call_started_at`, `call_duration_seconds`, `call_party` | Present iff `channel = 'call'` (CHECK). **There is no `recording_url`, `transcript`, or audio column to map** — the fields were removed from the spine, not nulled (Q14, specs/01 consent posture). |
| `Message.timestamp` | `messages.occurred_at` | The rollup's ordering source. Distinct from `created_at` (when we stored it). |
| `StoredMessage.message_ref` | `messages.message_ref` | Store-internal correlation, **not a spine field**. `UNIQUE (deal_id, message_ref)` = `CONSTRAINTS.message_dedupe`. |
| `StoredMessage.origin` | `origin_kind`, `origin_source` | `CHECK ((origin_kind = 'provider') = (origin_source IS NOT NULL))` — a fabricated in-app provider id is unrepresentable. |
| `Message.extracted_offer` | `messages.extracted_offer_id` → `offers` | Fill-once. `UPDATE … WHERE extracted_offer_id IS NULL` returning row count; 0 rows with the message present ⇒ `'already_set'`. |
| `Offer.fees[]` | `offer_fees (offer_id, idx, name, amount_cents)` | `idx` preserves order. Sign unconstrained — a negative line is a discount. |
| `Offer.flags[]` | `offer_flags (offer_id, flag)` | Set semantics via PK. `@store-pg` **stores** flags; it never computes one and holds no valuation input (that is `@flag-engine`). |
| `RollupState` | `dealer_threads.rollup_state jsonb` | `@comms` shape, verbatim (D7). |
| `IdentityRef` | `deal_identities` (normalized values, `bound_at`, `released_at`) | Stored already normalized; resolution is equality, never fuzzy (AC-7). |
| `QuarantinedRecord.parse_error` | `parse_error_code`, `parse_error_message` | `AdapterError` flattened to two columns; the payload is a **ref** (`raw_payload_ref`), never bytes. |
| `UnroutedRecord.inbound` | `unrouted_inbound.inbound jsonb` | Held **whole** and replayable. `account_id`/`deal_id` present exactly when the deal is known. |

### 3.4 The working set (in-session)

The session's engine mirrors the in-memory store's records exactly — thread records keyed by `dealership_id`, a `refIndex`, an account-private `contactIndex`, a `RollupState` per thread — plus two additions that only a durable backend needs:

- a **hydration set** of deal ids; a call naming anything else raises `PgStoreUnhydratedError` (D3);
- a **journal**: an ordered list of intents (`upsert_deal`, `upsert_thread`, `ensure_thread`, `bind_identity`, `bind_contact`, `insert_message`, `set_extracted_offer`, `write_current_offer`, `record_quarantined`, `record_unrouted`, `mark_processed`, `put_object`). The flush replays them **in journal order** so foreign keys are satisfied without a topological sort, and collapses repeated `write_current_offer` for one thread to its last value (the merge is already commutative and idempotent — ADR-006 — so the last value is the whole answer).

## 4. Error paths per operation

House rule: **failure is a value.** Every async entry point returns `DbResult`/`ReceiptResult`. The one exception is deliberate and bounded, and §4.1 is entirely about it.

### 4.1 The synchronous port has no error channel — what that forces

`CommsStore.appendMessage` returns `'appended' | 'duplicate'`; there is no third value for "the database was unreachable". The in-memory store already throws in the one comparable case (`mustDeal` → `throw new Error('unknown deal_id')`) and T-014 documented the consumer's response: the throw becomes a `retry` verdict, bounded attempts, then dead-letter **with the envelope intact**. This design keeps exactly that contract and adds nothing to it:

| Situation on a synchronous port call | Behaviour | Why it is safe |
|---|---|---|
| Deal not in the hydration set (D3) | `PgStoreUnhydratedError` (subclass of `Error`) | Consumer → `retry` → dead-letter. The message is **held**, never dropped. A distinct class means the log says "hydration bug", not "unknown deal". |
| Deal genuinely unknown | `throw new Error('unknown deal_id')` — byte-identical to the in-memory store | Behavioural parity (AC-10). |
| Postgres unreachable | **Cannot happen during a port call.** Connectivity is proved at `open()`, which is async and returns a `DbResult`; the port calls touch memory only. | This is the structural payoff of D1: the failure moves to a place that has an error channel. |
| Flush fails at `commit()` | `DbResult` `{ ok: false }`; the transaction rolls back **whole** | Nothing partial lands. The consumer retries the event; every write is keyed, so the replay is idempotent. |

### 4.2 `open(plan)`

| Failure | Retry / idempotency | Logged | Surfaces as |
|---|---|---|---|
| `BEGIN` fails / pool exhausted / host unreachable | Retryable at the caller; `@store-pg` implements **no retry loop** (T-016 §4.7 — a hidden retry re-executes a non-idempotent write) | `statement_failed`, SQLSTATE only | `DbResult` with `DbError.retryable` passed through unchanged |
| Identity resolves to nothing | Not a failure | nothing | `ok: true` with `scope: undefined`; the handler's `resolveDealByIdentity` returns `undefined` → `recordUnrouted('no_identity_match')` |
| A planned `deal_id` is absent **or belongs to another account** | Not a failure, not distinguishable (D6) | nothing | The deal is simply not in the hydration set; a later port call naming it raises `PgStoreUnhydratedError` → held, never silently mis-answered |
| Hydration query fails mid-plan | Transaction rolled back; nothing was written | `statement_failed` | mapped `DbError` |

### 4.3 `commit()` — the flush

| Failure | SQLSTATE → outcome | Retryable | What surfaces |
|---|---|---|---|
| Message ref already durable | `23505` avoided by `ON CONFLICT (deal_id, message_ref) DO NOTHING`, `row_count = 0` | — | Recorded as a `SessionDivergence`, logged `flush_divergence` at `warn`. **Expected traffic** under at-least-once redelivery, not an incident. |
| `(consumer, idempotency_key)` already durable | `ON CONFLICT (consumer, idempotency_key) DO NOTHING` | — | `SessionDivergence`. The belt was stale; the braces held. |
| Thread already durable | `ON CONFLICT ON CONSTRAINT dealer_threads_deal_dealership_uk DO NOTHING` | — | `SessionDivergence`. A second message **never** resets `process_step`, `working_with`, or `vehicle_instance` — the `DO NOTHING` is what guarantees it. |
| Unknown `account_id` / `dealership_id` / `deal_id` | `23503` → `unknown_reference` | no | Caller/seeding bug (D15). Whole transaction rolls back; consumer retries then dead-letters with the envelope intact. **Never** resolved by minting the missing row. |
| **Cross-account reference** | `23503` on `dealer_threads_contact_fk`, or `DC003` on `deal_identities` | no | `tenancy_violation`. Logged `tenancy_denied` at `error` with ids and constraint name, **never with the foreign value**. Surfaces to T-019/T-020 as not-found/forbidden — never as an echo. |
| Target make/model changed after lock | `DC002` → `store_bug` | no | This port cannot mutate `target_vehicle` (the "never on this port" list in `@comms`), so reaching it means a caller bug. T-020 owns the UX; the rejection is recorded as a **receipt event in its own statement**, never inside the aborted transaction. |
| `UPDATE`/`DELETE` on `receipt_entries` | `42501` (grant) or `DC001` (trigger) → `store_bug` | no | Unreachable by construction — no such statement exists in this package (§1.1 rule 5). If it ever fires, it is a review failure, logged `error`, never "fixed up" with a compensating row. |
| Serialization failure / deadlock | `40001` / `40P01` | **yes** | Rolled back whole; the caller replays the event. Safe precisely because every write that must not double-apply is protected by a unique key rather than by luck. |
| `statement_timeout` | `57014` | **no** | Re-running a query that already blew its budget reproduces the cost. Operator alert. |
| `COMMIT` itself fails | mapped `DbError` | per code | The client is destroyed rather than returned to the pool (`@db` §4.4). The session is finished; `rollback()` afterwards is a no-op. |

The client is **always** released — `finally`, no exceptions. A leaked client is a pool that dies slowly and presents as a mysterious timeout ten minutes later.

### 4.4 Per-operation posture, in one table

| Port operation | Durable statement | Idempotency source | Failure surfaces as |
|---|---|---|---|
| `putDeal` | `INSERT … ON CONFLICT (id) DO UPDATE SET` mutable columns (D10) | primary key | `scope_mismatch` pre-flight; `23503` for an unknown account |
| `putThread` | thread upsert + contact find-or-create (D9) + instance upsert | `UNIQUE (deal_id, dealership_id)`, `UNIQUE (thread_id)` | `23503` for an unknown dealership |
| `bindIdentity` | `INSERT … ON CONFLICT DO NOTHING` on the active partial indexes | `deal_identities_*_active_uidx` | `23505` ⇒ the value is live on another deal (Q9 — "a dealer reaches a stranger" is unrepresentable); `DC003` ⇒ another account held it before release |
| `bindThreadContact` | `INSERT … ON CONFLICT (deal_id, point_kind, point_value) DO UPDATE SET dealership_id` | deal-leading PK | **see E1 (§8.1)** |
| `resolveDealByIdentity` | `SELECT … WHERE phone_number = $1 AND released_at IS NULL` | pure read | `undefined` — exact match only, never fuzzy (AC-7) |
| `resolveDealershipByContact` | in-session lookup over the hydrated, deal-scoped index | pure read | `undefined` ⇒ unrouted (never a guess, never a new `Dealership`) |
| `resolveOrCreateThread` | `INSERT … ON CONFLICT DO NOTHING` then `SELECT` | `thread_per_dealership` | `23503` unknown dealership |
| `appendMessage` | `INSERT … ON CONFLICT (deal_id, message_ref) DO NOTHING` | `message_dedupe` | `'duplicate'` on `row_count = 0` — the keyed write that makes redelivery safe (specs/00: "Provider timeouts must never drop a dealer message") |
| `attachExtractedOffer` | insert offer, then `UPDATE messages SET extracted_offer_id = $ WHERE … AND extracted_offer_id IS NULL` | conditional predicate | `'already_set'` when the message exists and 0 rows update; `'not_found'` when the ref is unknown |
| `rollupCurrentOffer` | `mergeCurrentOffer` (imported, D7) → upsert the thread's single offer row + `rollup_state` | merge is commutative/associative/idempotent (ADR-006) | replay of a contribution is an exact no-op |
| `recordQuarantined` | guarded insert on `(source, raw_payload_ref)` (D13) | guard | duplicate held record possible under race — never a loss |
| `recordUnrouted` | guarded insert / conditional update on `(source, inbound->>'provider_message_ref')` (D13) | guard | same; `reason`/`deal_id` improve on replay, `recorded_at` keeps the **first** hold time |
| `hasProcessed` / `markProcessed` | hydrated read / `INSERT … ON CONFLICT DO NOTHING` | `processed_events_pkey` | belt is advisory, braces are authoritative (§2.4) |
| `ReceiptStore.append` | `INSERT` only; `seq`/`appended_at`/`channel` DB-assigned | `receipt_dedupe` partial index | `23505` ⇒ `AppendOutcome.deduplicated = true`, first-write-wins. A blank `dedupe_key` **appends normally** (T-016 D8) — a rejected append is a lost receipt entry, which is the one outcome the trail may not have |
| `ReceiptStore.read` | `SELECT … WHERE account_id = $1 AND receipt_bundle_id = $2 ORDER BY occurred_at, seq` | pure read | empty list for absent **and** foreign (D6) |
| `RawPayloadStore.stash` | ref computed synchronously; `object_refs` row + byte `put` journalled | content-addressed ref | flush failure rolls the whole session back |

### 4.5 What is logged

Only when a logger is supplied: `session_opened`, `session_committed`, `session_rolled_back`, `flush_divergence`, `tenancy_denied`, `statement_failed`.

**Never logged, at any level:** bound parameters, row values, message bodies, email subjects, `call_party`, phone numbers, email addresses, VINs, prices, raw payloads, or the connection string. This is not politeness — the receipt trail is evidence, and a log that mirrors it is an uncontrolled second copy of the very PII the tenancy split exists to contain.

## 5. Invariant touchpoints

| # | Invariant | Source | How this design protects it |
|---|---|---|---|
| 5.1 | **Ports are swap seams; swapping is wiring, not redesign** | specs/00 "Store"; AC-1 | Not one signature changes. `PgCommsSession.store` is typed `CommsStore` and is accepted by `createCommsService` without a cast — §6.1 T2 is that compile-level proof. No parallel store interface is introduced: `CommsRepository` sits **below** the port, it does not replace it (D4). |
| 5.2 | **Every repository call is account-scoped** | specs/01 "Account model"; specs/00 tenancy; AC-2 | `AccountScope` is a required first argument on every `CommsRepository` method except the four enumerated in §2.2, and §6.2 asserts that register is exhaustive against the actual signatures. The session pins one scope at `open()` and cannot widen it. E3 attaches there. |
| 5.3 | **Dealerships global, contacts account-private** | specs/00 "Dealership data tenancy"; Q12 AMENDED; AC-3 | This package **never writes `dealerships`** (D15) and never mints one from an unrecognised sender. Contact reads carry `account_id` in the predicate (D5) on top of the composite FK; the contact index is hydrated per deal, so a cross-account contact lookup is not expressible even in memory. |
| 5.4 | **Cross-account access returns nothing and mutates nothing** | specs/00 tenancy ("never exposed to another account"); AC-11 | Reads: `undefined`/empty, observably identical to absent (D6). Writes: `23503`/`DC003`, whole transaction rolled back, logged with ids and constraint names but never the foreign value. §6.1 T7 asserts both halves. |
| 5.5 | **Receipt entries are append-only** | specs/00 "Receipt layer"; AC-4 | `PgReceiptStore` exposes `append` + `read` and nothing else, because `ReceiptStore` has nothing else — the surface is inherited, not re-declared. No `UPDATE`/`DELETE` statement against `receipt_entries` exists in this package (§1.1 rule 5), and the database rejects one independently of that discipline via grant and trigger (T-016 D4). §6.1 T9 proves the DB layer holds when the code layer is bypassed. |
| 5.6 | **`current_offer` is per-field newest-message-wins** | ADR-006; AC-5 | `mergeCurrentOffer` is imported from `@comms` and called with the persisted `RollupState`; the result and the new state are written back (D7). No merge logic exists in this package and none in SQL. Because the merge is commutative and idempotent, out-of-order and redelivered contributions converge — which is what makes an unordered bus safe. |
| 5.7 | **A dealer message is never dropped** | specs/00 "Comms aggregation layer"; AC-6 | Four layers: `ON CONFLICT (deal_id, message_ref) DO NOTHING` (keyed append), `processed_events` PK (consumer ledger), the no-drop holding areas, and — the reason D1 matters — connectivity failures land at `open()`/`commit()`, which have error channels, instead of inside a port call that can only throw. Every failure direction is "held and retried", never "acknowledged and lost". |
| 5.8 | **Identity resolution is exact and provider-agnostic** | specs/00 ("`identity_ref` is deliberately provider-agnostic"); AC-7 | Equality over values normalized identically at bind and at resolve; no `LIKE`, no `similarity`, no trigram, no fallback. No provider name appears in any column, statement, or type in this package. D11's parity suite is what keeps "identically" true across two implementations. |
| 5.9 | **Bytes live in the object store** | specs/00 "Store"; AC-8 | `RawPayloadStore` persists a ref and delegates bytes to `RawByteSink` (D12). No `bytea` column exists to write to (T-016), and this package contains no base64, no `Buffer` column binding, and no attachment body path. |
| 5.10 | **No audio, no recording, no transcript** | specs/01 consent posture; Q14 | There is no column, no mapping, and no field to carry one. `object_refs` additionally rejects `audio/%` content types, so the byte sink cannot be used as a back door. |
| 5.11 | **Reads return spine aggregates, never driver rows** | specs/00 "Core domain model"; ADR-001; AC-9 | §3 maps in exactly one direction per function; no row interface is exported; `pg` is not imported in this package at all. An `Offer` comes back with no `id` and a `Deal` with no `account_id`. |
| 5.12 | **`sale_price` absent ⇒ UNEVALUABLE, never zero** | ADR-005 | §3.1 rule 1. `NULL` → key absent (conditional spread under `exactOptionalPropertyTypes`), for `sale_price`, `apr`, `term_months`, `monthly`, and every valuation band. §6.1 T6 round-trips an offer with no price and asserts the key is **absent**, not zero and not `undefined`-valued. |
| 5.13 | **`payment_packing` canonical; `above_market` exists** | ADR-002; ADR-007 | Flags are read and written as the `offer_flag` enum; a label outside `OFFER_FLAGS` cannot enter the type or the column. This package never computes a flag and holds no valuation input — `above_market` is `@flag-engine`'s comparison of the offer against that `VehicleInstance`'s own RETAIL band, and no SQL here approaches it. |
| 5.14 | **Fair price is per-instance; budget ceiling is per-deal** | specs/00 "Budget ceiling vs. fair price"; Q20 | Nothing here computes either. `walk_away_cents` is carried, never compared; valuation reads (a later task) key on `vehicle_instance_id` because that is the only shape the schema offers. A thread with no snapshot has no row, so "unevaluable" survives the round trip. |
| 5.15 | **One deal, one make/model; write-once after lock** | specs/00 "Cardinality invariants"; Q11 AMENDED | The comms port cannot mutate `target_vehicle` at all (the "never on this port" list). `upsertDeal`'s `DO UPDATE SET` list **excludes** `target_make`/`target_model`, so this package cannot trip `DC002` through its own seeding path; §6.1 T10 asserts that exclusion. |
| 5.16 | **Nothing is ever deleted** | specs/01 number lifecycle ("archived (never deleted)") | §1.1 rule 4: no `DELETE`, `TRUNCATE`, or `DROP` in source **or test teardown**. Test isolation is per-run schemas dropped by the harness's own migration path, never by deleting rows from a shared one. D10 is the same rule applied to upserts. |
| 5.17 | **No unapproved integration or spend** | CLAUDE.md invariant 2 | Zero new dependencies (§1.2), zero test-container libraries, no ORM, no query builder, no cloud client. No external service is contacted; KBB/Manheim/Carfax/AutoCheck appear nowhere in this package, not even as a string. The byte sink is a local interface, not an SDK. |
| 5.18 | **Spine defined once, imported everywhere** | ADR-001 | §2's import preamble. This package declares infrastructure types only. The one place a temptation exists — a "row type that happens to match `Message`" — is closed by keeping row shapes local to `src/sql/*` and unexported. |
| 5.19 | **No silent interpretive drift** | CLAUDE.md invariant 3 | D1–D15 log every call; §8 escalates the three that are not mine to make rather than routing around them. The largest — the synchronous port — is solved *inside* the seam and the alternative is recommended, not taken unilaterally. |

## 8. Blockers / deviations

**Blocked on E1.** One escalation must be resolved by another task's owner; four notes are resolved inside this design.

### 8.1 E1 — BLOCKER: `thread_contact_points` cannot be written before a thread exists

`bindThreadContact(deal_id, dealership_id, contact)` is called **before any thread exists** — that is its whole purpose, and the shipped harness does exactly this (`seedDeal` calls `putDeal` then `bindThreadContact`, and nine assertion sites across `intake.test.ts`, `pipeline.test.ts`, and `routing.test.ts` then require `getDeal(...).dealer_threads` to have length **0**). But migration `0007` gives the table:

```sql
CONSTRAINT thread_contact_points_thread_fk
  FOREIGN KEY (account_id, deal_id, dealership_id)
  REFERENCES dealer_threads (account_id, deal_id, dealership_id)
```

so the insert raises `23503`. The three ways to route around it are all worse than escalating:

- **create the thread row on bind** — breaks all nine `toHaveLength(0)` assertions outright, so AC-10 fails by construction;
- **hold the binding only in the session** — it never becomes durable, so the first inbound message from that dealer goes unrouted *forever*, in a way no operator could diagnose;
- **edit the migration** — `packages/db/migrations/**` is T-016's, and CLAUDE.md is explicit that a file I do not own is not mine to fix.

**Requested resolution (additive, one file, T-016-owned):** a migration `0015` that re-points the FK to the deal and the global dealership rather than to the thread —

```sql
ALTER TABLE thread_contact_points DROP CONSTRAINT thread_contact_points_thread_fk;
ALTER TABLE thread_contact_points ADD CONSTRAINT thread_contact_points_deal_fk
  FOREIGN KEY (account_id, deal_id) REFERENCES deals (account_id, id) ON DELETE RESTRICT;
ALTER TABLE thread_contact_points ADD CONSTRAINT thread_contact_points_dealership_fk
  FOREIGN KEY (dealership_id) REFERENCES dealerships (id) ON DELETE RESTRICT;
```

The deal-leading primary key is untouched, so the tenancy property T-016 §3.8 claims for this table — *a contact lookup that is not scoped to one deal is inexpressible at the index level* — is preserved exactly. What changes is only the modelling error: a contact point records that **this account, in this deal, believes this number belongs to that dealership**, which is knowledge the account has before any message arrives and therefore before any thread exists. Everything else in this design is buildable while this is pending; only T1 and the parts of T3 that seed via `bindThreadContact` are gated on it.

### 8.2 The synchronous port was solved, not changed — and the alternative is recommended (D1)

`CommsStore` and `RawPayloadStore` return plain values; `pg` is async. AC-1 and the task Notes forbid touching the signatures, so this design absorbs the mismatch in a transaction-scoped unit of work (§2.4) rather than in the port. That is a real solution with stated limits, not a workaround — but it is worth the lead's attention that `@receipt`'s store, designed in the same epic for the same durable future, is already `Promise`-returning and needs none of this machinery. **Recommendation (T-014 re-scope, not an edit here):** widen the `CommsStore`/`RawPayloadStore` returns to `Promise<…>`. Every call site is already inside an `async` function, so the change is mechanical, and it would delete `session.ts`, `working-set.ts`, `journal.ts`, and `plan.ts` — roughly a third of this package — along with every divergence and hydration concept in §2.4 and §4.1. Not doing it is survivable; doing it is strictly simpler. The decision is the lead's.

### 8.3 The holding areas have no dedupe constraint (D13)

The in-memory store dedupes quarantine on `(source, raw_payload_ref)` and unrouted on `(source, provider_message_ref)`; neither table shipped with a matching unique index. Guarded inserts reproduce the behaviour, and the residual race can only produce a **duplicate held record**, never a loss — the correct direction for a no-drop area. **Recommended additive migration (T-016-owned):** `UNIQUE (source, raw_payload_ref)` on `quarantined_payloads` and `CREATE UNIQUE INDEX … ON unrouted_inbound (source, (inbound->>'provider_message_ref'))`. Not blocking.

### 8.4 Normalization is duplicated, and proved equal rather than shared (D11)

`normalizePhone`/`normalizeEmail` are private to `services/comms/src/store/in-memory-store.ts`. Exporting them is a `@comms` edit outside this task. The divergence risk is closed by the parity suite (T3). **Recommendation:** add both to the `@comms` barrel in a later `services/comms` task and delete the copy here.

### 8.5 `DealershipContact` has no spine id, so the store must choose a natural key (D9)

Found-or-created on `(account_id, dealership_id, lower(name), role)`. Two genuinely distinct people sharing a name and role at one dealership inside one account collapse to one row. Inventing an id field would be a spine change; a natural-key unique index would turn the `SELECT`-then-`INSERT` into an `ON CONFLICT` and remove a race that can currently create a duplicate contact row under concurrency. Both are other tasks' calls; recorded so the gap is a decision rather than an oversight.
