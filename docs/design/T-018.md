## 2. Exposed interface signatures

Everything below is exported from `packages/object-store/src/index.ts` and nothing else is. `@core` supplies every domain-shaped and result-shaped type; **no spine type is redefined, widened, or mirrored** (ADR-001, AC-8).

### 2.1 Result and error vocabulary (imported, aliased, never redefined)

```ts
import type { AdapterError, AdapterErrorCode, AdapterResult, IsoTimestamp } from '@core';

/** Readability alias over @core's uniform adapter result (D1). NOT a new type. */
export type ObjectStoreResult<T> = AdapterResult<T>;
```

Operations **never throw across the boundary**; every failure is a value, exactly as `packages/core/src/adapters.ts` fixes for every adapter.

### 2.2 Artifact classes — the closed set, with no audio member

```ts
/**
 * The three artifact classes specs/00 "Store" assigns to the object store:
 * "email attachments, uploaded documents, and generated dossiers".
 *
 * There is no 'recording' / 'audio' / 'call' member and there will not be one:
 * specs/00 "No audio is stored"; specs/01 "no audio is ever captured or
 * stored". `put({ kind: 'recording', … })` is a COMPILE ERROR, not a runtime
 * rejection — the same construction @core used when it deleted
 * `Message.recording_url` rather than leaving it nullable.
 */
export type ArtifactKind = 'email_attachment' | 'document' | 'dossier';
```

### 2.3 References and locations

```ts
/**
 * A stable, bucket-free storage key. Postgres columns hold this verbatim as
 * TEXT (AC-5) — the relational core holds references, the object store holds
 * bytes. Bucket-free ON PURPOSE: moving buckets must not invalidate every
 * stored row.
 *
 * Shape: `acct/{account_id}/{deal_id}/{kind}/{content_sha256}`
 */
export type ObjectRef = string;

export interface ArtifactLocation {
  /** The owning account (specs/01 "Account owns Deals"). Supplied by the
   *  authenticated caller — NEVER derived, defaulted, or inferred here. */
  account_id: string;
  deal_id: string;
  kind: ArtifactKind;
  /** Lowercase sha-256 hex of the bytes. The object's whole identity (D4). */
  content_sha256: string;
}

export function buildArtifactRef(loc: ArtifactLocation): ObjectStoreResult<ObjectRef>;
export function parseArtifactRef(ref: ObjectRef): ArtifactLocation | undefined;
/** Pure, allocation-cheap, and evaluated BEFORE any network call (§4.3). */
export function isRefOwnedBy(account_id: string, ref: ObjectRef): boolean;
export function sha256Hex(bytes: Uint8Array): string;
```

### 2.4 The one internal interface (AC-1)

```ts
export interface ObjectStore {
  /** Adapter id for logs and AdapterError.source, e.g. "s3-object-store". */
  readonly source: string;

  put(req: PutArtifactRequest): Promise<ObjectStoreResult<PutResult>>;

  /** account_id is FIRST and MANDATORY on every read (AC-4). */
  get(account_id: string, ref: ObjectRef): Promise<ObjectStoreResult<StoredArtifact>>;
  head(account_id: string, ref: ObjectRef): Promise<ObjectStoreResult<ObjectMetadata>>;
  list(account_id: string, filter?: ListFilter): Promise<ObjectStoreResult<ListPage>>;
}
```

Four methods. **No `delete`, no `copy`, no `move`, no `putAtKey`, no `getSignedUrl`, no audio-anything** (D8, D9). The forbidden operations are absent rather than guarded, which is the difference between a rule and a hope.

`account_id` is the first parameter of all three reads, so *an unscoped read is inexpressible* — the same construction T-014 used to make an unscoped contact lookup impossible.

### 2.5 Factories and configuration

```ts
export interface ObjectStoreConfig {
  bucket: string;
  region: string;
  /** S3-compatible endpoint (MinIO or equivalent). Present ⇒ path-style
   *  addressing (D12). Absent ⇒ AWS default endpoint resolution. */
  endpoint?: string;
  /** Sent only when set. Default: unset — bucket-default encryption is a
   *  deployment concern, and a hard-coded SSE header breaks some
   *  S3-compatible backends. */
  server_side_encryption?: 'AES256' | 'aws:kms';
  /** Send ChecksumSHA256 on PUT so the server verifies integrity too.
   *  Default true; disable only for a backend that rejects the parameter. */
  checksums?: boolean;
  /** SDK retry attempts. Default 3. We add NO second retry layer (§4.2). */
  max_attempts?: number;
  /** Per-object byte cap. Default 25 MiB. */
  max_bytes?: number;
  clock?: () => IsoTimestamp;
  /** Structured, log-safe sink. Default: no-op. No logger dependency (§5). */
  log?: (event: ObjectStoreLogEvent) => void;
}

/**
 * `undefined`  ⇒ NOT configured. The caller composes the in-memory store
 *                 (ADR-008: default to in-memory, never fall back to it).
 * `{ ok:false }` ⇒ PARTIALLY configured — a real misconfiguration. The caller
 *                 FAILS FAST at startup (T-015 §4.4); it must not silently
 *                 degrade to a volatile store.
 */
export function readObjectStoreConfig(
  env: Readonly<Record<string, string | undefined>>,
): ObjectStoreResult<ObjectStoreConfig> | undefined;

export function createS3ObjectStore(config: ObjectStoreConfig): ObjectStore;

/** In-process fake. Same keys, same policy, same errors — no network, no
 *  credentials, no bucket. This is what the API composes when unconfigured
 *  and what every invariant test runs against. */
export function createInMemoryObjectStore(
  options?: { max_bytes?: number; clock?: () => IsoTimestamp },
): ObjectStore & { readonly size: () => number };
```

**No credential field exists on `ObjectStoreConfig`.** Credentials come from the AWS SDK's standard provider chain (`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / profile / instance role). A key or secret is never a parameter, never logged, never written to this repo — credential absence is the constitution's structural enforcement (CLAUDE.md "Approved integrations"; T-015 §3.5).

### 2.6 The `RawPayloadStore` seam (ADR-009; D5)

```ts
import type { RawPayloadStore } from '@comms';   // type-only — the T-014 port
import { canonicalJson } from '@comms';          // value — imported, never copied

export interface S3RawPayloadStore extends RawPayloadStore {
  /** Awaits every pending durable write. Call on graceful shutdown and in tests. */
  flush(): Promise<void>;
  /** The REAL operator replay path — `get()` cannot await (D5). */
  fetch(ref: string): Promise<ObjectStoreResult<unknown>>;
  /** Observability for the write-behind window (§4.7). */
  pendingCount(): number;
  failedRefs(): readonly string[];
}

export function createS3RawPayloadStore(
  config: ObjectStoreConfig,
  options?: { max_write_attempts?: number; backlog_warn_at?: number },
): S3RawPayloadStore;
```

`stash()` returns `sha256Hex(canonicalJson(payload))` — **bit-identical to `InMemoryRawPayloadStore`'s ref**, so the quarantine idempotency key `source + ':quarantine:' + ref` dedupes the same way before and after a store swap. That equality is asserted by test against the `@comms` implementation.

**T-018 does not ship an in-memory `RawPayloadStore`.** `@comms` already exports `InMemoryRawPayloadStore`; a second one would be the duplicate definition ADR-001 forbids.

### 2.7 Composition (illustrative — owned by T-019/T-020, fixed here)

```ts
import { createCommsService, InMemoryRawPayloadStore } from '@comms';
import type { RawPayloadStore } from '@comms';
import {
  createInMemoryObjectStore, createS3ObjectStore, createS3RawPayloadStore,
  readObjectStoreConfig, type ObjectStore,
} from '@object-store';

const cfg = readObjectStoreConfig(process.env);
if (cfg && !cfg.ok) throw new Error(`object store misconfigured: ${cfg.error.message}`); // fail fast

const raw: RawPayloadStore = cfg ? createS3RawPayloadStore(cfg.value) : new InMemoryRawPayloadStore();
```

The load-bearing property, same as T-015 §2.3: **both handles are annotated with the port type.** Swapping S3 in is an assignment, not a redesign.

## 3. Data shapes

### 3.1 Key convention (exact)

```
acct/{account_id}/{deal_id}/{kind}/{content_sha256}      ← account-scoped artifacts
ops/raw-payload/{sha256_of_canonical_json}               ← operator-only, no account (D3)
```

Rules, each mechanically checked in `keys.ts`:

1. `account_id` and `deal_id` must match `^[A-Za-z0-9_-]{1,64}$`. Anything else — a slash, a dot segment, a percent-escape, whitespace, empty string — is `invalid_input` **before** any key is built. This is the path-traversal guard: without it an `account_id` of `../other` would escape its own prefix and defeat the entire tenancy design.
2. `kind` is one of the three `ArtifactKind` literals. No other segment value can appear there.
3. `content_sha256` must match `^[0-9a-f]{64}$`.
4. The account prefix is the **first** segment group, so `acct/{account_id}/` is a valid `ListObjectsV2` prefix and an account-scoped list cannot see another account's keys — the isolation is enforced by the request, not by post-filtering.
5. The ordering account → deal → kind → hash makes `deal_id` and `kind` prefix-filterable in that order (§3.5).
6. **No filename ever appears in a key.** User-supplied names are display metadata only (§3.3).

### 3.2 Request / response shapes

```ts
export interface PutArtifactRequest {
  account_id: string;
  deal_id: string;
  kind: ArtifactKind;
  /** Must be on this kind's allowlist (§3.4). Never sniffed-and-corrected —
   *  a wrong label is a rejection, not something we quietly fix. */
  content_type: string;
  bytes: Uint8Array;
  /** Display name. Sanitized, capped at 255 chars, header-safe encoded.
   *  NEVER part of the key, never interpreted, never used to open anything. */
  filename?: string;
  /** Provenance the caller already holds; stored verbatim, never interpreted:
   *    email_attachment → the StoredMessage.message_ref it arrived on
   *    dossier          → the Deal's receipt_bundle_id

  origin_ref?: string;
}

export type PutOutcome = 'stored' | 'already_present';

  ref: ObjectRef;
  outcome: PutOutcome;
  metadata: ObjectMetadata;
}

export interface ObjectMetadata {

  account_id: string;
  deal_id: string;
  kind: ArtifactKind;
  content_type: string;
  byte_length: number;
  content_sha256: string;

```

`tsconfig.base.json` sets `exactOptionalPropertyTypes: true`: an absent optional is **omitted**, never set to `undefined`. Builder note — construct these with conditional spreads, exactly as `packages/receipt/src/dossier.ts` already does.

### 3.3 S3 object metadata written on PUT

| Header | Value | Note |
|---|---|---|
| `Content-Type` | the validated `content_type` | from the allowlist only |
| `Content-Length` | `bytes.byteLength` | |
| `ChecksumSHA256` | base64 of the same digest whose hex is in the key | when `checksums !== false`; the server verifies too |
| `x-amz-meta-kind` | `ArtifactKind` | redundant with the key, and deliberately so — a key-parse bug cannot silently reclassify an object |
| `x-amz-meta-account-id` | `account_id` | cross-checked against the key on read |
| `x-amz-meta-deal-id` | `deal_id` | |
| `x-amz-meta-sha256` | hex digest | |
| `x-amz-meta-filename` | sanitized display name | omitted when absent |
| `x-amz-meta-origin-ref` | caller provenance | omitted when absent |
| `ServerSideEncryption` | from config | **omitted unless configured** |

**No user-supplied header passes through.** Metadata values are ASCII-sanitized (control characters and non-ASCII stripped, length-capped) before they become headers; a raw filename in a header is a response-splitting surface and is treated as such.

### 3.4 Content-type policy (AC-3)

```ts
export const ALLOWED_CONTENT_TYPES: Readonly<Record<ArtifactKind, readonly string[]>> = {
  email_attachment: ['application/pdf', 'image/jpeg', 'image/png', 'image/webp',
                     'text/plain', 'text/csv'],
  document:         ['application/pdf', 'image/jpeg', 'image/png', 'image/webp',
                     'text/plain', 'text/csv'],
  dossier:          ['application/pdf'],           // specs/00: the dossier is a PDF
};
```

Three independent gates, all of which must pass:

1. **Positive allowlist** — the declared `content_type` must be listed for that `kind`. `audio/*` and `video/*` are not on any list and cannot be, because the list is a literal.
2. **Explicit media deny** — a declared type whose prefix is `audio/` or `video/` is rejected with its own distinct message before the allowlist is even consulted. Redundant today *on purpose*: if someone ever widens an allowlist, this gate still holds and the intent stays legible in the diff.
3. **Magic-byte gates** (first 16 bytes, no dependency — D7):
   - **Deny regardless of declared type:** `ID3` · MPEG frame sync (`FF Ex`/`FF Fx`) · `OggS` · `fLaC` · `RIFF`…`WAVE` at offset 8 · `ftyp` at offset 4 (MP4/M4A/MOV) · `FORM`…`AIFF` · `.snd` · `#!AMR` · `MThd` · `1A 45 DF A3` (Matroska/WebM).
   - **Require for declared type:** `application/pdf` → `%PDF-` · `image/png` → `89 50 4E 47 0D 0A 1A 0A` · `image/jpeg` → `FF D8 FF` · `image/webp` → `RIFF` + `WEBP` at offset 8 · `text/plain`/`text/csv` → no NUL byte in the first 512 bytes.

**Builder trap, stated because it is the one that gets missed:** WebP and WAVE are both RIFF containers. The deny rule must test bytes 8–11 for `WAVE` specifically — a bare `RIFF` deny would reject every legitimate WebP image, and a bare `RIFF` allow would admit audio. `content-policy.test.ts` covers both directions.

Size: `bytes.byteLength > max_bytes` (default 25 MiB) → `invalid_input`. There is **no multipart-upload path**; a single PUT is the only write, and the cap is the memory bound that makes buffering safe.

### 3.5 Listing

```ts
export interface ListFilter {
  deal_id?: string;
  /** Requires `deal_id` — `kind` alone is `invalid_input`, never silently ignored. */
  kind?: ArtifactKind;
  /** Default 1000, capped at 1000. */
  limit?: number;
  cursor?: string;
}

export interface ObjectSummary {
  ref: ObjectRef; account_id: string; deal_id: string;
  kind: ArtifactKind; content_sha256: string;
  byte_length: number; stored_at: IsoTimestamp;
}

export interface ListPage {
  items: readonly ObjectSummary[];
  truncated: boolean;
  next_cursor?: string;
}
```

- `ObjectSummary` carries only what the key and a `ListObjectsV2` response actually contain. `content_type` and `filename` are S3 *user metadata* and need a `head` — so they are absent here rather than fabricated. **ADR-005 discipline applied to storage:** a value that was not retrieved is absent, never a plausible-looking default.
- `truncated: true` with a `next_cursor` is returned instead of a silently short page. A truncated list that looks complete is exactly the kind of quiet lie the receipt layer exists to prevent.
- Key order is lexicographic on the content hash, which carries **no meaning**. Callers that need chronology sort on `stored_at`. The in-memory backend reproduces the same lexicographic order so tests are backend-agnostic.

### 3.6 Environment contract (no new names — T-015 §3.5, D12)

| Variable | Absent ⇒ | Present ⇒ |
|---|---|---|
| `OBJECT_STORE_BUCKET` | **not configured**: `readObjectStoreConfig` returns `undefined`; caller composes `createInMemoryObjectStore()`; `s3-live.test.ts` **skips** | S3 path selected |
| `OBJECT_STORE_REGION` | with bucket set ⇒ `{ ok:false, error.code:'auth' }` ⇒ **fail fast** | explicit region |
| `OBJECT_STORE_ENDPOINT` | AWS default endpoint resolution | S3-compatible endpoint **and** `forcePathStyle: true` (D12) |

Bucket absent + endpoint/region present is also `undefined` (not configured) — the bucket is the switch, and an orphan endpoint is noted in the returned log event rather than treated as intent.

## 4. Error paths per operation

Uniform posture: **never throw across the boundary**; every failure is an `AdapterError` carrying `code`, `retryable`, `source`, and a log-safe `message`. `retryable` is stated explicitly so no caller has to guess (`packages/core/src/adapters.ts`).

### 4.1 Provider-signal → `AdapterErrorCode` mapping (binding; D2)

| S3 / transport signal | `code` | `retryable` | Caller-visible |
|---|---|---|---|
| `NoSuchKey`, `NotFound` (404 on HEAD) | `not_found` | false | object does not exist |
| `AccessDenied`, `InvalidAccessKeyId`, `SignatureDoesNotMatch`, `ExpiredToken` | `auth` | false | alert operator; **never retried in a loop** |
| `NoSuchBucket`, missing/incoherent config | `auth` | false | D2 — same handling class, frozen code set |
| `SlowDown`, `TooManyRequests`, HTTP 429 | `rate_limited` | **true** | SDK backoff already applied |
| HTTP 5xx, `InternalError`, `ServiceUnavailable`, `RequestTimeout`, `ECONNREFUSED`, `ETIMEDOUT`, `EAI_AGAIN`, `AbortError` | `provider_unavailable` | **true** | transient |
| 200 GET with no `Body`; unparseable/absent required metadata; **sha-256 of retrieved bytes ≠ hash in the key** | `malformed_response` | false | integrity alarm — alert operator |
| Anything unrecognized | `provider_unavailable` | true | conservative: assume transient rather than declaring a permanent failure we cannot substantiate |

### 4.2 Retry / idempotency posture

- **One retry layer only.** `maxAttempts` is set explicitly on the `S3Client` (default 3) and **we add no second loop**. Two stacked retry layers multiply latency and turn a 3-attempt policy into 9 — a classic way to convert a blip into an outage.
- **`put` is idempotent by construction** (D4): the key is the content hash, so a retried PUT of the same bytes lands the same object at the same key. Retry is *always* safe. An at-least-once event consumer re-running an attachment save produces one object, not two.
- **`get` / `head` / `list` are read-only** and trivially retry-safe.
- Concurrent identical puts race harmlessly: both may HEAD-miss and both may PUT, but the bytes and the key are identical, so the outcome is the same object either way.

### 4.3 `put` — ordered failure sequence

| # | Check | On failure | Cost |
|---|---|---|---|
| 1 | `account_id` / `deal_id` match `^[A-Za-z0-9_-]{1,64}$` | `invalid_input` | local |
| 2 | declared type is not `audio/*` or `video/*` | `invalid_input`, message names the type | local |
| 3 | declared type is on this `kind`'s allowlist | `invalid_input`, message names the type | local |
| 4 | `byte_length ≤ max_bytes` | `invalid_input` | local |
| 5 | magic-byte deny list | `invalid_input`, message `"rejected media signature"` | local |
| 6 | magic-byte requirement for the declared type | `invalid_input`, message `"content does not match declared type"` | local |
| 7 | `HeadObject` on the computed key | see §4.1 | **1 round trip** |
| 8 | present with matching size ⇒ return `already_present`, **PUT is not issued** | — | — |
| 9 | present with mismatched size under an identical hash ⇒ `malformed_response`, alert | — | — |
| 10 | absent ⇒ `PutObject` | see §4.1 | 1 round trip |

**Steps 1–6 are all local**, so a hostile or malformed request never reaches the network. Step 7's extra round trip is the price of AC-7: the code path that would overwrite an existing object *literally does not run*. For this system's volume that is the right trade, and it is stated here so it reads as a decision rather than an oversight.

### 4.4 `get` / `head` — the tenancy path (AC-4)

| Condition | Result | Why |
|---|---|---|
| `ref` unparseable | `invalid_input` | caller bug |
| `parseArtifactRef(ref).account_id !== account_id` | **`not_found`**, and a `warn`-level `object_store.tenancy.reject` log event | Returning `not_found` rather than a distinct "forbidden" means a cross-account probe cannot confirm that an object exists. The check is **local and runs before any network call**, so there is no timing signal either. |
| key absent | `not_found` | |
| retrieved bytes hash ≠ key hash | `malformed_response` + operator alert | the content-addressing claim is *verified* on every read, not asserted |
| `x-amz-meta-account-id` ≠ the key's account segment | `malformed_response` + operator alert | belt-and-braces against a key-parse or migration fault |

`get` reads the body via the SDK's `Body.transformToByteArray()`. **That is the only place a stream type appears anywhere in this package**, and it appears inside `s3-backend.ts` only — no stream, no SDK type, and no S3 command object ever crosses the barrel (AC-1).

### 4.5 `list`

| Condition | Result |
|---|---|
| `kind` supplied without `deal_id` | `invalid_input` — never a silently ignored filter |
| `limit` above 1000 | clamped to 1000; the clamp is reported in the log event |
| truncated page | `{ truncated: true, next_cursor }` — never a short page that looks complete |
| provider failure | §4.1 |

An account-scoped list is issued with the literal prefix `acct/{account_id}/`. There is no code path that lists a bare bucket root, so "list everything" is not a thing this interface can express.

### 4.6 Configuration and startup

| State | Behaviour |
|---|---|
| `OBJECT_STORE_BUCKET` absent | `undefined` ⇒ compose in-memory. Log **once**, plainly, at startup: artifact storage is in-memory and does not survive restart (ADR-008 "Consequences"). |
| bucket present, region absent | `{ ok:false, code:'auth' }` ⇒ **fail fast, exit non-zero** |
| bucket present and coherent, endpoint unreachable at first use | `provider_unavailable` per call — the process does **not** fall back to in-memory |

The distinction ADR-008 draws is *default to in-memory*, **never fall back to it**. A configured-but-unreachable store that silently degraded would accept an artifact, return success, and lose it — healthy-looking data loss, which is the failure mode the fail-fast rule exists to make impossible.

### 4.7 `S3RawPayloadStore` — the write-behind window (D5, stated plainly)

| Stage | Behaviour |
|---|---|
| `stash(payload)` | computes `sha256Hex(canonicalJson(payload))`, inserts into the pending map, schedules the PUT, **returns synchronously**. The webhook ack is never blocked (specs/00: "webhooks ack immediately"). |
| PUT succeeds | entry leaves the pending map |
| PUT fails, retryable | retried with backoff up to `max_write_attempts` (default 5) |
| PUT fails, terminal or attempts exhausted | ref moves to `failedRefs()`, logged at **error** level with the ref — **never silently dropped** |
| backlog exceeds `backlog_warn_at` (default 256) | one error-level log per crossing; a sustained backlog means the store is down and must alarm |
| `get(ref)` | returns the payload **only while it is pending or in the bounded recent-write cache**; a miss is `undefined`. The port's sync signature admits nothing better. |
| `fetch(ref)` | the real durable read — `ObjectStoreResult<unknown>` |
| `flush()` | awaits all pending writes; called on graceful shutdown and at the end of every test that asserts durability |

**The window, named honestly:** between `stash()` returning and the flush completing, a process crash loses that payload, and the quarantine row's `raw_payload_ref` would dangle. Scope of the harm is bounded — this path carries only *unparseable* provider payloads, whose loss does not drop a dealer *message* (the parsed message path never touches this store) — but it is a real gap and it is the direct consequence of a synchronous port over a network store. **Recommendation to the lead:** a follow-up task, owning `services/comms/src/ports.ts`, should make `RawPayloadStore` async so `stash` can be awaited before the quarantine event is published. That file is T-014's; this design does not touch it.

### 4.8 Logging — what is recorded, what is never recorded

```ts
export interface ObjectStoreLogEvent {
  op: 'put' | 'get' | 'head' | 'list' | 'stash' | 'flush' | 'config';
  level: 'debug' | 'info' | 'warn' | 'error';
  source: string;
  outcome: 'ok' | AdapterErrorCode | 'tenancy_reject';
  account_id?: string;
  deal_id?: string;
  kind?: ArtifactKind;
  /** First 12 hex chars of the content hash. Enough to correlate, not enough
   *  to address — a full ref in a log line is a capability in a log line. */
  ref_prefix?: string;
  byte_length?: number;
  duration_ms?: number;
  message?: string;
}
```

**Never logged, under any level:** object bytes or any encoding of them · any content preview · the full `filename` (extension and length only) · the raw quarantine payload (the whole point of `RawPayloadStore` is that only the ref travels — `services/comms/src/ports.ts`: "The payload NEVER rides the bus or the logs") · credentials or any part of one · a signed URL or a request signature · a raw SDK error body, which can echo request content.

**Always logged at `warn`:** `object_store.tenancy.reject` — the requesting `account_id`, the ref's `account_id`, and `ref_prefix`. A cross-account read attempt is a security signal and must be visible, even though the caller only ever sees `not_found`.

No logging library is added. `config.log` is an optional callback defaulting to a no-op, so the package keeps exactly one dependency (`@aws-sdk/client-s3`) and the API wires its own sink.

## 5. Invariant touchpoints — and how this design protects each

| # | Invariant | Source | Protection |
|---|---|---|---|
| 5.1 | **No audio is stored — ever** | specs/00 "Store" ("No audio is stored"); specs/01 consent posture ("no audio is ever captured or stored") | Four layers, three of them structural. (a) `ArtifactKind` is a three-literal union with no audio member — `put({kind:'recording'})` **does not compile**. (b) `audio/*`/`video/*` are rejected by an explicit prefix deny before the allowlist. (c) Neither allowlist contains an audio type. (d) Magic-byte deny catches a mislabeled upload (D7), which is the *only* way the label-based gates could fail. `no-audio.test.ts` covers all four and **never skips**. There is no method, no key segment, and no content type through which a recording could enter. |
| 5.2 | **Account tenancy — one account's artifacts are not addressable from another** | specs/01 "Account model" ("`Account` owns `Deals`"); specs/00 "Dealership data tenancy" | `account_id` is the **first, mandatory** parameter of `get`/`head`/`list`, so an unscoped read is inexpressible. The key's first segment group is the account, so a list is prefix-confined at the request. `isRefOwnedBy` runs **before** any network call and a mismatch returns `not_found` (never "forbidden"), so a probe learns nothing. The `^[A-Za-z0-9_-]{1,64}$` id pattern blocks prefix escape via `../`. `x-amz-meta-account-id` is cross-checked against the key on read. |
| 5.3 | **Append-only receipt trail; a revision is a new object** | specs/00 "Receipt layer" ("append-only"); AC-7 | Content-addressed keys (D4): different bytes ⇒ different key, so in-place mutation is unrepresentable. The interface has no `delete`, `copy`, `move`, or caller-chosen key (D9). `put` HEADs first and **skips the PUT** when the object exists (§4.3 step 8). Read-time hash verification means a tampered object surfaces as `malformed_response` rather than as good data. |
| 5.4 | **Anti-corruption — core services never see a provider's shape** | specs/00 "Integrations — adapter layer"; AC-1 | `@aws-sdk/client-s3` is imported in exactly **one** file, `s3-backend.ts`, which is not exported from the barrel. No `PutObjectCommand`, `GetObjectOutput`, `S3ServiceException`, or stream type appears in any exported signature. Mechanically checkable: `grep -rn "@aws-sdk" packages/object-store/src` must return exactly one file. Swapping to another S3-compatible provider is a config change; swapping the SDK is one file. |
| 5.5 | **The spine is defined once and imported** | ADR-001; T-015 §2.2 rules 1–2; AC-8 | Zero domain types are declared here. `AdapterResult`/`AdapterError`/`AdapterErrorCode`/`IsoTimestamp` come from `@core`; `RawPayloadStore` and `canonicalJson` come from `@comms`. `ObjectStoreResult<T>` is an alias, not a definition. No `Deal`, `Message`, `Offer`, `VehicleInstance`, or `DealDossier` is mirrored — the store moves **bytes plus a location**, and knows nothing else about the domain. |
| 5.6 | **Absent ⇒ unevaluable, never zero / never fabricated** | ADR-005; specs/00 "Budget ceiling vs. fair price" | The storage-layer form of the same rule: a `get` miss is `not_found`, **never an empty `Uint8Array`**; `ObjectSummary` omits `content_type`/`filename` (which a list response does not carry) rather than defaulting them; an absent `filename`/`origin_ref` is omitted, not `''`; a truncated list says `truncated: true` instead of looking complete. Nothing in this package invents a value it did not retrieve. |
| 5.7 | **No unapproved integration, no spend** | CLAUDE.md invariant 2; ADR-008 | The manifest keeps exactly one dependency, `@aws-sdk/client-s3`, for the already-approved S3-compatible object store; only the `scripts` field is edited (ADR-009 §2). **No presigned-URL package, no CDN, no signing service, no image/PDF processing library, no logger, no test-container library** (D8, task notes). No mock-only target (KBB, Manheim, Carfax, AutoCheck, credit providers) is touched — this package has no notion of them. No credential field, no `.env`, no baked endpoint. |
| 5.8 | **No silent interpretive drift** | CLAUDE.md invariant 3 | Every non-obvious call is D1–D12 above with its spec/ADR basis. Two are flagged to the lead: D5 (sync port over an async store) and D6 (the `@object-store → @comms` import edge, already anticipated by ADR-009 §1 but not listed in T-015 §2.2). |
| 5.9 | **Webhooks ack immediately; a dealer message is never dropped** | specs/00 "Comms aggregation layer" | `stash()` stays synchronous and non-blocking (§4.7) — no S3 round trip enters the ack path. Failed durable writes are retried and then surfaced in `failedRefs()` with an error log; nothing is discarded. The parsed-message path does not touch this package at all, so an object-store outage cannot lose a dealer message. |
| 5.10 | **The dossier is a durable, exportable artifact; rendering stays in `@receipt`** | specs/00 "Receipt layer"; AC-6; T-012 §2.5 | `kind: 'dossier'` with a PDF-only allowlist stores and retrieves the rendered bytes. This package **does not render**: no PDF engine, no HTML, no hosting. `DossierExporter.renderPdf` / `publishWebLink` stay `not_implemented` in `@receipt` — a later task wraps `PutResult.ref` into T-012's `DossierArtifactRef { kind: 'pdf', ref, generated_at }`. `origin_ref` carries the `receipt_bundle_id` so the object traces back to its bundle. `publishWebLink` stays unimplemented because hosting is an unapproved integration (D8). |
| 5.11 | **One deal, one make/model; valuation is per-`VehicleInstance`** | specs/00 "Cardinality invariants", "Budget ceiling vs. fair price"; ADR-006/ADR-007 | Protected by *absence*, which is the strongest available form here: no key segment, metadata header, or exported type in this package encodes a make, model, year, trim, VIN, price, band, or flag. No rollup and no valuation logic exists here, so `current_offer` newest-wins (ADR-006) and `above_market`-vs-RETAIL (ADR-007) cannot be duplicated or contradicted by the storage layer. |
| 5.12 | **The fleet cannot mutate its constitution** | CLAUDE.md invariant 1 | Ownership is `packages/object-store/src/**`, `packages/object-store/test/**`, the `scripts` field of one manifest, one task file, and this document. `CLAUDE.md`, `thesis.md`, `specs/**`, `.claude/**` are untouched; so are `packages/core/**`, `services/comms/**`, `packages/object-store/tsconfig.json`, and all root config. |
