## 0. Interpretive calls made by this design (drift trip-wire log)

Each call stays inside spec ambiguity or is a mechanical consequence of the v0.5 spine. None adds an integration, none adds a dependency, none touches a protected path. **A builder who finds any of these insufficient must stop and escalate — do not improvise an alternative.**

| # | Call | Basis |
|---|------|-------|
| **D1** | The valuation mocks' **VIN length/charset validation is deleted**. VIN becomes an *optional fixture match key only*; a VIN that matches nothing falls through to the make/model/year key, and a malformed VIN is never an error. | Q16: VIN is "user-entered and **unvalidated** at launch — the buyer's own record, not a lookup key"; specs/01 Backlog item 4 puts decode validation out of scope. The current `invalid_input` on a non-17-char VIN (T-003 §4.1) is validation the v0.5 spine forbids. AC-6. |
| **D2** | The fixture match key becomes `target.make | target.model | instance.year`. `make`/`model` come from `VehicleTarget`, `year` from `VehicleInstance`. | `VehicleInstance` deliberately carries no make/model (T-010 D3/spine comment: "a thread that contradicts the anchor is unrepresentable"), so the only lawful source of make/model in a valuation request is the deal's `target`. |
| **D3** | `trim` and `condition` become **load-bearing** on the mock output via optional per-row `trim_adjustment` / `condition_adjustment` tables (integer-cent deltas, default 0), applied after the existing `mileage_adjustment` in a fixed order. | specs/00 "Budget ceiling vs. fair price": "no valuation source can price *Honda Accord* without year, trim, mileage, and condition". AC-2 requires the request to *carry* all four; carrying an attribute that provably changes nothing is a request-shape gesture, not a valuation. Adjustment tables (rather than multiplying fixture rows per trim × condition) keep fixture sets small and make the property assertable from one row. |
| **D4** | `ValuationFixtureRow.values` gains `private_party?`, and the **KBB default fixtures populate it**. Manheim rows never do. | Q15 RESOLVED + specs/00 "Valuation" row 3: "KBB private-party value" is the private-party source and it "still comes through the existing mock-only KBB approval". The spine band already exists (`ValuationSnapshot.private_party`, T-010 D5) and today nothing fills it. AC-9. |
| **D5** | **No comps adapter, no comps type, no marketplace anything is added.** `BlendedValuationSources.private_party` stays as a declared-but-unwired third slot. Buyer-entered comps are user-entered data, not an external feed, so they have no home in the anti-corruption layer at all. | Q15 RESOLVED ("no Facebook Marketplace integration: Meta publishes no API and scraping violates their terms"; "buyer sources their own comps"); specs/01 Backlog item 6; T-003 D9. AC-9. |
| **D6** | `blendSnapshots` **discards any contributing snapshot whose `vehicle_instance_id` differs from the first snapshot's**, and names only surviving contributors in `source`. | specs/00: a `ValuationSnapshot` is "ALWAYS of one specific car". A blend across two cars would be a snapshot of nothing; silently averaging them is the exact incomparability the one-vehicle rule exists to prevent. Dropping (rather than throwing) keeps the function pure and total — the head always survives, so a non-empty input always yields a result. |
| **D7** | `toVehicleData` takes the **`VehicleInstance` itself**, not a bare `vehicle_instance_id: string`. | AC-3 requires that every `VehicleData` carry an instance id; taking the instance makes forgetting or mistyping it unrepresentable, the same structural trick the frozen `ValuationRequest` uses for snapshots (T-010 D12). |
| **D8** | `toVehicleData` stays exported from **`@adapters/nhtsa`** and gains an optional `history` part, so a single assembler covers the NHTSA and vehicle-history contributions. | AC-3 names both packages, but `VehicleHistoryAdapter` returns `VehicleHistorySummary`, not `VehicleData` — the two only meet at assembly. `VehicleData`'s natural home is `@core`, which is frozen; a new shared package would need a 13th alias (ADR-009 fixes the map at 12) and a cross-package dependency edit (T-015-only). Keeping the existing, already-exported assembler is the minimum change. **If a later task opens a vehicle-data assembly home, this helper relocates there — record it as a known future move, not as settled architecture.** |
| **D9** | **Assemble only from successful observations.** A failed decode / recalls / history call produces **no** `VehicleData` for that pass; the previously cached record (if any) stands and the caller retries. `recalls: []` therefore means "vPIC answered: zero campaigns", never "we did not look". | ADR-005: a missing required input is UNEVALUABLE, "never zero and never *not triggered*". `VehicleData.recalls` is a required array in the frozen spine, so the only way `[]` can stay honest is if it is never written speculatively. Same shape as specs/00's rule that a thread with no valuation is unevaluable rather than "fine". |
| **D10** | **An instance with no VIN yields no `VehicleData` record and no history call** — absence of the record *is* the unevaluable state. This needs no runtime guard: `instance.vin` is `string | undefined` and every VIN-keyed adapter method takes `Vin`, so under `strict` + `exactOptionalPropertyTypes` passing it un-narrowed is a **compile error**. | Q16 (VIN absent is normal, not an error); T-010 spine comment on `VehicleInstance.vin`: "Absent is normal and not an error". The compiler is the enforcement; the tests record it with `@ts-expect-error`. AC-6. |
| **D11** | NHTSA's internal decode→recalls two-step (T-004 D2) is **retained** and is not what AC-6 forbids. | AC-6 bars a decode as a precondition "for producing a valuation or for accepting a `VehicleInstance`". Neither applies: the decode is the vehicle-data product itself, and it exists because the free public Recall API is vehicle-keyed rather than VIN-keyed. No valuation path and no instance-acceptance path calls it. |
| **D12** | `credit-prequal` is **unchanged** and gains **no** `VehicleInstance` binding. | A prequal is a property of the *buyer*, not of a car; specs/01 "Credit data residency" scopes the stored result to "a provider token + prequal results (qualified APR, amounts) and nothing else". Adding a vehicle reference would widen a deliberately minimal residency surface. AC-10. |
| **D13** | No `package.json`, `tsconfig.base.json`, `vitest.workspace.ts`, or lockfile edit; no new dependency; no `zod` in any adapter. | ADR-009: dependency edits are T-015-only and the `typecheck`-script exception names T-016…T-019, not T-013. ADR-008 puts `zod` at the API route boundary. The four packages already resolve, compile, and run under the existing root config. |

### 2.1 Fixture row (neutral shape — never a provider payload)

```ts
/**
 * One mock source's knowledge of one vehicle. Neutral by construction:
 * MoneyCents fields only, no provider field names, no wire shape.
 * A row has `values` XOR `error`.
 */
export interface ValuationFixtureRow {
  /**
   * Match key A — OPTIONAL, matched case-insensitively after trim.
   * NOT validated: Q16 makes VIN the buyer's own record, not a lookup key,
   * so an unmatched or malformed VIN falls through to `spec_key` (D1).
   */
  vin?: Vin;

  /** Match key B — `target.make` | `target.model` | `instance.year` (D2). */
  spec_key?: { make: string; model: string; year: number };

  /**
   * Bands this source knows. KBB rows populate trade_in / retail /
   * private_party (D4); Manheim rows populate wholesale. The type does not
   * enforce the split — the default fixture files and their tests do.
   */
  values?: {
    wholesale?: MoneyCents;
    trade_in?: MoneyCents;
    retail?: MoneyCents;
    /** Q15: KBB private-party value. No comps/marketplace source exists (D5). */
    private_party?: MoneyCents;
  };

  /** Deterministic, linear, opt-in. Uses `instance.mileage`. */
  mileage_adjustment?: {
    baseline_mileage: number;
    /** Subtracted per mile ABOVE baseline, added per mile below. */
    cents_per_mile: number;
  };

  /** Deterministic delta per condition; unlisted condition ⇒ 0 (D3). */
  condition_adjustment?: Partial<Record<VehicleCondition, MoneyCents>>;

  /** Deterministic delta per trim, keyed by trimmed+lowercased trim; unlisted ⇒ 0 (D3). */
  trim_adjustment?: Readonly<Record<string, MoneyCents>>;

  /** Simulated provider failure — lets callers exercise every error path offline. */
  error?: AdapterErrorCode;
}

export interface MockValuationOptions {
  /** Defaults to that mock's built-in fixture set. */
  fixtures?: readonly ValuationFixtureRow[];
  /** Injectable clock for deterministic `captured_at`. Defaults to system UTC now. */
  now?: () => IsoTimestamp;
}
```

### 2.3 Blend (specs/00 "Blend into wholesale vs trade-in vs retail. Snapshot + cache.")

```ts
export const BLEND_SOURCE_PREFIX = 'blend(';

/**
 * Pure merge, no I/O, total. Blending zero snapshots is a COMPILE error
 * (non-empty tuple), so no empty-input runtime path exists.
 *
 * Rules:
 *  - `vehicle_instance_id` = snapshots[0].vehicle_instance_id. Any snapshot
 *    with a different id is DISCARDED before merging (D6) and is absent from
 *    `source` — a blend is always of one specific car.
 *  - Each band is taken from the surviving snapshot that supplies it; if more
 *    than one does, the newest `captured_at` wins (ties: earliest input order).
 *  - `captured_at` = OLDEST surviving `captured_at` — the blend is only as
 *    fresh as its stalest input, keeping caller-side cache logic conservative.
 *  - `source` = 'blend(' + surviving sources in input order joined by '+' + ')'.
 */
export function blendSnapshots(
  snapshots: readonly [ValuationSnapshot, ...ValuationSnapshot[]],
): ValuationSnapshot;

/** Roles, not providers — the anti-corruption boundary holds at the composite too. */
export interface BlendedValuationSources {
  /** KBB-mock today: retail, trade-in, and (Q15) private-party bands. */
  retail_trade_in: ValuationAdapter;
  /** Manheim-mock today: wholesale. */
  wholesale: ValuationAdapter;
  /**
   * Deliberately DECLARED BUT UNWIRED (D5, T-003 D9). Q15 RESOLVED admits no
   * comps/marketplace source; a licensed aggregator is a future option. Nothing
   * in this repo may fill this slot without a new ADR.
   */
  private_party?: ValuationAdapter;
}

/** Composite that IS a ValuationAdapter — callers see one shape either way. */
export function createBlendedValuationAdapter(
  sources: BlendedValuationSources,
): ValuationAdapter;
```

> **Naming note (deliberate non-change):** the `retail_trade_in` role now also carries KBB's private-party band. The field is **not** renamed — it names the specs/00 "Valuation" table row it wires, and a rename would churn every composition root for no behavioral gain. The doc comment carries the clarification.

## 3. Data shapes and evaluation order — valuation

### 3.1 Request → snapshot

```
ValuationRequest { target: VehicleTarget, instance: VehicleInstance }
        │
        ├─ target.make, target.model            ← the deal anchor (immutable)
        └─ instance.{ id, vin?, year, trim?, mileage?, condition, additions }
                                                 ← the priceable attributes
        ▼
ValuationSnapshot {
  vehicle_instance_id: instance.id,     ← ALWAYS stamped; no other source
  wholesale?, trade_in?, retail?, private_party?,
  source: <adapter id or blend id>,
  captured_at: <injected clock>
}
```

`instance.additions` is deliberately **not** priced by the mocks: priced add-ons already live on the offer as `OfferFee` (T-010 D8), and inventing a per-addition valuation delta would be drift.

### 3.2 Matching (deterministic, in order)

1. If `instance.vin` is present **and** some row's `vin` equals it (both trimmed + uppercased) → that row. No length or charset check (D1).
2. Otherwise, build `key = lower(trim(target.make)) | lower(trim(target.model)) | instance.year` and take the first row whose `spec_key` produces the same key. `trim` and `condition` are **not** match keys.
3. No row → `not_found` (terminal).

### 3.3 Band computation (deterministic, in order)

For each band present on the row's `values`:

```
delta = mileage_delta + condition_delta + trim_delta
band  = max(0, base + delta)

mileage_delta   = mileage_adjustment && instance.mileage !== undefined
                    ? round((baseline_mileage - instance.mileage) * cents_per_mile)
                    : 0
condition_delta = condition_adjustment?.[instance.condition] ?? 0
trim_delta      = instance.trim !== undefined
                    ? (trim_adjustment?.[lower(trim(instance.trim))] ?? 0)
                    : 0
```

The order is fixed so results are reproducible; all arithmetic is integer cents (`MoneyCents`), never floats.

**Fixture discipline (asserted by tests, carried forward from T-003 §3 and extended):**
- KBB rows populate only `trade_in` / `retail` / `private_party`; Manheim rows only `wholesale`.
- Every demo vehicle appears in both fixture files with coherent numbers satisfying `wholesale < trade_in < private_party < retail`.
- At least one default row carries a `condition_adjustment` and at least one a `trim_adjustment`, so "all four attributes are load-bearing" is provable (D3).
- Fixtures stay deterministic TypeScript modules: no JSON loading, no I/O, no randomness, no clock.
- Error rows keep the existing partial/total-failure demo topology (BMW X5 partial, Audi A4 KBB-side failure, Jaguar XJ total failure).

### 3.4 Blend outcomes

| Contributors | Result |
|---|---|
| all `ok` | blended snapshot; `source` names every contributor |
| some fail, ≥1 `ok` | **`ok`, partial** — only surviving sources' bands present; `source` names contributors only, so provenance doubles as the degradation signal |
| all fail | one `AdapterError` (§4.1 row "blend, total failure") |
| a survivor's `vehicle_instance_id` ≠ head's | that survivor is **discarded** (D6); it contributes no band and is absent from `source` |

The composite stamps `vehicle_instance_id = req.instance.id` on the returned snapshot — authoritative, because every contributor was asked about that same instance.

## 4. Interface signatures and data shapes — `packages/adapters/nhtsa`

The adapter factory and its two spine methods are **unchanged**; only the aggregate assembler moves to the instance.

```ts
import type {
  IsoTimestamp,
  RecallRecord,
  VehicleData,
  VehicleDataAdapter,
  VehicleHistorySummary,
  VehicleInstance,
  VinDecode,
} from '@core';

export const NHTSA_SOURCE = 'nhtsa-vpic';

export interface NhtsaAdapterOptions {
  fetchFn?: typeof fetch;      // injected in tests — fixtures, never the network
  vpicBaseUrl?: string;        // default https://vpic.nhtsa.dot.gov/api
  recallsBaseUrl?: string;     // default https://api.nhtsa.gov
  timeoutMs?: number;          // default 10_000
}

/** UNCHANGED — decodeVin(vin) / getRecalls(vin), the frozen @core contract. */
export function createNhtsaVehicleDataAdapter(
  options?: NhtsaAdapterOptions,
): VehicleDataAdapter;

/**
 * The observations that were ACTUALLY OBTAINED for one instance.
 * Every field here comes from a SUCCESSFUL call (D9): `recalls: []` means
 * "vPIC answered: zero campaigns", never "we did not look". A failed call
 * means this function is not invoked for that pass (ADR-005).
 */
export interface VehicleDataParts {
  /** Absent when vPIC was not consulted or the instance has no VIN (Q16, D10). */
  decode?: VinDecode;
  /** Required. [] is an ANSWER, not a placeholder. */
  recalls: RecallRecord[];
  /** From @adapters/vehicle-history when a history call succeeded (D8). */
  history?: VehicleHistorySummary;
}

/**
 * Pure, total assembly of the cached, timestamped, INSTANCE-BOUND aggregate.
 * Taking the instance rather than a bare id makes an unbound VehicleData
 * unrepresentable (D7, AC-3). Caching/persistence is the caller's job — this
 * package holds no state.
 */
export function toVehicleData(
  instance: VehicleInstance,
  parts: VehicleDataParts,
  captured_at: IsoTimestamp,
): VehicleData;
```

Resulting shape:

```
VehicleData {
  vehicle_instance_id: instance.id,   ← ALWAYS stamped
  decode?, recalls: [...], history?,
  captured_at
}
```

`reliability` is not produced (T-010 D7: listed in specs/00 but with no shape defined anywhere — inventing one would be drift).

**Call sequence a composition root follows** (documented here, implemented by T-020, not by this package):

```
instance.vin === undefined            → no calls, NO VehicleData record (D10)
decodeVin(instance.vin) → !ok         → no record this pass, retry per `retryable` (D9)
getRecalls(instance.vin) → !ok        → no record this pass, retry per `retryable` (D9)
getHistory(instance.vin) → !ok        → assemble WITHOUT `history` (history is optional and
                                        a separate, paid, mock-only feed — its absence does
                                        not invalidate decode + recalls)
all obtained                          → toVehicleData(instance, parts, now())
```

## 7. Error paths per operation

Taxonomy is the frozen `@core` one — `invalid_input | not_found | auth | rate_limited | provider_unavailable | malformed_response` — and `retryable` is derived from the code (`rate_limited` and `provider_unavailable` are true; everything else false). **No adapter throws across the boundary**; every operation resolves to an `AdapterResult`. This instantiates `docs/design/T-001.md` §5.1; where the two differ, this section wins for `packages/adapters/**`.

### 7.1 `ValuationAdapter.getValuation(req)` — KBB-mock / Manheim-mock

| Condition | Code | retryable | Surfaces to caller | Logged | Notes |
|---|---|---|---|---|---|
| `req.instance.id` empty/whitespace | `invalid_input` | false | `AdapterError` | static message | A snapshot must name a car (AC-1); a blank id would satisfy the type and violate the spec. Caller bug — fix upstream, do not retry. |
| `req.target.make` or `.model` empty/whitespace | `invalid_input` | false | `AdapterError` | static message | The anchor is the only lawful make/model source (D2). |
| `req.instance.year` not a finite integer | `invalid_input` | false | `AdapterError` | static message | |
| `req.instance.mileage` present and negative / non-finite | `invalid_input` | false | `AdapterError` | static message | Existing rule, now read off the instance. |
| `req.instance.vin` malformed or unknown | *(not an error)* | — | falls through to the make/model/year key | nothing | **D1 / Q16.** Regression gate: a 4-character VIN must still return a valuation when the spec key matches. |
| No fixture row matches | `not_found` | false | `AdapterError` | static message | "This mock has no data for that car." Terminal — retrying the same request cannot change it. |
| Fixture row carries `error: <code>` | that code | derived | `AdapterError` | `simulated <code> from valuation fixture` | The offline drill for every downstream error path. |
| — | `auth` | — | **unreachable** | — | There are no credentials in this package to fail. That absence is the mock-only enforcement (CLAUDE.md invariant 2). |

**Never logged:** the VIN, any fixture contents, any band value, any buyer-identifying text. Messages are static per condition. The `vehicle_instance_id` is deliberately also kept out of messages — the caller already holds the request it made, so echoing it buys nothing and widens the log surface.

**Retry / idempotency:** pure function of `(request, fixtures, clock)` — zero internal retries, zero state, no I/O. Repeat calls return byte-identical results except `captured_at`. Safe to call any number of times; backoff policy is entirely the caller's (T-001 §5.1).

### 7.2 `createBlendedValuationAdapter(...).getValuation(req)`

| Condition | Result | Notes |
|---|---|---|
| All wired sources `ok` | `ok` — full blend | `source` names every contributor |
| ≥1 `ok`, ≥1 failed | **`ok` — partial** | Missing bands are **absent, never zero** (ADR-005). `source` names only contributors, so the degradation is visible in the snapshot itself and no side channel is needed. |
| All failed | `ok: false` — one `AdapterError` | `source` = the blend id. Code: a retryable contributor's code wins over a terminal one; among equals the wired-role order (`retail_trade_in`, `wholesale`, `private_party`) decides — deterministic. `retryable` = OR over contributors. `message` = `all valuation sources failed: <role>=<code>, …` — codes only, never provider text. |
| A survivor names a different `vehicle_instance_id` | that survivor is discarded (D6) | If **every** survivor is discarded the head still stands by construction, so the result is a snapshot of the head's car. Downgraded silently in the result but visibly in `source`. |

Fan-out is concurrent (`Promise.all`); one slow or failing source cannot make another's result unavailable. No internal retry, no caching — "Snapshot + cache" is caller-side (the store layer, T-017); this package holds no state, so repeated calls are idempotent.

### 7.3 `VehicleDataAdapter.decodeVin(vin)` / `.getRecalls(vin)` — NHTSA (unchanged, restated as the contract T-013 must not regress)

| Condition | Code | retryable | Notes |
|---|---|---|---|
| Local VIN shape check fails | `invalid_input` | false | Before any HTTP. This is a guard on a VIN the caller chose to send to a VIN-keyed endpoint, not validation of the buyer's record (AC-6, D11). |
| fetch rejects / times out (default 10 s) | `provider_unavailable` | true | |
| HTTP ≥ 500 | `provider_unavailable` | true | |
| HTTP 429 | `rate_limited` | true | |
| other HTTP ≥ 400 | `malformed_response` | false | Endpoint contract drifted — operator alert. |
| 200 with non-JSON body | `malformed_response` | false | |
| 200, shape does not match the recorded contract | `malformed_response` | false | Detail names the mismatch; the raw body is never logged. |
| vPIC has no usable data | `not_found` | false | Terminal. |
| vPIC reports the VIN structurally invalid | `invalid_input` | false | Provider's in-band verdict. |
| `getRecalls` — the internal decode fails | the decode's error, verbatim | as decoded | `source` stays `nhtsa-vpic`; the two-step is invisible to the caller (D11). |
| `getRecalls` — zero campaigns | **`ok: true, value: []`** | — | A successful answer, not an absence. Only reachable through a successful call, which is exactly what makes D9 safe. |

**Never logged:** the VIN, the raw provider payload, the full URL. **Retry:** stateless, zero internal retries, `retryable` reported truthfully, backoff is the caller's. Both operations are HTTP GETs — safe and idempotent by construction.

### 7.4 `toVehicleData(instance, parts, captured_at)`

Pure and total: no failure path, no clock read, no validation. It cannot produce a `VehicleData` without an instance (D7), and by the D9 calling rule it is only reached with successful observations. Blank-`instance.id` rejection belongs to the write path (T-016 schema constraint / T-020 API validation), not to a pure assembler — this design does not smuggle a validator in here.

## 8. Invariant touchpoints and how the design protects each

| Invariant | Source | Where it is touched | Structural protection |
|---|---|---|---|
| A `ValuationSnapshot` is **always of one specific car**, never of a bare make/model | specs/00 "Core domain model"; AC-1 | every `getValuation` return | `ValuationRequest` (frozen `@core`) *requires* an `instance`, and the implementation's only source for `vehicle_instance_id` is `req.instance.id`. There is no overload, no default, and no builder that omits it — **a snapshot without an instance is unrepresentable, not merely discouraged.** |
| A valuation request carries **year, trim, mileage, condition** | specs/00 "Budget ceiling vs. fair price"; AC-2 | request shape + band computation | All four ride on `VehicleInstance`, so they cannot be dropped. D3 makes each of the three optional ones observably move a band, so a test can prove they are load-bearing rather than decorative. Make/model come from `target` and from nowhere else (D2). |
| A `VehicleData` is **bound to one instance** | specs/00 "Core domain model"; AC-3 | `toVehicleData` | Takes the `VehicleInstance` itself (D7). The id cannot be forgotten, mistyped, or defaulted. |
| The **wholesale / trade-in / retail** spread survives, per instance | specs/00 "Valuation"; AC-4 | blend | Blend merges flat spine bands; contributors disagreeing on the instance are discarded (D6) rather than averaged, so the spread is always three readings of one car. Fixture discipline keeps `wholesale < trade_in < private_party < retail`. |
| **No provider shape reaches a caller** | specs/00 "Integrations — anti-corruption"; AC-5 | all four public surfaces | Each package's `src/index.ts` is its only alias target, so a deep import does not resolve. Raw NHTSA narrowing lives in non-exported `vpic.ts` / `recalls.ts`; fixture rows are `MoneyCents`-shaped, not wire-shaped; every factory returns the spine interface. Provider names survive only as `source` id strings. |
| **VIN is user-entered and unvalidated**; no decode is a precondition | Q16; specs/01 Backlog 4; AC-6 | valuation matching; instance acceptance | D1 deletes the valuation VIN check outright — a malformed VIN must still yield a valuation via the spec key, and that is a named regression test. NHTSA's internal decode serves recalls only (D11); no valuation path and no instance-acceptance path calls it. |
| Mock-only targets stay **mock-only** | CLAUDE.md "Approved integrations"; AC-7 | KBB, Manheim, Carfax, AutoCheck, credit | Zero HTTP, zero SDK, zero credential, zero env read in those four surfaces — fixtures are the entire data source. `auth` is structurally unreachable in each because there is no credential to fail. Credential absence is the enforcement; T-013 adds no configuration option through which one could be supplied. |
| NHTSA is the **live-approved** vehicle-data source, but tests stay offline | specs/00 "Vehicle data"; AC-8 | nhtsa tests | `fetchFn` injection keeps the default suite hermetic against recorded fixtures; the live smoke stays `describe.skipIf(!process.env.NHTSA_LIVE)`, opt-in and skipped by default. |
| **No private-party comps source**, no marketplace path | Q15 RESOLVED; specs/01 Backlog 6; AC-9 | KBB fixtures; blend's third slot | Private-party comes through the existing KBB mock band (D4). The `private_party` role stays declared-but-unwired (D5). No comps type, no scraper, no URL, no Meta anything is added — and buyer-entered comps are user data, so they have no adapter to live in. |
| Credit stays **pass-through**: token + prequal results only | specs/01 "Credit data residency"; Q3; AC-10 | credit-prequal | Unchanged (D12). `PrequalResult`'s four fields are the entire storable surface and none can hold raw credit data; the hosted-flow harness takes a scenario id and nothing applicant-shaped. |
| **No spine type is redefined** | ADR-001; AC-11 | all four packages | Every domain type is `import type … from '@core'`. Locally declared types (`ValuationFixtureRow`, `MockValuationOptions`, `BlendedValuationSources`, `NhtsaAdapterOptions`, `VehicleDataParts`, `MockHistoryOptions`, `PrequalFixture`) are adapter-local configuration, none a narrowing or restatement of a spine type. |
| A missing input is **unevaluable, never zero** | ADR-005 | partial blends; `VehicleData` assembly | Partial blends omit bands rather than zeroing them, and `source` records who contributed. D9 forbids writing a `VehicleData` from a failed observation, so `recalls: []` can only ever mean "vPIC said zero". D10 makes "no VIN ⇒ no record" a compile-time fact, so a fabricated clean record cannot be produced by accident. |
| `above_market` compares against the instance's **retail** band | ADR-007 | snapshot shape | The flat `retail` band is preserved through single-source and blended paths alike, so T-011's flag engine reads exactly the field ADR-007 names. A blend that discarded a foreign-instance contributor never lets another car's retail become this car's comparison basis. |
| Deal-level budget vs per-instance fair price stay **separate questions** | specs/00 "Budget ceiling vs. fair price"; Q20 | adapter surface | No adapter reads or receives `Deal.walk_away_number` or `budget` — those are not in `ValuationRequest` and there is no path to pass them. The adapter layer answers "what is this car worth?" only; "can I afford it?" is answered elsewhere, structurally. |
| **No dealership-directory source** | Q13; task note | all four packages | No adapter takes a `Dealership`, a location, or an address, and none is added. |
| Alias map and dependency set stay **frozen** | ADR-009; ADR-008 | root config | D13: no new package, no 13th alias, no dependency edit, no `typecheck` script, no `zod`. |

## 9. Test obligations (what "green" must mean)

Beyond keeping the existing suites passing, the following must be **asserted**, not assumed:

1. Every `getValuation` success stamps `vehicle_instance_id === req.instance.id` — single-source **and** blended.
2. A malformed / unknown `instance.vin` still returns a valuation when the spec key matches (the Q16 regression gate).
3. Changing only `instance.mileage`, only `instance.condition`, or only `instance.trim` changes at least one band — one test each (D3).
4. KBB output carries `private_party`; Manheim output never does; Manheim carries `wholesale` and KBB never does.
5. Blend: full, partial (missing bands **absent**, not `0`), total-failure, and foreign-`vehicle_instance_id` discard.
6. Blend `captured_at` equals the oldest surviving contributor's.
7. `toVehicleData` stamps `vehicle_instance_id` from the instance and never emits `vin` or `fetched_at`.
8. `@ts-expect-error` tests: an instance with no VIN cannot be passed to `decodeVin` / `getRecalls` / `getHistory` (D10).
9. Public-surface tests: no provider-shaped type is reachable through any of the four aliases (AC-5).
10. Grep-style gates: no `http`, no `fetch`, no credential/env read in `valuation`, `vehicle-history`, `credit-prequal`; `fetch` in `nhtsa` only, and the default suite never reaches it.
11. All four packages pass `npx tsc -p packages/adapters/<pkg> --noEmit` and `npx vitest run packages/adapters/<pkg>` with **no network** (AC-12).
